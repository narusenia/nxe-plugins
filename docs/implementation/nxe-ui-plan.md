# nxe-ui 実装計画

> 最終更新: 2026-08-25

`crates/nxe-ui` は全プラグインが共有する Vizia ウィジェットとテーマ。守るべき
規約は [`../../.agents/rules/vizia.md`](../../.agents/rules/vizia.md)、置き場所と
依存の向きは [`../specifications/architecture.md`](../specifications/architecture.md)。

状態は [`backlog.md`](backlog.md)、順序の根拠は [`roadmap.md`](roadmap.md)。

## 方針

**nih-plug を知らない。** ウィジェットは値とコールバックしか受け取らない。
この境界があるから `examples/gallery` が単体のデスクトップアプリとして起動でき、
DAW を開かずに UI を反復できる。

**gallery に無いウィジェットは作らない。** 追加は同じ変更で gallery にも並べる。
並んでいないものはレビューされない。

**widget にするのは描画かふるまいを持つものだけ。** Panel / Section / Row /
Label / Divider / Disclosure は CSS のクラスと Vizia 組み込みの `Button` で
足りる。これらを widget にすると数が増えて意味が増えない。

## コンポーネント一覧

| ウィジェット | 単位 | 誰が使うか |
|---|---|---|
| `Knob` | UI-4 | Doubler のマクロ層 |
| `Bar` | UI-5 | Doubler の Detail 表 |
| `SegmentedControl` | UI-6 | Doubler の `Voices` / `Source` |
| `PolarField` | UI-7 | Doubler の Voice Field |
| `CurveView` | UI-10 | Doubler の Filter View |
| `Meter` | UI-8 | まだ誰も使わない（下記） |
| `ToggleSwitch` | UI-9 | まだ誰も使わない（下記） |

`Meter` と `ToggleSwitch` は Doubler が使わない。それでも先に作るのは、
レベルメーターと on/off トグルはダイナミクス系・ディストーション系・bypass を
持つ何かで必ず必要になるため。**代償として実戦で検証されないまま gallery に
並ぶ**ので、最初に使うプラグインが出た時点で仕様を見直す前提で置く。

## 実装単位

### UI-1 — クレート骨格・テーマ・gallery ✅

`crates/nxe-ui` を作り、テーマトークンと CSS の土台を置く。トークンの一覧と値は
[`../../plugins/doubler/docs/specifications/ui.md`](../../plugins/doubler/docs/specifications/ui.md)
の「トークン」節が正（shadcn / IntentUI 系のニュートラル多段 + アクセント 1 色）。

**トークンは Rust の定数を正とし、CSS はそれを埋め込んで生成する。** カスタム
描画のウィジェットは Rust 側で色を必要とするので、CSS を正にすると二重管理に
なる。Vizia の CSS が custom property をどこまで解釈するかにも依存させない。

`examples/gallery.rs` が単体で起動し、トークンの色見本、角丸 3 段、間隔の
5 段、文字の 2 段、CSS のクラス（Panel / Section / Row / Label / Divider）を
並べる。

- **完了条件**: `mise run gallery` でウィンドウが開き、上記の見本が見える。
  色のリテラルが CSS にも `View::draw` にも直接書かれていない（すべて
  `theme` モジュール経由）。`nxe-ui` の依存に nih-plug が無い
- **依存**: INFRA-1

### UI-2 — Lucide アイコン ✅

`lucide.ttf` を埋め込んで `cx.add_font_mem()` で登録し、Lucide の
`font/info.json` から名前 → コードポイントの定数モジュールを生成する。生成物は
手で編集しない。

- **完了条件**: `nxe_ui::icon::CHEVRON_DOWN` のように参照して描ける ✅。gallery に
  使用するアイコンの一覧が並ぶ ✅。生成手順が書かれている ✅
  （`scripts/generate-icons.py` の docstring と `mise run icons:generate`）
- **依存**: UI-1
- **踏んだ罠**: **スタイルシートの `font-family` は埋め込みフォントを選ばない**
  （このピン留めされた vizia リビジョンでは）。宣言はパースされ変換コードも
  正しく見えるのに、フォールバックフェイスからグリフが来る。コードポイントが
  私用領域にあるため、**失敗が「無関係な CJK のグリフ」として描かれる**ので
  フォントファイルが壊れているように見える。`icon::label` が modifier で
  ファミリを指定する形にし、`.icon` クラスは色だけを持つ。`.icon` が
  `font-family` を含まないことをテストで固定した

### UI-3 — 共通の入力ふるまい ✅

`Knob` と `Bar` が共有する操作を 1 箇所に置く。個々のウィジェットで再実装
させない。

- 縦ドラッグで変更、`Shift` で微調整
- ダブルクリックで既定値に戻す
- `Ctrl` + クリックでインラインのテキスト入力（ダブルクリックはリセットに
  使うので別のキーに割り当てる）
- ホバーでツールチップ。表示文字列は呼び出し側が渡す
- ドラッグの開始と終了をコールバックで通知する（ホストのオートメーション記録を
  1 操作にまとめるために、プラグイン側が必要とする）

- **完了条件**: 5 つのふるまいが動く ✅。ドラッグ開始／終了のコールバックが
  1 回ずつ呼ばれる ✅
- **依存**: UI-1
- **決めたこと**:
  - **`UI-4`（Knob）と同時に実装した。** `UI-3` 単体では gallery に並べるものが
    無く、確認用のダミーウィジェットを作って後で捨てることになる。コミットは
    分けてあるので `UI-3` だけ revert できる
  - 値の直接入力は **`Cmd`（または `Ctrl`）+ クリック**。macOS では `Ctrl` +
    クリックが OS レベルで副ボタンになり、右クリックはホストのパラメータ
    メニューの領分なので
  - 値の算術（`Drag::value_after`）は純粋関数に切り出した。ここが壊れることが
    一番多いので、ウィンドウなしでテストできる形にしてある
  - **ツールチップ**（2026-08-26）: vizia の `.tooltip(…)` モディファイアが
    ビューの生成とホバーでの表示まで持っているので、`nxe-ui` がするのは
    **見た目を決めることだけ**。遅延はトランジションの中にある（500 ms）—
    ノブの列を横切るときに箱の跡が残らないように
  - **値の直接入力**（2026-08-26）: **数値ラベル自身が入り口**（`ValueEntry`）。
    ノブに `Cmd` + クリックする案から変えた — ノブにはテキスト欄を置く場所が
    無く、単位も解析も知らない。数値の上は人が最初に打ち込もうとする場所でもある
  - 解析は**パラメータ自身が持つ** nih-plug の `string_to_normalized_value`。
    `-3 dB` も `L70` もそれを意味するパラメータが読む。読めない文字列は
    値を変えない
  - 打ち込みも**1 組のジェスチャー**としてホストに届ける。ドラッグと同じ扱い
  - Detail 表の数値は**実効値**（マクロ × 形状）で、その積を持つものが無いので
    入力できない。編集は隣のバー
  - `Gesture::Edit` は通知として残す（ノブ側から拾いたい呼び出し側のために）

### UI-4 — Knob ✅

弧を `View::draw` で描く。大小 2 サイズ。値は正規化 0–1、表示は呼び出し側の
文字列。

- **完了条件**: gallery に大小が並び、UI-3 のふるまいが効く ✅。弧の描画が
  0 と 1 の端で破綻しない ✅
- **依存**: UI-3
- **決めたこと**:
  - **vizia の組み込み `Knob` は使わない。** `Lens` 前提で `on_changing` しか
    無く、プラグインが必要とする**ジェスチャーの開始と終了**を通知できない
    （ホストがオートメーションを 1 回の編集として記録できなくなる）。
    Shift 微調整・ダブルクリックリセット・値入力を閉じた view の外から足す道も
    無い
  - 値は `impl Res<f32>` で受ける。静的な `f32` とレンズの両方を受けられる
    vizia の仕組みなので、`nxe-ui` が nih-plug を知らないまま、プラグイン側は
    レンズを渡してオートメーション由来の更新を受け取れる
  - 弧に accent → accent-bright のグラデーションを掛けている。`ui.md` が
    「1 箇所だけ許す例外」としたところ

### UI-5 — Bar ✅

横方向の細いスライダ。塗りが値、右に呼び出し側の文字列。

- **完了条件**: gallery に並び、UI-3 のふるまいが効く（ドラッグは縦）✅
- **依存**: UI-3
- **決めたこと**:
  - **単極と双極の 2 形態を持つ。** Detail 表は `Delay_i` / `Gain_i` が単極、
    `Detune_i` / `Pan_i` が双極（中央から伸びる）。`Bar::new` と
    `Bar::bipolar` で切り替える
  - 双極のときは**中央のマークを塗りの上に描く**。バーがほぼ満杯でも「中央が
    どこか」が読めるように
  - 塗りの範囲を返す `Bar::span` を純粋関数に切り出した。双極が逆向きに伸びる
    のが一番起きやすい間違いなので、ウィンドウなしでテストしてある
  - `input.rs` をそのまま再利用できた（`UI-3` の切り出しが機能している確認）

### UI-6 — SegmentedControl ✅

ボタン列。選択中に `--accent`。2 択以上の任意個。

- **完了条件**: gallery に 2 択と 3 択が並び、クリックで選択が変わる ✅。
  キーボードの左右で移動できる ✅
- **依存**: UI-1
- **決めたこと**:
  - **`Knob` / `Bar` と違い `Lens` を要求する。** 各セグメントが「自分が選択中か」
    という反応状態を個別に持つ必要があり、それには選択値をセグメントごとに
    map しないといけない。`Res` にはその能力が無い。実際の呼び出し側（gallery の
    モデル、プラグインのパラメータ）はどちらもレンズを持っているので実害は無い
  - **`View::draw` を書かない。** 角丸の箱を並べて 1 つを強調するのは CSS の
    仕事で、スタイルシート経由にするとテーマのトランジションがそのまま効く。
    `:checked` 疑似クラスで選択中を表現している
  - ハンドラは `Arc` で共有する。vizia の `on_press` がアクションに
    `Send + Sync` を要求するため
  - **キーボード操作**（2026-08-26）: **フォーカスを持つのは行そのもの**で、
    個々のセグメントではない。1 つの選択肢なので `Tab` で 1 回止まり、
    左右で中を移動する。クリックしたときも行にフォーカスを渡すので、
    ポインタで選んだ続きをキーボードで動かせる
  - 端では**キーを consume しない**。何も起きないのに他へ渡らないのは、
    その先に別のキー操作があったときに困る
  - 現在値は**ビュー自身が持つ**（レンズからのバインドで同期）。矢印キーは
    「今どこか」を知る必要があり、`View::event` からレンズは読めない
  - フォーカスリングは `:focus-visible`。vizia は `Tab` で来たときだけ立てる
    ので、クリックした人には出ない

### UI-7 — PolarField ✅

半円の極座標フィールド。**領域知識を持たない** — 点の一覧（角度・半径・
大きさ・ラベル・有効かどうか）と、ドラッグのコールバックだけを知る。

- 半円の目盛りと外周・中心の基準点を描く
- 点をドラッグすると角度と半径を同時に通知する
- `Shift` で微調整、点のダブルクリックでリセットを通知
- ドラッグの開始と終了を通知する
- 無効な点はディム表示。ただしドラッグは許す
- 基準点（中心の ▲）は 1 個または 2 個を呼び出し側が指定する。2 個のときは
  各点がどちらの子かを線で示す（どちらの子かも呼び出し側が渡す）

- **完了条件**: gallery で 8 点を任意に動かせる ✅。基準点 1 個／2 個の両方が
  描ける ✅。点の値を外から変えると表示が追随する ✅
- **依存**: UI-3
- **決めたこと**:
  - **点にラベルを描かない。** vizia の `draw_text` は「その view 自身の
    テキスト」しか描けないので、1 つの view に 8 個の数字を別々の位置に置く道が
    無い。代わりに**ポインタが乗っている点の index を通知する**
    （`FieldGesture::Hover`）ので、呼び出し側が別の場所の対応する行を
    ハイライトできる。小さい数字 8 個より実用的
  - **`input::Drag` を再利用しない。** あちらは縦の移動を 1 つの値にする状態機械で、
    ここは点が 2 軸同時に動く。微調整の係数（`input::FINE`）だけ共有して、
    `Shift` の効き方は揃えてある
  - ドラッグは**ポインタの絶対位置ではなく掴んだ点からの移動量**で動かす。
    絶対追従だと微調整ができない
  - `FieldPoint` に vizia の `Data` を実装した（バインディングの変更検出に必要）。
    `PartialEq` があるので 1 行
  - 基準点の位置は呼び出し側が渡す。「モノなら中央 1 個、ステレオなら左右 2 個」は
    領域知識なので、ウィジェットが決めてはいけない

### UI-10 — CurveView ✅

曲線表示。**領域知識を持たない** — 折れ線の集合、帯の区間、目盛りの x 位置、
縦ドラッグ可能なハンドルしか知らない。座標はすべて正規化（`x` は 0..1、`y` は
0..1 で 0.5 が基準線）。

- 目盛り線と基準線を描く
- 折れ線を任意本数、帯をその背後に描く
- ハンドルを縦ドラッグすると値を通知する。`Shift` で微調整、ドラッグの開始と
  終了も通知する

- **完了条件**: gallery で折れ線と帯が描け、ハンドルを縦に動かせる ✅。
  値を外から変えると表示が追随する ✅
- **依存**: UI-3
- **決めたこと**:
  - **対数軸をウィジェットに持たせない。** 当初「対数の横軸と目盛り」を
    ウィジェットの仕事にしていたが、周波数 → 0..1 の写像を呼び出し側が持つ形に
    変えた。理由は 2 つ: (1) ウィジェットが完全に領域非依存になる、
    (2) **軸ラベルを呼び出し側が置ける** — vizia の `draw_text` は view 自身の
    テキストしか描けないので、ウィジェットは自分の目盛りにラベルを付けられない。
    写像を呼び出し側が持っていれば、同じ写像でラベルを絶対配置できる
  - 縦方向の値の算術は `input::Drag::value_after` をそのまま使う。ハンドルと
    ノブが同じ移動量で同じだけ動き、`Shift` の効きも揃う
  - **ハンドルの掴み判定は横方向の距離だけ**で行う。ハンドルは x 固定なので、
    y も近いことを要求すると「上端まで上げたハンドルを引き下ろせない」になる
  - `y` は 0..1 で 0.5 が基準線（`Bar::bipolar` と同じ流儀）。dB → 0..1 の
    写像は呼び出し側

### UI-8 — Meter

レベルメーター。**Doubler は使わない**（上記）。縦・横の両方向、ピークホールド
付き。値は呼び出し側が dB で渡す。

- **完了条件**: gallery で値を動かすと追随し、ピークホールドが減衰する
- **依存**: UI-1

### UI-9 — ToggleSwitch

on/off。**Doubler は使わない**（上記）。

- **完了条件**: gallery でクリックで切り替わり、状態が見て分かる
- **依存**: UI-1
