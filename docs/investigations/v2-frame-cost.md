# v2 の窓の描画コスト（V2-3 / V2-7）

**2026-11-24 の途中経過。standalone では予算の境目（約 10 %）。判定はホストで。** 決定 9 の予算は「1 コアの 10 %、
v0.2.0 の gallery 計測と同じ条件」。測り方は
[`ui-frame-cost.md`](ui-frame-cost.md) と同じで、起動後しばらく置いてから
`ps -o cputime=` の 20 秒の差分を取る。窓は前面。macOS、release ビルド。

## 数字

| 何を | 条件 | 1 コアに対して |
|---|---|---|
| `nxe-egui` の gallery（全部品） | 毎フレーム再描画（画面のリフレッシュ毎） | 18.3 % |
| 同 | 30 Hz、平滑化なし（`NXE_GALLERY_RAW=1`） | 17.2 % |
| 同 | 10 Hz、平滑化なし | 4.7 % |
| **何も描かない eframe の窓** | 30 Hz | **12.6 %** |
| Doubler 2 の standalone、窓なし（`--headless`） | 音声処理だけ | 2.9 % |
| **Doubler 2 の standalone、窓あり** | 無音（10 Hz で解析を見に行く） | 7.4 %（窓の分 約 4.5 %） |
| 同 | 音がある扱い、60 Hz | 20.8 %（窓の分 **約 18 %**） |
| 同 | 音がある扱い、**30 Hz** | 13.0 %（窓の分 **約 10 %**） |

「音がある扱い」は、再描画の判定を一時的に常に「音あり」にして測った
（standalone の入力はマイクで、許可のダイアログが出るので音を通していない）。
窓の分は、窓ありから `--headless` の 2.9 % を引いた値。

## 分かったこと

- **gallery の数字はプラグインの窓のコストではない。** 何も描かない eframe の
  窓が 30 Hz で 12.6 % を使う。プラグインは truce-egui の別の経路（baseview +
  自前の wgpu）で描くので、**判定はプラグインの窓で取る**
- **truce-egui は遅延付きの再描画要求を「今すぐ」と扱っていた。**
  `egui::Context::has_requested_repaint()` は `request_repaint_after(100 ms)`
  でも true を返し、truce-egui の描画の判定がそれを見ていたので、遅延は一度も
  守られず毎ティック描いていた。`patches/truce-egui` で判定から外し、遅延は
  egui が返す `repaint_delay` だけで扱う（上流へ送るもの）
- **truce-egui は入力かパラメータが変わったときしか描かない。** 解析の受け渡しは
  どちらでもないので、無音で開いた窓は再生が始まっても気づかない（CodeRabbit の
  指摘、#16）。窓が自分で 100 ms ごとに見に行き、音がある間は 30 Hz で描く
- **60 Hz は予算に入らなかった（約 18 %）。30 Hz で約 10 %。** 平滑化の再描画の
  上限を 30 Hz にした（`smooth::FRAME`）。`sample` で見ると、Doubler の `view`
  自体は小さく、残りは truce-egui の描画と GPU の受け渡し

## 残り（人の手）

**音を通したホストで測る。** 無音では解析の受け渡しが全部ゼロで、「信号が
動いている窓」の条件にならない。standalone の入力はマイクで、許可の
ダイアログが出るので自動では取っていない。

```bash
cargo truce install --user --clap --vst3 --au2 -p doubler
# 音を通したトラックに挿し、窓を前面に開いて
sample <daw-pid> 5 -f ~/Desktop/doubler2.txt
```

**30 Hz で境目にいる。** ホストで 10 % を超えたら、次に削るのは Voice Field の
背後の扇（24 個の多角形）と、Tone のスペクトラムの塗り（列ごとの四角形）。
