# v2 の窓の描画コスト（V2-3 / V2-7）

**2026-11-24 の途中経過。予算の判定はまだ。** 決定 9 の予算は「1 コアの 10 %、
v0.2.0 の gallery 計測と同じ条件」。測り方は
[`ui-frame-cost.md`](ui-frame-cost.md) と同じで、起動後しばらく置いてから
`ps -o cputime=` の 20 秒の差分を取る。窓は前面。macOS、release ビルド。

## 数字

| 何を | 条件 | 1 コアに対して |
|---|---|---|
| `nxe-egui` の gallery（全部品） | 毎フレーム再描画（画面のリフレッシュ毎） | 18.3 % |
| 同 | 60 Hz 上限 | 18.4 % |
| 同 | 30 Hz、平滑化あり | 18.8 % |
| 同 | 30 Hz、平滑化なし（`NXE_GALLERY_RAW=1`） | 17.2 % |
| 同 | 10 Hz、平滑化なし | 4.7 % |
| **何も描かない eframe の窓** | 30 Hz | **12.6 %** |
| **Doubler 2 の窓**（`cargo truce run -p doubler`） | 無音、入力なし | **3.6 %** |

## 分かったこと

- **gallery の数字はプラグインの窓のコストではない。** 何も描かない eframe の
  窓が 30 Hz で 12.6 % を使う。`sample` で見るとメインスレッドはほぼ
  `CAMetalLayer nextDrawable`（同期待ち）で、egui の組み立てと分割は全体の
  1.5 % ほど。部品の上乗せは約 4.5 % で、残りは eframe + wgpu の表示の経路。
  プラグインは truce-egui の別の経路（baseview + 自前の wgpu）で描くので、
  **判定はプラグインの窓で取る**
- 平滑化（`nxe_egui::smooth`）は動いている間だけ再描画を頼む。頼む間隔は
  **60 Hz を上限にした**（`smooth::FRAME`）。120 Hz の画面で「毎フレーム」
  にすると、目には同じ動きに倍の仕事をする
- Doubler 2 の窓は無音で 3.6 %。`Humanize` の揺れで点が常に動くので、無音でも
  描き続けている

## 残り（人の手）

**音を通したホストで測る。** 無音では解析の受け渡しが全部ゼロで、「信号が
動いている窓」の条件にならない。standalone の入力はマイクで、許可の
ダイアログが出るので自動では取っていない。

```bash
cargo truce install --user --clap --vst3 --au2 -p doubler
# 音を通したトラックに挿し、窓を前面に開いて
sample <daw-pid> 5 -f ~/Desktop/doubler2.txt
```

10 % を超えたら、まず `Humanize` の揺れを「値が変わったときだけ」にする
（今は常に描き直している）。
