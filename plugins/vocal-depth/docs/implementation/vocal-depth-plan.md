# Vocal Depth — 実装計画

> 最終更新: 2026-08-28

要件は [`../requirements/REQ-VDP.md`](../requirements/REQ-VDP.md)。
**DSP 仕様は書けた**（[`../specifications/dsp.md`](../specifications/dsp.md)、
2026-08-28）— 式・係数・時定数・耳で詰める定数の一覧まで入っている。
**数字は 1 つも測っていない。** **`ui.md` は未作成**で、`VDP-9` の前に書く。

**単位ごとに「完了条件」を満たしてからコミットする。** 完了条件は「動いた」
ではなく**測れること**で書く。

## 順序の考え方

```text
VDP-1  初期反射 ✅            ← v1 で唯一の新規 DSP。core もここで作った
VDP-2  直接音 ✅
VDP-3  DEPTH とラウドネス正規化 ← ゲート。**実装済み、判断待ちで未通過**
VDP-4  ラッパとパラメータ      ← ここで音が出る
VDP-5  DAMPING
VDP-6  距離依存のステレオ幅
VDP-7  CLARITY
VDP-8  詰め（レート・ブロック・極端値）
VDP-9  UI マクロ層と Advanced
VDP-10 UI の図
VDP-11 読み値・メーター・解析の配線
VDP-12 CPU 予算
VDP-13 既定値と耳
```

**ゲートが 1 番目ではない**（Air / Velour / Sparkleur とここが違う）。
`REQ-VDP-008`「`DEPTH` を動かしてもラウドネスが変わらない」は**連動する項が
全部揃って初めて測れる**ので、材料を 2 つ作ってから 3 番目に置く。
**それでもゲートであることは変わらない** — 崩れたら `DEPTH` を 1 本のマクロに
した意味が消え、パラメータの意味づけごとやり直しになる。

**`VDP-4`（ラッパ）が `VDP-5`〜`VDP-7` より前。** Velour の `VEL-5`、Air の
`AIR-4` と同じ判断。`DAMPING` の「布を被せた音にならない」も `CLARITY` の
「戻しすぎない」も**効いたかの判断が耳寄り**なので、音が出る状態を先に作る。

**共有クレートに上げるものが 2 つある**（`dsp.md` で出た。**当初「新規単位が
無い」と書いていたのを直した**）。どちらも数十行なので単位は起こさず、
下の `VDP-1` / `VDP-3` の中で片付ける。

| 何 | どこから | どの単位 | なぜ |
|---|---|---|---|
| `delay::DelayLine` | `doubler-core` から**移動** | `VDP-1` | **2 個目の客が要求した。** 整数読み `read_whole` を足す（タップ時刻が動かないので補間が要らない） |
| `biquad::Coefficients::magnitude` | **新規**（6 行） | `VDP-3` | 信号を見ない正規化が振幅特性を要求する |

`REQ-VDP-015` が要求する残りの既存ブロックは全部 `nxe-audio` にある。
**唯一の新規 DSP は初期反射**で、それは `vocal-depth-core` に置く
（`nxe-audio` に上げるのは 2 個目の客 = Vocal Glue が要求したとき）。

## Air から増えている道具

`AIR-*` で共有側に足したもの。**同じものを書き直さない。**

| | 何 |
|---|---|
| `nxe_audio::envelope::Power` | 二乗 → 非対称 1 次のパワーフォロワ。時定数は呼び出し側 |
| `nxe_audio::envelope::coefficient` | 秒 → 1 次係数。3 箇所に同じ式があったのをまとめた |
| `nxe_audio::guard::retune` / `set_thresholds` | 帯としきい値を**状態を保ったまま**動かす。作り直すと参照フォロワが空になり、相対検出器は空の参照に対して無限に harsh に見える |
| `nxe_ui::dots::DotField` | **Vocal Depth では使えない見込み。** 「足した層」を描く図で、こちらは原音そのものが処理を通る（`REQ-VDP-001`）。図は `VDP-10` で別に決める |

### VDP-1 — 初期反射 ✅

`reflections.rs`。**`vocal-depth-core` クレートもここで作った**
（`VEL-1` / `SPK-2` / `AIR-1` と同じ位置）。テスト 11 本、ワークスペース全体で
**474 → 486 本**。

タップ付き遅延 + 拡散のオールパス数段。**畳み込みも IR も使わない** —
距離で連続的に変化させる必要があり、IR は補間できない（`REQ-VDP-003`）。

- **完了条件**:
  - [x] `ROOM` = 0 で反射が**ちょうど**無音 — 追従が終わったあと厳密に 0
  - [x] 反射の遅延が **10〜120 ms** に収まる — 120 ms 以降 **−25.5 dB**、
        250 ms 以降 −140.7 dB、**500 ms 以降は厳密に 0**
  - [x] `DEPTH` を連続的に動かしてもクリックが出ない — **0.36 対 対照 88**
  - [x] 無音を入れて **3 秒以内に完全に無音** — **0.150 s**
  - [x] 44.1 / 48 / 96 / 192 kHz で遅延が**秒で**一致する — **0.08 dB 以内**
  - [x] `vocal-depth-core` の外から使える形（Glue が借りる）— `Settings` を
        取るだけで、`DEPTH` も `ROOM` も名前として知らない
  - [x] hostile な値で非有限を出さない — 入口で 1 回消毒（`SPK-9`）
- **要件**: REQ-VDP-003, REQ-VDP-015, REQ-VDP-017
- **依存**: なし
- **決めた**（`dsp.md`）: **タップ時刻は 1 サンプルも動かさない。** `DEPTH` は
  タップ列に掛かる**重み包絡**（幅 σ = 0.45 のガウス窓）の中心を動かす。
  補間もクリックも、掃いている間の detune も発生しない。要件が
  「`ROOM` が量、`DEPTH` が比」と言っているので、部屋の寸法は `DEPTH` の
  担当ではない
- **決めた**（`dsp.md`）: **素数 ms を L/R で交互に取る。** 素数なのでどの
  タップも他の小さい整数倍にならず、L と R は時刻を 1 つも共有しない
  （これが反射の相関を下げる唯一の機構。実測の相関 **−0.006**）
- **動いた**（実測）: **本数 13 → 10 本、最後のタップ 113 → 89 ms。**
  **拡散の尾は最後のタップにも乗る**ので、113 ms まで置くと**エネルギーの
  3 分の 1 が 120 ms の外**に出た（−4.6 dB）。`dsp.md` に「120 ms までに
  9 周して −47 dB」と書いていたのは**インパルスに対する**尾の計算で、
  タップ 1 本ごとの尾を数えていなかった
- **動いた**（実測）: **オールパスは `g` 0.55 → 0.45、最長 11.9 → 7.9 ms。**
  尾の長さを決めるのは**最長の段 × 周回数**。3 段・タップ列の前は変えていない
  （後ろに置くと 10 本それぞれに 3 段が要る。直達項 `−g·x` に遅れが無いので
  前に置いても 10 ms より早くエネルギーが出ない）
- **増えた**（実測）: **重みとバスのゲインを 5 ms の 1 次でスムーズする。**
  「重みを動かすだけだからクリックは出ない」は間違いで、**重みを動かすことは
  ゲインを動かすこと**。段が背景の 11 倍出た
- **決めた**（`dsp.md`）: **遅延線は書かない。** `doubler_core::delay::DelayLine`
  が要るものだったので `nxe-audio` に上げ、整数読みを 1 本足す
- **見込んでいる罠**: **遅延線の長さはサンプル数、時刻は秒。** 192 kHz で
  120 ms は 23 040 サンプルで、44.1 kHz の 5 292 の 4 倍以上。**確保は
  `initialize` で最大レートぶん**（`.agents/rules/rust.md`）
- **消えた罠**: **タップ時刻を動かすと補間が要る**、は上の判断で消えた。
  **動かさないので補間も detune も無い** — 代わりに**整数読み**で 10 本を
  読めるようになり、CPU が Catmull-Rom の 4 分の 1 で済む
- **踏んだ罠**: **対照実験が本番とほぼ同じ数字を出した。** ゲインを 4 分の 1 に
  跳ばす対照が 104.89、直したはずの本番が 104.94。理由は算術で、
  **`0.22` へ跳ぶのも `1.78` へ跳ぶのも 1 からの 0.78 の段**。
  **どちらが外れ値か分からない対照実験は対照実験ではない** —
  今は「同じ動きをスムージング無しで」やる形（`Channel::snap`）にしてある
- **踏んだ罠**: **1 次の追従は目標に着かないことがある。** 歩幅
  `remaining · coefficient` が重みの ulp を下回ると加算が何も変えなくなり、
  収束は `ulp(w) / coefficient` ≒ **7e-6** で止まる。しきい値を `1e-6` に
  置いていたので**永遠に「まだ動いている」**状態になり、無音でも毎サンプル
  スムージングを回していた。`1e-4`（重みの 70 dB 下）に上げた
- **見込んでいる罠**: **オールパスの尾はデノーマルへ落ちる。** ホストの中では
  nih-plug が FTZ を立てるので実害は無いが（`SPK-17`）、**テストはホストの
  外で走る**ので「3 秒で無音」は自分で床を切らないと通らない

### VDP-2 — 直接音 ✅

`direct.rs`。Presence の動的な**並列帯**（2〜5 kHz）と Transient の検出。
テスト 9 本、ワークスペース全体で **486 → 495 本**。

**シェルフではなく並列帯**（`dsp.md`）。`nxe_audio::biquad` にシェルフが無く、
シェルフだと 5 kHz より上も動いて `DAMPING` と帯域を取り合う。Velour と
Sparkleur と同じ `BandPass` を並列に足す形。**要件の 1 行を直した。**

- **完了条件**:
  - [x] `DIRECT` を動かすと 2〜5 kHz と Transient が**同時に**動く —
        帯域差 **14.79 dB**、うち Transient が **2.79 dB**
  - [x] Transient の鈍化が子音を潰しきらない — 上限 6 dB に対し **2.79 dB**
  - [x] 検出器が入力ゲインに依らない — ±12 dB で 0.2 dB 以内
  - [x] 新しい検出器を作っていない — `nxe_audio::envelope::Power` を 2 本、
        両方対称。リリースは比の後ろのホールド（60 ms）
- **要件**: REQ-VDP-004
- **依存**: なし
- **決めた**: **`DIRECT` と `DEPTH` を「近さ」1 本にまとめた。**
  `REQ-VDP-004` の受入条件が「`DIRECT` を動かすと 2〜5 kHz と Transient が
  同時に動く」なので、`dsp.md` の当初の式（Transient は `d` だけの関数）では
  条件を満たせなかった。`DIRECT` = 0.5 で従来と一致する形にしてある
- **動いた**（実測）: **Transient の検出を 2〜8 kHz の帯域通過の後ろに置いた。**
  子音の居場所であり、**`SNAP_RANGE_DB` を Air から借りる条件**でもある
  （`AIR-5` が同じことを要求している）
- **動いた**（実測）: **「定常状態で係数が厳密に 1」は間違いだった。**
  **正弦のパワーは周波数の 2 倍でリプルする**ので、2 ms のフォロワはその一部を
  追う。純音 110 Hz で開き具合 **0.204**。Air も定常正弦に 0.023 を出している
- **見込んでいた罠を踏まなかった**: フォロワは最初から両方対称にした（`SPK-6`）。
  ただし**対称性のテストを間違えた** — 立ち上がりを 63 % で止めてそこから
  立ち下がりを測ると 1 時定数が 0.54 τ になり、**対称なフォロワが 96 対 52 の
  非対称に見えた**。**折り返す前に落ち着かせる**
- **踏んだ罠**: **段のテストが零交差の上に落ちた。** 3 kHz は 48 kHz で
  16 サンプル周期なので、12 000 サンプル目はちょうど零交差。帯域の出力がそこで
  ほぼ 0 なので**段に掛ける相手が無く、対照実験まで 1.00 になった**。
  周期の整数倍を避ける（12 007）
- **踏んだ罠**: **開き具合から dB を見積もると悲観的すぎる。**
  「0.204 × 3 dB = 0.6 dB」は予算を越えるが、**110 Hz の純音は Presence 帯に
  エネルギーを持たない**。**Transient を切った同じ走行と比べる**と純音
  0.045 dB / ピンク 0.000 dB（予算 0.3 dB）。**測る対象を間違えると設計を
  作り直しかける**

### VDP-3 — DEPTH とラウドネス正規化（ゲート）🟡 **判断待ち**

`depth.rs` / `engine.rs`。連動マクロと、**距離とラウドネスの分離**。
実装は入っていて、テスト 12 本、ワークスペース全体で **495 → 511 本**。
**完了条件のうち 1 つが素材によって通らない**（下）。

- **完了条件**:
  - [x] 広帯域素材で `DEPTH` 全域の RMS が ±0.5 dB 以内 —
        **ピンク 0.14 dB / ホワイト 0.19 dB**
  - [ ] **疎な倍音列のフレーズで 1.39 dB**（要求は 0.5 dB）。
        **原因は判明していて、残っているのは判断**（下）
  - [x] 同じことが `MIX` の各点で成り立つ（広帯域素材で）
  - [x] `ROOM` を動かしてもラウドネスが動かない
  - [x] 正規化が**信号に依存していない**（4 素材で係数が完全一致）
  - [x] 測定が失敗できることを確かめた — 正規化を 1 に固定すると同じ掃引が
        **1.29 dB** 動く
- **要件**: REQ-VDP-002, REQ-VDP-008
- **依存**: VDP-1, VDP-2
- **決めた**（`dsp.md`）: **固定した 32 点のピンク重み格子の上で、直接音と
  反射のパワーを解析的に足して割る。** wet 経路は遅延と LTI フィルタだけなので
  時間領域で回す必要が無く、**振幅特性の 2 乗和で閉じる**（`shaper` の `g` は
  プローブ正弦を 64 点で積分するが、あちらは非線形だから）。
  `Coefficients::magnitude` をここで足す
- **決めた**（`dsp.md`）: **オールパスは式に入らない**（総エネルギーを
  変えない）。**Transient と `CLARITY` も入らない** — どちらも信号依存で、
  Transient の寄与は実測 **0.045 dB**（予算 0.3 dB）
- **動いた**（実測）: **Presence は並列帯ではなくピーキング。**
  並列帯 `x + (G−1)·BP(x)` は **`G` < 1 で帯域を下げない** — 帯域通過の位相の
  ぶん裾が持ち上がり（最悪 8.6 kHz で +0.57 dB）、名目 6 dB の cut が
  **0.18 dB しか減らさなかった**（ピーキングなら 0.71 dB）。
  `nxe_audio::biquad::Coefficients::peaking` を足した。
  **`REQ-VDP-004` が元々「シェルフ」と書いていたのは正しかった**
- **動いた**（実測）: **プローブの重みは対数格子の上では一様。**
  `1/f` を掛けると二重に傾き、**20 Hz が 3 kHz の 150 倍**になっていた。
  Presence 帯が総和に届かず、正規化が直す材料を持っていなかった
- **分かった**（実測）: **`REQ-VDP-008` の受入条件は素材を跨いでは満たせない。**
  Presence 帯の割合はピンク 10.3 % / ホワイト 13.4 % / フレーズ 1.2 % で、
  信号を見ない補正はどれかを選ぶしかない。補正率を振った表は `dsp.md` に
  あり、**最良の最悪値は 0.8 dB**（ホワイトを外して 0.62 dB）。
  **テイル・測り方・タップのコヒーレンスは 3 つとも測って否定した**
- **判断が要る**: `PRESENCE_COMPENSATION`（今 1.0）を下げるか、Presence の
  可動域を狭めるか、要求を緩めるか。**反射側は素材によらず正確**なので、
  壊れているのは帯域 EQ の項だけ
- **見込んでいる罠**: **信号依存の正規化にしない**（`REQ-VDP-008`）。
  素材ごとに `DEPTH` の効きが変わるほうが問題として大きい。`shaper` が
  同じ判断をしている
- **見込んでいる罠**: **ピンクノイズで測る。** ホワイトは「普通の素材」の
  代理ではない — 帯域幅の都合だけで上が持ち上がる
  （`nxe_audio::harmonics::pink`）

### VDP-4 — ラッパとパラメータ（ここで音が出る）

`vocal-depth` クレート。パラメータ宣言、`process()`、`MIX`。**UI はまだ持たず、
ホストの既定パラメータ UI で音を確認する。**

- **完了条件**:
  - [ ] `MIX` = 0 で出力が入力と**ビット一致**（原音は最初に分岐する、
        `REQ-VDP-001`）
  - [ ] 2→2 と 1→2 の両方のレイアウトで動く
  - [ ] 4 ホストで CLAP と VST3 が読み込まれる
  - [ ] `mise run bundle vocal-depth` / `install vocal-depth` が通る
  - [ ] `CLAP_ID` は `com.nxe.vocaldepth`。**出荷後に変えられない**
- **要件**: REQ-VDP-001, REQ-VDP-011, REQ-VDP-012, REQ-VDP-014
- **依存**: VDP-3
- **決めること**: **報告するレイテンシ。** Air と違い**遅延線がある** —
  初期反射は原音より遅れて来るものなので 0 で正しいはずだが、
  `REQ-VDP-012` を読んで確定する
- **見込んでいる罠**: **作ったばかりの `FloatParam` のスムーザは 0 から
  始まる**（`AIR-13`）。ホストは `initialize` で起こすが、テストがやらないと
  **全マクロが下限のプラグイン**を測ることになる。Air は層が −200 dB と出て
  「既定値は何も足していない」という harness だけの結論を一度出した。
  `defaults.rs` の `primed()` をそのまま持ってくる

### VDP-5 — DAMPING

`damping.rs`。**直接音と反射音で違う量**、Transient のときだけ高域を保つ。

- **完了条件**:
  - [ ] `DAMPING` が直接音と反射音に**違う量**で掛かる
  - [ ] Transient の瞬間に高域が保たれる（測って固定する）
  - [ ] `DAMPING` 全開でも子音が判別できる
  - [ ] `DAMPING` を動かしてもラウドネスが動かない（`VDP-3` の正規化に乗る）
- **要件**: REQ-VDP-005
- **依存**: VDP-4

### VDP-6 — 距離依存のステレオ幅

`REQ-VDP-007`。遠いほど反射の幅が広がり、直接音は中央に残る。

- **完了条件**:
  - [ ] `DEPTH` を上げると生成側の相関が下がる（`nxe_dsp::Correlation`）
  - [ ] 原音の定位が動かない
  - [ ] **モノ和で櫛形が出ない**（Air の `AIR-1` と同じ測り方。1/3 オクターブ
        帯の比のばらつきで見る、**対照実験は遅延ではなくオールパス**）
- **要件**: REQ-VDP-007, REQ-VDP-011
- **依存**: VDP-4
- **見込んでいる罠**: **こちらは位相を回す**（反射は遅延そのもの）ので、
  Air の「構造的に破れない」は使えない。**谷の深さを測って許容量を決める**

### VDP-7 — CLARITY

`REQ-VDP-006`。落ちすぎた明瞭度を戻す機構と、**働いた量の公開**。

- **要件**: REQ-VDP-006, REQ-VDP-018
- **依存**: VDP-5

### VDP-8 — 詰め

- **完了条件**:
  - [ ] ブロックサイズ 1 / 64 / 512 / 4096 の出力が一致
  - [ ] 44.1 / 48 / 96 / 192 kHz で係数が発散しない
  - [ ] 全パラメータの極端値で非有限値を出さず panic しない

## 見込んでいる罠（今日までに払った授業料）

`docs/HANDOVER.md` に全部あるが、Vocal Depth で特に効きそうなもの:

- **整形済みファイルへの文字列置換は黙って失敗する。** `AIR-*` で 6 回。
  **置換のあとは grep する**（`.agents/rules/rust.md`）
- **測定の側が間違っていることのほうが多い。** Air で落ちたテストの大半は
  実装ではなく測り方だった — 広い帯域通過はレートで歪む、蓋の上を測る
  フィルタは自分の裾を測る、櫛形の対照実験に遅延を使うと通ってしまう
- **しきい値は分布から置く**（`SPK-18`）。p50 / p95 / max を並べてから。
  **末尾の 1 サンプルの引き量で決めない**
- **「普通の素材で動かない」は 2 音のテストでは守れない。** 広帯域で測る
- **測定が失敗できることを同じテストの中で確かめる**（`VEL-10`）
