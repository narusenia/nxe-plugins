# Vocal Depth — DSP 仕様

> 最終更新: 2026-08-28

要件は [`../requirements/REQ-VDP.md`](../requirements/REQ-VDP.md)。守るべき規約は
[`../../../../.agents/rules/rust.md`](../../../../.agents/rules/rust.md)。
共有部品は `crates/nxe-audio`（`REQ-VDP-015`）。

**この文書と実装が食い違ったら実装が正。** 同じ変更でこの文書を直す。

**実装は 1 行も書いていない。** ここに書いてある数字は**全部設計時の値で、
1 つも測っていない**。「耳で詰める定数」の表が、どれを測って決めるつもりで
どれが耳かの正。**測った値には `VDP-n の実測` と書く** — 書いていないものは
まだ測っていない。

## 決めたこと（`vocal-depth-plan.md` が `dsp.md` に投げた 5 つ）

計画書が「`dsp.md` で決める」としていた開いた問いに、先に答えを置く。理由は
それぞれの節にある。

| 問い | 答え |
|---|---|
| タップ時刻を `DEPTH` で動かすのか、量だけか | **動かさない。** `DEPTH` はタップ列に掛かる**重み包絡**を動かす。補間もクリックもドップラーも発生しない |
| タップの本数と時刻 | **13 本 × 2 チャネル。10〜120 ms の素数 ms を L/R で交互に取る**（下の表） |
| オールパスの段数と係数 | **3 段、`g` = 0.55、タップ列の前**（入力拡散）。全タップで状態を共有するので 1 チャネル 3 段で済む |
| ラウドネス正規化の式 | **固定した 32 点のピンク重み格子の上で、直接音と反射のパワーを解析的に足して割る。** 信号を見ない。オールパスと Transient と `CLARITY` は式に入らない（それぞれ理由がある） |
| `DAMPING` が直接音と反射に掛ける比 | **オクターブで 1.2 : 3.0。** 全開で直接音 8.7 kHz、反射 2.5 kHz |

## 信号の流れ

```text
Input (L,R)
  │
  ├──────────────────────────────── dry ──────────────────────────────────┐
  │                                                                       │
  ├─ 直接音 ─ Presence 並列帯 ─ DAMPING(軽) ─ Side 減衰 ────────┐         │
  │           × 係数_trans      ↑ Transient で戻す              │         │
  │           + 戻し量_clarity                                  │         │
  │                                                             ├ × g ──┐ │
  │                                                             │       │ │
  ├─ 反射 ─ 拡散 AP 3 段 ─ 遅延線 ─ タップ 13 本 ─┐             │       │ │
  │         （入力拡散、L/R 別）                   │             │       │ │
  │                        × 重み包絡(DEPTH) ──────┤             │       │ │
  │                        × r(DEPTH) · ROOM       ├─ HP 200 Hz ─┘       │ │
  │                        ─ DAMPING(強) ─ WIDTH(M/S) ─┘                 │ │
  │                                                                      │ │
  └─ 検出（モノ和）─ Transient / CLARITY ────────────────────────────────┘ │
                                                                           │
        out = OUTPUT · ((1 − MIX) · dry + MIX · g · (direct + refl)) ───────┘
```

**原音は入口で分岐する**（`REQ-VDP-001`）。`MIX` = 0 のビット一致はこれ 1 つで
成立する — 直接音の側にフィルタが並んでいても、`MIX` = 0 の経路はそこを通らない。

**`MIX` はクロスフェード**（`out = (1−MIX)·dry + MIX·wet`）。Air は加算型なので
`dry + MIX·layer` だったが（`REQ-AIR-012` の議論）、ここでは wet が原音を
**置き換える** — 遠ざけるとは直接音を削ることなので、原音を残したまま足すと
「削ったもの」が原音で埋め戻されて距離にならない。Sparkleur と同じ判断。

**`OUTPUT` の既定は厳密に 1.0。** `MIX` = 0 のビット一致は「1.0 倍が
ビット一致」に依存しているので、既定値を 0.99 のような数にしてはいけない。

**レイテンシは 0**（`REQ-VDP-012`）。直接音の経路にバルク遅延が無い（並列帯と
1 次/2 次フィルタだけ）。反射は遅れて来るものなので、遅延線は補償の対象では
ない。**ルックアヘッドも持たない。**

## 初期反射

**v1 で唯一の新規 DSP ブロック**（`REQ-VDP-003`）。`vocal-depth-core` の
`reflections.rs` に置き、**Vocal Depth を知らない自立したモジュールとして書く**
（`REQ-VDP-015`）— パラメータ構造体ではなく `Settings` を受け取り、
`DEPTH` も `ROOM` も名前として知らない。2 個目の客（Vocal Glue の
`Ambience Glue`）が来たらファイルの移動だけで `nxe-audio` に上がる。

### 遅延線は書かない — `doubler-core` から上げる

**`doubler_core::delay::DelayLine` がそのまま要るものだった。** 2 の冪のリング、
`new` だけがヒープに触る、`read` は NaN を最小遅延にクランプする、テスト付き。
**リポジトリの規則どおり「2 個目の客が要求した」ので `nxe-audio` に上げる**
（`SPK-1` の `shaper` / `AIR-5` の `Power` と同じ手続き）。

- 移動は `nxe-audio` に `delay.rs` を置き、`doubler-core` は `pub use` を消して
  `nxe_audio::delay::DelayLine` を使う。**`doubler-core` は出荷済みだが
  crates.io に出していない**ので、外部に見えている API を壊さない
- **足すのは整数読み 1 本**（`read_whole(delay: usize)`）。タップ時刻が動かない
  ので Catmull-Rom は要らず、13 本 × 2 チャネルの補間を毎サンプル省ける。
  **これが「タップを動かさない」判断の CPU 側の見返り**
- `Doubler` は補間読みを使い続ける（あちらは読み位置が常に小数）

**計画書の「共有クレートの新規単位が無い」はこれで誤りになったので、同じ変更で
直した。** 上げるものが 2 つ出た（もう 1 つは下の `Coefficients::magnitude`）。
どちらも数十行なので `VDP-1` / `VDP-3` の中で片付け、単位は起こさない。

### 遅延線の確保

**長さはサンプル数、時刻は秒**（`REQ-VDP-017`）。

- **確保は `initialize` で、最大レートぶん**（`.agents/rules/rust.md`）。
  120 ms は 192 kHz で 23 040 サンプル、44.1 kHz の 5 292 の 4.4 倍
- レートが決まった時点で作り直す。`process()` の中では確保しない
- `DelayLine::new` が 2 の冪へ切り上げるので、実際に取るのは 32 768 サンプル
  （128 KiB / チャネル）。**リング長がレートで変わってもタップ時刻は ms で
  同じ**

### タップ

**13 本 × 2 チャネル。10〜120 ms の素数 ms を L/R で交互に取る。**

| | 時刻 (ms) |
|---|---|
| L | 11, 17, 23, 31, 41, 47, 59, 67, 73, 83, 97, 103, 109 |
| R | 13, 19, 29, 37, 43, 53, 61, 71, 79, 89, 101, 107, 113 |

- **素数 ms なのは、どのタップも他のタップの小さい整数倍にならないため。**
  整数倍が混ざると櫛の谷が同じ周波数で重なって、色が付く
- **L と R が 1 つも時刻を共有しない。** これが反射の相関を下げる唯一の
  機構で、位相を回す処理は 1 つも置かない（`WIDTH` の M/S は最後の 1 段だけ）
- **13 本の根拠は密度**。5 本では slapback に聞こえ、25 本では拡散して
  「テイル」になる（`REQ-VDP-020` が捨てたもの）。**耳で詰める**
- 振幅 `a_i = √(T_REF / t_i)`、`T_REF` = 11 ms。エネルギーが時刻に反比例する
  形で、遅いタップは遠い面から来るという素直な近似。11 ms で 1.0、109 ms で
  **0.318（−10 dB）**
- **極性は交互**（+ − + − …）。同符号で揃えると低域が積み上がって
  「近くで膨らむ」形になる。下の 200 Hz ハイパスと二重の保険

### `DEPTH` はタップ列の重み包絡を動かす

**タップ時刻は 1 サンプルも動かさない。** 動かすのは、タップ列に掛かる窓の
中心。

```text
p_i = (t_i − 10 ms) / (120 ms − 10 ms)          タップの正規化位置
w_i(d) = exp(−(p_i − d)² / (2 σ²))              σ = 0.45
```

- `d` = 0（CLOSE）: 早いタップだけが残る → **直接音との間隔が短く、疎**
- `d` = 1（FAR）: 遅いタップに寄る → **間隔が長く、密に聞こえる**
- σ = 0.45 は「窓の中に常に 6 本以上入る」ための幅。狭くすると `DEPTH` の
  途中で 1 本だけが立って slapback になる

**なぜ時刻を動かさないか。** 3 つある。

1. **読み位置を動かすと補間が要る。** 整数サンプルで跳ばすとクリック
   （計画書が挙げていた罠）
2. **補間しても、動かしている間はピッチが動く。** 読み位置の速度がそのまま
   ドップラーで、`DEPTH` をオートメーションで掃くと反射だけが detune する。
   **これは補間の精度では消えない**
3. **要件がそれを求めていない。** `REQ-VDP-003` は
   「**`ROOM` が量、`DEPTH` が比**」。部屋の寸法は `DEPTH` の担当ではないので、
   タップ時刻は固定でよい

**距離の手がかりのうち、時刻が担っているぶんは窓が代わりに出す** — 窓が遅い側に
寄ると最初の反射までの間隔（ITDG）が実効的に伸びる。**動かしているのは重みだけ
なので連続で、クリックも detune も無い。**

### 拡散 — オールパス 3 段、タップ列の**前**

```text
L: 5.1, 7.3, 11.9 ms    g = 0.55
R: 5.9, 8.7, 13.1 ms    g = 0.55
```

Schroeder のオールパス（`y[n] = −g·x[n] + x[n−D] + g·y[n−D]`）を 3 段直列。

- **タップ列の前に置く**（入力拡散）。後ろに置くと 13 本それぞれに 3 段が要る。
  前なら 1 チャネル 3 段で全タップが拡散済みになる
- **オールパスの直達項は `−g·x` で遅れが無い**ので、拡散を前に置いても
  **10 ms より早い時刻にエネルギーが出ない**（`REQ-VDP-003` の下限）
- **総エネルギーを変えない。** これが後ろの正規化の式からオールパスが
  落ちる理由（下）
- 段の遅延も互いに素な ms。`g` = 0.55 は 1 周ごとに 5.2 dB 落ちる

**尾は 120 ms を越える。** 最後のタップが 113 ms で、その上にオールパスの
再帰が乗るため。**「テイルを持たない」を測れる形に書き直す**:

> 120 ms 以降に残るエネルギーが、反射全体に対して **−40 dB 以下**

`g` = 0.55 / 13.1 ms なら 120 ms までに 9 周して −47 dB。**設計上は通るが
測っていない**（`VDP-1`）。

### 反射のハイパス — 200 Hz、2 次

`Coefficients::highpass(200.0, BUTTERWORTH_Q)`。理由が 3 つある。

1. **濁る。** 声の基音が反射で二重になると距離ではなく「箱」になる
2. **正規化の前提を作る。** 直接音と反射のパワーを足し算にできるのは、
   両者が無相関なとき。最も早いタップが 11 ms なので **約 90 Hz より上では
   位相が回りきって無相関**になるが、その下は相関が残る。**ハイパスで
   その帯域を落としてしまえば、前提が崩れる帯域にエネルギーが無い**
3. `REQ-VDP-007` の「直接音は M にしか居ない」を、反射の低域が M を汚さない
   形で補強する

### 無音への収束

**3 秒以内に完全な 0**（`REQ-VDP-003`）。

- 遅延線は 120 ms 後に 0 で埋まる — ここは厳密
- **オールパスの再帰は 0 に到達しない**（`SPK-16` と同じ形）。`g` = 0.55 なら
  幾何級数で落ちるが、`f32` はデノーマルに座る
- **`SILENCE_FLOOR` = 1e-9 を下回ったら状態を 0 にする。** ホストの中では
  nih-plug が FTZ を立てるので実害は無いが（`SPK-17`）、**テストはホストの外で
  走る**ので自分で床を切らないと通らない
- 検出のフォロワ 2 本にも同じ床を置く

## 直接音

`direct.rs`。近さを作る側（`REQ-VDP-004`）。

### Presence は並列帯 — 要件の「シェルフ」を 1 行直した

`REQ-VDP-004` は元は「**2〜5 kHz の動的なシェルフ**、`nxe_audio::biquad`」
だったが、**`nxe_audio::biquad` にシェルフもピーキングも無い**
（`lowpass` / `highpass` / `BandPass` だけ）。**要件の 1 行を同じ変更で直した。**
採るのは並列帯:

```text
direct = x + (10^(g_pres/20) − 1) · BandPass(2 kHz, 5 kHz)(x)
```

- **シェルフではなく帯域が要件の意図に合う。** `REQ-VDP-002` の表は
  「2〜5 kHz Presence」で、シェルフだと 5 kHz より上も一緒に動く —
  そこは `DAMPING` の担当なので、2 つのパラメータが 1 つの帯域を書くことになる
- **Velour と Sparkleur が同じ形をしている**（`BandPass` を並列に足す）。
  シェルフを `nxe-audio` に足すと**新しい共有単位**になり、それは
  この製品が要求していない
- `g_pres` = 0 のとき係数が厳密に 0 になるので、**帯域を通さない状態が
  ビット一致で作れる**

`g_pres` の組み立て:

```text
g_pres = lerp(+4 dB, −8 dB, d)          DEPTH（CLOSE → FAR）
       + (DIRECT − 0.5) · 8 dB          DIRECT（独立、既定 0.5 で寄与 0）
       + 3 dB · c_t · (1 − 2 d)         Transient（CLOSE で立て、FAR で鈍らす）
       + 戻し量_clarity                 CLARITY（下）
       を ±10 dB でクランプ
```

**CLOSE と FAR が対称でない**（`REQ-VDP-002`）。上げるのは +4 dB で頭打ち、
下げるのは −8 dB まで続く。

### Transient — 対称フォロワ 2 本、定常で厳密に 1

`nxe_audio::envelope::Power` を 2 本。**新しい検出器を作らない**
（`REQ-VDP-004`）。

| | attack | release |
|---|---|---|
| fast | 2 ms | 2 ms |
| slow | 80 ms | 80 ms |

- **両方とも対称**（`SPK-6` の授業料）。非対称なフォロワを比の分子に置くと
  **定常音でも 3 dB 出て**、ゲートが開いたままになる
- **リリースは比の後ろのホールドに置く**（60 ms、1 次）
- `c_t = clamp(10·log10(fast / slow), 0, SNAP_RANGE_DB) / SNAP_RANGE_DB`、
  `SNAP_RANGE_DB` = 6 dB
- **定常状態では fast == slow なので `c_t` は厳密に 0**、つまり係数は 1。
  これが正規化の式から Transient を外せる理由（下）
- 検出は**モノ和でリンク**（`REQ-VDP-011`）
- 比なので**入力ゲインに依らない**。±12 dB で 0.2 dB 以内を測る
- **立ち上がりまでは無限に反応する**（`SPK-18`）。**100〜250 ms 捨ててから
  測る**

### 直接音の Side 減衰

`REQ-VDP-007` の「直接音の幅はやや狭く」の実装。

```text
g_side = lerp(−3 dB, 0 dB, d)      直接音の Side にだけ掛ける
```

**Side を減衰させるだけで、Side へ何も置かない。** モノ和は M しか見ないので
**失うものが無い** — これが「直接音のモノ和が無傷」の実装そのもの。

## DEPTH

`depth.rs`。1 本で 7 項を連動させる（`REQ-VDP-002`）。**曲線は Advanced に
出さない** — 出すのは各項の偏差（`REQ-VDP-009`）。

| 項 | 式 | CLOSE (d=0) | FAR (d=1) |
|---|---|---|---|
| 直接音の比 | 反射側で表現 | ↑ | ↓ |
| Presence | `lerp(+4, −8) dB` | +4 dB | −8 dB |
| 反射の量 | `r(d) = lerp(−24, −4) dB` | −24 dB | −4 dB |
| 反射の重み中心 | `w_i` の中心 `= d` | 早いタップ | 遅いタップ |
| 高域減衰 | `DAMPING` の実効量に `d` が乗る | 軽い | 強い |
| Transient | `3 dB · c_t · (1 − 2d)` | +3 dB | −3 dB |
| 直接音の幅 | `g_side = lerp(−3, 0) dB` | やや狭 | 維持 |
| 反射の幅 | `s = WIDTH · (0.6 + 0.4 d)` | 0.6 · WIDTH | 1.0 · WIDTH |

**偏差は相対**（`REQ-VDP-009`）。Advanced は上の各行に `±1` の偏差を持ち、
0 のときこの表どおりになる。**絶対量にすると 2 つのパラメータが 1 つの値を
書く。**

### `ROOM` は量

```text
ROOM_gain = ROOM^1.5 · 2.0        0 → 0（厳密）、0.5 → −3 dB、1.0 → +6 dB
```

- **`ROOM` = 0 で反射がちょうど無音**（`REQ-VDP-003`）。dB でマップすると
  0 が −∞ になって「ちょうど 0」を分岐で特別扱いすることになるので、
  **線形のべきにする**
- 指数 1.5 は「つまみの中央が −3 dB」に来るための数。**耳で詰める**
- `ROOM` と `DEPTH` は掛け算で独立 — **小さい部屋で遠い / 大きい部屋で近い**が
  どちらも作れる（`REQ-VDP-003`）

## ラウドネス正規化 — ゲート（`REQ-VDP-008`）

**`DEPTH` を動かしても出力のラウドネスが変わらない。** 崩れたら製品の主張が
成立しない。**耳ではなく単体テストで通す。**

### 式

固定した格子の上で、wet のパワーを解析的に出して割る。

```text
格子      f_k、K = 32 点、20 Hz〜20 kHz を対数等間隔（コンパイル時に固定）
重み      W_k ∝ 1 / f_k、Σ W_k = 1                      ← ピンク
直接音    P_d = Σ W_k · |H_pres(f_k)|² · |H_damp_d(f_k)|² · κ_side
反射      P_r = (ROOM_gain · r(d))² · (Σ_i w_i² a_i²)
              · Σ W_k · |H_hp(f_k)|² · |H_damp_r(f_k)|² · κ_width
正規化    g = √(1 / (P_d + P_r))、[−12 dB, +12 dB] にクランプ
```

- **`P_d + P_r` が足し算でよいのは、両者が無相関だから。** 最も早いタップが
  11 ms、しかも反射は 200 Hz でハイパスしてある（上）。**相関が残る帯域に
  エネルギーが無い**
- **オールパスは式に入らない。** 拡散は総エネルギーを変えないので
  `|H| = 1`。**3 段の係数を後から動かしても正規化を作り直さなくてよい**のは
  この性質の帰結
- **`Σ_i w_i² a_i²` はタップの非干渉和。** タップ同士も時刻が素数 ms で
  離れているので、パワーで足す
- `κ_side` / `κ_width` は M/S の項。**入力の相関に依存する**ので、
  **無相関と完全相関の中点で置く**（`κ = 2 / (1 + g²)` の形）。
  **残差は測ってゲートの予算に当てる**

### プローブは信号ではない

**`nxe_audio::shaper` の `g` と同じ考え方**で、**同じ違いがある**。shaper は
プローブ正弦を 64 点で積分して RMS を測る（`Shaper::set`）。こちらの wet 経路は
遅延と LTI フィルタだけなので、**時間領域で回す必要が無く、振幅特性の
2 乗和で閉じる**。

- **信号を見ない**（`REQ-VDP-008`）。素材ごとに `DEPTH` の効きが変わるほうが
  問題として大きい
- **ピンクで重み付ける。** ホワイトは「普通の素材」の代理ではない — 帯域幅の
  都合だけで上が持ち上がる（`VDP-3` の罠）
- 32 点の根拠は「これ以上増やしても答えが動かない」ところ。**測って固定する**
  （shaper の `PROBE_POINTS` = 64 と同じ扱い）

### `Coefficients::magnitude` を足す

`|H(f)|` が要る。`nxe_audio::biquad::Coefficients` に

```rust
pub fn magnitude(&self, hz: f32, sample_rate: f32) -> f32
```

を足す（6 行程度）。**これが 2 つ目の共有クレートへの追加**（1 つ目は
`DelayLine`）。テストは既知の 2 次バターワースのコーナーで −3.01 dB。

### 式に入れないもの、と予算の割り振り

**入れないものが 2 つある。どちらも信号依存だから。**

| | なぜ入れないか | 予算 |
|---|---|---|
| Transient | 定常状態で `c_t` が厳密に 0（= 係数 1）。**動くのは過渡だけ**で、そこはプログラムの RMS にほとんど寄る量が無い | 0.3 dB |
| `CLARITY` | 相対検出の出力なので信号依存。**普通の素材では 0**（`SPK-18` の再発防止条件）で、働くのは FAR で明瞭度が落ちたときだけ | 0.3 dB |

**静的な項（上の式）は構造として厳密**なので、`±0.5 dB` のゲートは
**この 2 つの残差にほぼ全部を使える**。合計が予算を越えたら、
**`CLARITY` の上限（6 dB）を下げる**のが先 — Transient の深さは
`REQ-VDP-004` が求めている効き幅で、`CLARITY` の上限は測って決める数だから。

### いつ計算するか

- **ブロックレート**。パラメータが 1 つも動いていなければ何もしない
  （`Shaper::set` と同じ早期 return）
- **スムージング後の値から計算する。** 前で計算すると、スムーズしていない
  係数で割ることになって `DEPTH` の掃引に段が出る
- コストは 32 点 × 4 本の `magnitude` ≈ 400 flops / ブロック。
  512 サンプルなら 1 サンプルあたり 1 flop 未満
- **ゼロ割の番人**: `P_d + P_r` が `1e-8` を下回る、または非有限なら
  `g = 1.0`（`shaper` の `GAIN_FLOOR` と同じ形）

## DAMPING（`REQ-VDP-005`）

**直接音と反射で違う量。** 同じ 1 本を両方に掛けると「こもっただけ」になる。

```text
u_d = DAMPING · (0.35 + 0.65 d)      直接音の実効量
u_r = DAMPING · (0.50 + 0.50 d)      反射の実効量

corner_d = 20 kHz · 2^(−1.2 · u_d) · 2^(TRANS_KEEP_OCT · c_t)
corner_r = 20 kHz · 2^(−3.0 · u_r)
```

- 2 次バターワースのローパス（`Coefficients::lowpass`）を各 1 本
- **全開で直接音 8.7 kHz、反射 2.5 kHz** — 1.8 オクターブ離れている。
  この比が「距離」と「布を被せた音」を分ける
- **Transient のときだけ直接音の高域を戻す**。`TRANS_KEEP_OCT` = 1.0
  オクターブ、20 kHz でクランプ。これが無いと FAR で子音が消える
- 反射側は戻さない。**遠くから届く子音は直接音が運ぶ**
- コーナーは**上限を `0.45 · fs`** で切る（192 kHz で係数が発散しないため、
  `REQ-VDP-017`）

---

## CLARITY（`REQ-VDP-006`）

**Guard の裏返し。** Guard は「基準に対して過剰な帯域を引く」、これは
「基準に対して不足した帯域を戻す」。

### 符号違いは帯域の入れ替えで作る

`nxe_audio::guard::RelativeGuard<1>` を**そのまま使い、検出帯と参照帯を
入れ替える**。

| | 帯域 |
|---|---|
| `RelativeGuard` の「検出帯」 | **200 Hz〜1.2 kHz**（下の帯域） |
| `RelativeGuard` の「参照帯」 | **2〜5 kHz**（Presence） |

- Presence が不足すると参照が下がる → Guard は「検出帯が過剰」と読む →
  `reduction_db` が増える。**これが Presence の不足量そのもの**で、
  dB で 1 : 1
- 出力は引くのではなく**足す**: `戻し量 = CLARITY · min(reduction_db, 6 dB)` を
  `g_pres` に加算する。**新しいフィルタは 1 本も要らない**（Presence の
  並列帯に乗る）
- **`CLARITY` = 0 で厳密に 0**（`REQ-VDP-006`）
- **参照帯が検出帯を含んでいない。** `SPK-18` で De-Harsh がここを踏んで、
  10 dB の harsh が 2 dB にしか読めなかった。**帯域は上下に分ける**
- 相対なので**入力ゲインに依らない**（±12 dB で 0.2 dB 以内を測る）
- **立ち上がりまでは無限に不足に見える**（`SPK-18`）。**100〜250 ms 捨てて
  から測る**

しきい値は**未測定**。`VDP-7` で実素材の p50 / p95 / max を並べてから置く
（`SPK-18`: **末尾の 1 サンプルの引き量で決めない**）。**普通の素材で
戻し量が 0** が条件。

**戻した量は画面に出す**（`REQ-VDP-018`）。完全に自動で隠すと「遠くしたのに
遠くならない」理由が見えない。

## WIDTH（`REQ-VDP-007`）

**反射だけに掛かる。** 直接音は Side 減衰だけ（上）。

```text
M = (L + R) / 2、S = (L − R) / 2
s = WIDTH · (0.6 + 0.4 d)
out_L = M + s · S、out_R = M − s · S
```

- **`WIDTH` = 0 で L == R**（`REQ-VDP-011`）
- 反射の相関が下がるのは**タップ時刻が L/R で違うから**で、`WIDTH` は
  そこにある差をどれだけ通すかだけ。**位相を回す処理はここにも無い**
- **モノ和で反射は減る。それは物理的に正しい**（`REQ-VDP-007` が
  約束の書き方を変えている）。測るのは**直接音のモノ和**で、そこに櫛形の
  谷が出ないこと
- **対照実験は遅延ではなくオールパス**（`AIR-1` の授業料 — 12 サンプルの
  遅延は 1/3 オクターブ帯より細かい櫛を作るので 0.9 dB しか出ない）

## 出力とスムージング

```text
out = OUTPUT · ((1 − MIX) · dry + MIX · g · (direct + refl))
```

- パラメータはラッパ側でブロックレートにスムーズする。**`g` はその後で
  計算する**（上）
- **段変化の継ぎ目は 2 階差分で測る**（`AIR-7` — 絶対値の跳びでは測れない）
- 係数の再計算は「動いていなければ何もしない」。`DAMPING` の 2 本と
  Presence の帯域が対象

## 既定値

**未定。`VDP-13` の仕事。** 決め方だけ先に置く。

- **測れるものを先に測って `defaults.rs` に固定する**（`AIR-13` / `SPK-18` の
  形）。**ラッパ側から `default()` を読む** ので、測る数と出荷する数がずれない
- **`DEPTH` の中央が「素直なスタジオの距離」に聞こえること**が最終条件
  （`REQ-VDP-021`）
- **新しい `FloatParam` のスムーザは 0 から始まる**（`AIR-13`）。
  `primed()` を最初から置く — 置かないと**全マクロが下限のプラグイン**を
  測ることになる
- 聴く先: リードボーカル、ダブル、ハーモニー、ラップ、ささやき

## 検証

| 何 | どう測るか | 要件 |
|---|---|---|
| **`DEPTH` でラウドネスが動かない** | ピンクノイズと歌、`DEPTH` を刻んで出力 RMS が **±0.5 dB 以内** | `REQ-VDP-008` **ゲート** |
| 同じことが `MIX` の各点で | `MIX` を 0.25 刻みで同じ測定 | `REQ-VDP-008` |
| `ROOM` でも動かない | `ROOM` を刻んで同じ測定 | `REQ-VDP-008` |
| 正規化が信号に依存しない | 4 素材で `g` が**完全に同一** | `REQ-VDP-008` |
| `MIX` = 0 でビット一致 | 乱数列を L/R に通して入力と一致 | `REQ-VDP-001` |
| `ROOM` = 0 で反射が厳密に 0 | 反射バスを直接取り出して全サンプル 0 | `REQ-VDP-003` |
| 反射が 10〜120 ms | インパルスを入れて最初の非零が 11 ms、120 ms 以降が **−40 dB 以下** | `REQ-VDP-003` |
| `DEPTH` の掃引にクリックが無い | **2 階差分**を段の周りと他で比べる。**測定が失敗できることを同じテストで確かめる**（`VEL-10`） | `REQ-VDP-003` |
| 無音への収束 | 3 秒以内に**厳密に 0**（ホストの外、FTZ 無し） | `REQ-VDP-003` |
| レート非依存 | 44.1 / 48 / 96 / 192 kHz でタップ時刻が同じ ms（±1 サンプル）。**ノイズで測る**（`SPK-9`: 定在音は位相が回る） | `REQ-VDP-017` |
| ブロック非依存 | 1 / 64 / 512 / 4096 で出力一致 | `REQ-VDP-017` |
| `process` で確保しない | 数えるグローバルアロケータ。レート変更で確保が起きること**も**確かめる | `REQ-VDP-016` |
| Presence と Transient が同時に動く | `DIRECT` を刻んで 2〜5 kHz と `c_t` の両方 | `REQ-VDP-004` |
| 検出が入力ゲインに依らない | ±12 dB で 0.2 dB 以内 | `REQ-VDP-004` |
| Transient が定常で 1 | 定常正弦で `c_t` が**厳密に 0** | `REQ-VDP-004` |
| `DAMPING` が別の量で掛かる | 直接音と反射を別々に取り出してコーナーを測る | `REQ-VDP-005` |
| Transient で高域が保たれる | バースト列の立ち上がりで直接音のコーナーが上がる | `REQ-VDP-005` |
| `CLARITY` = 0 で厳密に 0 | 戻し量が全サンプル 0 | `REQ-VDP-006` |
| `CLARITY` が普通の素材で 0 | **広帯域**（ピンク）で測る。2 音では守れない（`SPK-18`） | `REQ-VDP-006` |
| `CLARITY` が `DEPTH` で増える | `DEPTH` を刻んで単調増加、CLOSE で 0 | `REQ-VDP-006` |
| **直接音のモノ和に櫛形が出ない** | 直接音だけ取り出し、1/3 オクターブ帯の比のばらつき。**対照実験はオールパス** | `REQ-VDP-007` |
| `WIDTH` = 0 で L == R | 反射バスで全サンプル一致 | `REQ-VDP-011` |
| 反射の相関が `DEPTH` で下がる | `nxe_dsp::Correlation`、単調減少 | `REQ-VDP-007` |
| 片寄った素材で定位が動かない | L だけに信号、直接音の L/R 比が入力と同じ | `REQ-VDP-007` |
| 2→2 と 1→2 | 両レイアウトで動く。モノ入力は 1 本目を複製 | `REQ-VDP-011` |
| レイテンシ 0 | ホストへの申告が 0、直接音の群遅延にバルク成分が無い | `REQ-VDP-012` |
| 極端値 | 全パラメータ・全サンプルに NaN / ±inf / ±1e9。**遅延線と検出器がラッチしない** | `REQ-VDP-016` |
| 全パラメータにコントロール | `#[id]` を走査（`VDP-9`） | `REQ-VDP-013` |
| `Handoff` が全部書かれている | スキャンテスト（`VDP-11`。Air は publish を落として**テスト全通のまま窓が静止**した） | `REQ-VDP-018` |
| CPU | criterion、512 / 48 kHz で 533 µs 以内 | `REQ-VDP-016` |

**測定が失敗できることを同じテストの中で確かめる**（`VEL-10`）。相関の単調性も
櫛形も、**対照実験が差を出すこと**を 1 行示してから本番のアサートを書く。

## CPU（見込み、まだ測っていない）

1 サンプル 1 チャネルあたり:

| | 見込み |
|---|---|
| タップ 13 本（**整数読み**） | 13 |
| 拡散オールパス 3 段 | 12 |
| Presence の `BandPass`（2 次 × 2） | 10 |
| `DAMPING` のローパス 2 本 | 10 |
| 反射の HP | 5 |
| M/S 2 箇所 | 6 |

**約 60 flops / サンプル / チャネル。** 512 サンプル × 2 チャネルで 60k flops、
それに検出 2 本と `CLARITY` の帯域通過（モノ和なので 1 本ぶん）。

**オーバーサンプリングも FFT も無い**（`REQ-VDP-016`）。**見込みは 60 µs 未満**
で、Air の 47 µs と Doubler の 85 µs の間。**タップを整数読みにできたのが
効いている** — Catmull-Rom なら 13 本で 65 flops、ここだけで 4 倍になる。

`VDP-12` で内訳を測る。**重いのは検出とフィルタ**で、遅延線とオールパスは安い。

## 共有クレートに上げるもの

**計画書の「共有クレートの新規単位が無い」は、この文書で 2 つ増えた**（計画書と
バックログは同じ変更で直してある）。どちらも数十行なので単位は起こさず、
`VDP-1` と `VDP-3` の中で片付ける。

| 何 | どこから | どの単位で | なぜ |
|---|---|---|---|
| `delay::DelayLine` | `doubler-core` から**移動** | `VDP-1` | **2 個目の客が要求した**（リポジトリの規則）。整数読み `read_whole` を足す |
| `biquad::Coefficients::magnitude` | **新規**（6 行） | `VDP-3` | 正規化が振幅特性を要求する。信号を見ない正規化の代金 |

**初期反射そのものは `vocal-depth-core` に置く**（`REQ-VDP-015`）。
`nxe-audio` に上がるのは Vocal Glue が要求したとき。それまで
**Vocal Depth を知らない自立したモジュール**として書く。
