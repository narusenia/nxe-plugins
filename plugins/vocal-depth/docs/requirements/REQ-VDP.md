# REQ-VDP — Vocal Depth 要件定義

> 最終更新: 2026-08-31

## 概要

Vocal Depth は**声の前後位置を操作する**ミックスプロセッサ。狙いは 1 つ。

> **Reverb を足すのではなく、声の「距離」を動かす。**

人が「近い / 遠い」と感じる要因は Wet 量ではなく、直接音と反射音の比・
Presence・高域の損失・初期反射・Transient の明瞭さ・ステレオ幅の**合成**で、
どれか 1 つを動かしても距離にはならない。これらを `DEPTH` 1 本に連動させる。

対象は Bitwig / Ableton Live / Reaper / Studio One。**AU は対象外**
（`REQ-VDP-014`）。

**製品名は `NXE Parallax` に決めた**（2026-08-31、`VDP-15`）。「奥行きに
よって見え方が変わる」を名で言う語で、Velour / Sparkleur / Air と同じ
**喚起的な 1 語**の register に乗る。`NXE Vocal Depth` は Doubler と同じ
記述的な名前で、ラインの中で 2 系統になっていた。**改名は出荷より前に済ませる**
— `CLAP_ID` は出荷後に変えられないため（`AGENTS.md`）。改名の単位は
`VDP-15` で、そこでこの文書も `REQ-PAR.md` になり `VDP-*` は `PAR-*` になる。

## 設計の中心にある 5 つの判断

**原音は処理を通る。Air の逆。** 遠ざけるとは Presence を削り高域を落とし
Transient を鈍らせることなので、**直接音そのものを触らずに距離は作れない**。
Air（`REQ-AIR-001`）が純粋な加算型なのと正面から違う。`MIX` 用の原音だけを
最初に分岐して、透明性の約束はそこに閉じ込める（`REQ-VDP-001`）。

**リバーブのテイルを持たない。** 扱うのは 10〜120 ms の**初期反射だけ**。
長い残響は「空間の大きさ」を作るが「声の距離」は作らないし、歌詞の明瞭さを
真っ先に壊す。この判断が **v1 で唯一の新規 DSP ブロックを小さく保つ**
（`REQ-VDP-003`）。

**距離が変わっても音量は変わらない。** これがゲート（`REQ-VDP-008`）。
`DEPTH` を回して音量が動くなら、それは距離ではなく Wet 量とフェーダを同時に
触っているだけで、製品の主張が成立しない。**耳ではなく測って通す。**
**許容は ±1.0 dB**（`VDP-3` の実測で ±0.5 dB は素材を跨いでは達成できないと
分かったため。理由は `REQ-VDP-008`）。

**明瞭度は自動で保つが、隠さない。** `DEPTH` を上げれば Presence は自然に
落ちる。落ちすぎたぶんだけ戻す機構を持つが（`REQ-VDP-006`）、働いた量は
画面に出す。Sparkleur の Guard と同じ扱いで、完全に自動で隠すと「遠くしたのに
遠くならない」理由が見えなくなる。

**`FOCUS` と `AIR` という名前を使わない。** 構想はどちらも使っているが、
ラインの中で既に別の意味を持っている — `FOCUS` は Velour / Sparkleur / Air で
「帯域をまとめて上下に動かす」、`AIR` は Velour と Sparkleur のノブ。
それぞれ **`CLARITY`** と **`DAMPING`** にする（`REQ-VDP-010`）。

## REQ-VDP-001: トポロジと原音の扱い

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 直接音は**処理を通る**。反射音は生成する。`MIX` 用の原音だけを
  入口で分岐する。

```text
Input ─┬───────────────────── dry ────────────────────────┐
       │                                                  │
       ├─ 直接音の処理 ─────────┬── wet ──────────────────┤─ MIX ─ OUTPUT
       │  (Presence / Transient │                         │
       │   / DAMPING)           │                         │
       │                        │                         │
       └─ 初期反射の生成 ───────┘                         │
```

- **Air の逆側に立つ。** `REQ-AIR-001` は「原音は入口から出口まで一切触らない」
  を要件にしているが、**遠ざけるとは直接音を削ること**なので、同じ約束は
  できない。**この 2 つが混同されると片方の設計が壊れる**ので、要件として
  書いておく。
- **`MIX` = 0 でビット一致。** Doubler / Velour / Sparkleur / Air から
  引き継ぐ唯一の透明性の約束。
- **`DEPTH` = CLOSE は「何もしない」ではない。** CLOSE 側でも Presence を
  上げ Transient を立てる（構想の CLOSE の表）。素通しが欲しいなら `MIX` = 0。
- **受入条件**:
  - [ ] `MIX` = 0 で出力が入力と**ビット一致**
  - [ ] `DEPTH` を掃引して不連続が出ない
  - [ ] 直接音と反射音を別々に取り出せる（テストと UI が同じ値を使う）
- **依存**: なし

## REQ-VDP-002: DEPTH（連動マクロ）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: `CLOSE ←→ FAR` の 1 本で 7 つを連動させる。

| | CLOSE | FAR |
|---|---|---|
| 直接音の比 | ↑ | ↓ |
| 2〜5 kHz Presence | ↑ | ↓ |
| 初期反射 | ↓ | ↑ |
| 高域減衰 | ↓ | ↑ |
| Transient の明瞭さ | ↑ | ↓（鈍る） |
| 直接音の幅 | やや狭 | 維持 |
| 反射音の幅 | ↓ | ↑ |

- **連動の曲線は Advanced に出さない。** 出すのは各項の**偏差**
  （`REQ-VDP-009`）。曲線そのものを触れるようにすると「距離」という
  1 つの概念が 7 個の独立した設定に戻る。
- **CLOSE と FAR は対称ではない。** 近づけるのは足し算（Presence を上げる）
  で頭打ちがあるが、遠ざけるのは引き算でいくらでも続けられる。可動域は
  FAR 側に長い。
- **受入条件**:
  - [ ] `DEPTH` を掃引して 7 項が**同時に**動く
  - [ ] `DEPTH` の両端で構想の表どおりの向きになる
  - [ ] 出力のラウドネスが動かない（`REQ-VDP-008`）
- **依存**: REQ-VDP-003, REQ-VDP-004, REQ-VDP-005, REQ-VDP-007

## REQ-VDP-003: 初期反射

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 10〜120 ms の初期反射を生成する。**v1 で唯一の新規 DSP ブロック。**

- **テイルを持たない**（`REQ-VDP-020`）。拡散する尾を足すと、それは
  「空間の大きさ」であって「声の距離」ではない。しかも歌詞の明瞭さを
  最初に壊す。
- **構造**: タップ付き遅延 + 拡散のためのオールパス数段。**畳み込みも
  IR も使わない** — 距離で連続的に変化させる必要があり、IR は補間できない。
- **`ROOM` が量、`DEPTH` が比。** `ROOM` は反射の絶対量、`DEPTH` は
  直接音との比。どちらも要る — 小さい部屋で遠い、大きい部屋で近い、が
  どちらも成立する。
- **この 3 製品で共有される。** ロードマップ上、初期反射の客は Vocal Depth /
  Vocal Glue の `Ambience Glue` / Impact の `SIZE` で 3 つ
  （`docs/implementation/roadmap.md`）。**`vocal-depth-core` に置き、
  2 個目が要求した時点で `nxe-audio` に上げる**（`REQ-VDP-015`）。
  それまでは **Vocal Depth を知らない自立したモジュールとして書く。**
- **受入条件**:
  - [ ] `ROOM` = 0 で反射がちょうど無音
  - [ ] 反射の遅延が 10〜120 ms の範囲に収まる（テイルが伸びていない）
  - [ ] `DEPTH` を連続的に動かしてもクリックが出ない
  - [ ] 無音を入れて 3 秒以内に完全に無音へ収束する
  - [ ] `vocal-depth-core` の外から使える形になっている（Glue が借りる）
- **依存**: REQ-VDP-001

## REQ-VDP-004: 直接音の処理

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 近さを作る側。Presence、Transient、子音の明瞭さ。

- **Presence は 2〜5 kHz の動的な帯域**。`nxe_audio::biquad::BandPass` を
  並列に足す（`x + (g − 1) · BP(x)`）。**シェルフではない** — `nxe-audio` に
  シェルフが無いのと、シェルフだと 5 kHz より上も動いて `DAMPING`
  （`REQ-VDP-005`）と同じ帯域を 2 つのパラメータが書くことになるため。
  **`dsp.md` を書く時点でこの 1 行を直した**（元は「動的なシェルフ」）。
  Velour と Sparkleur が同じ形をしている。
- **Transient は既存の検出器**（速い/遅いフォロワの比、`nxe_audio::envelope`）。
  CLOSE で立て、FAR で鈍らせる。**新しい検出器を作らない。**
- **`DIRECT` は直接音の近さ**。`DEPTH` から独立して触れる。
- **受入条件**:
  - [ ] `DIRECT` を動かすと 2〜5 kHz と Transient が同時に動く
  - [ ] Transient の鈍化が子音を潰しきらない（`REQ-VDP-006` が受け止める）
- **依存**: REQ-VDP-001

## REQ-VDP-005: DAMPING（距離による高域損失）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 遠距離で起きる高域の損失を模す。

- **直接音と反射音で減衰が違う。** 同じ 1 本のフィルタを両方に掛けると
  「こもっただけ」になる。反射側を強く落とし、直接音側は軽く。
- **Transient のときだけ高域を保つ。** 遠くても子音の立ち上がりは届く。
  これが無いと FAR が「布を被せた音」になる。`REQ-VDP-004` の検出器を
  そのまま使う。
- **名前は `AIR` にしない**（`REQ-VDP-010`）。
- **受入条件**:
  - [ ] `DAMPING` が直接音と反射音に**違う量**で掛かる
  - [ ] Transient の瞬間に高域が保たれる
  - [ ] `DAMPING` 全開でも子音が判別できる
- **依存**: REQ-VDP-004

## REQ-VDP-006: CLARITY と明瞭度の保持

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 遠ざけたときに失われる明瞭度を、必要な量だけ戻す。
  **構想の `FOCUS` と `PRESENCE LOCK` を 1 本に畳んだもの。**

- **機構は `nxe_audio::guard` の裏返し。** Guard は「基準に対して過剰な
  帯域を引く」。これは「基準に対して不足した帯域を戻す」。**同じ相対検出器の
  符号違い**なので、新規開発がほとんど無い（`SPK-1` の `RelativeGuard<N>`）。
- **絶対量ではなく相対で判定する。** 「2〜5 kHz が下の帯域に対してどれだけ
  有るか」を見る。絶対量で見ると入力ゲインで挙動が変わる（`REQ-SPK-008` が
  同じ理由で相対にしている）。
- **戻した量を画面に出す**（`REQ-VDP-018`）。完全に自動で隠すと「遠くしたのに
  遠くならない」理由が見えない。
- **`CLARITY` = 0 で完全に無効**。掛からない状態を選べることが、何をしている
  かを確認する手段になる。
- **受入条件**:
  - [ ] `CLARITY` = 0 で補正がちょうど 0
  - [ ] `DEPTH` を上げるほど補正量が増える
  - [ ] 補正量が入力ゲイン ±12 dB で 0.2 dB 以内
  - [ ] `DEPTH` = CLOSE では補正が働かない（元から明瞭なので）
- **依存**: REQ-VDP-002, REQ-VDP-004

---

## REQ-VDP-007: 距離依存のステレオ幅

- **優先度**: Must
- **ステータス**: Draft
- **説明**: **声本体はセンターに残したまま、反射だけを広げる。**

```text
DEPTH ↑
  直接音の幅      やや ↓
  反射音の幅        ↑
```

- **Air の「位相を回さない」約束は、ここでは使えない。** 初期反射は本質的に
  遅延タップなので、モノ和で櫛形が出る。**これは避けられない**ので、
  約束の書き方を変える:

```text
Air (REQ-AIR-008)      位相を回さないので、モノ和に櫛形が出ない
Vocal Depth (ここ)     直接音は M にしか居ないので、モノ和で無傷。
                       反射音は減るが、それは物理的に正しい
```

- **直接音を Side に出さない。** これが上の約束の実装。直接音の「やや狭く」は
  Side の**減衰**であって Side への配置ではないので、モノ和で失うものが無い。
- **受入条件**:
  - [ ] モノ和で**直接音**に櫛形の谷が出ない（直接音だけ取り出して測る）
  - [ ] `WIDTH` = 0 で L == R
  - [ ] `DEPTH` を上げると反射音の相関が下がる
  - [ ] 片チャネルに寄った素材で直接音の定位が動かない
- **依存**: REQ-VDP-003

## REQ-VDP-008: 距離とラウドネスの分離

- **優先度**: Must
- **ステータス**: Decided（2026-08-28 に許容を **±0.5 → ±1.0 dB** に改訂）
- **説明**: **`DEPTH` を動かしても出力のラウドネスが変わらない。**
  これが Vocal Depth のゲート。

- **崩れたら製品の主張が成立しない。** 音量が動くなら、ユーザーは
  「距離」ではなく「Wet 量とフェーダ」を同時に触っている。`DEPTH` を
  1 本のマクロにした意味が消える。
- **Velour の `VEL-1`（倍音の正規化）と同じ位置づけ**で、**耳ではなく
  単体テストで通る**。実装は同じ形 — 連動する各項が総エネルギーに与える
  寄与を打ち消す正規化を、パラメータが変わったときに計算する
  （`nxe_audio::shaper` の `g` と同じ考え方）。
- **信号依存の正規化にしない。** 素材ごとに `DEPTH` の効きが変わるほうが
  問題として大きい。`shaper` が同じ判断をしている理由と同じ。
### 許容を ±1.0 dB に改訂した（`VDP-3` の実測）

**±0.5 dB は素材を跨いでは達成できない。** 帯域 EQ が信号の総パワーをどれだけ
動かすかは、その信号が帯域にどれだけ入っているかで決まり、それは素材の性質で
**パラメータからは分からない** — Presence 帯（2〜5 kHz）の割合はピンク
ノイズ **10.3 %**、ホワイト 13.4 %、疎な倍音列のフレーズ **1.2 %**。
「信号に依存しない正規化」（上）と両立しない。

補正率を振った実測（`DEPTH` 全域の出力 RMS のばらつき）:

| 補正率 | ピンク | ホワイト | フレーズ | 最悪 |
|---|---|---|---|---|
| 0.00 | 1.46 | 1.79 | 0.22 | 1.79 |
| 0.50 | 0.63 | 0.96 | 0.62 | 0.96 |
| **0.60**（採用） | **0.48** | **0.80** | **0.77** | **0.80** |
| 1.00 | 0.14 | 0.19 | 1.39 | 1.39 |

**採ったのは「要求を ±1.0 dB に緩め、補正率 0.6」**。もう 1 つの手（Presence の
可動域を半分にする）は表全体を縮めて ±0.5 dB に入るが、**製品の主効果が
半分になる**ので採らなかった。**残差は「音量が動く」より「音色が動く」に近い。**

**否定した説明が 3 つある**（どれも測って否定した）: テイル（500 ms 以降は
厳密に 0）、測り方（EBU 風の相対ゲートでも 1.38 dB、上位 4 分の 1 でも
1.21 dB）、タップのコヒーレンス（ビブラート 1.5 % と息で 1.26 dB）。

**反射側は素材によらず正確に補正できている**（広帯域なので）。**残差は帯域 EQ
の項だけ**が出している。

- **受入条件**:
  - [x] `DEPTH` 全域で出力の RMS が **±1.0 dB 以内**（ピンクノイズと歌の両方）
        — 実測 ピンク 0.48 / ホワイト 0.80 / フレーズ 0.77
  - [x] 同じことが `MIX` の各点で成り立つ
  - [x] `ROOM` を動かしてもラウドネスが動かない
- **依存**: REQ-VDP-002

## REQ-VDP-009: 二層パラメータモデル

- **優先度**: Must
- **ステータス**: Draft
- **説明**: メインの 7 本と Advanced の偏差。Velour / Sparkleur / Air と
  同じ形。

| メイン | 役 |
|---|---|
| `DEPTH` | Close ↔ Far |
| `DIRECT` | 直接音の近さ |
| `ROOM` | 初期反射の量 |
| `DAMPING` | 距離による高域損失 |
| `WIDTH` | 空間成分の広がり |
| `CLARITY` | 明瞭度の保持 |
| `MIX` | Dry / Wet |

- **Advanced に出すもの**: `DEPTH` が連動させる 7 項の偏差、反射の遅延範囲と
  拡散、Presence の帯域、Transient の時定数、`CLARITY` の帯域。
- **偏差は必ず相対。** 絶対量にすると 2 つのパラメータが 1 つの値を書く。
- **受入条件**:
  - [ ] メインだけで一通りの距離が作れる
  - [ ] 偏差 0 のときマクロの表どおりの値になる
  - [ ] どのメインを動かしても偏差の値が書き換わらない
- **依存**: REQ-VDP-002

## REQ-VDP-010: ラインの中での語の一意性

- **優先度**: Must
- **ステータス**: Decided
- **説明**: 構想が使っている `FOCUS` と `AIR` を、両方とも使わない。

| 構想の語 | 衝突相手 | 採る語 |
|---|---|---|
| `FOCUS`（遠距離時の明瞭度） | Velour / Sparkleur / Air の `FOCUS`（帯域を上下に動かす） | **`CLARITY`** |
| `AIR`（距離による高域感） | Velour / Sparkleur のノブ | **`DAMPING`** |

- **`PRESENCE LOCK` は `CLARITY` に吸収する**（`REQ-VDP-006`）。同じことを
  2 つの名前で呼ぶことになるため。
- **出荷済み 3 本の語は変えない。** セッションは壊れないが、既存ユーザーが
  戸惑う。**新しい製品の側が譲る。**
- Air が同じ理由でメインマクロを `AIR` ではなく `SURFACE` にしている
  （`REQ-AIR-010`）。

## REQ-VDP-011: ステレオの扱いとバス構成

- **優先度**: Must
- **ステータス**: Draft
- **説明**: **直接音の像は変えない。** 変わるのは反射音の広がりだけ。
- **バス構成は 2→2 と 1→2。** 反射音はステレオで生成されるので、モノ出力は
  製品の意味を捨てる。Doubler / Air と同じ判断。**1→1 は出さない。**
- **モノ入力では 2 本目のチャネルが未定義。** 読まずに 1 本目を複製する。
- **検出はすべてリンク。** Transient と `CLARITY` は L/R をまとめて見る。
- **受入条件**:
  - [ ] `MIX` = 0 で L/R それぞれが入力とビット一致
  - [ ] 2→2 と 1→2 の両方で動く
  - [ ] `WIDTH` = 0 のとき L == R
- **依存**: REQ-VDP-007

- **受入条件**:

  - [ ] ホストへ報告するレイテンシが 0
- **依存**: REQ-VDP-001

## REQ-VDP-015: コアのホスト非依存と共有 DSP

- **優先度**: Must
- **ステータス**: Draft
- **説明**: DSP は `vocal-depth-core` に置き、フレームワークも Vizia も
  知らない。

| 使う既存ブロック | 使うところ |
|---|---|
| `nxe_audio::biquad` | Presence、`DAMPING`、反射の減衰 |
| `nxe_audio::envelope` | Transient の検出 |
| `nxe_audio::guard` | `CLARITY`（符号違い） |
| `nxe_dsp::Handoff` / `Level` | 表示 |

- **新規は初期反射だけ**（`REQ-VDP-003`）。`vocal-depth-core` に置き、
  **Vocal Glue が要求した時点で `nxe-audio` に上げる**。それまでは
  Vocal Depth を知らない自立したモジュールとして書き、移動がファイルの
  移動だけで済む状態にする（`REQ-VEL-015` / `SPK-1` の形）。
- **`nxe-dsp` に入れない。** あちらは解析で、音を変えない。
- **ライセンス**: `vocal-depth-core` は **MIT OR Apache-2.0** の側
  （`LICENSING.md`）。`nih_plug` への依存を持ち込まない。
- **受入条件**:
  - [ ] `vocal-depth-core` がフレームワークにも Vizia にも依存しない
  - [ ] 初期反射のモジュールが Vocal Depth のパラメータ構造体を知らない
- **依存**: なし

## REQ-VDP-016: リアルタイム安全性と CPU 予算

- **優先度**: Must
- **ステータス**: Draft
- **説明**: `process()` の中で確保・ロック・IO・panic をしない。
- **予算**: 533 µs、目標 250 µs。参考値は Doubler 85 µs、Velour 128 µs、
  Sparkleur 129 µs。
- **見積り**: 遅延線とタップ、オールパス数段、biquad 十数段、検出 2 本。
  **オーバーサンプリングも FFT も要らない**ので、Doubler に近い 100 µs 未満を
  見込む。
- **受入条件**:
  - [ ] criterion で 512 サンプル / 48 kHz が 533 µs 以内
  - [ ] 極端値で非有限値を出さず panic しない
  - [ ] 非有限のサンプル 1 個で検出器や遅延線がラッチしない
  - [ ] 音声スレッドの経路に確保が無い（数えるアロケータ）
- **依存**: REQ-VDP-003

---

## REQ-VDP-017: サンプルレート・ブロックサイズ非依存

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 同じ設定がどのサンプルレートでも同じ音になる。
- **反射の遅延はミリ秒で持つ。** サンプル数で持つと 96 kHz で部屋が半分に
  なる。**遅延線の確保はサンプルレートが決まった時点**で、`process()` の
  中ではしない。
- **時定数はすべて秒で持つ。**
- **受入条件**:
  - [ ] 44.1 / 48 / 96 / 192 kHz で反射の遅延が同じミリ秒になる
  - [ ] ブロックサイズ 1 / 64 / 512 / 4096 の出力が一致する
  - [ ] レート変更で遅延線が再確保され、`process()` の中では確保しない
- **依存**: REQ-VDP-003

## REQ-VDP-018: 通っている音の表示

- **優先度**: Should
- **ステータス**: Draft
- **説明**: UI に渡す解析値。受け渡しは `nxe_dsp::Handoff`。

- **受入条件**:

  - [ ] 解析を止めても音が変わらない
- **依存**: REQ-VDP-006, REQ-VDP-007

## REQ-VDP-019: MOTION

- **優先度**: Won't (v1)
- **ステータス**: Decided
- **説明**: 距離を時間的に動かす（LFO / エンベロープ / サイドチェイン /
  MIDI）。
- **v1 に入れない理由**:
  - **Air が同じものを同じ理由で落としている**（`REQ-AIR-020`）。変調源と
    その UI が v1 に乗る
  - **Growl Shaper が同じ変調源を要求している**（LFO / エンベロープ /
    ステップシーケンサ）。**あちらで 1 個作ってから共有するほうが安い**
    （`docs/implementation/roadmap.md`）
  - **オートメーションで代用できる。** `DEPTH` は 1 本のマクロなので、
    Verse で近く Chorus で遠く、はホスト側で書ける
- v2 で入れるときは、変調源を `nxe-audio` から借りるところから始める。

## REQ-VDP-020: リバーブテイル

- **優先度**: Won't (v1)
- **ステータス**: Decided
- **説明**: 初期反射の後に続く拡散した残響。
- **v1 に入れない理由**:
  - **距離を作らない。** テイルは「空間の大きさ」を作る。近い声を大きな
    部屋で鳴らすことも、遠い声を小さな部屋で鳴らすこともできるので、
    **距離とは独立した軸**
  - **歌詞の明瞭さを最初に壊す。** `REQ-VDP-006` が戻そうとしているものを
    別のところから削る
  - **v1 で唯一の新規ブロックを小さく保てる。** 初期反射だけならタップ付き
    遅延とオールパスで済み、3 製品で共有できる（`REQ-VDP-003`）
- v2 で入れるなら、`ROOM` の先に独立した軸として足す。**`DEPTH` には
  繋げない。**

## REQ-VDP-021: プリセットを持たない

- **優先度**: Should
- **ステータス**: Draft
- **説明**: プリセットブラウザを持たない。**`DEPTH` 1 本がその役**。
- Doubler / Velour / Sparkleur / Air と同じ判断。
- **帰結として既定値が製品の顔になる。** `DEPTH` の中央が「素直な
  スタジオの距離」に聞こえることが最終の受入条件。
