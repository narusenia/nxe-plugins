# REQ-GLU — Vocal Glue 要件定義

> 最終更新: 2026-08-27

## 概要

Vocal Glue は**ボーカルバスのまとめ役**。Lead / Double / Harmony / Adlib が
混ざったバスに挿して、狙いは 1 つ。

> **「別々に録った複数の声」を「1 つの声群」として聞こえるようにする。**

バスコンプだけでは音量は揃っても、声質の差・ステレオの分離感・空間の違いは
残る。それらを 1 本の `GLUE` に連動させる。

対象は Bitwig / Ableton Live / Reaper / Studio One。**AU は対象外**
（`REQ-GLU-014`）。

**製品名は暫定**（`REQ-DIO` と同じ理由）。**ラッパを作る単位までに決める。**

## この要件が構想から一番大きく変えたところ

**バスに届くのは 1 本の信号で、そこに何本の声が入っているかは分からない。**
構想の中で、これを前提にしてしまっている機能が 2 つある。

**`Timing Cohesion` は原理的に不可能**（`REQ-GLU-019`）。混ざった後の和から、
Double だけを数 ms 動かすことはできない。**落とす。** 狙いの「発音がまとまって
聞こえる」は `ATTACK CENTERING`（子音の瞬間だけ Side を狭める）が別の手段で
達成していて、そちらはバスで成立する（`REQ-GLU-007`）。

**`Spectral Cohesion` は「トラック同士を合わせる」ことはできない。**
構想は「Lead だけ明るい / Double だけ鼻声」を直すと書いているが、和からは
どれが Lead かが分からない。**できるのは和のスペクトルを目標の傾きへ寄せる
ことと、突出した帯域を均すこと**で、それは十分有用だが別のことなので、
**やれることの側に定義を書き直す**（`REQ-GLU-003`）。

## 設計の中心にある 4 つの判断

**新規 DSP がほぼ無い。** 数えたら、共有ダイナミクス・共通サチュレーション・
帯域ごとの幅・保護は全部既存ブロックの値違いで、初期反射は Diorama が
先に作る（`REQ-GLU-015`）。**Vocal Glue が 3 番目に置かれているのはこのため**
（`docs/implementation/roadmap.md`）。

**`Spectral Cohesion` は `RelativeGuard<N>` の一般化。** 「基準に対して
過剰な帯域を引く」は Sparkleur の De-Harsh とまったく同じ機構で、`SPK-1` で
N 帯域版が既に書かれている。**3 個目の客**なので、ここで
`nxe-audio` 側の一般化が正当化される（`REQ-GLU-003`）。

**`LEAD ANCHOR` は v1 に入れない**（`REQ-GLU-020`）。サイドチェイン入力は
このリポジトリで前例が無く、CLAP と VST3 でホスト側の見え方が違い、
**DAW を開くまで壊れているか分からない**。Glue には既に `Spectral Cohesion`
という新規がある。

**`Ambience Glue` は薄い。** Wet 0.5〜3%。**リバーブではなく「同じ場所に
居る感じ」**で、それ以上入れると「全員が同じ部屋に居る」ではなく
「全員が遠い」になる（`REQ-GLU-005`）。

## REQ-GLU-001: トポロジと原音の扱い

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 直列。処理の順序が意味を持つ。

```text
Input ─┬──────────────────────── dry ─────────────────────────┐
       │                                                      │
       └─ BIND ─ Spectral ─ COLOR ─ Stereo ─ Ambience ─ wet ──┤─ MIX ─ OUT
```

- **順序は変えられない。** `BIND` が先なのは、レベルが揃っていない状態で
  スペクトルを見ると小さい声の寄与が過小評価されるため。`COLOR` が
  `Spectral` の後なのは、整えた後のものに共通の色を乗せるため。
  `Ambience` が最後なのは、生成した空間まで飽和させないため。
- **`MIX` = 0 でビット一致。** 5 製品で共通の透明性の約束。
- **`GLUE` = 0 は「何もしない」。** 直列の各段が unity になるだけで、
  経路の迂回はしない（`REQ-SPK-001` と同じ判断 — オートメーションで
  0 から離れた瞬間に不連続が出るのを避ける）。
- **受入条件**:
  - [ ] `MIX` = 0 で出力が入力と**ビット一致**
  - [ ] `GLUE` = 0 かつ全マクロ既定で、出力が入力と ±0.1 dB 以内で平坦
  - [ ] `GLUE` を掃引して不連続が出ない
- **依存**: なし

## REQ-GLU-002: GLUE（連動マクロ）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 1 本で 5 段を連動させる。

```text
GLUE ↑
  BIND（共有ダイナミクス）      ↑
  Spectral Cohesion             ↑
  COLOR（共通サチュレーション） ↑
  Stereo Cohesion               ↑
  Ambience Glue                 ↑
```

- **ユーザーが考えるのは Ratio でも Threshold でもなく、「この声たちは
  どれだけ一体化して聞こえてほしいか」。** それが 1 本の軸になっていること
  が製品の主張。
- **各段は独立したマクロでも触れる。** `GLUE` は 5 つを同時に振り、
  個別のマクロがその上に乗る（`REQ-GLU-009`）。
- **`GLUE` を上げてもラウドネスが動かない。** Diorama の
  `REQ-DIO-008` と同じ理由 — 動くなら「一体化」ではなく「音量を上げた」に
  なる。**ゲートはこちらではなく `REQ-GLU-003`**（後述）だが、受入条件には
  入れる。
- **受入条件**:
  - [ ] `GLUE` を掃引して 5 段が**同時に**動く
  - [ ] `GLUE` 全域で出力の RMS が ±0.5 dB 以内
  - [ ] 各段のマクロが `GLUE` の値を書き換えない
- **依存**: REQ-GLU-003, REQ-GLU-004, REQ-GLU-005, REQ-GLU-006, REQ-GLU-007

## REQ-GLU-003: Spectral Cohesion

- **優先度**: Must
- **ステータス**: Draft
- **説明**: **和のスペクトルを目標の傾きへ動的に寄せ、突出した帯域を均す。**
  これが Vocal Glue のゲート。

- **構想の定義は達成できない。** 「Lead だけ明るい / Double だけ鼻声」を
  直すには、どれが Lead でどれが Double かを知る必要があり、**混ざった和には
  その情報が無い**。`Timing Cohesion` を落としたのと同じ理由
  （`REQ-GLU-019`）。ここは落とさず、**やれることに書き直す**:

```text
できない   トラック同士のスペクトルを合わせる
できる     和のスペクトルを目標の傾きへ寄せる（動的ティルト）
できる     周囲の帯域に対して突出した帯域を、動的に均す
```

  結果として得られるのは「スタックが 1 つの音色の中に収まる」で、**それが
  構想の狙っていた体感の大部分**。要件を実装可能な形に落としているのであって、
  機能を削っているのではない。
- **機構は `RelativeGuard<N>` の一般化。** Sparkleur の De-Harsh は
  「参照帯に対して過剰な帯域を引く」で、これは**同じものを N 帯域に広げて
  参照を移動平均にしたもの**。`SPK-1` で N 帯域版が既に書かれている。
  **3 個目の客**（Velour の Harsh Guard、Sparkleur の De-Harsh、ここ）なので、
  `nxe-audio` 側で一般化する筋が通る。
- **これがゲート。** 崩れたら「音色を揃える」が成立せず、製品が
  「バスコンプ + サチュレータ」に縮む。**測って通る** — 意図的に傾きの違う
  素材を作り、`GLUE` を上げたときに和のスペクトルが目標へ単調に寄ることを
  確かめる。Velour の `VEL-1`、Sparkleur の `SPK-2`、Air の
  `REQ-AIR-008` と同じ位置づけ。
- **普通の素材を触らない。** Sparkleur が出荷時のしきい値で普通の素材から
  常時 1.3 dB 引いていた（`SPK-18`）。**参照が検出帯を含まないこと**を
  受入条件に入れる。
- **受入条件**:
  - [ ] 傾きの違う 2 種の素材に対し、`GLUE` を上げると和のスペクトルが
        目標へ**単調に**寄る
  - [ ] **スペクトル的に普通の素材で動作量がちょうど 0 dB**
        （`SPK-18` の再発防止）
  - [ ] 動作量が入力ゲイン ±12 dB で 0.2 dB 以内
  - [ ] 目標の傾きが素材によって変わらない（信号依存の学習をしない）
- **依存**: REQ-GLU-004

## REQ-GLU-004: BIND（共有ダイナミクス）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 瞬間ピークではなく**フレーズ単位の包絡**を見て、スタック全体の
  呼吸を揃える。

- **時定数が普通のバスコンプと違う。** 狙いは「小さい Harmony が置いて
  いかれない」なので、release は数百 ms〜秒のオーダー。**速い attack は
  持たない** — 子音を潰すと `ATTACK CENTERING` が揃えようとしているものを
  先に壊す。
- **機構は既存。** `nxe_audio::envelope` の検波と、Sparkleur の
  gain computer（上下コンプ）。**上げ側があること**が「小さい声を
  置いていかない」の実装で、Sparkleur の `REQ-SPK-003` と同じく
  **上限が機構として要る**（無いとノイズフロアと尻尾が持ち上がる）。
- **検波は L/R リンク。** 片チャネルだけ動くと像が動く。
- **受入条件**:
  - [ ] `BIND` を上げるとフレーズ間のレベル偏差が単調に縮む
  - [ ] 子音の立ち上がりが `BIND` 全開でも潰れない
  - [ ] 上げ側に上限が効いていて、無音区間が持ち上がらない
- **依存**: REQ-GLU-001

## REQ-GLU-005: Ambience Glue

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 非常に薄い共通の空間。**Wet 0.5〜3%。**

- **Diorama の初期反射をそのまま借りる**（`REQ-DIO-003`）。**ここが
  2 個目の客**なので、`diorama-core` から `nxe-audio` へ上げるのは
  この時点（`REQ-GLU-015`）。
- **リバーブではない。** 目的は「全員が同じ場所に居る」で、量を増やすと
  「全員が遠い」に変わる。**上限を機構として持つ** — 3% を超えられない。
  超えたいときは Diorama を挿すのが正しい。
- **`ROOM` が量。** `GLUE` が連動させる。
- **受入条件**:
  - [ ] `ROOM` = 0 で反射がちょうど無音
  - [ ] Wet が 3% を超えられない
  - [ ] 無音を入れて 3 秒以内に完全に無音へ収束する
- **依存**: REQ-GLU-001

---

## REQ-GLU-006: COLOR（共通の質感）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 全部の声を同じ非線形に通し、**同じ機材を通したような共通の
  質感**を作る。

- **`nxe_audio::shaper` をそのまま使う。** Velour / Sparkleur / Air と
  同じカーブ。新しいものを作らない。
- **構想の `AIR Cohesion` をここに畳む。** 高域感の共通化は「共通の質感」の
  一部で、別のノブにすると `AIR` という語がラインで 4 個目になる
  （`REQ-GLU-010`）。`COLOR` を上げると高域の粗さがわずかに減る、という
  連動として持つ。
- **オーバーサンプリングは要る。** 非線形なので、Velour / Sparkleur / Air と
  同じ **4x で折り返し −60 dB 以下**の基準を適用する。
- **受入条件**:
  - [ ] `COLOR` = 0 で非線形がちょうど無効（unity）
  - [ ] 4x で最悪ケースの折り返しが −60 dB 以下
  - [ ] `COLOR` を掃引して基音が ±0.5 dB 以内（`shaper` の `g` が効いている）
- **依存**: REQ-GLU-003

## REQ-GLU-007: ステレオの結束と ATTACK CENTERING

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 帯域と時間に応じて幅を制御する。

```text
Low-mid   → やや Center
High      → やや Wide
子音の瞬間 → Center
持続       → Wide
```

- **`ATTACK CENTERING` が `Timing Cohesion` の代役**（`REQ-GLU-019`）。
  子音の瞬間だけ Side を狭めると、発音が揃って聞こえる。**和から個々の
  トラックを分離する必要が無い**ので、バスで成立する。
- **位相を回さない。** 動かすのは M と S の**ゲインだけ**。オールパスも
  ディレイも使わないので、モノ和で櫛形が出ない。Air の `REQ-AIR-008` と
  同じ約束で、ここでは M/S のゲインという形で実現する。
- **帯域分割は既存**（`nxe_audio::biquad` の LR4）。Sparkleur が使っている
  ものと同じで、**帯域数は 3 で足りる**（low-mid / mid / high）。5 帯域は
  要らない。
- **トランジェント検出も既存**（速い/遅いフォロワの比）。
- **受入条件**:
  - [ ] モノ和で櫛形の谷が出ない（M/S のゲインしか触っていない帰結）
  - [ ] `WIDTH` = 0 で L == R
  - [ ] 子音の瞬間に相関が上がり、持続で戻る
  - [ ] 帯域分割の和が unity のとき ±0.1 dB 以内で平坦
- **依存**: REQ-GLU-001

## REQ-GLU-008: STACK

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 大量の Double / Harmony を 1 枚のスタックにまとめる方向へ、
  複数を同時に振るマクロ。

```text
STACK ↑
  高域の幅            ↑
  Ambience            ↑
  COLOR               ↑
  Spectral Cohesion   ↑
```

- **`GLUE` との違いは向き。** `GLUE` は「一体化」、`STACK` は
  「一体化 + 大きく」。`BIND` を含まないのが差 — スタックを厚く見せる
  のにダイナミクスの結束は要らない。
- **構想の `Timing差を軽くSmooth` は含まない**（`REQ-GLU-019`）。
- **受入条件**:
  - [ ] `STACK` を上げると 4 項が同時に動く
  - [ ] `STACK` = 0 で `GLUE` の設定を書き換えない
- **依存**: REQ-GLU-002

## REQ-GLU-009: 二層パラメータモデル

- **優先度**: Must
- **ステータス**: Draft
- **説明**: メインの 7 本と Advanced の偏差。

| メイン | 役 |
|---|---|
| `GLUE` | 全体の一体感 |
| `BIND` | 共有ダイナミクス |
| `COLOR` | 共通の質感 |
| `STACK` | スタックの厚み |
| `WIDTH` | ステレオの結束 |
| `ROOM` | 共通の空間 |
| `MIX` | Dry / Wet |

- **`AIR` を置かない**（`REQ-GLU-010`）。`COLOR` に畳んである。
- **Advanced に出すもの**: `BIND` の時定数と上限、`Spectral Cohesion` の
  目標の傾きと帯域数、`ATTACK CENTERING` の量と時定数、帯域ごとの幅、
  `Ambience` の遅延範囲と減衰。
- **`GLUE` と `STACK` が同じ値を書く段がある**（`COLOR`、`Ambience`、
  `Spectral`）。**片方が他方を上書きしてはいけない** — 両方の寄与を
  合成した値を段に渡す。Doubler のマクロと per-voice が同じ問題を
  解いている（`.agents/rules/vizia.md`）。
- **受入条件**:
  - [ ] メインだけで一通りの結束が作れる
  - [ ] `GLUE` を動かしても `STACK` の値が書き換わらない（逆も）
  - [ ] 偏差 0 のときマクロの表どおりの値になる
- **依存**: REQ-GLU-002, REQ-GLU-008

## REQ-GLU-010: ラインの中での語の一意性

- **優先度**: Must
- **ステータス**: Decided
- **説明**: 構想が使っている `AIR` と `ANCHOR` を使わない。

| 構想の語 | どうするか |
|---|---|
| `AIR`（高域感の共通化） | **`COLOR` に畳む**（`REQ-GLU-006`）。ラインで 4 個目の `AIR` を作らない |
| `ANCHOR`（Lead 優先度） | **v1 に無い**（`REQ-GLU-020`）。v2 で入れるときに改めて決める |

- Velour / Sparkleur が `AIR` を持ち、Air が製品名。**新しい製品の側が
  譲る**（`REQ-DIO-010` と同じ判断）。

## REQ-GLU-011: ステレオの扱いとバス構成

- **優先度**: Must
- **ステータス**: Draft
- **説明**: **バス構成は 2→2 のみ。**
- **1→2 を持たない。** Doubler / Air / Diorama はモノ入力から像を作る
  製品だが、**Vocal Glue は既にステレオに配置された複数の声をまとめる**
  製品。モノ入力は「まとめる対象が 1 本しかない」ということなので、
  この製品の前提が成立していない。**1→1 も出さない。**
- **検波・検出はすべて L/R リンク**（`BIND`、`Spectral`、
  `ATTACK CENTERING`）。
- **受入条件**:
  - [ ] `MIX` = 0 で L/R それぞれが入力とビット一致
  - [ ] 2→2 のみが提示される
  - [ ] 片チャネルに寄った素材で定位が動かない
- **依存**: REQ-GLU-007

## REQ-GLU-012: ミックス・出力・レイテンシ

- **優先度**: Must
- **ステータス**: Draft
- **説明**: `MIX` は dry / wet、`OUTPUT` は最終ゲイン。
- **レイテンシはゼロ。** ルックアヘッドを持たない。`ATTACK CENTERING` は
  検出した瞬間から効かせる（先読みで滑らかにしたくなるが、それは
  レイテンシ申告という新しいホスト連携を買うことになる）。
- **受入条件**:
  - [ ] `MIX` = 0 でビット一致
  - [ ] ホストへ報告するレイテンシが 0
- **依存**: REQ-GLU-001

## REQ-GLU-013: UI

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 1 画面。規則は `.agents/rules/ui.md`。
- **主役はスペクトルと目標の傾き。** 和のスペクトルと、`Spectral Cohesion`
  が寄せようとしている目標を重ねて描く。**動作量がその差として見える。**
  これが「何をしているか分からない」を防ぐ唯一の手段
  （`REQ-GLU-003` は自動で働くので、隠すと Sparkleur の Guard と同じ問題に
  なる）。
- **読み値**: `BIND` のゲインリダクション、`Spectral` の最大動作量、
  相関、IN / OUT。
- **受入条件**:
  - [ ] 全パラメータにコントロールがある（`#[id]` を走査するテスト）
  - [ ] 音が止まると表示が減衰して消える（3 秒以内に 0）
  - [ ] 窓の高さが部品から計算されている
  - [ ] `.class("root")` が根に付いている
- **依存**: REQ-GLU-018

## REQ-GLU-015: コアのホスト非依存と共有 DSP

- **優先度**: Must
- **ステータス**: Draft
- **説明**: DSP は `vocal-glue-core` に置き、フレームワークも Vizia も
  知らない。**新規 DSP がほぼ無いのがこの製品の特徴。**

| 使う既存ブロック | 使うところ |
|---|---|
| `nxe_audio::guard` | `Spectral Cohesion`（**N 帯域への一般化が要る**） |
| `nxe_audio::envelope` | `BIND` の検波、`ATTACK CENTERING` の検出 |
| `nxe_audio::biquad` | 帯域分割、`Spectral` の帯域通過 |
| `nxe_audio::shaper` | `COLOR` |
| `nxe_audio::oversample` | `COLOR` の経路 |
| 初期反射 | `Ambience Glue`。**Diorama が作る**（`REQ-DIO-003`） |

- **初期反射はここで `nxe-audio` に上がる。** 2 個目の客なので、
  `architecture.md` の「要求されるまで上げない」の条件を満たす。
- **`guard` の一般化が要る。** 今は固定の帯域と固定の参照。
  `Spectral Cohesion` は帯域数を増やし、参照を移動平均にする必要がある。
  **`RelativeGuard<N>` が既に N 帯域を持っている**ので、参照の作り方を
  呼び出し側に出すのが変更点。
- **ライセンス**: `vocal-glue-core` は **MIT OR Apache-2.0** の側
  （`LICENSING.md`）。
- **受入条件**:
  - [ ] `vocal-glue-core` がフレームワークにも Vizia にも依存しない
  - [ ] `guard` の一般化後も Velour と Sparkleur のテストが全部通る
  - [ ] 初期反射を `nxe-audio` に移した後も Diorama のテストが全部通る
- **依存**: なし

## REQ-GLU-016: リアルタイム安全性と CPU 予算

- **優先度**: Must
- **ステータス**: Draft
- **説明**: `process()` の中で確保・ロック・IO・panic をしない。
- **予算**: 533 µs、目標 250 µs。
- **見積り**: 3 帯域分割、検波 2 本、`Spectral` の N 帯域検出、`COLOR` を
  4x、初期反射 1 本。**Sparkleur（129 µs）と同程度**を見込む。
  `Spectral` の帯域数が一番効くので、**帯域数は仕様で決めて可変にしない。**
- **受入条件**:
  - [ ] criterion で 4x / 512 サンプル / 48 kHz が 533 µs 以内
  - [ ] 極端値で非有限値を出さず panic しない
  - [ ] 非有限のサンプル 1 個で検波器がラッチしない
  - [ ] 音声スレッドの経路に確保が無い
- **依存**: REQ-GLU-003, REQ-GLU-006

## REQ-GLU-017: サンプルレート・ブロックサイズ非依存

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 同じ設定がどのサンプルレートでも同じ音になる。
- **時定数はすべて秒、反射の遅延はミリ秒。** `BIND` の release は数百 ms
  オーダーなので、ここを取り違えると効きが 2 倍変わる。
- **受入条件**:
  - [ ] 44.1 / 48 / 96 / 192 kHz で `BIND` の時定数が同じ秒になる
  - [ ] ブロックサイズ 1 / 64 / 512 / 4096 の出力が一致する
  - [ ] レート変更で係数が発散しない
- **依存**: REQ-GLU-004, REQ-GLU-005

---

## REQ-GLU-018: 通っている音の表示

- **優先度**: Should
- **ステータス**: Draft
- **説明**: UI に渡す解析値。受け渡しは `nxe_dsp::Handoff`。
  - **和のスペクトラム**（`nxe_dsp::Spectrum`）
  - **`Spectral Cohesion` の目標と、帯域ごとの動作量**（**図の主役**）
  - **`BIND` のゲインリダクション**
  - **相関**（`nxe_dsp::Correlation`）
  - **IN / OUT のレベル**（`nxe_dsp::Level`）
- **`Spectral` を見せないと製品が「何もしていない」に見える。** 自動で
  働く処理なので、Sparkleur の Guard と同じ扱いにする（`REQ-SPK-008`）。
- **受入条件**:
  - [ ] 音が止まると表示が減衰して消える（3 秒以内に 0）
  - [ ] 解析を止めても音が変わらない
  - [ ] 帯域ごとの動作量が上下に出る（引いた / 戻した の向きが分かる）
- **依存**: REQ-GLU-003, REQ-GLU-004

## REQ-GLU-019: Timing Cohesion

- **優先度**: Won't (v1)
- **ステータス**: Decided
- **説明**: 発音タイミングの微小差を検出し、マイクロディレイで揃える。
- **v1 に入れない理由**:
  - **バスでは原理的に不可能。** 混ざった後の 1 本の信号から、Double
    だけを数 ms 動かすことはできない。**実装の難しさではなく、情報が
    無い**
  - **狙いは別の手段で達成される。** 「発音がまとまって聞こえる」は
    `ATTACK CENTERING`（子音の瞬間だけ Side を狭める）が、和だけを見て
    実現する（`REQ-GLU-007`）
- **v2 でも同じ形では入らない。** 入れるなら Lead / Double / Harmony を
  **別々の入力で受ける製品**になり、「バスに挿す」とは別の製品になる。
  そのときは要件から書き直す。

## REQ-GLU-020: LEAD ANCHOR

- **優先度**: Won't (v1)
- **ステータス**: Decided
- **説明**: サイドチェインで Lead を受け、Lead が鳴っている間だけ周囲の
  声を退かせる。
- **v1 に入れない理由**:
  - **aux 入力はこのリポジトリで前例が無い。** nih-plug は持っているが、
    **CLAP と VST3 でホスト側の見え方が違い**、DAW を開くまで壊れているか
    分からない。この種のホスト連携を避けるのが、6 本の着手順を決めた
    軸そのもの（`docs/implementation/roadmap.md`）
  - **Glue には既に新規がある。** `Spectral Cohesion`（`REQ-GLU-003`）が
    ゲートで、そこに未検証のホスト連携を重ねると、失敗したときにどちらが
    原因か分からない
  - **無くても製品が成立する。** `GLUE` / `BIND` / `COLOR` / `STACK` /
    `WIDTH` / `ROOM` で「1 つの声群」は作れる
- v2 で入れるときは、**空のプラグインでルーティングだけ先に通す**
  （`REQ-AIR-014` が同じ手順を書いている）。
