## 信号の流れ

```text
Input (L,R)
  │
  ├──────────────────────────────── dry ────────────────────────────┐
  │                                                                 │
  ├─ Crossover ─┬─ band 1 ─ Dynamics ─ × gain₁ ──┐                  │
  │  LR4 + AP   ├─ band 2 ─ Dynamics ─ × gain₂ ──┤                  │
  │  (5 帯域)   ├─ band 3 ─ Dynamics ─ × gain₃ ──┼─ Σ ─── wet ──────┤
  │             ├─ band 4 ─ Dynamics ─ × gain₄ ──┤                  │
  │             │            ↑ De-Harsh          │                  │
  │             └─ band 5 ─ Dynamics ─ × gain₅ ──┤                  │
  │                   │                          │                  │
  │                   └─ Sparkle ────────────────┘                  │
  │                      (4x → shaper → HPF → × snap × AIR)         │
  │                                                                 │
  └─ 検波（モノ和、帯域ごと 1 本）→ 上下のゲイン計算                  │
                                                                    │
                                          out = dry + MIX·(wet − dry) ┴─ × OUTPUT
```

**原音は分割前で分岐する**（`REQ-SPK-001`）。`MIX` = 0 が加算 1 回で入力
そのものになるのはこれだけが理由。

**`MIX` はクロスフェード**（`SPK-8` で確定）。`dry + MIX·(wet − dry)` は
`MIX` = 0 でちょうど `dry`（有限の値に 0 を掛けて足すだけ）なので、
「加算 1 回で入力そのもの」を満たしたまま `MIX` = 1 が wet になる。
`dry + MIX·wet` だと `MIX` = 1 で 6 dB 上がってしまう。

**De-Harsh は `SPARK` に乗る**（`SPK-8`）。概念文書の
`Spark ↑ → Harshness Suppression ↑` はこの掛け算のこと（`REQ-SPK-008`）で、
**同時に `SPARK` = 0 の平坦性を成立させているのもこれ** — 乗せないと、
2 kHz の単音は自分の参照帯に対してしきい値を超えているので、ダイナミクスを
切っていても De-Harsh に引かれて −3.6 dB 出る。実測で見つけた。

**`BODY` / `AIR` は帯域ごとの `SPARK` を倍率する**（`SPK-8`）。傾き 0 で
`SPARK` のまま、`+1` で 2 倍、`-1` で無音。Advanced の重みは触らない —
「マクロが per-band を倍率する」規約そのまま（`.agents/rules/vizia.md`）。
`AIR` は最上帯域のダイナミクスと Sparkle の量の**両方**に乗る。

**`SPEED` は `CHARACTER` からの双極の偏差**（`SPK-8`）。De-Harsh /
Sub Protect と同じ形で、0 が「軸の言うとおり」。

## クロスオーバー

Linkwitz-Riley 4 次 = Butterworth（`Q = 1/√2`）を 2 段。`nxe_audio::biquad` の
`lowpass` / `highpass` をそのまま重ねる。

境界 4 点（`FOCUS` = 0 のとき）:

| 境界 | Hz |
|---|---|
| 1 / 2 | 120 |
| 2 / 3 | 400 |
| 3 / 4 | 1 500 |
| 4 / 5 | 6 000 |

`FOCUS`（−1〜+1）で全部を `2^(focus · 1.5)` 倍する（±1.5 オクターブ）。
**4 点とも** `min(edge · shift, host_rate · 0.45)` で切る（実装は 4 点に
同じ式を当てている — 上端以外は 44.1 kHz 以上では絶対に当たらないので、
1 点だけ特別扱いする理由が無い）。

**天井が順序を崩しても平坦性は落ちない。** `LP(f) + HP(f) = AP(f)` は
コーナーの値に依らないので、境界が 2 つ同じ周波数に乗ると間の帯域が空に
なるだけで、和は相変わらずオールパス。順序を守らせるのは画面に出す数字の
都合であって、音の都合ではない。

### オールパス補正

木構造で分けると、**先に分けた帯域は後段のクロスオーバーの位相回転を受けない**
ので、和にリプルが出る。補正は「既に分けた帯域を、残りのクロスオーバーと同じ
オールパスに通す」。

```text
split(120):   low₁, rest₁
split(400):   low₂, rest₂  ← rest₁ から
split(1500):  low₃, rest₃  ← rest₂ から
split(6000):  low₄, band5  ← rest₃ から

band1 = low₁ を AP(400) · AP(1500) · AP(6000) に通したもの
band2 = low₂ を          AP(1500) · AP(6000) に通したもの
band3 = low₃ を                     AP(6000) に通したもの
band4 = low₄
band5 = band5
```

`AP(f)` は LR4 のクロスオーバーと同じ位相を持つ 2 次オールパスを 2 段
（`LP(f) + HP(f)` の和と等価）。**素直に `LP + HP` を計算して足す実装でよい** —
biquad は安いので、専用のオールパスを書くより読める。

**検証**: 全帯域 unity で和を取り、20 Hz〜20 kHz の振幅が **±0.1 dB 以内**
（`REQ-SPK-001`）。これが通らない限り他のテストは意味を持たない。

**通った**（`SPK-2`）。44.1 / 48 / 96 / 192 kHz と `FOCUS` −1〜+1 の全部で
±0.1 dB 以内。

**帯域の裾は 24 dB/oct とは限らない。** 木構造なので、ある帯域は自分の
境界だけでなく**上流の全部のハイパス**も通っている。band 5 の 6 kHz より
1 オクターブ下は `HP(1500)` がまだ効いていて **30 dB/oct** で落ちる。
24 dB/oct が素で見えるのは境界が 1 つしか効かないところだけ（band 1 の
120 Hz より上、band 2 の 120 Hz より下）。**検波や UI がここを勘違いすると
「フィルタの次数が違う」と読める。**

**コスト**: 1 チャネルあたり biquad 40 個（分割 4 × 4 + 補正 6 × 4）。
補正を専用の 2 次オールパス（1 個 = biquad 1）にすると 22 個まで落ちる。
**`SPK-17` で予算が厳しければ最初に触るのはここ** — 同じフィルタなので
音は変わらない。

## 検波

帯域ごとに 1 本、**モノ和**を帯域通過した後のパワー（`REQ-SPK-004`）。
`nxe_audio::guard` の `Follower` と同じ形。

```text
e_i ← 二乗して attack_i / release_i の 1 次追従
L_i = 10·log10(max(e_i, 1e-10))        (dBFS 相当のパワー)
```

**帯域通過は要らない。** クロスオーバーが既に分けているので、その帯域の信号を
そのまま二乗すればよい（Velour の Guard は分割していない信号から検出する必要が
あったので BPF を持っていた — ここは構造が違う）。

**モノ和も只で手に入る。** クロスオーバーは線形なので、モノ和を分割したものは
**両チャネルの帯域の平均**と厳密に一致する。3 本目の `Crossover` は要らず、
既に持っている 2 つを平均するだけ（`SPK-3`）。

**読み値は RMS とピークパワーの間に座る**（`SPK-3` の実測）。非対称な
1 次追従なので平均には落ち着かず、どこに座るかは attack/release の比が決める:
比 4（床が効いている band 1）で RMS の **+0.05〜0.9 dB**、比 20（band 5、
`SPEED` 最速）で **+2.5 dB**。**素直なコンプの挙動**であって直すものではないが、
`T_down` / `T_up` はこの目盛りの上にある — だから計算で出さず `SPK-18` で耳で
決める。**振幅ではなく RMS 基準**（全振幅の正弦は −3.01 dB から始まる）。

最上帯域の上端は **20 kHz**（ナイキストで抑える）。`√(0 · 120)` が 0 になって
床が無限大にならないよう、最下帯域の下端は 30 Hz 扱い。

## 時定数（`SPEED`）

```text
f_ref_i   = √(low_i · high_i)                 最下段の low は 30 Hz として扱う
floor_a_i = 2 / f_ref_i                       2 周期
floor_r_i = 8 / f_ref_i                       8 周期
attack_i  = max(A(speed), floor_a_i)
release_i = max(R(speed), floor_r_i)

A(speed) = 1 ms  · (50/1)^(1−speed)           速い側 1 ms / 遅い側 50 ms
R(speed) = 20 ms · (400/20)^(1−speed)         速い側 20 ms / 遅い側 400 ms
```

`speed` は 0〜1 で、**大きいほど速い**。`CHARACTER` が中心をずらす
（POLISH で遅い側、CRUSH で速い側）。

導出された床の実際の値:

| 帯域 | `f_ref` | attack の床 | release の床 |
|---|---|---|---|
| 1（30〜120） | 60 Hz | 33 ms | 133 ms |
| 2（120〜400） | 219 Hz | 9.1 ms | 37 ms |
| 3（400〜1.5k） | 775 Hz | 2.6 ms | 10 ms |
| 4（1.5k〜6k） | 3.0 kHz | 0.7 ms | 2.7 ms |
| 5（6k〜20k） | 11 kHz | 0.2 ms | 0.7 ms |

**床が効くのは下のほうだけ**で、上では `SPEED` が支配する。これが「LOW だけ
速くできない」の実装（`REQ-SPK-005`）。`SPEED` 最速での実測（`SPK-3`）:
**attack の床は帯域 1〜3、release の床は帯域 1〜2** に効く（1 ms より遅い
attack の床を持つのが 3 本、20 ms より遅い release の床を持つのが 2 本）。
`SPEED` 最遅では帯域 1 の attack 以外どこにも効かない。

**定常正弦は床の効果を見るには弱い。** 50 Hz では release の 20 ms が単独で
読み値を持ち上げてしまうので、床の有無でリプルがほとんど変わらない
（`SPK-3` で 1 ms attack でも 1.0 dB）。**差が出るのはステップ応答**で、
床のある帯域 1 は自分の中心周波数の 2 波長を切れず、床の届かない帯域 5 は
`SPEED` の 1 ms で追従する（33 倍差）。

## ゲイン計算

帯域ごと、検波値 `L`（dB）から。

```text
down = min(0, (T_down − L) · (1 − 1/R_down))        しきい値超過を圧縮
up   = max(0, (T_up   − L) · (1 − 1/R_up))          しきい値以下を持ち上げ
up  ← min(up, CEILING_i)                            上限（帯域ごと）
up  ← up · taper(L)                                 床
gain_db_i = (down · w_down_i + up · w_up_i) · SPARK + GAIN_i
```

- `w_down_i` / `w_up_i` は per-band の**重み**（0〜1、`REQ-SPK-009`）。
  `SPARK` が倍率。
- `R_down` / `R_up` / ニー幅は `CHARACTER` が決める。**しきい値は `MODE` が
  決める**（`REQ-SPK-022`）。しきい値は**入力レベルに対する絶対値**で、
  **目盛りは検波値**なので帯域の RMS より 0.05〜2.5 dB 上（`SPK-3`）。

  | `MODE` | `T_down` | `T_up` |
  |---|---|---|
  | Soft（既定、出荷時のまま） | −18 dB | −36 dB |
  | Hard | **−24 dB** | **−18 dB** |

  **Soft は 18 dB の死角を残していて、混ぜた声はその中に居る**（`SPK-20`）。
  −18 dBFS の素材で帯域は −19.6〜−24.8 dB を読むので、全部最大にしても出力は
  0.03 dB しか動かない。**Hard の 2 つは素材を挟むように置いてある** —
  下げがすぐ下から、上げがすぐ上から働き、間にあるものは両側から窓へ寄せられる。
  到達量は 0.7 dB から 6.9 dB になり、出力は 0.4 dB 以内に留まる（`SPK-21`）。
- ニーは 2 次の soft knee。幅 `W`（`CHARACTER`、広い 12 dB ↔ 硬い 1 dB）。
  下げと上げは**同じ関数の鏡像**で、「しきい値からどちら向きに何 dB 出たか」
  を渡し分けるだけ（`SPK-4`）。
- **`GAIN_i` は `SPARK` の外側**（上の式のとおり）。つまり **`SPARK` = 0 が
  振幅平坦なのは `GAIN_i` = 0 のとき**で、トリムを付けた帯域はトリムを
  保つ。`GAIN` はダイナミクスではなく静的な EQ だから、というのが理由。
- **ゲインには算術上の上限 `MAX_GAIN_DB` = ±48 dB がある**（`SPK-4`）。
  `CHARACTER` が届く範囲（上限 15 dB）のはるか外側で、趣味の制限ではない —
  **有限の dB は有限のゲインではない**ので、hostile な値が音声パスに無限大の
  倍率を渡さないための蓋。

### 床（taper）

```text
FLOOR_DB = −60          仮。Advanced で −90 まで開けられる
FADE_DB  = 12

taper(L) = clamp((L − (FLOOR_DB − FADE_DB)) / FADE_DB, 0, 1)
```

**これが無いと無音とノイズフロアとリリースの尻尾が持ち上がる**
（`REQ-SPK-003`）。OTT でベースに使ったときのポンピングの正体。
**Advanced で床を下げられる**（`LIFT`）ようにしてあるのは「VO-TT の代わり」を
名乗るための逃げ道で、振り切ると OTT らしい呼吸が出る。

**上限と床のどちらが先に効くかは `CHARACTER` が決める**（`SPK-4` の実測）。
既定の床 −60 dB では、POLISH（比 1.2 / 上限 6 dB）も GLOSS（1.5 / 9 dB）も
**上限に届く前に床が消してしまう** — 最大でも 4.0 dB と 8.0 dB。CRUSH
（3.0 / 15 dB）だけが既定の床でも上限に当たる。**聴き手が実際に聴いている
のがどちらの制限か**が `CHARACTER` で入れ替わるということなので、`SPK-18` で
数字を動かすときはここを見る。

**低域の THD**（`SPK-4`、48 kHz・`SPEED` 最速・50 Hz 半振幅）:
ダイナミクス無しで 0.0005%、床ありで **0.26%**（−52 dB）、床を外すと
**2.0%**（−34 dB）。**床ありが 0 にならないのは当然**で、33 ms の attack は
20 ms の周期の中でも少しは動く。ベースを圧縮することの正直な代価であって、
床が防いでいるものの 7.6 分の 1。

### Sub Protect

専用の処理ではない。`CEILING_i` の値違い（`REQ-SPK-008`）。

```text
CEILING_i = CHARACTER の上限 × (i == 1 ? (1 − sub_protect) : 1)
```

`sub_protect` = 1 で LOW の上げがちょうど 0 になる。

**実装は帯域ごとの `ceiling_scale`**（`SPK-7`）。`Weights` に 1 項目足しただけで、
ゲイン計算は 1 本のまま。「専用の処理を足さない」がコードの形にそのまま出る。

## CHARACTER

アンカー 3 点の表を補間（`REQ-SPK-006`）。Velour の `texture.rs` と同じ機構で、
**同じコードにはしない**（乗っている項目が違う）。

| | POLISH | GLOSS | CRUSH |
|---|---|---|---|
| `R_down` | 1.5 | 2.5 | 6.0 |
| `R_up` | 1.2 | 1.5 | 3.0 |
| `CEILING` (dB) | 6 | 9 | 15 |
| ニー幅 `W` (dB) | 12 | 6 | 1 |
| Sparkle `h` | 0.15 | 0.35 | 0.80 |
| Sparkle `β` | 0.50 | 0.30 | 0.10 |
| De-Harsh | 1.0 | 0.6 | 0.2 |
| Sub Protect | 0.0 | 0.4 | 1.0 |
| `SPEED` の中心 | 0.35 | 0.5 | 0.75 |
| レベルトリム (dB) | 仮 0 | 仮 0 | 仮 0 |

**レベルトリムは最初から置く。** Velour で `TEXTURE` を作ったとき、
カーブを変えるとレベルが −3.0 dB 動いて後から吸収する必要が出た。
**同じことが起きる場所**（比とニーを変えれば平均レベルは動く）なので、
最初から枠を用意して `SPK-18` で詰める。

**実測ではまだ要らなかった**（`SPK-5`）。5 帯域それぞれに正弦を置いた素材で
軸を端から端まで動かして **0.98 dB**（許容は ±1.5 dB）。トリムは 3 点とも
0 のまま。**枠だけ先にあることに意味がある** — Velour は完成した後に
9 個のトリムを差し込む羽目になった。

**しきい値は軸に乗らない**（`SPK-5`）。しきい値が `CHARACTER` で動くと、軸が
「何が起きているか」と「どれくらい起きているか」の両方を動かすことになり、
`REQ-SPK-010` が分けたがっているものが混ざる。

**`MODE` が動かすのはしきい値だけ**（`REQ-SPK-022`）。比もニーもトリムも
`CHARACTER` のもので動かない — **軸がどんな種類のことが起きるかを言い、
モードがどのレベルから起き始めるかを言う**。混ぜると `MODE` が 2 つ目の
`CHARACTER` になる。

既定位置は **0.27**（POLISH 寄り。`REQ-SPK-006`）。

## PUNCH

**Sparkle の検出器の、ホールドを通す前のタップを使う**（`REQ-SPK-020`）。
新しい検出器は作らない — 同じ素材について 2 つの意見を持たせると、端で食い違う。

```text
rise = max(0, transient − slow_copy(transient))     slow_copy は 60 ms の一極
wet *= 10^(PUNCH_MAX_DB · PUNCH · rise · SPARK / 20)
```

- **読むのはホールドの前**（`Sparkle::transient`）。層が乗っている
  `opening` は「子音が 2 つ続いても 1 回の開き」に見せるためにホールドを持って
  いて、**音符の本体の間ずっと開いたまま**。そこから駆動するとアタックが
  1.2 dB・全体が 3.1 dB 上がる — 名前だけトランジェントのゲインになる
- **さらに立ち上がりだけを取る。** 速い/遅いの比は遅いフォロワが追い付くまで
  立ちっぱなしなので、**同じ読み値の遅いコピーを引く**。残るのは端だけ
- **和に掛ける、帯域ごとではない。** トランジェントは広帯域なので、1 帯域だけ
  叩くと鋭くなるのではなく傾く
- **`SPARK` に乗る**（`REQ-SPK-009`）。`PUNCH_MAX_DB` = 6 dB

実測（バースト状のピンクノイズ、頭 10 ms 対 続く 40 ms）:

| `PUNCH` | アタック | レベル |
|---|---|---|
| 0.00 | −2.62 | +0.06 |
| 0.50 | −1.49 | +0.71 |
| 1.00 | **−0.40** | +1.51 |

**アタックが 2.22 dB 動いてレベルは 1.45 dB** — 差がトランジェント強調である
ことの証拠で、ゲインならこの 2 つは同じだけ動く。

## Sparkle

```text
band5 ─→ 上蓋 ─→ Oversampler(4x) ─→ shaper(β, h) ─→ HPF(帯域の下端) ─→ × g ─→ 加算
   │                                                                    ↑
   ├─ fast follower (1 ms 対称) ─┐                                      │
   └─ slow follower (100 ms 対称) ┴─ 比 → snap ─→ ホールド(40 ms) ───────┘

snap  = clamp(10·log10(fast/slow) / SNAP_RANGE_DB, 0, 1)     SNAP_RANGE_DB = 仮 6
g     = AIR · ((1 − SNAP) + SNAP · snap)
```

**フォロワは両方とも対称で、40 ms のリリースは比の後ろに置く**（`SPK-6` で
書き換えた）。元の仕様は fast を 1 ms / 40 ms の非対称にしていたが、**非対称な
追従は平均とピークの間に座り、位置は attack/release 比が決める**（`SPK-3`）。
1:40 の fast は対称な slow より**どんな定常音でも約 3 dB 高い**ので、比を取ると
持続音でゲートが**半開き**になる（実測 0.44）。`REQ-SPK-007` が禁じている挙動
そのもの。対称にすれば比は定常音で必ず 1 になり、連続する子音でゲートが
バタつかないようにする役目は**ゲート側のホールド**（40 ms、開くのは即時）が
そのまま引き受ける。実測: 無音 0.000 / アタック 1.000 / 持続音 0.008
（6.5 kHz でも 0.010）。

**HPF は 6 kHz 固定ではなく帯域の下端に追従する**（`SPK-6`）。フィルタの役目が
「自分が出てきた帯域より下に足さない」なので、`FOCUS` が境界を動かせば一緒に
動くのが筋。`FOCUS` = 0 では仕様どおり 6 kHz。

**カーブのドライブは 1 つの定数**（`sparkle::DRIVE` = 仮 4.0）。`AIR` は量で
**出力ゲインを動かす**（`REQ-SPK-007`）ので、ドライブは制御ではない。仕様が
値を書いていなかったので `SPK-6` で置いた。上限はエイリアシングで、Velour の
`DRIVE_MAX` と同じ性質。

- `SNAP` = 0 → `g = AIR`（完全に静的。Velour と同じ挙動）
- `SNAP` = 1 → `g = AIR · snap`（アタックのときだけ光る）
- **入力に上蓋**: `band5` の上端を **`min(12 kHz, host_rate · 0.25)`** で切る。
  Velour の `AIR_INPUT_CEILING` と同じ理由で、**無いとどんなドライブでも
  −44 dB で折り返す**。**絶対値は 20 kHz ではなく 12 kHz**（`SPK-9`）—
  分数だけだと 44.1 kHz で 11 kHz、96 kHz で 20 kHz になり、7 kHz の音が
  両者で **1.0 dB** 違う（`REQ-SPK-017` の許容は 0.5）。絶対値を入れると
  分数が効くのは 48 kHz 未満だけになり、そこは本当に余裕が無い。
- 生成後の HPF は「足すのは上だけ」を保証する。倍音は下にも降りてくるので、
  切らないと中域が濁る（Velour の各帯域の出力フィルタと同じ役割）。
- **`shaper` の正規化がそのまま効く。** `nxe_audio::shaper` は参照振幅での
  RMS ゲインを 1 に正規化してあるので、`CHARACTER` で `(β, h)` が動いても
  **足す量は動かない**。`REQ-SPK-010` の直交はこれに乗っている。

## De-Harsh

`nxe_audio::guard`（一般化後の `RelativeGuard`）を 1 インスタンス。

| | 値 |
|---|---|
| 検出帯 | 1.5〜5 kHz |
| 参照帯 | **200 Hz〜1.2 kHz**（検出帯の下。重ねない） |
| しきい値 | **0 dB**（帯域/参照のパワー比。実測で決めた、`SPK-18`） |
| 引く相手 | band 4（PRESENCE）の出力ゲイン |
| 上限 | 12 dB |
| 弾道 | attack 2 ms / release 60 ms |

**相対検出なので入力ゲインに依存しない** — 分子と分母が一緒に動く。
Velour の Harsh Guard で実測して固定してある性質（±12 dB で 0.2 dB 以内）。
**Sparkleur 側でも同じ測定を通した**（`SPK-7`）。`SPK-1` で機構を共通に
上げた甲斐がここで出ている — 2 つの製品が同じコードの同じ性質を別々に
測っている。

**軸の値と Advanced の偏差は加算**（`SPK-7`）。0 で `CHARACTER` に従い、
偏差を最下端に振ると**軸が何を言っていてもちょうど無効**になる。絶対量に
すると 2 つが 1 つの値を書くことになる（`.agents/rules/vizia.md`）。

**検出帯は分割後の band 4 ではなく、専用の帯域通過**で取る。理由: band 4 の
境界は `FOCUS` で動くが、「耳に痛い場所」は動かない。

**参照帯は検出帯の下に置く。重ねない**（`SPK-18`）。最初は Velour の
300 Hz〜8 kHz をそのまま借りていたが、それだと**検出帯が自分の参照帯の中に
入る**。1.5〜5 kHz を +10 dB 持ち上げると参照帯も 6 dB 上がるので、
**10 dB の harsh が 2 dB にしか読めない**。検出帯を参照から抜くと同じ 10 dB が
7.1 dB として読める。

| 参照帯 | neutral | +10 dB harsh | 読み取り幅 |
|---|---|---|---|
| 300 Hz〜8 kHz（当初） | −4.06 | −2.01 | 2.04 dB |
| 300 Hz〜1.5 kHz | −0.89 | +4.76 | 5.65 dB |
| **200 Hz〜1.2 kHz** | **−1.69** | **+5.43** | **7.12 dB** |

**しきい値 0 dB は実測で置いた**（`SPK-18`）。落ち着いた 4 秒間の分布:

| 素材 | p50 | p95 | max |
|---|---|---|---|
| 定常倍音列 6 本 | −7.04 | −6.80 | −6.69 |
| **ピンクノイズ** | **−1.67** | **−0.40** | **+0.29** |
| ピンク + presence 6 dB | +2.69 | +3.77 | +4.86 |
| ピンク + presence 10 dB | +5.57 | +6.45 | +7.58 |

つまり 0 dB は「1.5〜5 kHz がその下の中域と同じパワーを持ったら」で、
**普通の素材は 1.7 dB 下にいる**。出荷時の −8 dB はこの表の全部より下に
あったので、ピンクノイズから既定値で 1.3 dB 引いていた。

**Velour は合わせて変えない。** 公開済みで `CLAP_ID` がプロジェクトに入って
おり、別の帯域についての別の判断でもある。`SPK-1` が分けたのはまさにこれ —
**共有した機構が片方の製品のチューニングを黙って運ばないこと**。

## CHARACTER のレベルトリム

**答えは「数字は無い」だった**（`SPK-18`）。トリム列は軸がラウドネスを動かす
のを打ち消すために置いてあるが、実機と同じ `Engine` で 4 素材を測ると:

| 素材（`SPARK` 全開、軸中央からのずれ） | POLISH | GLOSS | CRUSH |
|---|---|---|---|
| ピンク −18 dBFS | −0.07 | 0 | +0.08 |
| ピンク −30 dBFS | +0.01 | 0 | +0.09 |
| 定常倍音列 6 本 | −0.13 | 0 | +0.08 |
| **ハイハット** | **+1.23** | 0 | **−1.18** |

**4 つのうち 3 つは動かない。** ハットだけが 2.4 dB 動く。ここでハットを
平らにするトリムを入れると、**他の 3 つが同じだけ逆に傾く** — 1 素材のずれを
全素材のずれに変える。

ハットが動くのは**比が効いているから**。CRUSH は 6:1、POLISH は 1.5:1 で、
ハイハットはほぼ全部がトランジェントなので、比が硬いほどレベルが減る。
**それは要求している処理そのもの**で、打ち消す対象ではない。
`REQ-SPK-006` の ±1.5 dB は**持続音についての条件**として読む。

**トリムは配線した**（`SPK-18`）。`Character::trim_db` は補間だけされて
**エンジンが一度も読んでいなかった** — 直す手段が最初から効かない状態だった。
`Curve::trim_db` に移して **`SPARK` の内側**に足す（比が取った分を返すので、
比と同じだけ効くべき。外側だと `SPARK` = 0 が静的ゲインになって
`REQ-SPK-009` が壊れる）。値は 0 のまま。

## 耳で詰める定数

**機構が仕様、値は仮**（`SPK-17`）。

**半分は耳の問題ではなかった**（`SPK-18`）。「無音で呼吸しない」「普通の素材で
どちらも動く」「ハットで光ってパッドで光らない」「残留が −60 dB 以下」は
どれも測れる。測れるものは
`plugins/sparkleur/sparkleur/src/defaults.rs` が**出荷時の既定値そのもの**を

| 何 | 値 | どう決まったか |
|---|---|---|

| `SNAP_RANGE_DB` | 6 dB | **測定で確認済み。** ハット ゲート 1.000 / パッド 0.107、平均で 14 倍 |

## 検証

| 何 | どう測るか |
|---|---|
| 分割の平坦性 | 全 unity で和を取り、対数スイープの振幅が ±0.1 dB 以内 |
| `MIX` = 0 | 出力が入力とビット一致 |
| 下げの比 | 一定正弦の振幅を変えて、しきい値超過分と出力の傾きの比 |
| 上げの上限 | 微小信号を入れてゲインが `CEILING` を超えないこと |
| 床 | 無音（+ ノイズ）でゲインが上がらないこと |
| 時定数の床 | `SPEED` 最速で LOW の attack を測り、導出値を下回らないこと |
| 低域の歪み | `SPEED` 最速、50 Hz 正弦で THD を測る |
| Sparkle の折り返し | 最悪ケースの入力で 4x の折り返しが −60 dB 以下 |
| レート非依存 | **ノイズで**測る。定在音は位相で打ち消し合う（下） |
| 確保が無いこと | 数えるグローバルアロケータ（`tests/allocation.rs`） |
| De-Harsh の入力ゲイン非依存 | ±12 dB で動作量が 0.2 dB 以内 |
| レート非依存 | 44.1 / 48 / 96 kHz でレベル 0.5 dB / 倍音比 10% 以内 |
| ブロック非依存 | 1 / 32 / 512 / 2048 で出力一致 |
| hostile な値 | 全パラメータ・全サンプルに NaN / ±inf / ±1e9 を入れて非有限を出さない |
| CPU | criterion で 4x / 512 / 48 kHz が 533 µs 以内 |

## レートを跨いだときに何が同じで何が違うか

`SPK-9` の実測（`spark` = 1、`AIR` 全開）。

| 何 | 44.1 / 48 / 96 kHz |
|---|---|
| 分割だけ（`SPARK` = 0） | **完全に一致**（−7.959 dB、3 レートとも同じ数字） |
| コンプまで（Sparkle 無し） | 0.2 dB 以内 |
| ノイズを通した出力レベル | **0.33 dB 以内** |
| 倍音比（2 倍音 / 入力） | **9.1% 以内**（許容 10%） |
| **定在音の基音振幅** | **最大 1.0 dB 違う** |

**最後の 1 行だけが要件を外れる。理由は位相で、処理の中身ではない。**
Sparkle の層は IIR のオーバーサンプラを通っていて、**その遅延はサンプル数で
固定**なので、同じ周波数に対する位相がレートで回る。層が自分の出てきた帯域と
足し算されるとき、その位相差ぶんだけ和が変わる。定在音でしか起きない
（実素材はそこまで止まっていない）ので、**レート非依存の検証はノイズで測る**。

**倍音比の 9.1% はほとんどが上蓋**。エイリアシングの安全のために
`host_rate · 0.25` が要るので、44.1 kHz では上蓋が本当に低い。
