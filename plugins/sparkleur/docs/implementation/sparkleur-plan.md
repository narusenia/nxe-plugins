# Sparkleur — 実装計画

> 最終更新: 2026-08-26

要件は [`../requirements/REQ-SPK.md`](../requirements/REQ-SPK.md)、
DSP 仕様は [`../specifications/dsp.md`](../specifications/dsp.md)、
UI 仕様は [`../specifications/ui.md`](../specifications/ui.md)。

**単位ごとに「完了条件」を満たしてからコミットする。** 完了条件は
「動いた」ではなく**測れること**で書く。Doubler と Velour で 3 回学んだ順序が
あるので、それを踏む。

## 順序の考え方

**Velour で 4 回起きたことをここでも見込む**: 実測が仕様の数字を否定する。
だから「測れる土台」を先に作り、耳の判断を最後にまとめる。

```text
SPK-1  共有クレート ✅     ← ここが通らないと何も書けない
SPK-2  クロスオーバー      ← 平坦性が全部の前提（ゲート）
SPK-3  検波と時定数
SPK-4  ゲイン計算（上下）  ← 製品の核
SPK-5  CHARACTER
SPK-6  Sparkle
SPK-7  De-Harsh / Sub Protect
SPK-8  ラッパとパラメータ  ← ここで初めて音が出る
SPK-9  詰め（レート・ブロック・極端値）
SPK-10 nxe-ui の delta 符号付き化
SPK-11 param_bind の共通化
SPK-12 UI マクロ層
SPK-13 UI Band Field
SPK-14 UI 小窓とメーター
SPK-15 UI Advanced
SPK-16 解析の配線
SPK-17 CPU 予算
SPK-18 既定値と耳
```

**`SPK-2` がゲート。** 分割の和が平坦でなければ「全部 0 で何もしない」が成立
せず、その上の全部が意味を持たない。Velour の `VEL-1`（カーブのレベル正規化）と
同じ位置。

### SPK-1 — 共有クレート `nxe-audio` ✅

`velour-core` から `shaper` / `oversample` / `biquad` / `envelope` / `guard` を
新クレート `crates/nxe-audio` に移す。`guard` は一般化する。

- **完了条件**:
  - [x] `nxe-audio` が nih-plug / Vizia / `velour-core` に依存しない
  - [x] **Velour のテストが 1 本も落ちない**（241 本が 241 本のまま通り、
        `N = 1` の形を固定する 1 本を足して **242 本**）
  - [x] `RelativeGuard` が帯域・参照帯・しきい値を引数で受ける
  - [x] Velour 側が「Harsh と Sib を 2 個作る薄いラッパ」になり、既存の
        `guard::tests` がそのまま回帰テストとして残る（信号で駆動する 7 本は
        そのまま。純関数の 2 本は `gain_of` と一緒に `nxe-audio` へ）
  - [x] `velour-core` に残るのは `bands` / `texture` / `density` / `engine` と、
        Velour のチューニングだけになった `envelope` / `guard`
- **要件**: REQ-SPK-015
- **依存**: なし
- **決めたこと**: `nxe-dsp` には入れない。あちらは「音を変えない」ことが
  doc に書かれた契約で、**解析はバグっても絵が壊れるだけ、処理はバグると音が
  壊れる**（リスクの階級が違う）
- **決めたこと**: `density` は移さない。Sparkleur のコンプは上下マルチバンドで
  別物。**要求されるまで上げない**（`architecture.md`）
- **決めたこと**: `RelativeGuard<N>` は**参照フォロワを 1 本だけ持ち、帯域を
  N 本持つ**。「Velour が 2 個作る」だと同じ信号に同じ帯域通過を 2 回かけて
  同じ答えを得ることになる。`VEL-16` の内訳が示すとおり、この構造で効くのは
  フィルタの本数
- **決めたこと**: 設定は `Settings<N>`（参照帯・帯域としきい値・時定数・傾き・
  最大引き量）を**呼び出し側の `const` 1 個**で渡す。引数 5 本より、何を
  どこまで守るのかが 1 ブロックで読める
- **決めたこと**: 互換の再輸出を置かない。`velour` も `nxe-audio` を直接引く。
  例外は測定ヘルパの `harmonics` 1 つだけ（下）
- **踏んだ罠**: **`harmonics` も一緒に移すことになった。** 移す 5
  モジュールのテストが全部これで書かれていて、`nxe-audio` は `velour-core` に
  依存できない（向きが逆）。計画では「`velour-core` に残る」と書いていたが、
  残すと移動先のテストが 1 本も書けない。移して `velour_core` が再輸出する形に
  した — `crate::harmonics::tone` と書いてある既存のテストが無修正で通る
- **踏んだ罠**: **`envelope` は「ファイルの移動だけ」では済まなかった。**
  attack 5 ms / release 150 ms と `REFERENCE_DB` −18 dB は**歌に対して耳で
  決めた数**で、Sparkleur は `SPEED` と帯域中心から導出する（`REQ-SPK-005`）。
  時定数を `Envelope::new` の引数に出し、Velour の 3 つの数は
  `velour_core::envelope`（`vocal()` と `REFERENCE_DB`）に残した。**共有部品が
  片方の製品の好みを黙って運ばないこと**が境界の引き方

### SPK-2 — クロスオーバー（ゲート）

`crossover.rs`。LR4 の木 + オールパス補正、5 帯域、`FOCUS`。

- **完了条件**:
  - [ ] 全帯域 unity のとき、**20 Hz〜20 kHz の和の振幅が ±0.1 dB 以内**
  - [ ] 各帯域が隣の帯域と 24 dB/oct で交差する
  - [ ] `FOCUS` で 5 境界が**まとめて**動き、比が保たれる
  - [ ] `FOCUS` を振り切っても最上端がナイキストを超えない
  - [ ] 44.1 / 48 / 96 / 192 kHz で平坦性が保たれる
  - [ ] 係数の再計算がブロック単位（サンプルごとに入っていない）
  - [ ] hostile な `FOCUS` で非有限を出さない
- **要件**: REQ-SPK-001, REQ-SPK-002
- **依存**: SPK-1
- **決めること**: オールパスを専用に書くか `LP + HP` の和で済ますか。
  **読める方を採る**（biquad は安い）

---

### SPK-3 — 検波と時定数

`detector.rs`。帯域ごとのパワー追従、`SPEED` からの時定数、帯域からの床。

- **完了条件**:
  - [ ] 一定の正弦で検波値がその振幅を読む（±0.5 dB）
  - [ ] `SPEED` 最速でも LOW の attack が**導出された床（33 ms）を下回らない**
  - [ ] 弾道が 44.1 / 48 / 96 / 192 kHz で同じ
  - [ ] 非有限のサンプル 1 個でラッチしない
  - [ ] `SPEED` 最速・50 Hz 正弦で **THD が上がらない**（波形変調していない）
- **要件**: REQ-SPK-004, REQ-SPK-005
- **依存**: SPK-2

---

### SPK-4 — ゲイン計算（上下コンプ）

`dynamics.rs`。下げ・上げ・上限・床・ニー。**製品の核。**

- **完了条件**:
  - [ ] `SPARK` = 0 で全帯域のゲインが**ちょうど 0 dB**
  - [ ] 下げの比が設定どおり（入力 +12 dB に対する出力の傾きで測る）
  - [ ] 上げの比が設定どおり
  - [ ] 上げが `CEILING` を超えない、かつ**ちゃんと上限に到達する**
  - [ ] **無音（+ ノイズフロア）でゲインが上がらない**（床が効いている）
  - [ ] 床を開放すると上がる（`LIFT` が効いている）
  - [ ] ニーが連続（しきい値の前後で微分が飛ばない）
  - [ ] per-band の重みが線形にスケールする
  - [ ] hostile な値で非有限を出さない
- **要件**: REQ-SPK-003, REQ-SPK-009
- **依存**: SPK-3

---

### SPK-5 — CHARACTER

`character.rs`。アンカー 3 点の補間。

- **完了条件**:
  - [ ] 3 つのアンカー位置でちょうど表の値になる
  - [ ] 端から端まで動かして不連続が無い
  - [ ] 軸を動かしてもラウドネスが **±1.5 dB 以内**（トリムで吸収）
  - [ ] POLISH と CRUSH で倍音の偶奇比が **1.5 倍以上**違う
  - [ ] hostile な位置で中央にフォールバックする
- **要件**: REQ-SPK-006, REQ-SPK-010
- **依存**: SPK-4, SPK-6
- **決めたこと**: レベルトリムの枠を**最初から置く**。Velour で `TEXTURE` が
  −3.0 dB 動いて後から吸収する必要が出た。比とニーを変えれば平均レベルは
  動くので、同じことが起きる

---

### SPK-6 — Sparkle

`sparkle.rs`。オーバーサンプル → シェイパ → HPF → トランジェントゲート。

- **完了条件**:
  - [ ] `AIR` = 0 で生成層が**ちょうど無音**
  - [ ] `SNAP` = 0 で静的、= 1 で持続音に対して光らずアタックで光る
  - [ ] 4x で最悪ケースの折り返しが **−60 dB 以下**
  - [ ] 入力の上蓋が**ホストレート**基準（内部レートではない）
  - [ ] `CHARACTER` で偶奇比が動き、**足す量は動かない**（正規化の帰結）
  - [ ] 生成物が HPF より下に漏れない
- **要件**: REQ-SPK-007
- **依存**: SPK-2
- **踏むと分かっている罠**: Velour の `VEL-3` で AIR の入力に上蓋を付けるまで
  **どんなドライブでも −44 dB で折り返した**。上蓋を**内部レート**基準に
  書いて 1 回間違えた（`FOCUS` +1 で 48 kHz まで開いた）ので、**ホストレート**
  基準で書く

---

### SPK-7 — De-Harsh / Sub Protect

`nxe_audio::RelativeGuard` を 1 個 + `CEILING` の値違い。**新しい機構を
足さない。**

- **完了条件**:
  - [ ] 入力ゲインを ±12 dB 変えても動作量が **0.2 dB 以内**
  - [ ] 偏差を最小にすると De-Harsh がちょうど無効
  - [ ] バランスの取れた素材では発火しない / 偏った素材では 3 dB 以上引く
  - [ ] Sub Protect が LOW の上げ量だけを制限し、他の帯域を触らない
  - [ ] `reduction_db` を公開する（`SPK-13` の図が描く）
- **要件**: REQ-SPK-008
- **依存**: SPK-4, SPK-5

---

### SPK-8 — ラッパとパラメータ（ここで音が出る）

`sparkleur/src/{lib.rs, params.rs}` と `engine.rs`。パラメータ 33 個。

- **完了条件**:
  - [ ] Live で読み込めて音が出る
  - [ ] `MIX` = 0 で**ビット一致**
  - [ ] `SPARK` = 0 で振幅が ±0.1 dB 以内に平坦（位相は回る）
  - [ ] 2→2 と 1→1 の両レイアウトで動く
  - [ ] `OUTPUT` = 0 dB がちょうど unity
  - [ ] ホストに報告するレイテンシが 0
  - [ ] ブロック単位の値は `next_step(samples)`、サンプル単位は `next()`
- **要件**: REQ-SPK-001, REQ-SPK-011, REQ-SPK-012, REQ-SPK-014
- **依存**: SPK-4, SPK-5, SPK-6, SPK-7
- **踏むと分かっている罠**: `smoothed.next()` をブロックに 1 回だけ読むと
  ランプがブロック長ぶん伸びる（Velour の `VEL-5`）

---

### SPK-9 — 詰め

レート・ブロックサイズ・極端値。

- **完了条件**:
  - [ ] ブロックサイズ 1 / 32 / 512 / 2048 で出力一致
  - [ ] 44.1 / 48 / 96 kHz でレベル 0.5 dB / 倍音比 10% 以内
  - [ ] 全パラメータを範囲外まで振っても非有限を出さず panic しない
  - [ ] **非有限のサンプル 1 個で検波器がラッチしない**（Velour の `VEL-10` で
        見つけたバグと同じ形。モノ和を 1 か所で消毒する）
  - [ ] どのノブを速く動かしても、止めているときの最大段差の 1.3 倍を超えない
  - [ ] 音声スレッドの経路に確保が無い
- **要件**: REQ-SPK-016, REQ-SPK-017
- **依存**: SPK-8

---

### SPK-10 — `nxe-ui` の `delta` 符号付き化

`Band::reduction`（0〜1、下向き専用）を `delta`（−1〜1）に変える。
gallery も同じ変更で更新する。

- **完了条件**:
  - [ ] 負の値で下に沈み、正の値で上に伸びる
  - [ ] unity の線が描かれる
  - [ ] Velour の見た目が変わらない（負の値しか渡していない）
  - [ ] gallery のパネルで上下に動かせる
- **要件**: REQ-SPK-013
- **依存**: なし（`SPK-13` の前まで）

---

### SPK-11 — `param_bind` の共通化

Doubler と Velour で同内容が 2 つある。**3 個目が要求したので上げる。**

- **完了条件**:
  - [ ] 新クレート（仮 `nxe-plug-ui`）が nih-plug と vizia を知り、**`nxe-ui`
        はどちらも知らないまま**
  - [ ] `mise run gallery` が nih-plug をリンクせずに起動する
  - [ ] Doubler と Velour の UI が変わらない
- **要件**: REQ-SPK-013
- **依存**: なし
- **決めたこと**: `nxe-ui` に入れない。入れると gallery が単体起動できなくなり、
  **DAW を開かずに UI を反復する**という土台が消える

### SPK-12 — UI マクロ層（メインタブ）

7 ノブ + タブ。`CHARACTER` の読み値は「近いアンカー名 + %」。

- **完了条件**: 7 個すべてが効き、ホストへジェスチャー開始／終了を通知する。
  タブが切り替わる
- **要件**: REQ-SPK-013
- **依存**: SPK-9, SPK-11
- **先に読む**: `.agents/rules/vizia.md`。特に **`font-size` に単位を書かない** /
  **未指定のサイズは `Stretch(1.0)`** / **`cx.add_timer` は発火しない** /
  **カスタム描画のウィジェットには明示的な高さを与える**

### SPK-13 — UI Band Field（5 区画）

- **完了条件**: 区画のドラッグで per-band `GAIN` が動き、逆も反映される。
  **上げコンプが線より上に描かれる。** レールで `FOCUS` が動く。
  De-Harsh の沈みが出る
- **要件**: REQ-SPK-013
- **依存**: SPK-10, SPK-12, SPK-16
- **決めたこと**: 区画の左右は**クロスオーバーが調律に使う関数から取る**
  （Velour の `Generator::input_range` と同じ手）。図と音が同じ数から出る

### SPK-14 — UI 小窓とメーター

ダイナミクスの伝達曲線（入力 dB → 出力 dB）と IN / OUT メーター。

- **完了条件**: `CHARACTER` を回すと**ニーが 2 つ同時に動く**。45° の線が
  基準として読める。メーターが IN / OUT で動く
- **要件**: REQ-SPK-013, REQ-SPK-018
- **依存**: SPK-12, SPK-16
- **踏むと分かっている罠**: Velour で窓を**固定天井**で描いたので、
  ドライブを上げるほど曲線が小さくなった。**窓を埋めるようにスケールする**

### SPK-15 — UI Advanced タブ

per-band UP / DOWN / GAIN / SOLO × 5、`FOCUS`、De-Harsh / Sub Protect の偏差、
`SNAP`、`LIFT`、オーバーサンプル。

- **完了条件**: 24 個すべてが効く。行にポインタを乗せると図の区画が光り、
  逆も効く
- **要件**: REQ-SPK-009, REQ-SPK-013
- **依存**: SPK-13
- **踏むと分かっている罠**: **バーに高さを指定しないと当たり判定が 0 になる。**
  Velour の Advanced 表がまるごと「動かないコントロール」になった

---

### SPK-16 — 解析の配線

`Spectrum` 1 本、帯域ごとの実効ゲイン 5 個、De-Harsh のリダクション、
Sparkle の包絡、`Level` 4 個。受け渡しは `Handoff`、UI 側は `cx.spawn`。

- **完了条件**: 音が止まると表示が減衰して消える。上げが上・下げが下に出る。
  **解析を止めても音が変わらない**
- **要件**: REQ-SPK-018
- **依存**: SPK-8
- **決めること**: `Spectrum` のバンド数。Velour は 48（倍音を見るため）だが、
  ここは背景なので 32 で足りる可能性がある。`SPK-17` の実測で決める

---

### SPK-17 — CPU 予算

criterion。4x / 512 サンプル / 48 kHz。

- **完了条件**: 合計が **533 µs 以内**（目標 250 µs）。測定値を
  `backlog.md` に記録する
- **要件**: REQ-SPK-016
- **依存**: SPK-16
- **決めること**: 超えた場合の削り順 — (1) `Spectrum` のバンド数、
  (2) オールパス補正を落とす（**音質を捨てるので最後**）、
  (3) 4x → 2x の既定変更。**クロスオーバーの次数と上下コンプは削らない**
  （製品そのもの）

---

### SPK-18 — 既定値と耳

**耳が要る。** 33 個の既定値と、`dsp.md` の「耳で詰める定数」の表。

- **完了条件**: 実素材（声・ベース・シンセ・ドラムバス）で 1 周して、
  既定値が「挿しただけで良い」と言える
- **要件**: REQ-SPK-021
- **依存**: SPK-17

## 見込んでいる罠（Velour で払った授業料）

前の 2 製品で時間を溶かした形が、そのまま来る場所が分かっている。

| 罠 | どこで来るか |
|---|---|
| **テスト信号を周期数で書く** | `SPK-2` の平坦性、`SPK-6` の折り返し。`nxe_audio::harmonics::tone(amplitude, hz, rate, length)` を使う |
| **往復すれば分かるは嘘** | `SPK-2`。「和が平坦」を通しても、非線形がその間に居ると別の話 |
| **引き算で層を取り出すな** | `SPK-6`。生成層は `SOLO` で直接取る |
| **仕様の数字が実測で動く** | `SPK-4`（しきい値）、`SPK-5`（トリム）、`SPK-6`（`SNAP_RANGE`）。動いたら**理由と実測値をここと `dsp.md` に残す** |
| **テストが何も検出できずに通る** | `SPK-9` のジッパー。**測定が失敗できることを同じテストで確かめる** |
| **バーに高さが無い** | `SPK-15` |
| **中央寄せがストレッチを食う** | `SPK-14` |
| **固定天井で曲線が縮む** | `SPK-14` |
| **`.accent` は塗り、`.subtle` と `.value` はサイズが違う** | `SPK-12` |
