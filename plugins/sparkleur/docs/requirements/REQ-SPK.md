# REQ-SPK — Sparkleur 要件定義

> 最終更新: 2026-08-26

## 概要

Sparkleur は**マルチバンドダイナミクス + 動的な倍音生成**。狙いは 2 つあって、
両方を 1 つの製品で成立させることが要件の全部にかかっている。

- **VO-TT / OTT 系の代わりになる。** 5 帯域の上下コンプレッサを持ち、
  per-band の UP / DOWN / GAIN を触れる。挿して 1 本回せば密度が出る
- **手軽に「綺麗」「煌びやか」が出る。** 倍音生成と Air が、静的な EQ では
  作れない艶を、常時シャリシャリさせずに足す

対象は Bitwig / Ableton Live / Reaper / Studio One。**AU は対象外**なので
Logic Pro と GarageBand では読み込めない（`REQ-SPK-014`）。

姉妹製品 Velour（ボーカルの存在感を生成するサチュレータ）とは担当が分かれる。
**Velour は原音を通さず足すだけ、Sparkleur は分割して均す。** 倍音生成カーブと
オーバーサンプラと相対検出器は共有するが（`REQ-SPK-015`）、掛かり方が別の製品
になる。

## 設計の中心にある 5 つの判断

**分割する。Velour の裏返し。** 圧縮は「足す」ではできない — その帯域を取り
出さないと下げられない。だから Sparkleur は 5 帯域のクロスオーバーを持ち、
`REQ-VEL-001`（原音は歪みを通らない）の逆側に立つ（`REQ-SPK-001`）。
代わりに**分割の和が unity のとき厳密にオールパス**であることを要件にする。

**時定数は設定ではなく物理。** 100 Hz の 1 波長は 10 ms で、それより速い
attack はエンベロープではなく波形そのものを変調する。だから per-band の
Attack / Release を出さず、**`SPEED` 1 本 + 帯域の中心周波数から導出**する
（`REQ-SPK-005`）。「LOW だけ速く」はできてはいけない操作。

**上げコンプには床と上限が機構として要る。** 上げは しきい値以下**すべて**を
持ち上げるので、素のままではノイズフロアとリリースの尻尾が持ち上がる
（`REQ-SPK-003`）。概念文書の Sub Protect はその症状を後から抑えているだけで、
**上限をパラメータとして持てば同じ機構の値違いになる**。

**質の軸は 1 本、離散モードにしない。** Soft / Hard の 2 モードではなく
`CHARACTER`（POLISH ↔ CRUSH）の連続軸。Velour の `TEXTURE` と同じ判断で、
2 モードだと「Soft の 8 割」が到達不能になる（`REQ-SPK-006`）。

**光るのは瞬間。静的な倍音付加は Velour の担当。** Sparkle は高域の速い/遅い
フォロワの比でトランジェントを見て、**生成した層の出力ゲインを開く**
（`REQ-SPK-007`）。`SNAP` = 0 で静的にもできるが、それは Velour と同じ挙動に
なるという意味で、既定ではない。

## REQ-SPK-001: 分割型トポロジと原音の扱い

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 入力を 5 帯域に分割し、帯域ごとにダイナミクスを掛けて再合成する。
  **`MIX` 用の原音は分割前で分岐して取っておく。**

```text
Input ─┬─────────────────────────── dry ──────────────┐
       │                                              │
       └─ Crossover ─ 5 × Dynamics ─┬─ Sum ─── wet ───┤─ MIX ─ OUTPUT
                                    │                 │
                        band 5 ─ Sparkle ─────────────┘
```

- **`MIX` = 0 でビット一致。** 原音は分割前で分岐しているので、`MIX` = 0 は
  加算 1 回で入力そのもの。Velour から引き継ぐ唯一の透明性の約束。
- **`SPARK` = 0 は「何もしない」ではない。** 分割を通っているので**振幅は
  平坦だが位相は回る**（LR4 の和はオールパス）。`SPARK` = 0 のときだけ分割を
  迂回する実装は**採らない** — オートメーションで 0 から離れた瞬間に不連続が
  出る。逃げ道は `MIX` = 0 の側に用意する。
- **受入条件**:
  - [ ] `MIX` = 0 で出力が入力と**ビット一致**（ラッパが要る — `SPK-8`）
  - [x] すべての帯域が unity・ダイナミクス無効のとき、和の**振幅が ±0.1 dB 以内**
        で平坦（位相は回る）— `SPK-2`。44.1 / 48 / 96 / 192 kHz、`FOCUS` 全域
  - [ ] `SPARK` を 0 から上げても不連続が出ない
- **依存**: なし

## REQ-SPK-002: 5 帯域のクロスオーバーと FOCUS

- **優先度**: Must
- **ステータス**: Draft
- **説明**: Linkwitz-Riley 4 次（Butterworth 2 段）の木構造 +
  **オールパス補正**。5 帯域、境界 4 点。

| | 帯域 | 何 | メインのノブ |
|---|---|---|---|
| 1 | 〜120 Hz | SUB / 土台 | — |
| 2 | 120〜400 Hz | BODY — 太さ | `BODY` |
| 3 | 400 Hz〜1.5 kHz | MID — 芯・こもり | — |
| 4 | 1.5〜6 kHz | PRESENCE — 前に出る / 痛くなる | — |
| 5 | 6 kHz〜 | AIR — 艶・煌めき | `AIR` |

- **オールパス補正は省略しない。** 木構造で素直に組むと、先に分けた帯域が
  後段のクロスオーバーの位相回転を受けないので ±0.3〜0.5 dB のリプルが出る。
  「全部 unity のとき何もしない」が製品の土台なので、**既に分けた帯域を残りの
  クロスオーバーと同じオールパスに通す**。
- **直線位相 FIR は採らない。** レイテンシとプリリンギングを買う。v2 で
  トランジェント強調をやる製品（`REQ-SPK-020`）が、トランジェントを滲ませる
  フィルタを土台に置くのは筋が悪い。
- **端は固定 + `FOCUS` で全体スライド（±1.5 オクターブ）。** 4 点を個別可変に
  すると「どこを動かしたか分からない状態」が 4 個できる。Velour の
  `REQ-VEL-002` と同じ判断で、可動域だけ広い（素材が声からベースまで広いため）。
- **受入条件**（すべて `SPK-2` で通した）:
  - [x] 5 帯域の和が unity で振幅平坦（`REQ-SPK-001`）
  - [x] `FOCUS` で 5 帯域の境界が**まとめて**動く（比も保たれる）
  - [x] `FOCUS` を振り切っても最上端がナイキストを超えない
  - [x] 高いサンプルレートで係数が発散しない（192 kHz まで確認）
- **依存**: REQ-SPK-001

## REQ-SPK-003: 上下コンプレッサ（gain computer）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 帯域ごとに **Downward（上を下げる）と Upward（下を上げる）**を
  持つ。両方 1 つの検波から計算する。

```text
L        = 検波した帯域レベル（dB）
down_db  = min(0, (T_down − L) · (1 − 1/R_down))     しきい値超過分を圧縮
up_db    = max(0, (T_up   − L) · (1 − 1/R_up))       しきい値以下を持ち上げ
up_db   ←  min(up_db, CEILING)                       上限
up_db   ←  up_db · taper(L)                          床（下記）
gain_db  = down_db + up_db + GAIN_i
```

- **上げには上限と床が要る。** 上限（`CEILING`、`CHARACTER` が決める 6〜15 dB）
  が無いと、無音がしきい値まで持ち上がる。床（`FLOOR_DB` = 仮 −60 dB。そこから
  下 12 dB で unity に戻る）が無いと、**ノイズフロアとリリースの尻尾が持ち
  上がる** — OTT でベースに使うと出るポンピングの正体。
- **Sub Protect は専用処理ではない。** 「LOW の `CEILING` だけ小さい」で同じ
  ことになる（`REQ-SPK-008`）。機構を 1 つにして、インスタンスの値で違いを
  作る（Velour の Guard が 1 機構 2 インスタンスだったのと同じ形）。
- **床は Advanced で開放できる。** 既定は安全側だが、振り切ると OTT らしい
  呼吸が出る。「VO-TT の代わり」を名乗るなら逃げ道が要る。
- ニーは `CHARACTER` が決める（広い ↔ 硬い）。
- **受入条件**（すべて `SPK-4` で通した）:
  - [x] `SPARK` = 0 で全帯域のゲインが**ちょうど 0 dB**
  - [x] 一定の正弦に対して、しきい値を超えた分だけ比どおりに下がる
  - [x] しきい値以下を持ち上げる量が `CEILING` を超えない
  - [x] **無音を入れてもゲインが上がらない**（床が効いている）
  - [x] 入力を 12 dB 上げたとき、下げ量が比から予想される量だけ増える
- **依存**: REQ-SPK-002

## REQ-SPK-004: 検波

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 帯域ごとに 1 本、**モノ和**から。パワー（二乗）を追従する。
- **モノ和である理由**は Velour と同じ（`REQ-VEL-011`）。片側だけゲインが動くと
  像が横に飛ぶ。逆相成分が実際より小さく読まれるのが代償。
- **`STEREO LINK` のパラメータは持たない。** 0〜100% の途中に意味のある音が
  無く、「半分リンク」が何を約束するのか説明できない。
- **ピークではなくパワー。** 上下コンプが見たいのは「その帯域がどれくらい
  鳴っているか」で、トランジェントは v2 の担当（`REQ-SPK-020`）。
- **受入条件**:
  - [ ] L == R の入力で出力も L == R（ラッパが要る — `SPK-8`）
  - [ ] 片側に寄った入力で無音のチャネルが無音のまま（同上）
  - [x] 検波が 44.1 / 48 / 96 kHz で同じ弾道 — `SPK-3`（192 kHz まで確認）
  - [x] 非有限のサンプル 1 個で検波器がラッチしない — `SPK-3`
- **依存**: REQ-SPK-003

## REQ-SPK-005: 時定数と SPEED

- **優先度**: Must
- **ステータス**: Draft
- **説明**: Attack / Release を per-band で出さない。**`SPEED` 1 本**が全体の
  速さを決め、各帯域の時定数はその帯域の**幾何中心周波数の周期**から導出する。

```text
f_ref_i   = √(low_i · high_i)          最下段の low は 30 Hz として扱う
floor_a_i = 2 周期 / f_ref_i
floor_r_i = 8 周期 / f_ref_i
attack_i  = max(SPEED が決める attack , floor_a_i)
release_i = max(SPEED が決める release, floor_r_i)
```

- **理由は物理。** 100 Hz の 1 波長は 10 ms。それより速い attack は
  エンベロープではなく波形を変調する = 歪む。**低い帯域は遅くしかできない**
  のだから、できないほうが正しい。
- 導出された床が効くのは下の 2 帯域だけで、上の 3 帯域では `SPEED` が支配する。
- **受入条件**:
  - [x] `SPEED` を最速にしても LOW の attack が導出された床を下回らない — `SPK-3`
  - [x] 同じ設定・同じ素材で 48 kHz と 96 kHz の弾道が一致 — `SPK-3`
  - [x] `SPEED` を速い側に振っても低域が歪まない（THD で確認）— `SPK-4` の
        `tests/chain.rs`。50 Hz・`SPEED` 最速で **0.26%**、床を外すと 2.0%
- **依存**: REQ-SPK-004

## REQ-SPK-006: CHARACTER 軸（POLISH / GLOSS / CRUSH）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 1 本の連続軸。アンカー 3 点の表を補間する（Velour の `TEXTURE` と
  同じ機構）。**離散モードにしない** — 2 モードだと「Soft の 8 割」が到達不能。

| | POLISH | GLOSS | CRUSH |
|---|---|---|---|
| Down 比 | 1.5:1 | 2.5:1 | 6:1 |
| Up 比 | 1.2:1 | 1.5:1 | 3:1 |
| Up の上限 | 6 dB | 9 dB | 15 dB |
| ニー | 広い | 中 | 硬い |
| Sparkle の硬さ `h` | 0.15 | 0.35 | 0.80 |
| Sparkle の偶奇 `β` | 0.50（偶数寄り） | 0.30 | 0.10（奇数寄り） |
| De-Harsh | 1.0 | 0.6 | 0.2 |
| Sub Protect | 0.0 | 0.4 | 1.0 |
| `SPEED` の中心 | 遅い | 中 | 速い |

- **全部仮の数字。** 機構が仕様で、値は耳（`SPK-17`）。
- **偶奇が軸に乗っているのが要点。** POLISH 側は偶数倍音（艶・厚み）、
  CRUSH 側は奇数倍音（エッジ）。`nxe_audio::shaper` が `(β, h)` で連続的に
  出せるので**新しい DSP は要らない**。
- 既定は **POLISH 寄り（0.25〜0.30）**。「手軽に綺麗」が主戦場で、CRUSH は
  振り切って使うもの。
- **受入条件**:
  - [ ] 端から端まで動かして不連続が無い
  - [ ] POLISH と CRUSH で**別の質感**に聞こえる（倍音の偶奇比で測る）
  - [ ] 軸を動かしてもラウドネスが ±1.5 dB 以内
  - [ ] 3 つのアンカー位置でちょうど表の値になる
- **依存**: REQ-SPK-003, REQ-SPK-007

## REQ-SPK-007: Sparkle（動的な倍音生成）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 最上帯域（AIR）の信号を波形整形して倍音を作り、**トランジェントで
  ゲートする**。静的なシェルフでは作れない艶を、常時シャリシャリさせずに足す。

```text
band 5 ─→ Oversampler ─→ shaper(β, h) ─→ highpass ─→ × gain ─→ 加算
                                                       ↑
      速いフォロワ / 遅いフォロワの比 ──→ snap 包絡 ────┘
```

- **検出は高域の速い/遅いフォロワの比。** スペクトル変化量（flux）は音声
  経路に `Spectrum` を置くことになり（48 バンドで 22 µs）、しきい値の妥当性が
  耳頼みになる。高域だけを見た速い/遅い比は**実質トランジェント検出**で、
  部品が既にある（`nxe_audio::envelope`）。
- **動かすのは生成層の出力ゲイン、カーブではない。** `nxe_audio::guard` に
  書いてある判断の裏返し — カーブの drive を揺らすと質感が揺れて何が起きたか
  読めなくなる。Guard が「痛いとき下げる」なら Sparkle は「立ち上がりで上げる」。
- **`AIR` が量、`SNAP` がトランジェントへの委ね方。** `SNAP` = 0 で完全に
  静的（Velour と同じ挙動）、1 でアタックのときだけ光る。既定は中〜高。
  **0 も選べることが、Velour との差を自分で確認する手段になる。**
- **入力に上蓋を付ける。** Velour の `AIR_INPUT_CEILING`（ホストレートの 1/4）
  が無いと、AIR はどんなドライブでも −44 dB で折り返す。最初から入れる。
- **受入条件**:
  - [ ] `AIR` = 0 で生成層が**ちょうど無音**
  - [ ] `SNAP` = 1 で、持続音に対しては光らずアタックで光る
  - [ ] `SNAP` = 0 で静的な倍音付加になる
  - [ ] 4x で最悪ケースの折り返しが **−60 dB 以下**
  - [ ] `CHARACTER` で偶奇比が動く
- **依存**: REQ-SPK-002, REQ-SPK-006

## REQ-SPK-008: 保護（De-Harsh / Sub Protect）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 2 つとも**既にある機構の値違い**として実装する。専用の処理を
  足さない。

| | 何 | 機構 |
|---|---|---|
| De-Harsh | 1.5〜5 kHz が広い参照帯に対して過剰なとき PRESENCE 帯を引く | **相対検出器**（`nxe_audio::guard`。Velour の Harsh Guard と同じもの） |
| Sub Protect | LOW の上げコンプの上限を下げる | **`REQ-SPK-003` の `CEILING` の値違い** |

- **量は `CHARACTER` が決める。** 「明るくなるのに痛くならない OTT」が製品の
  約束なら、保護は既定で軸に付いてくるべき。概念文書の
  `Spark ↑ → Harshness Suppression ↑` がこれで成立する。
- **Advanced には双極の偏差を出す。** 0 で軸に従い、± で強め/弱め。絶対量に
  すると `CHARACTER` と 2 つが 1 つの値を書くことになり、規約
  （`.agents/rules/vizia.md`）違反。
- **効いていることが図に出る。** Velour の Guard と同じで、働いた瞬間に
  その区画が沈む（`REQ-SPK-013`）。完全自動で隠すと、AIR を上げても何も
  起きない理由がユーザーから見えない。
- **受入条件**:
  - [ ] 偏差 0 のとき `CHARACTER` の表どおりの量になる
  - [ ] 偏差を最小にすると De-Harsh がちょうど無効
  - [ ] 入力ゲインを ±12 dB 変えても De-Harsh の動作量が 0.2 dB 以内
        （相対検出の帰結）
  - [ ] Sub Protect が LOW の上げ量だけを制限し、他の帯域を触らない
- **依存**: REQ-SPK-003, REQ-SPK-006

## REQ-SPK-009: 二層パラメータモデル

- **優先度**: Must
- **ステータス**: Draft
- **説明**: **第 1 層が量、第 2 層が配分。** 規約（`.agents/rules/vizia.md`）の
  「マクロと per-band は互いを上書きしない。per-band は正規化された形で、
  マクロがそれを倍率する」をそのまま適用する。

```text
第 1 層   SPARK ──────── ダイナミクスと Sparkle の総量
第 2 層   BODY / AIR ─── どこを厚くするか（双極、0 で SPARK のまま）
Advanced  per-band UP / DOWN / GAIN ── 重み（絶対量ではない）
```

- **`SPARK` は「マクロのマクロ」にしない。** 概念文書の `SPARK`（0% 原音 →
  25% density → 50% presence+air → 75% harmonics+width → 100% extreme）は
  `REQ-VEL-019`（DISTANCE）が却下されたのと同じ形 — **触ったときに何が起きたか
  説明できない**。`SPARK` は量そのものに落とす。
- **per-band の UP / DOWN は重み。** `SPARK` を上げると全部が深くなり、
  UP/DOWN の比は保たれる。VO-TT の触り心地はここで出る。
- **受入条件**:
  - [ ] `SPARK` を動かしても per-band の値が変わらない（型で保証）
  - [ ] per-band を動かしても `SPARK` の値が変わらない
  - [ ] `SPARK` = 0 でダイナミクスと Sparkle の両方が無効
- **依存**: REQ-SPK-003

## REQ-SPK-010: 4 層の直交

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 4 つの層が別のものを動かす。

| 層 | 何を変える | 変えないもの |
|---|---|---|
| `SPARK` | どれだけ処理するか | 質感、帯域の配分 |
| `CHARACTER` | どういう処理か（比・ニー・偶奇・保護） | 量 |
| per-band | どこに配分するか | 総量 |
| `MIX` | バス全体の混ぜ量 | 上の 3 つ |

- **`CHARACTER` を動かしてラウドネスが動くなら直交していない。** Velour で
  `TEXTURE` が −3.0 dB 動いた（トリムで吸収した）のと同じ問題が出る場所なので、
  最初からアンカーごとのレベルトリムを持つ。
- **受入条件**:
  - [ ] `CHARACTER` を端から端まで動かしてラウドネスが ±1.5 dB 以内
  - [ ] `SPARK` を動かしても倍音の偶奇比が変わらない
  - [ ] 4 つのどれを動かしても他の 3 つの値が変わらない
- **依存**: REQ-SPK-006, REQ-SPK-009

## REQ-SPK-011: ステレオの扱いと像の保存

- **優先度**: Must
- **ステータス**: Draft

  **検波はすべてリンク**（`REQ-SPK-004`）。
- **バス構成は 2→2 と 1→1。** WIDTH / Shimmer Spread が v1 に無い

- **受入条件**:

  - [ ] 2→2 と 1→1 の両方のレイアウトで動く
  - [ ] 片チャネルに寄った素材で定位が動かない
- **依存**: REQ-SPK-004

  - [ ] ホストに報告するレイテンシが 0
- **依存**: REQ-SPK-001

  - [ ] 上げコンプが線より上に描かれる
  - [ ] De-Harsh の動作が図で読める

## REQ-SPK-015: コアのホスト非依存と共有 DSP

- **優先度**: Must
- **ステータス**: Draft
- **説明**: DSP は `sparkleur-core` に置き、nih-plug も Vizia も知らない。
  **Velour と共有する部品は新クレート `nxe-audio` に上げる**
  （`docs/specifications/architecture.md`）。

| `nxe-audio` に上げる | Sparkleur が使うところ |
|---|---|
| `shaper` | Sparkle のカーブ、`CHARACTER` の偶奇 |
| `oversample` | Sparkle の経路 |
| `biquad` | LR4 クロスオーバー、検波の帯域通過 |
| `envelope` | Sparkle の検出、`SPEED` |
| `guard` | De-Harsh（**一般化が必要** — 今は Velour 語彙） |
| `harmonics` | 上の 5 つのテストが全部これで書かれている（`SPK-1` で判明） |

- **`nxe-dsp` に入れない。** あちらは「解析」で、doc に
  「**None of it changes the audio**」と書いてある。解析はバグっても絵が
  壊れるだけ、処理はバグると音が壊れる — **リスクの階級が違う**。
- **`guard` の一般化**: `Guarded::Presence/Air` と Harsh/Sib のしきい値を
  呼び出し側に出す。**実装は `RelativeGuard<N>`**（`SPK-1`）— 参照フォロワを
  1 本共有して帯域を N 本持ち、`Settings<N>` を `const` で受ける。N 個の
  独立インスタンスにしなかったのは、同じ参照帯の帯域通過を N 回走らせる
  ことになるから。Velour 側は「2 帯域の `Settings` を渡す薄いラッパ」で、
  既存のテストがそのまま回帰テストになった。
- **`density` / `texture` / `bands` は動かさない。** Sparkleur が要求して
  いないので `velour-core` に残す（`architecture.md` の「要求されるまで
  上げない」）。
- **受入条件**:
  - [ ] `sparkleur-core` と `nxe-audio` が nih-plug / Vizia に依存しない
        （`nxe-audio` は満たした。`sparkleur-core` はまだ無い）
  - [x] `nxe-audio` に移した後も Velour のテストが全部通る（`SPK-1`）
  - [x] `nxe-audio` の各モジュールが Velour も Sparkleur も知らない
- **依存**: なし

## REQ-SPK-016: リアルタイム安全性と CPU 予算

- **優先度**: Must
- **ステータス**: Draft
- **説明**: `process()` の中で確保・ロック・IO・panic をしない。ホストから
  来る値はクランプする。
- **予算**: 512 サンプル / 48 kHz のブロック周期 10.67 ms の 5% = **533 µs**。
  目標 250 µs。参考値は Doubler 85 µs、Velour 128 µs。
- **見積り**: LR4 の木 + 補正で biquad 約 24 段 × 2 チャネル、検波 5 本、
  Sparkle の経路 1 本を 4x。Velour が 3 帯域 4x + 解析で 128 µs だったので
  **同程度**を見込む。
- **受入条件**:
  - [ ] criterion で 4x / 512 サンプル / 48 kHz が 533 µs 以内
  - [ ] 全パラメータを範囲外の極端値にしても非有限値を出さず panic しない
  - [ ] 非有限のサンプル 1 個で検波器がラッチしない（Velour の `VEL-10` で
        見つけたバグと同じ形）
  - [ ] 音声スレッドの経路に確保が無い
- **依存**: REQ-SPK-002

## REQ-SPK-017: サンプルレート・ブロックサイズ非依存

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 44.1 / 48 / 88.2 / 96 / 176.4 / 192 kHz で同じ音。ブロックサイズを
  変えても出力が変わらない。時定数はすべて秒で持つ。
- **ナイキストを超える帯域を持たない**: `FOCUS` を上げた AIR の上端が
  ナイキストを超える場合は上蓋で切る（`REQ-SPK-007`）。
- **受入条件**:
  - [ ] 48 kHz と 96 kHz で出力が聴感上同じ（レベル 0.5 dB / 倍音比 10% 以内）
  - [ ] ブロックサイズ 1 / 32 / 512 / 2048 で出力が一致
  - [ ] 192 kHz で係数が発散しない
- **依存**: REQ-SPK-002

## REQ-SPK-018: 通っている音の表示

- **優先度**: Should
- **ステータス**: Draft
- **説明**: UI に渡す解析値。受け渡しは `nxe_dsp::Handoff`。
  - **原音のスペクトラム** 1 本（`nxe_dsp::Spectrum`）
  - **帯域ごとに実際に掛かっているゲイン** 5 個（これが図の主役）
  - **De-Harsh のリダクション**
  - **Sparkle の包絡**（光った瞬間が見える）

  代わりに**帯域ごとのゲイン**がその役をする。
- **受入条件**:
  - [ ] 音が止まると表示が減衰して消える
  - [ ] 上げコンプが線より上、下げが下に出る
  - [ ] 解析を止めても音が変わらない（表示専用）
- **依存**: REQ-SPK-003

## REQ-SPK-019: WIDTH / Shimmer Spread

- **優先度**: Won't (v1)
- **ステータス**: Decided
- **説明**: 高域だけを左右に広げる（デコリレーション / オールパス /
  マイクロピッチ / Haas）。
- **v1 に入れない理由**:
  - **モノ互換の約束を壊す唯一の機能。** テストの道具立て（相関、M/S の
    エネルギー比、モノ和での打ち消し）が全部新規で、他の機能と共有できない
  - **`REQ-SPK-011` と正面から衝突する。** 「像を変えない」を要件にしている
    製品に「像を変える」機能を足すので、線引きを別に書く必要がある
  - **2 製品がそれ無しで出荷できている。** Doubler は像を作る製品だが、
    あれは voice ごとの pan で作っていて、この機能とは別物
- v2 で入れるときは `REQ-SPK-011` を書き直すところから始める。
