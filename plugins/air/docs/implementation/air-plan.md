# Air — 実装計画

> 最終更新: 2026-08-27

要件は [`../requirements/REQ-AIR.md`](../requirements/REQ-AIR.md)。
DSP 仕様は [`../specifications/dsp.md`](../specifications/dsp.md)（式・係数・
時定数・耳で詰める定数の一覧）。**UI 仕様は未作成** — `AIR-8` の前に書く。

**単位ごとに「完了条件」を満たしてからコミットする。** 完了条件は「動いた」
ではなく**測れること**で書く。

## 順序の考え方

```text
AIR-1  ノイズ層と WIDTH      ← ゲート。ここが通らないと製品の主張が立たない
AIR-2  倍音層
AIR-3  BLEND / CHARACTER / FOCUS
AIR-4  ラッパとパラメータ     ← ここで音が出る
AIR-5  Follow Engine          ← 耳が使える状態で作る
AIR-6  保護（Excess Guard）
AIR-7  詰め（レート・ブロック・極端値）
AIR-8  UI マクロ層
AIR-9  UI スペクトルの重ね描き
AIR-10 UI 読み値と Advanced
AIR-11 解析の配線
AIR-12 CPU 予算
AIR-13 既定値と耳
```

**`AIR-1` がゲート**（`REQ-AIR-008`）。`WIDTH` 全域でモノ和に櫛形が出ない
ことが崩れたら、`WIDTH` の設計ごと書き直しになり、その上に載っている
「層を独立した対象として配置する」という主張が成立しない。Velour の `VEL-1`、
Sparkleur の `SPK-2` と同じ位置。

**`AIR-4`（ラッパ）が `AIR-5`（Follow）より前。** Velour が `VEL-5` を
`VEL-4` より前に置いたのと同じ判断。**Follow Engine は Air の正体だが、
効いたかの判断が一番耳寄り**（「元音から Air が出ているように感じるか」）。
層が鳴る状態を先に作れば、そこから先の判断が速い。

**共有クレートの新規単位が無い。** Sparkleur が `SPK-1` で `nxe-audio` を
作ったが、Air が要求する既存ブロックは全部そこにある（`REQ-AIR-015`）。
唯一の新規はノイズ生成器で、それは `air-core` に置く。

### AIR-1 — ノイズ層と WIDTH（ゲート）✅ **ゲート通過**

`noise.rs`。**`air-core` クレートもここで作る**（`VEL-1` / `SPK-2` と同じ位置）。

ノイズの生成、傾き、粒立ち、そして `WIDTH` の共有モデル。

- **完了条件**:
  - [ ] `WIDTH` 全域で、**モノ和のスペクトルに櫛形の谷が出ない**
        （平坦性 ±1 dB 以内）
  - [ ] `WIDTH` = 0 で L/R の相関が 1.0、`WIDTH` = 1 で 0 付近
  - [ ] `WIDTH` = 1 のモノ和が片チャネルに対し **−3 dB ±0.5 dB**
  - [ ] `WIDTH` を掃引して相関が単調に減る
  - [ ] 44.1 / 48 / 96 / 192 kHz で**可聴帯域のレベルが ±0.5 dB 以内**
  - [ ] 明示シードで出力が完全に再現する
  - [ ] ゲイン 0 でちょうど無音、**無音入力でキープアライブが厳密に 0**
        （`dsp.md`。Follow の深さ側に下限を置くと `REQ-AIR-007` が壊れるので、
        下限はノイズ層自身が持つ）
  - [ ] 傾きを振り切っても可聴帯域外にエネルギーが逃げない
  - [ ] hostile な値で非有限を出さない
- **要件**: REQ-AIR-004, REQ-AIR-008, REQ-AIR-017
- **依存**: なし
- **決めた**（`dsp.md`）: 傾きは **1 次のティルト 1 段**（極 1 個の低域通過と
  その補数を逆向きのゲインで足す）。ピボットは HPF のコーナーに乗せる。
  `FOCUS` は `2^(focus·1.5)`、`BASE_CORNER_HZ` = 3 kHz
- **決めること**: `TILT_MAX_DB` と `GRAIN_SECONDS` の実値（耳）
- **見込んでいる罠**: **サンプルレート補正を忘れる。** 総パワーは
  レート不変だが `fs/2` に広がるので、可聴帯域の密度がレートに反比例する。
  `sqrt(fs / 48000)` の補正が要る（`REQ-AIR-017`）。**ノイズなので耳では
  気付けない** — 最初からテストで固定する
- **見込んでいる罠**: **テスト用ノイズに DC が乗る。** `SPK-18` で
  `(state >> 8) / 2^23 * 2.0 - 1.0` が値域 `-1..3` になっていて、ピンク化の
  1 段目の極が DC を 425 倍していた。**`nxe_audio::harmonics` の
  `noise` / `pink` は修正済み**なので、そちらを使う。自分で書かない
- **見込んでいる罠**: 相関の測定は `nxe_dsp::Correlation` を使う。
  自前で書くと `1e30²` が f32 で `inf` になり `inf/inf` = NaN になる
  （Doubler で踏んで `CEILING` を入れた）
- **踏んだ罠**: **「あり得ない設定」の番兵は全部のフィールドを外す。**
  `set` はフィールドごとに「動いていなければ何もしない」で守っているので、
  1 つだけ NaN にした番兵だと**残りのフィールドの係数が初期化されない**。
  `width` が既定と一致していて `shared` / `independent` が 0 と 0 のまま
  だったので、**層が完全な無音**で出てきた。テストは 8 本落ちたが、
  落ち方は「ノイズが出ない」ではなく「相関が測れない」だった
- **踏んだ罠**: **櫛形の対照実験に遅延を使うと通ってしまう。** 12 サンプルの
  遅延は 4 kHz ごとに櫛が立ち、それは 1/3 オクターブ帯より細かいので
  帯の裾から隣の山が入り、**0.9 dB しか出ない**。オールパス（`REQ-AIR-008` が
  拒んでいる手法そのもの）に替えて 6.6 dB
- **踏んだ罠**: **レート非依存を広い帯域通過で測ると、測定側が歪む。**
  14 kHz の 2 次ローパスは 44.1 kHz でナイキストの 0.64、192 kHz で 0.15 に
  居るので、同じ「14 kHz」が 10 kHz を 0.4 dB 落とすか 1.0 dB 落とすかが
  変わる。0.53 dB のずれが出て**全部が測定の側だった**。1/3 オクターブ帯で測る
- **測って捨てた**: 上の 1 オクターブのレート差（16 kHz で 3.83 dB）を
  スカラで補正すると、層全体の RMS は 0.72 → 0.30 dB になる代わりに**核の
  4 帯域が 0.39 → 1.26 dB に開く**。平らな誤差を傾きに両替しただけなので
  戻した。詳細と実測値は `dsp.md`

### AIR-2 — 倍音層 ✅

`harmonic.rs`。`nxe_audio::shaper` を借りて、前後に HPF、入力に上蓋。

- **完了条件**:
  - [ ] ゲイン 0 でちょうど無音
  - [ ] 4x で最悪ケースの折り返しが **−60 dB 以下**
  - [ ] 上蓋が**ホストレート**に対して効いている（96 / 192 kHz で確認）
  - [ ] `WIDTH` によらず L == R（倍音層は広がらない）
  - [ ] `CHARACTER` で偶奇比が動き、足す量は ±3 dB 以内
- **要件**: REQ-AIR-003
- **依存**: AIR-1
- **決めた**（`dsp.md`）: 生成後 HPF は前段の **1 オクターブ上**（`2·corner`）。
  足すものを「原音の複製」ではなく「原音に無かった倍音」に寄せるため。
  Velour の AIR 帯域は逆に**下へ**ずらしていて、あちらは「その帯域の存在感を
  作る」製品なのでそれが正しい
- **決めること**: `shaper` の `k` = 4.0 で艶が足りるか（耳）
- **見込んでいる罠**: **上蓋を内部レートに対して書く。** Velour が
  `VEL-3` でやった。4x のとき 48 kHz まで開いてしまう。ホストレートの
  1/4（`AIR_INPUT_CEILING`）
- **踏んだ罠**: **`CHARACTER` の効きを「3 倍音 ÷ 2 倍音」で測ると 1.7 % しか
  動かない。** 膝が奇数次を増やすのと同時にバイアスが偶数次も増やすので比が
  相殺される。**「3 倍音 ÷ 基音」で見ると 0.150 → 0.248**（Velour の
  `dsp.md` が最初からそう書いている）。最初のテストは「`CHARACTER` は何も
  しない」と報告したが、層は変わっていた
- **測った**: 折り返し **−70.0 dB**（許容 −60、10 dB 余っている）、
  `CHARACTER` のレベルの動き **0.55 dB**、3.5 kHz の音が層に戻る量
  **−23.7 dB**

### AIR-3 — BLEND / CHARACTER / FOCUS

`layer.rs`。2 系統を 1 個の対象としてまとめる。

- **完了条件**:
  - [ ] `BLEND` を掃引して生成層の総エネルギーが ±1 dB 以内で平坦
        （電力保存のクロスフェード）
  - [ ] `BLEND` を振り切ると、もう一方がちょうど無音
  - [ ] `CHARACTER` をどこで動かしても、`BLEND` の位置によらず音が変わる
  - [ ] `FOCUS` で 2 系統の帯域がまとめて動き、比が保たれる
  - [ ] `FOCUS` を振り切っても最上端がナイキストを超えない
  - [ ] 係数の再計算がブロック単位（再構築カウンタで測る）
- **要件**: REQ-AIR-005, REQ-AIR-006
- **依存**: AIR-1, AIR-2
- **決めた**（`dsp.md`）: `CHARACTER` は**常に両系統へ同じ正規化値を渡す**。
  聞こえるのは `BLEND` が選んだ系統だけなので、意味は自動的に移る。分岐は要らない
- **決めること**: `NOISE_TRIM` / `HARMONIC_TRIM`（測定。ピンクノイズ −18 dBFS で
  `BLEND` を掃引して ±1 dB）

### AIR-4 — ラッパとパラメータ（ここで音が出る）

`air` クレート。パラメータ宣言、`process()`、`MIX`。**UI はまだ持たず、
ホストの既定パラメータ UI で音を確認する。**

- **完了条件**:
  - [ ] `MIX` = 0 で出力が入力と**ビット一致**
  - [ ] `SURFACE` = 0 で出力が入力と**ビット一致**
  - [ ] `2→2` と `1→2` の両方のレイアウトで動く
  - [ ] 4 ホストで CLAP と VST3 が読み込まれる
  - [ ] `mise run bundle air` / `install air` が通る
- **要件**: REQ-AIR-001, REQ-AIR-011, REQ-AIR-012, REQ-AIR-014
- **依存**: AIR-3
- **決めること**: **バックエンド。** nih-plug のままか、nice-plug + vizia-plug へ
  移るか（`LICENSING.md`、`REQ-AIR-014`）。**Air は出荷済み ID もセッションも
  無いので、移行を試すならここが一番安い。** 判断材料は `air-core` が
  フレームワークを知らないこと — 駄目なら戻すのはラッパだけ
- **決めること**: `CLAP_ID` は `com.nxe.air`。**出荷後に変えられない**
- **見込んでいる罠**: モノ入力では 2 本目のチャネルが未定義。読まずに
  1 本目を複製する（Doubler がやっている）

### AIR-5 — Follow Engine

`follow.rs`。3 本の検出と、`(1 − 深さ) + 深さ × 検出値` の合成。

- **完了条件**:
  - [ ] 深さが全部 0 のとき、係数が入力によらず**厳密に 1**
  - [ ] `ENVELOPE` 深さ 1 で、無音入力に対し層が無音へ収束
  - [ ] `BRIGHTNESS` 深さ 1 で暗い素材に対し層が閉じる
  - [ ] `BRIGHTNESS` の動作量が入力ゲイン ±12 dB で 0.2 dB 以内
  - [ ] `TRANSIENT` 深さ 1 で、持続音に閉じアタックで開く
  - [ ] ノイズ層の `ENVELOPE` に下限が効いていて 0 にできない
  - [ ] 3 つの係数が個別に取り出せる（UI が使う）
  - [ ] **深さ全部 0 = Velour、`TRANSIENT` だけ 1 = Sparkleur の Sparkle**
        の形になっている（`REQ-AIR-002` の監査）
- **要件**: REQ-AIR-002, REQ-AIR-007
- **依存**: AIR-4
- **決めた**（`dsp.md`）: `TRANSIENT` は**検出帯に通してから**比を取る。
  これで Sparkleur の band 5 とほぼ同じ状況になり、`SNAP_RANGE_DB = 6.0` が
  出発点として使える。フルバンドのままだと低域の遅いエンベロープに薄められて
  ハットでも開かない。帯域通過は `BRIGHTNESS` と共用で 1 本
- **やること**: **`nxe_audio::envelope::Power` を上げる。** パワーフォロワの
  実装が既に 2 つある（`guard::Follower` と `sparkle::Power`、どちらも private）。
  Air が 3 つ目なので、architecture.md の「3 個目の客が来たら上げる」に当たる。
  **時定数は上げない** — 秒で受け取るだけにして値は呼び出し側に残す（`SPK-1`）
- **決めること**: `BRIGHT_MIN_DB` / `RANGE`（測定）と `ENV_FLOOR_DB`（耳）
- **見込んでいる罠**: **エンベロープが絡むテストはブロックごとに
  パラメータを設定して測る。** Velour の `EMOTION` が**全部逆に測れた**
  （検波器がまだ無音しか見ていなかった）。`blocked` 相当のヘルパを先に作る

### AIR-6 — 保護（Excess Guard）

`guard.rs`。`nxe_audio::guard` の値違い。検出帯は `FOCUS` に追従。

- **完了条件**:
  - [ ] **スペクトル的に普通の素材でちょうど 0 dB**
        （ピンクノイズと定常倍音列。`SPK-18` の再発防止）
  - [ ] 動作量が入力ゲイン ±12 dB で 0.2 dB 以内
  - [ ] 偏差を最小にすると保護がちょうど無効
  - [ ] `FOCUS` を動かすと検出帯が追従する
  - [ ] 生成層のゲインだけを触り、原音に一切影響しない
- **要件**: REQ-AIR-009
- **依存**: AIR-5
- **見込んでいる罠**: **参照帯が検出帯を含む。** Sparkleur が出荷時の
  しきい値でこれをやっていて、**普通の素材から常時 1.3 dB 引いていた**
  （`SPK-18`）。`FOCUS` で両方が動く Air は踏みやすい

### AIR-7 — 詰め

レート・ブロックサイズ・極端値・スムージング。

- **完了条件**:
  - [ ] ブロックサイズ 1 / 64 / 512 / 4096 の出力が一致
  - [ ] 44.1 / 48 / 96 / 192 kHz で係数が発散しない
  - [ ] 全パラメータの極端値で非有限値を出さず panic しない

  - [ ] 音声スレッドの経路に確保が無い（数えるアロケータ）
  - [ ] パラメータの段変化でジッパーが出ない（**測定が失敗できることも

- **依存**: AIR-6
- **見込んでいる罠**: 検出器のラッチ。Sparkleur では**実際にラッチして

### AIR-9 — UI スペクトルの重ね描き

**画面の主役。** 原音と生成層を重ねる。

- **完了条件**:
  - [ ] `FOCUS` で層の山が動き、`SURFACE` で高さが変わる
  - [ ] 保護が働くと山が沈む
  - [ ] `SURFACE` = 0 で生成層の描画がちょうど 0
  - [ ] 新規ウィジェットを作ったなら `examples/gallery.rs` に同じ変更で入れた
- **要件**: REQ-AIR-013, REQ-AIR-018
- **依存**: AIR-8
- **決めた**: **点のスペクトラム**を `nxe-ui` に新規ウィジェットとして起こす。
  原音は細い線、生成層は点の格子で、レベルが上がるほど点が密になる。
  `BLEND` を倍音側へ振ると点が縦に揃い、ノイズ側で散る — **2 系統の違いが
  そのまま図になる**。`FOCUS` で山が動き、`SURFACE` で高さが変わり、保護が
  働くと沈む、は全部この 1 枚で成立する
- **気をつけること**: **点の配置をフレームごとの乱数にしない。** 明滅して
  読めなくなるうえ、gallery で見ても同じ絵が 2 度出ないのでレビューできない。
  スペクトルからの決定的な関数にする。点の数は上限を決める（femtovg に
  数百個の矩形を毎フレーム投げることになる）

## 見込んでいる罠（Velour と Sparkleur で払った授業料）

`docs/HANDOVER.md` に全部あるが、Air で特に効きそうなもの:

- **テスト信号の周波数を「周期数」で書かない。** `harmonics::tone` と
  `bin_of` を使う。Velour で 3 回踏んだ
- **引き算で「足した層」を取り出さない。** `出力 − 原音` は精度をほぼ捨てる。
  **Air は加算型なので層を直接取れる** — テスト用に取り出せる形で書く
- **テスト信号は自分でも測る。** `SPK-18` の DC が乗ったノイズ
- **測定が失敗できることを同じテストで確かめる。** `VEL-10`
