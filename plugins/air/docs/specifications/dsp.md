## 信号の流れ

```text
Input (L,R)
  │
  ├──────────────────────────────── dry ─────────────────────────────┐
  │                                                                  │
  ├─ 倍音層 ─ 上蓋 ─ 4x ─ shaper ─ HPF ─ × trim_h ─┐                 │
  │           （L/R 別、センター固定）              │                 │
  │                                                ├─ BLEND ─┐       │
  │  noise(s,l,r) ─ 傾き ─ HPF ─ 上蓋 ─ × 粒 ──────┘         │       │
  │                （WIDTH が s と l/r の混合比）             │       │
  │                                                          │       │
  │                                    × SURFACE ────────────┤       │
  │                                    × 係数_env            │       │
  │                                    × 係数_bright  ← Follow        │
  │                                    × 係数_trans          │       │
  │                                    × keepalive           │       │
  │                                    × guard_gain  ← 保護   │       │
  │                                                          │       │
  └─ 検出（モノ和）─────────────────────────────────────────┘       │
                                                                     │
                              out = OUTPUT · (dry + MIX · layer) ────┘
```

**原音は入口で分岐して、出口の加算までどのフィルタも通らない**（`REQ-AIR-001`）。
`MIX` = 0 と `SURFACE` = 0 のビット一致はどちらもこれ 1 つで成立する。

### `MIX` は原音を消さない — 要件を 1 行直した

`REQ-AIR-012` の受入条件に **「`MIX` = 1 で原音が完全に消える」** があったが、
これは `REQ-AIR-001` の **「`SURFACE` = 0 で出力が入力とビット一致」** と
両立しない。`out = (1−MIX)·dry + MIX·layer` にすると、層が無いとき
（`SURFACE` = 0）でも `MIX` > 0 なら原音が `(1−MIX)` 倍に減る。

加算型では **`MIX` は「足した層をどれだけ通すか」** であって
「原音をどれだけ残すか」ではない。`out = dry + MIX·layer` を採り、要件の
受入条件を「`MIX` = 1 で層が全量足される」に直した。**逃げ道が 2 つあることに
意味を持たせたのは `REQ-AIR-001` のほう**なので、そちらを立てている。

層を単体で聴きたいという要求（`REQ-AIR-001` の「生成層を単独で取り出せる」）は
**テストとコアの API で満たす**（`Engine::layer()`）。パラメータにはしない —
Velour の `SOLO` がセッションに保存されて戻せない宿題になっている
（`docs/HANDOVER.md`）。

## ノイズ層

**v1 で唯一の新規 DSP**（`REQ-AIR-004`）。`air-core/src/noise.rs`。
**Air を知らない自立したモジュールとして書く** — 上がる先は Growl の `TEETH` と
Vocal Glue の `AIR Cohesion` で、2 個目が要求した時点で `nxe-audio` に移す
（`REQ-AIR-015`）。

### 生成器

**splitmix32 を 4 本。** 3 本が信号（共有・左・右）、1 本が粒の変調。

```text
state += 0x9E37_79B9
z = state
z ^= z >> 16 ;  z *= 0x21F0_AAAD
z ^= z >> 15 ;  z *= 0x735A_2D97
z ^= z >> 15
```

**振幅は `(z >> 8) / 2^23 − 1.0`。** 24 ビットを 2^23 で割ると `0..2`、
1 を引いて `−1..1`。**先に 2 倍してから 1 を引くと `−1..3` になり、平均 +1 の
DC が乗る** — `SPK-18` で測定用ノイズがこれをやっていて、ピンク化の 1 段目の極が
DC を 425 倍し、「ピンクノイズ」がほぼ定数になっていた。同じ式を自分で書き直す
場所なので、ここに残す。

一様分布 `−1..1` の RMS は `1/√3`。**`√3` を掛けて 1 本あたり RMS 1.0 に
正規化する**ので、`SURFACE` = 1 のときの層の絶対レベルは
`NOISE_TRIM`（下）だけが決める。

**シードは外から渡す**（`Noise::new(sample_rate, seed)`）。`air-core` は時計も
トランスポートも読まない。ラッパは**プロセス内のインスタンス番号**（`AtomicU32`）を
混ぜたシードを渡す — 同じプロジェクトのステレオ 2 本に同じノイズが乗るのを
避けるためで、時刻を読まないので**同じ順序で立ち上げれば書き出しは再現する**。
`REQ-AIR-017` は決定性を約束していないが、只で手に入るぶんは受け取る。

### サンプルレート補正 — `√(fs / 48000)`

毎サンプル乱数を出すと**総パワーはレート不変**だが、それが `0..fs/2` に広がるので
**単位 Hz あたりの密度がレートに反比例する**。96 kHz では可聴帯域の中身が
48 kHz の半分 = **−3 dB** になる（`REQ-AIR-017`）。

```text
振幅 = √3 · √(fs / 48000) · NOISE_TRIM
```

**補正は生成器の出力スケールに 1 回だけ入れる**（`new` とレート変更時に計算）。
傾きも HPF も上蓋も Hz で定義されているので、後段はレートを知らない。

**上蓋がこの補正を検証可能にしている。** 補正だけだと 192 kHz の層は
20 kHz 以上に 48 kHz のときの 4 倍のパワーを持つ（可聴帯域は正しいのに）。
`min(20_000, 0.45·fs)` の 2 段バターワースで蓋をすると、**層の全帯域 RMS が
そのままレート非依存の指標になる**。`REQ-AIR-004` の「傾きを振り切っても
可聴帯域外にエネルギーが逃げない」も同じ 1 個のフィルタが満たす。

**検証は帯域通過してから測る。** 44.1 kHz では上蓋が 19.85 kHz で、48 kHz の
20 kHz と 0.4 dB 前後違う。全帯域 RMS で比べると許容 ±0.5 dB の内側ぎりぎりを
争うことになるので、**100 Hz〜16 kHz に通してから RMS を比べる**
（`REQ-AIR-017` が言っているのは可聴帯域のレベル）。

### 傾き（`FOCUS`）

**1 次のティルトを 1 段。** 極 1 個の低域通過とその補数を、逆向きのゲインで
足し直す:

```text
lp   ← lp + (x − lp) · a          （a は corner の 1 次係数）
out  = g_lo · lp + g_hi · (x − lp)

g_hi = 10^( t/20)      t = focus · TILT_MAX_DB
g_lo = 10^(−t/20)
```

**ピボットは HPF のコーナーと同じ点**（下の `FOCUS`）。固定の周波数に置くと、
`FOCUS` を上げてコーナーがピボットを追い越した瞬間に**傾きが通過域全体に効く
ただのゲイン**になる。コーナーに乗せておけば、通過域の中では常に片側だけが
効く。

- `focus` > 0 — コーナーから上へ持ち上がる（BREATH / 空気）
- `focus` < 0 — コーナーのすぐ上に重心が残る（DUST / FIZZ）

**1 次で足りる。** pink（−3 dB/oct）や blue（+3）を厳密に作るには段数が要るが、
ここで要るのは「連続に動く傾き」であって名前の付いた傾斜ではない
（`REQ-AIR-004`「White / Pink / Blue は傾きの別名なので離散のモードにしない」）。
1 次の遷移は 2 デケードかけて起きるので、可聴帯域の中では滑らかな傾きに見える。
その代わり端の `±TILT_MAX_DB` には**帯域内では届かない** — だから
`TILT_MAX_DB` は「見える傾き」ではなく「係数」で、耳で詰める（下の表）。

**`FOCUS` を端から端まで振ると層のレベルが動く。** 打ち消さない — 帯域を上下に
動かせば聞こえる量が変わるのは仕事のうちで、`REQ-AIR-006` はレベル不変を
要求していない。**動く量は `AIR-1` で測って記録する**（`SPK-18` の
「ずれているから補正する前に、そのずれが仕事かどうかを見る」）。

### 粒（`CHARACTER`）

**振幅変調で作る。** 位相も遅延も使わない（`REQ-AIR-008`）。

```text
v   ← 平滑した白色雑音、分散 1 に正規化（GRAIN_SECONDS の 1 次）
m    = 1 + d · v                  d = character（ノイズ側の意味）
out  = layer · m / √(1 + d²)
```

- **正規化が閉じた形で書ける。** `v` の分散が 1 なら `E[m²] = 1 + d²`。
  `d` を振っても層のパワーが動かない
- **1 次の出力分散は `a/(2−a)`** なので、平滑の係数から `√((2−a)/a)` を
  掛ければ分散 1 になる。実行時の測定は要らない
- **変調器は L と R で共有する。** 左右で別の粒を掛けると `WIDTH` = 0 でも
  相関が 1.0 を割る。共有していればモノ和の比も相関も粒に影響されない
- 符号は反転しうる（`d` = 1 で `m` < 0）。**ノイズの符号反転は聞こえないので
  クランプしない** — クランプすると上の正規化が閉じた形でなくなる

### `WIDTH` — 共有と独立の混合

**これが Air のゲート**（`REQ-AIR-008`）。独立な 3 本から作る:

```text
L = a·s + b·l
R = a·s + b·r

a = cos(width · π/2)
b = sin(width · π/2)
```

| | `a` | `b` | 相関 | モノ和 `(L+R)/2` |
|---|---|---|---|---|
| `WIDTH` = 0 | 1 | 0 | 1.0 | **0 dB**（L そのもの） |
| `WIDTH` = 1 | 0 | 1 | 0 | **−3.01 dB** |
| 中間 | `cos` | `sin` | `a²` | その間を単調に |

- **`a² + b² = 1`** なのでチャネルあたりのパワーは `WIDTH` によらず一定
- **相関は `a² = cos²(width·π/2)`** で、`WIDTH` に対して単調に減る
- **モノ和の約束は「谷を何 dB 以内に抑える」ではない。** 位相を回す処理が
  経路に 1 つも無いので、モノ和は独立成分が `1/√2` になるだけで
  **櫛形が構造的に出ない**（`REQ-AIR-008`）
- **モノ和は `(L+R)/2`** と定義する。`L+R` だと `WIDTH` = 0 で +6 dB になり、
  受入条件の「片チャネルに対し −3 dB」の基準が変わる

**傾きと上蓋は L/R それぞれ 1 個ずつ**（3 本ぶんは要らない）。混合が線形で
係数が同じなので、**混ぜてから濾しても濾してから混ぜても同じ** — 安いほうを取る。

### キープアライブ — ノイズが無音で鳴り続けないための機構

**倍音層は元音から作るのでタダで止まるが、ノイズは放っておくと定常ヒス**
（`REQ-AIR-004`）。

```text
env   ← nxe_audio::Envelope(5 ms / 250 ms) にモノ和を入れる
q      = clamp((env_db − KEEPALIVE_OFF_DB) / KEEPALIVE_RANGE_DB, 0, 1)
```

`KEEPALIVE_OFF_DB` = **−72 dB**、`KEEPALIVE_RANGE_DB` = **12 dB**。
音楽はまず −60 dBFS を割らないので、**開くか閉じるかであって音楽の中では
動かない**。`Envelope` の床が `1e-6`（−120 dB）なので、無音では `q` が
**厳密に 0** になる（1 次の裾がデノーマルへ落ちていくのを画面が「閉じきらない
ゲート」として描く問題が起きない — `SPK-16`）。

**これが `REQ-AIR-004` の「下限」の実装**で、Follow の深さのほうには下限を
置かない。深さ側に置くと 2 つ壊れる:

- `REQ-AIR-007` の「深さが全部 0 のとき、係数が入力によらず**厳密に 1**」
- `REQ-AIR-002` の「深さ 全部 0 → Velour」という監査

**キープアライブは監査を壊さない。** 閉じるのは無音のときだけで、Velour の
倍音層も無音からは何も作らない。**むしろ 2 系統の無音での振る舞いを揃える**のが
この機構で、要件のほうを直した（`REQ-AIR-004`）。

## 倍音層

`air-core/src/harmonic.rs`。**新規開発ゼロ**（`REQ-AIR-003`）。

```text
入力 ─ 上蓋 ─ 4x ─ shaper(k, β, h) ─ HPF(2·corner) ─ × trim_h
```

- **`nxe_audio::shaper` をそのまま使う。** `k`（奇数次）・`β`（偶数次）・
  `h`（膝）は Velour と Sparkleur と同一のカーブ。`REQ-AIR-002` が引いた線の
  **反対側**なので、ここに v1 の予算を使わない
- **前段の HPF は `corner`**、**生成後の HPF は `2·corner`**。
  生成後を 1 オクターブ上に置くのは、**足すものを「原音の複製」ではなく
  「原音に無かった倍音」に寄せるため**（`REQ-AIR-001` の主張そのもの）。
  Velour の AIR 帯域は入力 4.8 kHz / 出力 4 kHz で**下に**ずらしていて、
  あちらは「その帯域の存在感を作る」製品だから正しい。Air は逆向き
- **上蓋は `min(0.25·fs, 12_000)`**。Sparkleur の `sparkle::INPUT_CEILING` と
  同じ形で、**ホストレートに対して書く** — 内部レートに対して書くと 4x のとき
  48 kHz まで開く（`VEL-3` で 1 回やっている）。絶対値の 12 kHz が要るのは
  レート非依存のため（`SPK-9`）
- **`WIDTH` は掛からない。** 元音由来で L/R が相関しているので、広げるには
  オールパス脱相関が要り、モノ和で櫛形が出る（`REQ-AIR-008`）。
  **L と R は別のフィルタ状態で走るが、同じ係数・同じ入力なら同じ出力**なので、
  モノ入力では L == R がビット単位で成立する

**群遅延はオーバーサンプラのぶんだけ層に乗り、原音には乗らない。**
ホストへ報告するレイテンシは 0（`REQ-AIR-012`）。**量は `AIR-2` で測って
ここに書く。**

## FOCUS

**1 本で 2 系統の居場所をまとめて動かす**（`REQ-AIR-006`）。

```text
shift  = 2^(focus · 1.5)                 focus ∈ [−1, +1]、既定 0
corner = clamp(BASE_CORNER_HZ · shift, 200, 0.30 · fs)
```

| 何 | 周波数 |
|---|---|
| ノイズの HPF（2 次 × 2） | `corner` |
| ノイズの傾きのピボット | `corner` |
| 倍音層の前段 HPF | `corner` |
| 倍音層の生成後 HPF | `2 · corner` |
| 保護と `BRIGHTNESS` の検出帯 | `corner` 〜 `min(20k, 0.45·fs)` |
| 保護と `BRIGHTNESS` の参照帯 | `200 Hz` 〜 `corner / 2` |

`BASE_CORNER_HZ` = **3 000 Hz**、可動域 **±1.5 オクターブ**（Sparkleur の
`FOCUS` と同じ幅、同じ理由 — 素材が声からベースまで広い）。
端は **1 061 Hz 〜 8 485 Hz**。

**要件の表を 1 行広げた。** `REQ-AIR-006` はノイズ側について「`FOCUS` が
傾きを動かす」とだけ書いていたが、**傾きだけでは「2 系統の帯域がまとめて動く
（比も保たれる）」が測れない** — 傾きに帯域という測れる量が無い。ノイズ層にも
`corner` の HPF を持たせ、**両系統が同じ `shift` で動くことを比の保存とした**。
併せて、傾きだけのノイズは 200 Hz にもヒスを足すので、そもそも
「高域テクスチャ生成器」にならない。

**ナイキストは `0.30·fs` で切る。** 44.1 kHz で 13.2 kHz なので `FOCUS` の
上端（8.5 kHz）には当たらない — 当たるのは誰かが `BASE_CORNER_HZ` を動かした
ときで、そのとき黙って発散しないためにある。

## BLEND と CHARACTER

```text
g_h = cos(blend · π/2) · HARMONIC_TRIM      blend = 0 → 倍音だけ
g_n = sin(blend · π/2) · NOISE_TRIM         blend = 1 → ノイズだけ
```

- **電力保存のクロスフェード。** 2 系統は無相関なので、振幅で混ぜると中間で
  −3 dB 凹む（`REQ-AIR-005`）
- **振り切ったほうは厳密に 0。** `cos(π/2)` は f32 で `-4.37e-8` になるので、
  **端は数式に任せず定数で潰す**（`blend == 1.0` なら `g_h = 0.0`）。
  「ちょうど無音」を要求している受入条件がある
- **トリム 2 個は測定で決まる。** 電力保存が成立するのは 2 系統が同じ RMS の
  ときだけで、倍音層のレベルは素材に依存する。`AIR-3` でピンクノイズ
  −18 dBFS を通し、`BLEND` を掃引して総エネルギーが ±1 dB 以内に収まる値を
  入れる。**初期値は両方 1.0**

`CHARACTER`（`c` ∈ [0, 1]）は**常に両系統へ同じ正規化値を渡す**:

| 系統 | 受け取り方 |
|---|---|
| 倍音 | `h = H_SOFT + c · (H_HARD − H_SOFT)`（膝の硬さ） |
| ノイズ | `d = c`（粒の深さ） |

**「`BLEND` の位置で意味が移る」ための分岐は要らない。** 聞こえるのは
`BLEND` が選んだ系統だけなので、両方に同じ値を渡せば意味は自動的に移る
（`REQ-AIR-005` の表がそのまま実装になる）。`k` と `β` は Advanced。

## Follow Engine

**Air の正体**（`REQ-AIR-002`）。3 本とも既にある部品の値違い。

```text
係数ᵢ    = (1 − 深さᵢ) + 深さᵢ × 検出値ᵢ
層のゲイン = SURFACE × 係数_env × 係数_bright × 係数_trans × q × guard
深さᵢ    = clamp(FOLLOW + 偏差ᵢ, 0, 1)
```

**深さ 0 で係数は厳密に 1** — 検出値が何であっても `(1−0) + 0·v = 1`。
浮動小数の丸めも入らない（`REQ-AIR-007`）。

### 3 本の検出

| 検出 | 何を見るか | 部品 | 時定数 |
|---|---|---|---|
| `ENVELOPE` | モノ和の音量 | `nxe_audio::Envelope` | 10 ms / 200 ms |
| `BRIGHTNESS` | 検出帯 ÷ 参照帯のパワー比 | `nxe_audio::guard` の相対検出器 | 20 ms / 200 ms |
| `TRANSIENT` | **検出帯**の速い/遅いフォロワの比 | `sparkle.rs` と同じ機構 | 1 ms / 100 ms + ホールド 40 ms |

```text
検出値_env    = clamp((env_db − ENV_FLOOR_DB) / ENV_RANGE_DB, 0, 1)
検出値_bright = clamp((ratio_db − BRIGHT_MIN_DB) / BRIGHT_RANGE_DB, 0, 1)
検出値_trans  = clamp(excess_db / TRANSIENT_RANGE_DB, 0, 1)
```

### `TRANSIENT` は帯域通過してから見る — `SNAP_RANGE_DB` を借りるための条件

`sparkle.rs` の `SNAP_RANGE_DB = 6.0` は **band 5（6 kHz 以上）だけを見た数**で、
全帯域を見る Air にそのまま持ってくると効かない — フルバンドの速い/遅い比は
低域の遅いエンベロープに薄められるので、同じ 6 dB では**ハットでもほとんど
開かない**。

**検出帯（`corner` 〜 上端）に通してから比を取る**ことにした。これで Sparkleur の
band 5 とほぼ同じ状況になり、**6.0 dB が「借りられる出発点」になる**。
`BRIGHTNESS` の検出帯と同じ帯域なので、**帯域通過は 1 本で足りる**。

**フォロワは両方対称にする**（`SPK-6`）。非対称なフォロワは平均とピークの間に
座り、その位置は attack/release の比で決まる（`SPK-3`）。速い側だけ非対称に
すると**定常音でも比が 3 dB 出て、ゲートが開いたまま**になる。連続したアタックで
チャタらないようにするホールドは、**比の後ろ**に置く。

### `BRIGHTNESS` は相対で見る

絶対の高域量で判定すると入力ゲインで挙動が変わる（`REQ-AIR-007`）。
検出帯と参照帯のパワー比なので、分子と分母が一緒に動く。
**±12 dB で 0.2 dB 以内**が受入条件（De-Harsh と同じ数字）。

**参照帯は検出帯を含まない** — `200 Hz 〜 corner/2` と `corner 〜 上端` で
重ならない。Sparkleur は出荷時のしきい値でここが破れていて、**普通の素材から
常時 1.3 dB 引いていた**（`SPK-18`）。`FOCUS` で両方が動く Air は踏みやすい。

### `Power` を `nxe-audio` に上げる（`AIR-5`）

パワーフォロワ（二乗 → 非対称 1 次）の実装が **今 2 つある** —
`guard::Follower`（private）と `sparkle::Power`（private）。Air が 3 つ目を
要求するので、**`nxe_audio::envelope::Power` として上げ、既存 2 つをそこへ
差し替える**。「上げるのは 3 個目の客が来てから」という
`docs/specifications/architecture.md` の規則そのもの。

**時定数は上げない。** 秒で受け取るだけにして、値は呼び出し側に残す
（`SPK-1` で `envelope` の機構だけ移して Velour の 5 ms / 150 ms を
`velour_core::envelope::vocal()` に置いたのと同じ）。

## 保護（Excess Guard）

`nxe_audio::guard::RelativeGuard<1>` の値違い（`REQ-AIR-009`）。

| | |
|---|---|
| 検出帯 | `corner` 〜 `min(20k, 0.45·fs)`（`FOCUS` に追従） |
| 参照帯 | `200 Hz` 〜 `corner / 2`（一緒に動く。重ならない） |
| attack / release | 5 ms / 150 ms |
| slope | 1.0 |
| `max_reduction_db` | 12 dB |
| しきい値 | **`AIR-6` で測る**（下） |

- **見るのは出力**（`dry + layer`）で、入力ではない。判定したいのは
  「**足した結果**が音楽に対して過剰か」なので、足す前を見ても答えにならない
- **1 サンプル遅れのフィードバック。** 検出器に渡すのは前サンプルの出力の
  モノ和。時定数が ms なので 1 サンプルは効かず、ゲインは下げる方向にしか
  動かないので発散しない
- **触るのは層のゲインだけ。** 原音には一切掛からない（`REQ-AIR-001`）
- **しきい値は固定・常時オン・マクロに結び付けない**（`REQ-AIR-009`）。
  Sparkleur が `CHARACTER` に乗せたのは、あちらの約束が
  「明るくなるのに痛くならない」という**度合いのある約束**だったから
- Advanced には**双極の偏差**（0 で既定、± で強め/弱め）。絶対量にすると
  2 つのパラメータが 1 つの値を書く

**しきい値は分布から決める**（`SPK-18`）。ピンクノイズと定常倍音列を
`SURFACE` 既定で通し、検出帯 ÷ 参照帯の **p50 / p95 / max** を並べてから
置く。**末尾の 1 サンプルの引き量で決めない** — ノイズではそれは 1 つの
偶然の瞬間。受入条件は「**普通の素材でちょうど 0 dB**」。

**2 音のテストでは守れない**（`SPK-18`）。検出帯にほとんど何も無い信号は
どんなしきい値でも通る。**しきい値のテストは広帯域で書く。**

**相対検出器は立ち上がるまで無限に harsh に見える**（`SPK-18`）。参照フォロワが
0 から始まるので、サンプル 0 から測るとピンクノイズが上限いっぱい引く。
**100〜250 ms 捨ててから測る。**

## 出力とスムージング

```text
out = OUTPUT · (dry + MIX · layer)
```

- `MIX` は線形（`REQ-AIR-012`）。電力保存にしない
- `MIX` = 0 は**有限の値に 0 を掛けて足すだけ**なのでビット一致
- `SURFACE` = 0 のとき層は**厳密に 0**（乗算の結果ではなく早期に返す）。
  4x のブロックを回さないので CPU も返ってくる（`REQ-SPK-007` と同じ扱い）

**スムージングはラッパの責任。** パラメータは**サンプルごとに**読む
（`.agents/rules/rust.md` の「ブロック単位で読むな」）。**係数の再計算だけが
ブロック単位** — `FOCUS` が動いたときのフィルタ 10 個ぶんで、`set` が
「前回と同じなら何もしない」で守る（`sparkle::set` と同じ形）。

**入口で 1 回消毒する**（`SPK-9`）。非有限のサンプル 1 個で検波器も
クロスオーバーもラッチする。**原音は消毒しない** — 通り道なので NaN を
送ってきたホストには NaN が返る。

## 耳で詰める定数

**機構が仕様、値は仮。** 測れるものは測ってから耳に回す（`SPK-18` では
半分が測定で決まった）。

| 何 | 設計時の値 | どう決めるか |
|---|---|---|
| `BASE_CORNER_HZ` | 3 000 Hz | **耳。** 「表面」がどこから始まるか。素材を跨いで `FOCUS` の可動域が足りるかで見る |
| `FOCUS` の可動域 | ±1.5 oct | **測定で確認する**（`AIR-1`）。3 レートで上端がナイキストに当たらないこと |
| `TILT_MAX_DB` | 12 dB | **耳。** 1 次なので帯域内では端まで届かない。「DUST と BREATH が別のものに聞こえる」が基準 |
| 生成後 HPF の比 | `2 · corner` | **測定できる**（`AIR-2`）。層の中で 2 倍音帯が基音帯より大きいこと。**どれだけ上が良いかは耳** |
| `GRAIN_SECONDS` | 6 ms | **耳。** 「粒」に聞こえるか「ざらつき」に聞こえるか。パワーは正規化済みなので量は動かない |
| `KEEPALIVE_OFF_DB` / `RANGE` | −72 / 12 dB | **測定で確認する**（`AIR-1`）。無音で厳密に 0、実素材で常に全開 |
| `NOISE_TRIM` / `HARMONIC_TRIM` | 1.0 / 1.0 | **測定で決まる**（`AIR-3`）。`BLEND` の掃引で ±1 dB |
| `H_SOFT` / `H_HARD` | 0.10 / 0.90 | **耳。** 両端が別の質感か。Velour の `TEXTURE`、Sparkleur の `CHARACTER` と同じ問い |
| `shaper` の `k` | 4.0 | **折り返しの側は測れる**（`AIR-2`、−60 dB）。**艶が足りるかは耳** |
| `ENV_FLOOR_DB` / `RANGE` | −48 / 36 dB | **耳。** 弱いフレーズで層が消えすぎないか |
| `BRIGHT_MIN_DB` / `RANGE` | −18 / 15 dB | **測定で決める**（`AIR-5`）。ピンクノイズがどこに座るかを見てから |
| `TRANSIENT_RANGE_DB` | 6 dB | **測定で決める**（`AIR-5`）。帯域通過を挟んだので Sparkleur の数が出発点として使える。ハットで開きパッドで開かないこと |
| 保護のしきい値 | **未定** | **測定で決める**（`AIR-6`）。分布を並べてから置く |
| 既定値（メイン 7 本） | — | **耳**（`AIR-13`）。プリセットが無いので既定値が製品の顔 |

## 検証

| 何 | どう測るか | 要件 |
|---|---|---|
| モノ和に櫛形が出ない | 層だけを取り出し、`WIDTH` 全域でモノ和のスペクトルの平坦性 ±1 dB | `REQ-AIR-008` **ゲート** |
| `WIDTH` = 0 の相関 | `nxe_dsp::Correlation` で 1.0 | `REQ-AIR-008` |
| `WIDTH` = 1 のモノ和 | 片チャネルに対し −3 dB ±0.5 dB | `REQ-AIR-008` |
| 相関の単調性 | `WIDTH` を刻んで単調減少 | `REQ-AIR-008` |
| レート非依存 | 4 レート、**100 Hz〜16 kHz に通してから** RMS が ±0.5 dB | `REQ-AIR-017` |
| ブロック非依存 | 1 / 64 / 512 / 4096 で出力一致 | `REQ-AIR-017` |
| 決定性 | 同じシードで完全に一致 | `REQ-AIR-017` |
| 無音への収束 | キープアライブが**厳密に 0** を出す | `REQ-AIR-004` |
| 帯域外へ逃げない | 傾き振り切りで 20 kHz 上のパワーが上蓋どおり | `REQ-AIR-004` |
| `MIX` = 0 / `SURFACE` = 0 | 乱数列を通して入力とビット一致 | `REQ-AIR-001` |
| 折り返し | 4x で最悪ケースが −60 dB 以下 | `REQ-AIR-003` |
| 上蓋がホストレート基準 | 4 レート、倍率を変えても動かない | `REQ-AIR-003` |
| 倍音層が広がらない | `WIDTH` 全域で L == R | `REQ-AIR-008` |
| `BLEND` の平坦性 | ピンクノイズ、掃引して総エネルギー ±1 dB | `REQ-AIR-005` |
| `BLEND` の端 | 反対側がちょうど 0 | `REQ-AIR-005` |
| `FOCUS` が比を保つ | 2 系統の帯域が同じ `shift` で動く | `REQ-AIR-006` |
| 深さ 0 で係数 1 | 入力によらず**厳密に** 1.0 | `REQ-AIR-007` |
| `BRIGHTNESS` の入力ゲイン非依存 | ±12 dB で 0.2 dB 以内 | `REQ-AIR-007` |
| 監査（Velour / Sparkleur） | 深さ全部 0 で静的、`TRANSIENT` だけ 1 で Sparkle の形 | `REQ-AIR-002` |
| 保護が普通の素材で 0 dB | ピンクノイズと定常倍音列、**広帯域で** | `REQ-AIR-009` |
| 保護が原音に触らない | `SURFACE` = 0 でビット一致のまま | `REQ-AIR-009` |
| 極端値 | 全パラメータ・全サンプルに NaN / ±inf / ±1e9 | `REQ-AIR-016` |
| 確保が無いこと | 数えるグローバルアロケータ | `REQ-AIR-016` |
| CPU | criterion、4x / 512 / 48 kHz で 533 µs 以内 | `REQ-AIR-016` |

**測定が失敗できることを同じテストの中で確かめる**（`VEL-10`）。`WIDTH` の
単調性も、レート非依存も、**対照実験が差を出すこと**を 1 行で示してから
本番のアサートを書く。

**テスト信号は自分でも測る**（`SPK-18`）。`nxe_audio::harmonics` の
`noise` / `pink` は DC を修正済みなので、**そちらを使う。自分で書かない。**

**引き算で層を取り出さない**（Velour の宿題）。`出力 − 原音` は原音のほうが
大きいと層の精度をほとんど捨てる。**Air は加算型なので層を直接取れる** —
`Engine` はテストから層をそのまま読める形で書く。
