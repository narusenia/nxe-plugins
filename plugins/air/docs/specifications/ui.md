## 設計方針

**足した層が見える。** これが Air の主張そのもの（`REQ-AIR-001`）で、
**加算型だから描ける**。Sparkleur は分割型なので「足した層」という信号が
存在せず、帯域ごとのゲインがその役をしていた（`REQ-SPK-018`）。Air は
`Engine::layer()` が層をそのまま返すので、**引き算をせずに**図にできる。

**層は粒に見える。** 元音の線の上に、生成層を**点の格子**で重ねる。
`BLEND` を倍音側に振ると点が縦に揃い、ノイズ側で散る — **2 系統の違いが
図の見た目そのもの**になり、「今どちらを聞いているか」を読み値ではなく
形で言える。

**閉じている検出器が見える。** Follow の 3 本は**掛け算**なので、1 つでも
閉じていれば層は出ない（`REQ-AIR-007`）。合成後の 1 本だけを出すと
「暗いパッドで `BRIGHTNESS` が閉じている」のか「量が足りない」のか
「保護が引いている」のかが区別できない。**3 本とも出す**（`REQ-AIR-018`）。

**保護が見える。** Air の保護は引ける対象が自分の層しか無いので、
強く効くと**層が消える**（`REQ-AIR-009`）。見せないと「壊れている」と読まれる。
引き量を数字で出す。

**約束が見える。** `REQ-AIR-008` は「位相を回さないのでモノで櫛形が出ない」を
約束している。**その約束を画面で確かめられる**ようにするため、生成層の相関を
出す（Doubler が既に `nxe_dsp::Correlation` を使っている）。

**普段触るのは 7 つのノブだけ。** パラメータは 15 個で、常用するのは
`SURFACE` / `BLEND` / `CHARACTER` / `FOCUS` / `WIDTH` / `FOLLOW` / `MIX`。
残りは同じ画面の下段（**タブは持たない** — `REQ-AIR-013`、`SPK-19`）。

**幅は `theme::WINDOW_WIDTH`。** 5 本で 1 つの定数を共有していて、**並べたときに
1 つの製品に見える**ため（`.agents/rules/ui.md`）。

**高さは算術**。上から順に足す:


**図の高さは 3 本と同じ 200。** 別々に詰めた図は、それぞれ単体では正しくて
**並べると揃わない**（`.agents/rules/ui.md`）。

## 点のスペクトラム（`nxe_ui::dots::DotField`）

**新規ウィジェット。** `nxe-ui` に置き、**同じ変更で `examples/gallery.rs` に
並べる**（規約）。

```rust
DotField::new(
    cx,
    source,     // impl Res<Curve>  原音のスペクトラム。細い線
    layer,      // impl Res<Curve>  生成層のスペクトラム。点
    alignment,  // impl Res<f32>    0..1。1 で点が縦に揃う
)
```

- **格子は列 × 行**。列は `layer` の点の数、行は定数（16）
- **セル `(c, r)` が光る条件は `layer[c] > r / rows`。** つまり高さは
  レベルそのもので、**上端のセルだけ端数ぶん不透明度を落とす**ので縁が
  階段にならない
- **散らしは `(c, r)` から決まるハッシュ。** セル幅の 4 割まで、
  `(1 − alignment)` を掛けて振る
- **フレームごとの乱数にしない。** 明滅して読めなくなるうえ、gallery で
  見ても同じ絵が 2 度出ないので**レビューできない**
- 塗りはフラットなアクセント（`UI-21`）。量は点の密度が言う
- 原音は 1 本の細い線。`FOREGROUND` を薄く（解析の重ね描きと同じ扱い）

### なぜ層がアクセントで原音がニュートラルか

規約は「設定はアクセント、信号はニュートラル」と書いている
（`crates/nxe-ui/README.md`）。この図には**設定が 1 つも写っていない** —
2 本とも信号なので、軸を読み替える。

**生成層は 7 本のノブが作ったものそのもの**で、`SURFACE` を上げれば高くなり、
`FOCUS` で動き、保護が働けば沈む。図の中で「設定の結果」に一番近いのは
層のほうなので、アクセントは層に付ける（`REQ-AIR-013` が求めているのも
これ）。原音は背景として敷く。

### 何が図で読めるか

- **`SURFACE`** — 点の山の高さ
- **`FOCUS`** — 山が左右に動く。原音の線は動かないので、**層だけが動く**のが
  そのまま見える
- **`BLEND`** — 点が縦に揃うか散るか。倍音側は元音の倍音列に沿って柱が立ち、
  ノイズ側は帯全体に散る
- **保護** — 働いた瞬間に山が沈む（Sparkleur の区画が沈むのと同じ扱い）
- **Follow** — 音が止まると山が消える。**`ENVELOPE` が効いていることが
  図で分かる**

### 描かないもの

- **周波数の数値を図の中に書かない。** vizia の `draw_text` は view 自身の
  テキストしか描けないので、目盛りは呼び出し側が `Label` を絶対配置する
  （`BandField` と同じ）。**一番右の目盛りは `left: 1s; right: 0px`** で
  逆側から吊る — `left: 100%` はそこが**始まり**なので窓の外に出る
- **掴めるようにしない。** 図の中に書き込む先が無い（`FOCUS` はノブ、
  `SURFACE` もノブ）。掴めそうに見えるものを置かない
- **層と原音の差を描かない。** 引き算は層の精度をほとんど捨てる
  （`docs/HANDOVER.md`）。層は `Engine::layer()` から直接来る

## 読み値の帯

`nxe_ui::readout::strip` に 7 セル。**新しく測るものは 1 つも無い** —
全部 `Engine` が既に持っている（`analysis.rs`）。

| セル | 何 | 出どころ |
|---|---|---|
| `IN` / `OUT` | 入出力のレベル | `nxe_dsp::Level` |
| `GUARD` | 保護の引き量、dB | `Engine::guard_reduction_db` |
| `WIDTH` | 生成層の相関 | `nxe_dsp::Correlation` |
| `ENV` / `BRT` / `TRN` | Follow の 3 係数 | `Engine::follow_coefficients` |

- **3 本は個別に出す。** 掛け算なので 1 本でも閉じれば層は出ない
  （`REQ-AIR-018`）
- **`GUARD` は常に符号付き**（`-0.0` が静止状態）。引きは一方向にしか
  動かないので符号は情報を持たないが、**働いた瞬間に符号が現れると数字が
  跳ねて「自信が無い」ように読める**（`.agents/rules/ui.md`）
- **無音は `—`。** `-142.0 dB` は 6 文字のノイズ
- **`WIDTH` の相関は約束の証明**。`WIDTH` を 0 に振れば 1.00、1 に振れば
  0 付近。**位相を回していないことがここで見える**

## メーター

右の縦帯。Velour / Sparkleur と同一（`nxe_ui::meter::Meter` × 4、
IN / OUT × L / R、ピークホールド付き）。

**保護のメーターは持たない。** 読み値の `GUARD` と、図の山が沈むことで
見えている。

## メインの 7 本

```text
  SURFACE   BLEND   CHARACTER   FOCUS   WIDTH   FOLLOW   MIX
     ◯       ◯         ◯        ◯       ◯       ◯      ◯
```

**全部同じ大きさ。** Sparkleur は「音を作る 5 つ」と「どれだけ届くかの 2 つ」で
サイズを分けたが、Air は 7 本とも層の作り方を決める — `MIX` すら
「足した層をどれだけ通すか」であって原音を減らさない（`REQ-AIR-012`）。

読み値は全部パーセント。**`FOCUS` だけオクターブ**（`-1.00`〜`+1.00`）。

**`CHARACTER` に名前を付けない。** Sparkleur の `POLISH / GLOSS / CRUSH` は
3 つのアンカーがあったが、Air の `CHARACTER` は**意味が `BLEND` の位置で
移る**（膝 ↔ 粒、`REQ-AIR-005`）ので、どの位置にも 1 つの名前が付かない。
名前を付けると `BLEND` を動かした瞬間に嘘になる。パーセントだけ出す。

## ADVANCED

```text
  DRIVE ──●──    ENV ──●──     OVERSAMPLE        OUTPUT
  BIAS  ──●──    BRT ──●──     [ 2x ][ 4x ]        ◯
  GUARD ──●──    TRN ──●──
```

**2 列。3 列は窓に入らなかった**（`AIR-13` の実機確認）。148 px の列 3 本と
側の列と隙間で 700 px になり、パネルが持っているのは 628 px。Morphorm は
`Pixels` の子を縮めないので、**はみ出した分はそのまま端の外に描かれ**、
`OUTPUT` のノブがメーターの下に潜っていた。**テストは 1 本も落ちない** —
はみ出したレイアウトもレイアウトではある。

`DRIVE` / `BIAS` / `GUARD` は名前だけで何かが分かるので、列に見出しは要らない。
`ENV` / `BRT` / `TRN` は**読み値の帯と同じ 3 つの名前**で、そちらが今どれだけ
開いているかを見せている。

- `DRIVE` / `BIAS` はカーブそのものの数。**`CHARACTER` が届かない**のが
  設計（`REQ-AIR-010`）。`Bar`（左端から）
- `ENV` / `BRT` / `TRN` は **`FOLLOW` からの双極の偏差**（0 = マクロの言うとおり）。
  `Bar::bipolar`
- `GUARD` は保護の双極の偏差。**下端でちょうど無効、上端でしきい値 −9 dB**
  （`dsp.md`）。`Bar::bipolar`
- `OVERSAMPLE` は `SegmentedControl`
- `OUTPUT` は小さい `Knob`。**幅を明示する** — `knob_block` は
  `Stretch(1.0)` を要求し、**`Auto` 幅の親の中では 0 に潰れる**ので、
  ノブとラベルと数値が同じ原点から描かれて隣に重なった
  （`.agents/rules/vizia.md`）
- **バーには必ず高さを指定する。** Velour で指定を忘れて Advanced の表が
  「動かないコントロール」になった（`.agents/rules/vizia.md`）

### 新規

| コンポーネント | 何 | なぜ |
|---|---|---|
| `nxe_ui::dots::DotField` | 点のスペクトラム | **加算型でしか描けない図**。`CurveView` は曲線と帯とハンドルの道具で、点の格子は別の描き方。`BandField` は掴める区画の道具で、Air には掴む先が無い |
| `examples/gallery.rs` | `DotField` のパネル | 規約（ウィジェットを足したら gallery も同じ変更で） |

**`CurveView` を拡張しない。** 点の格子は曲線 1 本と帯とハンドルのどれでも
なく、`CurveView` に 4 つ目の描き方を足すと**そのどれも使わない呼び出し側が
4 つの空の `Vec` を渡す**ことになる。`BandField` を `CurveView` から分けた
のと同じ判断（`crates/nxe-ui/src/band.rs`）。
