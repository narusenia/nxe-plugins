# REQ-AIR — Air 要件定義

> 最終更新: 2026-08-27

## 概要

Air は**信号駆動のテクスチャ生成器**。狙いは 1 つで、要件の全部がそこに
かかっている。

> **元音に存在していない高域成分を生成し、元音の動きに追従させる。**

エキサイタは既にある高域倍音を強調する。Air は**無かったものを作って、元音が
居ない場所に置く**。ユーザーは高域を「上げる」のではなく、光らせる・粒を足す・
ザラつかせる・息を与える・周囲に広げる、という感覚で音の表面をデザインする。

対象は Bitwig / Ableton Live / Reaper / Studio One。**AU は対象外**なので
Logic Pro と GarageBand では読み込めない（`REQ-AIR-014`）。

姉妹製品との担当は `REQ-AIR-002` で線を引く。**倍音生成カーブ・オーバー
サンプラ・相対検出器・エンベロープは 3 製品で共有する**（`REQ-AIR-015`）が、
掛かり方が別の製品になる。

## 設計の中心にある 6 つの判断

**差は生成器ではなく、生成した層の扱いにある。** Sparkleur の Sparkle と
構想の `SHINE` は信号経路が字面まで同じで、しかも Sparkleur は `SNAP` = 0 で
静的な倍音付加になる（`REQ-SPK-007`）。「倍音か、ノイズか」で線を引くと
`FIZZ` まで巻き添えになって製品が崩れる。**Air の正体は Follow Engine と
Stereo Air** — 生成した層を独立した対象として配置・変調できることで、
Sparkleur には無い（`REQ-AIR-002`）。

**原音は入口から出口まで一切触らない。** 層を独立した対象として扱うなら、
層は出力まで原音と分かれていないといけない。Velour の `REQ-VEL-001` と同じ側で、
Sparkleur の分割型（`REQ-SPK-001`）の逆。構想の Harshness Control にある
`Dynamic notch` だけがこれを破るので**落とす** — 刺さる原因が自分の足した層に
あるなら、足すのをやめれば直る（`REQ-AIR-009`）。

**位相を回す処理を 1 つも置かない。** ノイズは左右を別々に生成すれば脱相関が
タダで手に入り、モノ和は −3 dB になるだけで櫛形が出ない。倍音は元音由来で
相関しているので、広げるにはオールパスが要り、モノ和で櫛形が出る。だから
**`WIDTH` はノイズ層にだけ効き、倍音層はセンター固定**。約束が「谷を何 dB 以内
に抑える」ではなく「**そもそも位相を回さない**」になり、構造的に破れなくなる
（`REQ-AIR-008`）。

**追従の合成に他 2 製品が座標として入る。** 各 Follow は「1 と検出値の間を
混ぜる」形で、Sparkleur の `SNAP` と同じ（`REQ-AIR-007`）。深さが全部 0 なら
静的 = Velour、`TRANSIENT` だけ 1 なら Sparkleur の Sparkle。**境界が要件の
中で監査可能になる。**

**質の軸は 1 本、離散モードにしない。** 構想の Character Morph の三角形は
2 系統に畳んだ。系統ごとに質軸を持たせると「今 `BLEND` がそっちに寄って
いないと何も起きないノブ」が 2 本できるので、`BLEND` の位置で意味が連続的に
移る 1 本にする（`REQ-AIR-005`）。Velour の `TEXTURE`、Sparkleur の
`CHARACTER` と同じ判断。

**保護は好みではなく判定。** 「足したものが音楽に対して過剰か」はマクロで
強さが変わるべきものではないので、しきい値は固定で常時オン。ただし Air は
引ける対象が自分の層しか無く、強く効くと層が消える = 何もしていないように
見えるので、**引き量を必ず画面に出す**（`REQ-AIR-009`、`REQ-AIR-018`）。

## REQ-AIR-001: 加算型トポロジと原音の扱い

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 入力から生成層を作り、原音に足す。**原音は入口から出口まで
  一切の処理を通らない。**

```text
Input ─┬───────────────────── dry ──────────────────────┐
       │                                                │
       ├─ 倍音層 ─┐                                     │
       │          ├─ BLEND ─ × Follow ─ × Guard ─ wet ──┤─ MIX ─ OUTPUT
       └─ ノイズ層┘                                     │
       │                                                │
       └─ 検出（Follow 3 本 / Guard）────────────────────┘
```

- **`MIX` = 0 でビット一致。** 原音は分岐しているだけなので、`MIX` = 0 は
  加算 1 回で入力そのもの。Velour から引き継ぐ透明性の約束。
- **`SURFACE` = 0 でも同じく入力そのもの。** 分割型の Sparkleur と違い、
  Air には「通っているだけで位相が回る」経路が無い（`REQ-SPK-001` の裏返し）。
  逃げ道が 2 つあることになるが、片方を実装の分岐にはしない — どちらも
  ゲインが 0 になるだけで、経路は常に同じものが走る。
- **構想の `Dynamic notch` は落とす。** 和に動的 notch を入れると、原音が
  処理を通ることになり、`MIX` = 0 のビット一致と「層を単体で聴ける」の
  両方が同時に壊れる。原音が元から刺さっているなら、それは Sparkleur の
  De-Harsh の仕事（`REQ-SPK-008`）。
- **受入条件**:
  - [ ] `MIX` = 0 で出力が入力と**ビット一致**
  - [ ] `SURFACE` = 0 で出力が入力と**ビット一致**
  - [ ] `SURFACE` を 0 から上げても不連続が出ない
  - [ ] 生成層を単独で取り出せる（テストから。UI の重ね描きが同じ値を使う）
- **依存**: なし

## REQ-AIR-002: Sparkleur / Velour との境界

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 3 製品が同じ倍音生成カーブを使う。**差は生成器ではなく、
  生成した層の扱いにある。**

| | Velour | Sparkleur | Air |
|---|---|---|---|
| トポロジ | 加算 | 分割 | 加算 |
| 層の居場所 | 帯域ごとに原音へ | band 5 の中に混ぜて消える | **原音が居ない場所に置ける** |
| 層の変調 | 無し（静的） | トランジェント 1 本（`SNAP`） | **4 系統のうち 3 本**（`REQ-AIR-007`） |
| ノイズ | 無し | 無し | **有り**（`REQ-AIR-004`） |
| 層を単体で聴くと | 意味がある | 意味が無い | 意味がある |

- **一文で言うと**: Velour は原音の存在感を作り、Sparkleur は元音を磨き、
  **Air は元音に無かった表面を足す**。
- **監査可能な形で書ける。** Follow の深さは他 2 製品の挙動を含む
  （`REQ-AIR-007`）:

```text
深さ 全部 0            → Velour（静的な倍音付加）
TRANSIENT だけ 1       → Sparkleur の Sparkle
それ以外               → Air の領分
```

- **重複を隠さない。** `BLEND` を倍音側に振り切って Follow を全部 0 にすると
  Velour と同じ音になる。これは欠陥ではなく、**ユーザーが差を自分で確認する
  手段**（`REQ-SPK-007` が `SNAP` = 0 について書いているのと同じ）。
- **受入条件**:
  - [ ] Follow の深さが全部 0 のとき、生成層のゲインが入力によらず一定
  - [ ] `TRANSIENT` だけ 1 のとき、Sparkleur の Sparkle と同じ形の包絡になる
        （持続音で閉じ、アタックで開く）
- **依存**: REQ-AIR-007

## REQ-AIR-003: 倍音層

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 入力を波形整形して倍音を作り、生成後に高域だけ残す。
  **`nxe_audio::shaper` をそのまま使い、新しいカーブを作らない。**

```text
Input ─→ HPF ─→ cap ─→ 4x ─→ shaper(k, β, h) ─→ HPF ─→ × gain
```

- **新規開発ゼロ。** `k`（drive / 奇数次）・`β`（バイアス / 偶数次）・
  `h`（soft ↔ hard knee）は Velour と Sparkleur が使っているものと同一。
  **境界の判断（`REQ-AIR-002`）から、ここに v1 の予算を使うのは線の
  反対側への投資**なので、意図的に借り物で済ませる。
- **入力に上蓋を付ける。** Velour の `AIR_INPUT_CEILING`（ホストレートの
  1/4）が無いと、どんなドライブでも −44 dB で折り返す（`VEL-3`）。
  最初から入れる。**上蓋はホストレートに対して書く** — 内部レートに対して
  書く間違いが Velour で 1 回起きている。
- **前段の HPF は `FOCUS` が動かす**（`REQ-AIR-006`）。生成後の HPF も同じ。
- **`CHARACTER` が `h` を動かす**（`REQ-AIR-005`）。`k` と `β` は
  Advanced（`REQ-AIR-010`）。
- **受入条件**:
  - [ ] 倍音層のゲインが 0 のとき**ちょうど無音**
  - [ ] 4x で最悪ケースの折り返しが **−60 dB 以下**（Velour / Sparkleur と
        同じ基準）
  - [ ] `CHARACTER` で偶奇比が動き、足す量は ±3 dB 以内で動かない
  - [ ] 上蓋がホストレートに対して効いている（96 / 192 kHz で確認）
- **依存**: REQ-AIR-005, REQ-AIR-006

## REQ-AIR-004: ノイズ層

- **優先度**: Must
- **ステータス**: Draft
- **説明**: ノイズを生成し、傾きと粒立ちを整えて足す。**v1 で唯一の
  新規 DSP。**

```text
noise(L) ─→ 傾き ─→ 粒 ─→ × gain
noise(R) ─┘        （WIDTH が L/R の共有度合いを決める。REQ-AIR-008）
```

- **オーバーサンプリングは要らない。** 非線形が 1 つも無いので折り返しが
  発生しない。倍音層だけが 4x を通る（`REQ-AIR-016` の見積りがこれに乗る）。
- **傾きは `FOCUS`、粒立ちは `CHARACTER`。** 構想の DUST / BREATH は同じ
  生成器の両端（`REQ-AIR-005`）。White / Pink / Blue は傾きの別名なので
  離散のモードにはしない。
- **エンベロープ追従に機構としての下限を持つ。** 倍音層は元音から作るので
  元音が止まればタダで止まるが、**ノイズは放っておくと永久に鳴る定常ヒス**。
  「追従の深さ 0」が有効な設定なのは倍音層だけなので、ノイズ層の
  `ENVELOPE` には 0 にできない下限を置く（`REQ-SPK-003` の `CEILING` と
  同じ扱い — パラメータではなく機構）。
- **サンプルレートと決定性は `REQ-AIR-017`。** ここが一番踏みやすい罠。
- **受入条件**:
  - [ ] ノイズ層のゲインが 0 のとき**ちょうど無音**
  - [ ] 無音を入れたとき、**下限を含めて**出力が無音に収束する
  - [ ] 傾きを振り切っても可聴帯域外にエネルギーが逃げない
  - [ ] `air-core` の外から明示シードを渡すと決定的に再現する
- **依存**: REQ-AIR-005, REQ-AIR-006, REQ-AIR-007, REQ-AIR-017

## REQ-AIR-005: BLEND と CHARACTER

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 2 系統を 1 本で混ぜ、質を 1 本で決める。

```text
BLEND       倍音 ←──────────────→ ノイズ
CHARACTER   意味が BLEND の位置で連続的に移る
```

| `BLEND` の位置 | `CHARACTER` が動かすもの |
|---|---|
| 倍音寄り | `shaper` の `h`（soft ↔ hard） |
| ノイズ寄り | 粒立ち（滑らか ↔ 粒） |
| 中間 | 両方に同じ正規化値を渡す |

- **系統ごとに質軸を持たせない。** メインが 8 本になるうえ、そのうち 2 本は
  **`BLEND` がそちらに寄っていないと触っても音が変わらない**。二層モデル
  （`REQ-AIR-010`）が避けてきたもの。
- **離散モードにしない。** 構想の Gloss / Dust / Fizz / Breath は 4 つの
  モードとして書かれているが、2 モードだと「Soft の 8 割」が到達不能になる
  という判断を Velour（`TEXTURE`）と Sparkleur（`REQ-SPK-006`）で 2 回して
  いる。3 回目も同じにする。
- **`BLEND` は電力保存でクロスフェードする。** 振幅で混ぜると中間で凹む。
  2 系統は無相関なので `sqrt` 則。
- **受入条件**:
  - [ ] `CHARACTER` をどこで動かしても、`BLEND` の位置によらず音が変わる
  - [ ] `BLEND` を振り切ると、もう一方の系統が**ちょうど無音**
  - [ ] `BLEND` を掃引して生成層の総エネルギーが ±1 dB 以内で平坦
- **依存**: REQ-AIR-003, REQ-AIR-004

## REQ-AIR-006: FOCUS（層の居場所）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 生成した層がどこに座るかを 1 本で動かす。**名前と意味を
  Velour / Sparkleur と揃える** — 「この製品が触る帯域をまとめて上下に
  動かす」（`REQ-VEL-002` / `REQ-SPK-002`）。

| 系統 | `FOCUS` が動かすもの |
|---|---|
| 倍音層 | 前段と生成後の HPF のコーナー |
| ノイズ層 | ノイズの傾き |

- **固定にしない。** 構想の用途表がそのまま反証になっている — スネアの
  `DUST` は 2〜8 kHz、パッドの `BREATH` は 8〜16 kHz、ベースの `FIZZ` は
  1〜5 kHz。固定帯域はどれも満たさない。
- **系統ごとに持たない。** 「層は 1 個の対象」というモデル（`REQ-AIR-002`）
  が崩れる。系統ごとの微差は Advanced の偏差（`REQ-AIR-010`）。
- **可動域は Sparkleur と同じ ±1.5 オクターブを起点にする。** 素材が声から
  ベースまで広いのも同じ理由。
- **保護の検出帯も一緒に動く**（`REQ-AIR-009`）。
- **受入条件**:
  - [ ] `FOCUS` で 2 系統の帯域が**まとめて**動く（比も保たれる）
  - [ ] 振り切っても最上端がナイキストを超えない
  - [ ] 高いサンプルレートで係数が発散しない（192 kHz まで）
- **依存**: REQ-AIR-003, REQ-AIR-004

## REQ-AIR-007: Follow Engine

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 生成した層を元音の動きに追従させる。**これが Air の正体**
  （`REQ-AIR-002`）。v1 は 3 系統。

| 検出 | 何を見るか | 使う既存ブロック |
|---|---|---|
| `ENVELOPE` | 入力の音量 | `nxe_audio::envelope` |
| `BRIGHTNESS` | 高域が下の帯域に対してどれだけ有るか | `nxe_audio::guard` の相対検出器 |
| `TRANSIENT` | 速い/遅いフォロワの比 | `sparkle.rs` と同じ機構 |

- **新規開発はゼロ。** 3 つとも既にある部品の値違い。
- **合成は「1 と検出値の間を混ぜる」形。** Sparkleur の `SNAP` と同じ
  （`REQ-SPK-007`）:

```text
係数ᵢ = (1 − 深さᵢ) + 深さᵢ × 検出値ᵢ
層のゲイン = 量 × 係数_env × 係数_bright × 係数_trans
```

  深さ 0 で係数 1 なので、**その検出は存在しないのと同じになる**。3 本の
  ゲートを素朴に掛け算すると「大きくて明るくてアタックのとき」しか鳴らなく
  なるが、この形なら深さがそれを調停する。
- **`BRIGHTNESS` は相対で見る。** 絶対の高域量で判定すると入力ゲインで
  挙動が変わる。De-Harsh が入力ゲイン ±12 dB で 0.2 dB 以内に収まっている
  のと同じ理由（`REQ-SPK-008`）。
- **ノイズ層の `ENVELOPE` には下限がある**（`REQ-AIR-004`）。
- **どれが閉じているかを画面に出す**（`REQ-AIR-018`）。3 本が掛け算なので、
  1 つでも閉じていれば層は出ない。見せないと `REQ-SPK-008` が警告している
  状態 —「上げても何も起きない理由がユーザーから見えない」— になる。
- **受入条件**:
  - [ ] 深さが全部 0 のとき、係数が入力によらず厳密に 1
  - [ ] `ENVELOPE` の深さ 1 で、無音の入力に対して層が無音に収束する
  - [ ] `BRIGHTNESS` の深さ 1 で、暗い素材に対して層が閉じる
  - [ ] `BRIGHTNESS` の動作量が入力ゲイン ±12 dB で 0.2 dB 以内
  - [ ] `TRANSIENT` の深さ 1 で、持続音に対して閉じアタックで開く
  - [ ] 3 つの係数が個別に UI へ渡る
- **依存**: REQ-AIR-001

## REQ-AIR-008: WIDTH と位相を回さない約束

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 生成した層を左右に広げる。**位相を回す処理を 1 つも置かない。**

```text
WIDTH 0    L と R が同じノイズ列        → センター、モノ和で 0 dB
WIDTH 1    L と R が独立なノイズ列      → 最大幅、モノ和で −3 dB
中間       共有成分と独立成分の混合      → その間
```

- **これが Air のゲート。** 崩れたら `WIDTH` の設計ごと書き直しになり、
  その上に載っている「層を独立した対象として配置する」という製品の主張が
  成立しない。Velour の `VEL-1`、Sparkleur の `SPK-2` と同じ位置づけで、
  **耳ではなく単体テストで通る**。
- **倍音層は広げない。** 元音由来なので L/R が相関していて、広げるには
  オールパス脱相関が要り、モノ和で櫛形が出る。**`WIDTH` はノイズ層にだけ
  効き、倍音層はセンター固定。** これは境界の判断とも噛み合う — 倍音系は
  Sparkleur の担当で、Air の正体はノイズ層の側にある。
- **Sparkleur が v2 に落としたもの**（`REQ-SPK-019`「モノ互換の約束を壊す
  唯一の機能。テストの道具立てが全部新規」）を、Air は v1 で持つ。ただし
  **位相を回さないことで道具立てが要らなくなっている** — 測るのは相関と
  モノ和のレベルだけで、`nxe_dsp::Correlation` が既にある。
- **構想の Motion は入らない**（`REQ-AIR-020`）。Random pan / Micro delay /
  All-pass decorrelation / Stereo flutter は全部この約束を破る。
- **受入条件**:
  - [ ] `WIDTH` 全域で、モノ和のスペクトルに**櫛形の谷が出ない**
        （生成層だけを取り出して測る。平坦性 ±1 dB 以内）
  - [ ] `WIDTH` = 0 で L と R の相関が 1.0
  - [ ] `WIDTH` = 1 で相関が 0 付近、モノ和のレベルが片チャネルに対し
        **−3 dB ±0.5 dB**
  - [ ] `WIDTH` を掃引して相関が単調に減る
  - [ ] 倍音層は `WIDTH` によらず L == R
- **依存**: REQ-AIR-004

## REQ-AIR-009: 保護（Excess Guard）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 足した層が音楽に対して過剰になったとき、**層のゲインを引く**。
  `nxe_audio::guard` の値違いとして実装し、専用の処理を足さない。

- **引ける対象は自分の層だけ。** Sparkleur は 5 帯域のどれかを引けたが、
  Air には引ける帯域が無い。**足すのをやめる以外の手が無いのは欠陥ではなく、
  加算型の正しい帰結**（`REQ-AIR-001`）。
- **検出帯は `FOCUS` に追従する。** 固定にすると、`FOCUS` を上げたとき層が
  検出帯の外へ出て保護が二度と働かない。参照帯も一緒に下へずらす。
- **参照帯は検出帯を含んではいけない。** Sparkleur は出荷時のしきい値で
  ここが破れていて、**普通の素材から常時 1.3 dB 引いていた**（`SPK-18`）。
  同じ間違いを繰り返さないために、受入条件に「普通の素材でちょうど 0 dB」を
  入れる。
- **しきい値は固定、常時オン、マクロに結び付けない。** 「足したものが音楽に
  対して過剰か」は好みではなく判定なので、`SURFACE` や `CHARACTER` で
  強さが変わるべきではない。Sparkleur が `CHARACTER` に付けたのは、あちらの
  製品の約束が「明るくなるのに痛くならない」という**度合いのある約束**
  だったため。
- **Advanced には双極の偏差を出す。** 0 で既定、± で強め/弱め。絶対量に
  すると 2 つのパラメータが 1 つの値を書くことになり、規約違反。
- **引き量を必ず画面に出す**（`REQ-AIR-018`）。強く効くと層が消えるので、
  見せないと「壊れている」と読まれる。
- **受入条件**:
  - [ ] **スペクトル的に普通の素材でちょうど 0 dB**（ピンクノイズと
        定常倍音列。`SPK-18` の再発防止）
  - [ ] 入力ゲインを ±12 dB 変えても動作量が 0.2 dB 以内
  - [ ] 偏差を最小にすると保護がちょうど無効
  - [ ] `FOCUS` を動かすと検出帯が追従する
  - [ ] 保護は生成層のゲインだけを触り、原音に一切影響しない
- **依存**: REQ-AIR-001, REQ-AIR-006

## REQ-AIR-010: 二層パラメータモデル

- **優先度**: Must
- **ステータス**: Draft
- **説明**: メインの 7 本と、Advanced の偏差。Velour / Sparkleur と同じ形
  （`REQ-VEL-010` / `REQ-SPK-009`）。

| メイン | 役 |
|---|---|
| `SURFACE` | どれだけ表面を作るか |
| `BLEND` | 倍音 ↔ ノイズ |
| `CHARACTER` | 質（`BLEND` の位置で意味が移る） |
| `FOCUS` | どこに座るか |
| `WIDTH` | どこまで広がるか |
| `FOLLOW` | 何にどれだけ反応するか |
| `MIX` | Dry / Wet |

- **`AIR` という名前のノブを置かない。** Velour と Sparkleur が両方
  `AIR` を持っているので、製品名が Air のうえにノブまで `AIR` だと
  ラインの中で 3 重になる。メインマクロは製品の主張をそのまま名前にする —
  構想の言葉で「元音の**表面**そのものを作る」。
- **`FOLLOW` は 3 本の深さを一括で振るマクロ。** 個別の深さは Advanced に
  双極の偏差として出す。
- **Advanced に出すもの**: Follow 3 本の偏差、系統ごとの帯域の偏差、
  倍音層の `k` と `β`、ノイズ層の下限、保護の偏差、時定数。
- **マクロと偏差が同じ値を書かない。** 偏差は必ず相対で、絶対量にしない。
- **受入条件**:
  - [ ] メインだけで一通りの音が作れる（Advanced を開かずに成立する）
  - [ ] 偏差 0 のときマクロの表どおりの値になる
  - [ ] どのメインを動かしても偏差の値が書き換わらない
- **依存**: REQ-AIR-005, REQ-AIR-006, REQ-AIR-007, REQ-AIR-009

## REQ-AIR-011: ステレオの扱いとバス構成

- **優先度**: Must
- **ステータス**: Draft
- **説明**: **原音の像は変えない。** 変わるのは生成層の広がりだけ

  - [ ] `MIX` = 0 で L/R それぞれが入力とビット一致（`REQ-AIR-001`）
  - [ ] 2→2 と 1→2 の両方のレイアウトで動く
  - [ ] 片チャネルに寄った素材で**原音の**定位が動かない
  - [ ] `WIDTH` = 0 のとき L == R（生成層を含めて）
- **依存**: REQ-AIR-008

## REQ-AIR-012: ミックス・出力・レイテンシ

- **依存**: REQ-AIR-001

## REQ-AIR-016: リアルタイム安全性と CPU 予算

- **優先度**: Must
- **ステータス**: Draft
- **説明**: `process()` の中で確保・ロック・IO・panic をしない。ホストから
  来る値はクランプする。
- **予算**: 512 サンプル / 48 kHz のブロック周期 10.67 ms の 5% = **533 µs**。
  目標 250 µs。参考値は Doubler 85 µs、Velour 128 µs、Sparkleur 129 µs。
- **見積り**: 倍音層 1 本を 4x（Velour の 1 帯域ぶん）、ノイズ層 2 本を
  等倍、検出 3 本、保護 1 本、`Spectrum` 2 本（原音と生成層）。
  **クロスオーバーの木が無いぶん Sparkleur より軽い**見込みで、100 µs 前後。
  `Spectrum` を 2 本持つのが一番効く（Sparkleur では 32 バンドで 15.2 µs）。
- **受入条件**:
  - [ ] criterion で 4x / 512 サンプル / 48 kHz が 533 µs 以内
  - [ ] 全パラメータを範囲外の極端値にしても非有限値を出さず panic しない
  - [ ] 非有限のサンプル 1 個で検出器がラッチしない（Sparkleur では
        **実際にラッチしていた**ので入口で消毒する）
  - [ ] 音声スレッドの経路に確保が無い（数えるアロケータ）
- **依存**: REQ-AIR-003, REQ-AIR-004

## REQ-AIR-017: サンプルレート非依存とノイズの決定性

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 同じ設定がどのサンプルレートでも同じ音になる。**ノイズが
  この要件を特別に難しくする。**

毎サンプル乱数を出すと総パワーはレートによらず一定だが、それが `fs/2` の
帯域に広がるので**単位 Hz あたりの密度がレートに反比例する**:

```text
48 kHz   ノイズ全体が 0〜24 kHz に      可聴帯域の密度 = P
96 kHz   同じパワーが 0〜48 kHz に      可聴帯域の密度 = P/2  → −3 dB
```

- **ノイズのスペクトルをナイキストではなく Hz で定義する。** 振幅を
  `sqrt(fs / 48000)` で補正する。**要件に書かないと誰も気付かない種類の
  バグ** — 96 kHz のセッションだけ Air が 3 dB 小さいが、ノイズなので
  「気のせいかも」で片付いてしまう。
- **時定数はすべて秒で持つ。** Follow 3 本と保護。
- **決定性は約束しない。** ノイズ列は構築時にシードして自走し、ホストの
  トランスポートを読まない。同じプロジェクトを 2 回書き出すと波形は一致
  しないが、**守る約束は `MIX` = 0 のビット一致だけで足り、それは加算型
  なので影響を受けない**（`REQ-AIR-001`）。テストは `air-core` に明示
  シードを渡して決定的に書く — **ラッパの挙動とテストの決定性は別問題**。
  再現するバウンスのためにトランスポートを読むのは、このリポジトリが
  避けている種類のホスト連携を 1 つ買うことになる。
- **受入条件**:
  - [ ] 44.1 / 48 / 96 / 192 kHz で、**可聴帯域のノイズ層のレベルが
        ±0.5 dB 以内**
  - [ ] 同じレートで、ブロックサイズ 1 / 64 / 512 / 4096 の出力が一致する
  - [ ] 明示シードで `air-core` の出力が完全に再現する
  - [ ] レート変更で係数が発散しない
- **依存**: REQ-AIR-004

## REQ-AIR-018: 通っている音の表示

- **優先度**: Should
- **ステータス**: Draft
- **説明**: UI に渡す解析値。受け渡しは `nxe_dsp::Handoff`。
  - **原音のスペクトラム**（`nxe_dsp::Spectrum`）
  - **生成層のスペクトラム**（同上。**これが図の主役**）
  - **Follow の 3 係数**（`ENVELOPE` / `BRIGHTNESS` / `TRANSIENT` 個別に）

  閉じている」のか「量が足りない」のか「保護が引いている」のかが区別
  できない。**Sparkleur は追従が 1 本だけでもメーターを付けた**
  （`REQ-SPK-018` の「Sparkle の包絡」）。
- **相関を出すのは約束を証明するため。** `REQ-AIR-008` が「位相を回さない
  のでモノで櫛形が出ない」を約束しているので、**その約束を画面で確かめ
  られる**状態にする。Doubler が既に `Correlation` を使っている。
- **受入条件**:
  - [ ] 音が止まると表示が減衰して消える（3 秒以内に完全に 0）
  - [ ] 生成層のスペクトラムが `SURFACE` = 0 でちょうど 0 になる
  - [ ] 解析を止めても音が変わらない（表示専用）
  - [ ] `WIDTH` を動かすと相関の表示が追従する
- **依存**: REQ-AIR-007, REQ-AIR-008, REQ-AIR-009

## REQ-AIR-021: Fold / Bit Crush

- **優先度**: Won't (v1)
- **ステータス**: Decided
- **説明**: 構想の `FIZZ` が挙げている波形の折り返しと量子化。
- **v1 に入れない理由**:
  - **共有の `shaper` では作れない。** `k` / `β` / `h` の hard 端は

  - **Bit Crush は折り返し規律と正面から衝突する。** `REQ-VEL-005` /
    `REQ-SPK-007` は「4x で最悪ケースの折り返しが −60 dB 以下」を要件に
    していて、Velour の `DRIVE_MAX` はその測定で 20 → 6 → 8 と 2 回
    動いている。**量子化ノイズは狙って出す成分**なので、この約束の外に
    置く要件を別に書かないと入らない
  - **倍音層は Sparkleur の担当**（`REQ-AIR-002`）。線の反対側を厚くする
    投資になる
- v2 で入れるときは、**折り返しの約束をどう書き換えるか**から始める。

---

## REQ-AIR-022: プリセットを持たない

- **優先度**: Should
- **ステータス**: Draft
- **説明**: プリセットブラウザを持たない。**`SURFACE` / `BLEND` /
  `CHARACTER` の 3 本がその役**。
- Doubler / Velour / Sparkleur と同じ判断（`REQ-VEL-020` / `REQ-SPK-021`）。
  プリセットは「マクロが足りていない」ことの告白。
- **帰結として既定値が製品の顔になる。** 既定値を耳で詰めることが最後の
  実装単位になる。Sparkleur では**測定に置き換えられる部分が半分あった**
  （`SPK-18`）ので、Air でも先に測れるものを測る。
- **既定値で「元音に無かった表面が足されている」が成立していること**が
  最終の受入条件。挿して 1 本回せば分かる、を狙う。
