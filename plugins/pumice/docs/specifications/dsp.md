## 決めたこと（計画書が `dsp.md` に投げた 6 つ）

| 問い | 答え |
|---|---|
| 対数軸の平滑を FFT のビン上でどう作るか | **パワースペクトルの前置和（prefix sum）を 1 本持ち、ビンごとに違う幅の区間平均を O(1) で引く。** 幅がいくつでも総コストは O(N)。対数格子への再標本化は要らない |
| WHERE と WHEN をどう合成するか | **dB の `min`。** 「恒常的に出っ張っている」かつ「今出っ張っている」の論理積がそのまま `min` になる |
| WHERE は何の長期平均か | **超過量 `e[k]` の長期平均**であって、レベルの長期平均ではない。超過量は既に入力ゲインに依存しないので、長期側で正規化を作り直さずに済む |
| ノードの形 | **対数周波数上のガウシアン。`width` は半値全幅（オクターブ）**。重みは `1 + Σ depth·bump` で、有効なノードが 0 本なら厳密に 1 |
| musical noise をどう止めるか | **最終ゲイン曲線を 1/12 オクターブで平滑する。固定値で、`SHARPNESS` からは触れない**（`REQ-PUM-005`） |
| 窓と正規化 | **解析・合成とも Hann、hop = N/4。** Hann² の 4 重なりの和は 1.5 なので、**2/3 を掛ける** |

## 信号の流れ

```text
                    ┌─ DelayLine(3N/4) ──────────── dry ─────────┐
                    │                                            │
Input ─ (L+R)/2 ────┤                                            ├─ MIX ─ OUTPUT ─ Out
        pow │       │                                            │
            │       └─ 窓 ─ rFFT ─┬─ |X|² ─ 参照 ─ e[k]          │
            │                     │            │                 │
            │                     │            ├─ WHEN（速い）─┐ │
            │                     │            └─ WHERE（遅い）┤ │
            │                     │                     min ───┤ │
            │                     │                            │ │
            │                     │              ノード重み ───┤ │
            │                     │                      DEPTH ┤ │
            │                     │                            ▼ │
            │                     └────────── × g[k] ─ irFFT ─ 窓 ┘
            │                                          OLA   wet
            └── 検波は L/R 平均パワー。g[k] は両チャネルに同じものを掛ける
```

**dry は STFT を通らない**（`REQ-PUM-001`）。通すと `MIX` = 0 が
再構成誤差を含むことになり、`MIX` の意味が「原音との比」でなくなる。

## STFT

### N の決め方

**固定サンプル数ではなく固定ビン幅**（`REQ-PUM-017`）。`N` は
`sample_rate / 目標ビン幅` に**最も近い 2 の冪**。

| `QUALITY` | 目標ビン幅 | 44.1 kHz | 48 kHz | 96 kHz | 192 kHz |
|---|---|---|---|---|---|
| `LOW` | 46.9 Hz | 1024 | 1024 | 2048 | 4096 |
| **`NORMAL`** | **23.4 Hz** | **2048** | **2048** | **4096** | **8192** |
| `HIGH` | 11.7 Hz | 4096 | 4096 | 8192 | 16384 |

実装は `N = 2^round(log2(rate / target))`。**この表をテストで固定する** —
式を書き間違えても表が落ちる。

**44.1 kHz だけ 3 段とも目標から 8.1% 下に出る**（`NORMAL` で 21.5 Hz）。
`REQ-PUM-008` の受入条件（±10%）には入るが、端が近い。

- **hop = N/4**（75% オーバーラップ）。時間変化するゲインを掛けるので、
  50% では継ぎ目が出る。
- **申告レイテンシ = N − hop = 3N/4。** 48 kHz `NORMAL` で 1536 サンプル =
  **32.0 ms**。
- **確保は最大 N = 16384 で 1 回。** `QUALITY` の変更は「使う長さ」を
  変えるだけで、`process()` に確保が来ない（`REQ-PUM-016`）。

### 窓と正規化

解析・合成とも Hann（`nih_plug::util::window` は使わない。
`pumice-core` は `nih_plug` を知らない — `REQ-PUM-015`）。

```text
w[n] = 0.5 − 0.5·cos(2πn/N)
```

hop = N/4 のとき `Σ w²` は 1.5 に収束するので、**合成後に 2/3 を掛ける**。
これで全ビンのゲインが 1 のとき再構成が unity になる（`REQ-PUM-007` の
「−120 dB 以下」はこの帰結）。

## 参照 — 何と比べて「突出」と呼ぶか

ビン `k` の参照 `R[k]` は、**そのビンの周りの対数幅 `w` オクターブの区間の
平均パワー**。

```text
lo(k) = round(k · 2^(−w/2))
hi(k) = round(k · 2^(+w/2))
R[k]  = (S[hi] − S[lo]) / (hi − lo)      S は |X|² の前置和
```

- **前置和を 1 本持つのが要点。** 幅がビンごとに違っても、区間和は 2 回の
  参照で済む。`w` を広げてもコストが増えない。
- **`k` 自身を参照から抜かない。** 抜くと幅の狭い端で分母が 0 になる。
  代わりに超過量のしきい値でそのぶんを吸う（下）。
- **`lo == hi` になる低いビンでは参照を作らない。** `k < 4` は
  動作範囲の下限より下なので、重みが 0 になる（下）。

`w` は `SHARPNESS` が動かす。

| `SHARPNESS` | `w` |
|---|---|
| 0.0 | 1.00 オクターブ |
| 1.0 | 0.17 オクターブ（1/6） |

補間は `w = 1.0 · (0.17/1.0)^SHARPNESS`（**対数で線形**）。

超過量は dB で持つ。

```text
e[k] = 10·log10( |X[k]|² / R[k] )
```

**入力ゲインに依存しない**（分子と分母が一緒に動く）。
`nxe_audio::guard` が相対検出を選んだのと同じ理由。

## WHERE と WHEN

どちらも `e[k]` の 1 次フォロワ。**係数は `nxe_audio::envelope::coefficient`
に秒を渡して作る。ただし刻みはサンプルではなく hop** — hop 1 回が
`hop / sample_rate` 秒。

```text
WHEN [k] ← 非対称。上りは attack、下りは release（SPEED）
WHERE[k] ← 対称。時定数 τ_w（3〜10 秒、耳）
```

**WHERE は周波数方向にもう一度平滑する。** 同じ音程が続くパートで倍音が
長期平均に残るため。幅は **1/6 オクターブ固定**、前置和は参照と同じ機構。

```text
ADAPTIVE   drive[k] = min( WHEN[k], WHERE[k] )
STATIC     drive[k] = WHEN[k]
```

**`min` が製品そのもの。** 倍音は「今出っ張っているが恒常的ではない」ので
`WHERE` が低く、`min` が低い。共鳴は「恒常的だが今は鳴っていない」ときに
`WHEN` が低く、`min` が低い。**両方が立ったときだけ削る。**

## ゲイン計算

```text
excess[k] = max(0, drive[k] − THRESHOLD)
raw[k]    = min(SLOPE · excess[k], CEILING)          dB
g_db[k]   = −raw[k] · weight[k] · DEPTH
```

- **`THRESHOLD` は超過量のしきい値であって、レベルのしきい値ではない。**
  ピンクノイズの `e[k]` がちょうど 0 dB 付近に来るので、**`THRESHOLD` が 0 なら
  普通の素材から引かない**（`REQ-PUM-003` の受入条件、`SPK-18` の再発防止）。
- **`CEILING` が機構としての上限**（`REQ-PUM-023`）。Advanced の最大削減量は
  これを超えられない。
- **`DEPTH` は最後に掛かる。** だから `DEPTH` = 0 で `g_db` が厳密に 0。

### ノード重み

対数周波数上のガウシアン。`width` は**半値全幅**（オクターブ）。

```text
bump_i(f)  = exp( −ln2 · (2·log2(f/freq_i) / width_i)² )
weight(f)  = clamp( 1 + Σ depth_i · bump_i(f), 0, 2 )
```

有効なノードが 0 本なら `Σ` が空で **`weight` は厳密に 1**（`REQ-PUM-004`）。
`depth_i` は `−1..=+1` で、`+1` はそこの削減を倍に、`−1` は 0 にする。

**動作範囲**は Advanced の 2 値で、範囲外は `weight = 0`。端は
**1/2 オクターブのレイズドコサイン**で落とす（段にすると帯域の縁で
削減が切り替わって聞こえる）。

| | 既定 |
|---|---|
| 下端 | 100 Hz |
| 上端 | 18 kHz |

`weight` はパラメータが動いたときだけ組み直す。**ノードは 6 本、ビンは最大
8192 本**なので、毎 hop 組み直すと無駄が大きい。

### 最後の平滑 — musical noise の床

`g_db[k]` を **1/12 オクターブ**で平滑してから線形ゲインに直す。前置和は
参照と同じ機構を使い回す。

- **固定値で、`SHARPNESS` からは触れない**（`REQ-PUM-005`）。ビンごとに独立した
  ゲインは「EQ っぽい音」ではなく「電話っぽい音」を作る。**ユーザーが 0 に
  できてはいけない。**
- 平滑は dB の上で行う。線形で平滑すると深い削減の底が浅くなる。

## 適用と再構成

```text
X'[k] = X[k] · 10^(g_db_smoothed[k] / 20)
```

**位相は触らない。** 大きさだけを動かすので、位相の再構成問題が発生しない。

L と R には**同じ `g_db`** を掛ける（`REQ-PUM-011`）。検波は
`(|X_L|² + |X_R|²) / 2` — 振幅ではなくエネルギーで合成するのは
`nxe_audio::guard` と同じ理由。

## dry と MIX と DELTA

```text
dry[n]   = DelayLine.read(3N/4)
delta[n] = wet[n] − dry[n]
out[n]   = (DELTA ? delta[n] : lerp(dry[n], wet[n], MIX)) · OUTPUT
```

- **`DELTA` は `MIX` の前**（`REQ-PUM-019`）。削っている物そのものを聴きたい。
- ディレイラインは `nxe_audio::DelayLine`。長さは最大 N の 3/4 = 12288。

## CPU

**予算 533 µs、目標 250 µs**（512 サンプル / 48 kHz、`REQ-PUM-016`）。

| | |
|---|---|
| rFFT 順逆 × 2ch | N=2048 を 512 サンプルあたり 1 hop |
| 前置和 × 3（参照 / WHERE / ゲイン平滑） | O(N) |
| フォロワ × 2 × N/2 ビン | **hop ごと。サンプルごとではない** |
| ノード重みの組み直し | パラメータが動いたときだけ |

**見積り 50〜80 µs。** フォロワが hop レートで回るのが効いていて、
サンプルレートで回るバンドパス列（Velour の `Spectrum` 48 バンド × 2 本 =
45 µs）より安い。**`Spectrum` を別に回さない**ので、表示のぶんは 0
（`REQ-PUM-018`）。

## 耳で詰める定数

**`PUM-11` で全部詰める。** ここに書いてある値は設計時のもので、
測定でも耳でもない。

| 定数 | 設計時の値 | 何で決まるか |
|---|---|---|
| `THRESHOLD` | **0 dB** | **ピンクノイズで削減量がちょうど 0**（`REQ-PUM-003`）。`SPK-18` は −8 dB で出荷して普通の素材から 1.3 dB 引いた |
| `SLOPE` | 0.7 dB/dB | 超過 1 dB あたり何 dB 引くか。1.0 は「参照まで完全に均す」 |
| `CEILING` | **18 dB** | ここを超えると「守られた」ではなく「無くなった」（`REQ-PUM-023`）。7 kHz で 30 dB は舌足らずになる |
| `τ_w`（WHERE） | **6 秒** | **フレーズをまたぐ長さ**。短いと倍音が WHERE に残り、長いと曲の途中で変わった共鳴に追従しない |
| WHERE の周波数平滑 | 1/6 オクターブ | 一定音程のパートで倍音を潰すための保険。広げると細い共鳴も鈍る |
| `SPEED` の attack | 5 〜 40 ms | 速い端は hop（10.7 ms）で床に当たる |
| `SPEED` の release | 40 〜 400 ms | 短いとポンピング、長いと次のフレーズまで引きずる |
| `SHARPNESS` の幅 | 1.00 〜 0.17 oct | 広い端で「なだらかな盛り上がり」が拾えるか、狭い端で共鳴 1 本に効くか |
| ゲイン平滑 | 1/12 オクターブ | **musical noise が出ない最小**。広げると削減が鈍る |
| 動作範囲 | 100 Hz 〜 18 kHz | 下端を上げすぎると箱鳴りが残り、下げすぎると基音を削る |
| `DEPTH` の既定 | — | **ノード 0 本で挿しただけで成立する値**（`REQ-PUM-024`） |

## まだ答えの無い問い

- **`DEPTH` という名前が使えるか。** Diorama の `DEPTH` は距離で、
  意味が違う（`REQ-PUM-010`）。ラインの規則では新しい側が譲る。
  **`PUM-11` までに決める。**
- **`SLOPE` をユーザーに出すか。** soothe は出していない。Advanced に置くか、
  `DEPTH` に畳むかは `PUM-3` で音を聴いてから。
- **44.1 kHz の 8.1% のずれを許すか。** 受入条件には入るが端が近い。
  目標ビン幅を 2 の冪に寄せて選び直せばゼロにできる（44.1 kHz を基準にすると
  48 kHz 側がずれる）。**どちらの端をずらすかは `PUM-2` で決める。**
