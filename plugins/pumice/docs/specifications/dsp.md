## 決めたこと（計画書が `dsp.md` に投げた 6 つ）

| 問い | 答え |
|---|---|
| 対数軸の平滑を FFT のビン上でどう作るか | **パワースペクトルの前置和（prefix sum）を 1 本持ち、ビンごとに違う幅の区間平均を O(1) で引く。** 幅がいくつでも総コストは O(N)。対数格子への再標本化は要らない |
| WHERE と WHEN をどう合成するか | **dB の `min`。** 「恒常的に出っ張っている」かつ「今出っ張っている」の論理積がそのまま `min` になる |
| WHERE は何の長期平均か | **超過量 `e[k]` の長期平均**であって、レベルの長期平均ではない。超過量は既に入力ゲインに依存しないので、長期側で正規化を作り直さずに済む |
| ノードの形 | **対数周波数上のガウシアン。`width` は半値全幅（オクターブ）**。重みは `1 + Σ depth·bump` で、有効なノードが 0 本なら厳密に 1 |
| musical noise をどう止めるか | **最終ゲイン曲線を 1/12 オクターブで平滑する。固定値で、`SHARPNESS` からは触れない**（`REQ-PUM-005`） |
| 窓と正規化 | **解析・合成とも Hann、hop = N/4。** Hann² の 4 重なりの和は 1.5 なので、**2/3 を掛ける** |

## 信号の流れ

```text
                    ┌─ DelayLine(N) ─────────────── dry ─────────┐
                    │                                            │
Input ─ (L+R)/2 ────┤                                            ├─ MIX ─ OUTPUT ─ Out
        pow │       │                                            │
            │       └─ 窓 ─ rFFT ─┬─ |X|² ─ 参照 ─ e[k]          │
            │                     │            │                 │
            │                     │            ├─ WHEN（速い）─┐ │
            │                     │            └─ WHERE（遅い）┤ │
            │                     │                     min ───┤ │
            │                     │                            │ │
            │                     │              ノード重み ───┤ │
            │                     │                      DEPTH ┤ │
            │                     │                            ▼ │
            │                     └────────── × g[k] ─ irFFT ─ 窓 ┘
            │                                          OLA   wet
            └── 検波は L/R 平均パワー。g[k] は両チャネルに同じものを掛ける
```

**dry は STFT を通らない**（`REQ-PUM-001`）。通すと `MIX` = 0 が
再構成誤差を含むことになり、`MIX` の意味が「原音との比」でなくなる。

## STFT

### N の決め方

**固定サンプル数ではなく固定ビン幅**（`REQ-PUM-017`）。`N` は
`sample_rate / 目標ビン幅` に**最も近い 2 の冪**。

| `QUALITY` | 目標ビン幅 | 44.1 kHz | 48 kHz | 96 kHz | 192 kHz |
|---|---|---|---|---|---|
| `LOW` | 46.9 Hz | 1024 | 1024 | 2048 | 4096 |
| **`NORMAL`** | **23.4 Hz** | **2048** | **2048** | **4096** | **8192** |
| `HIGH` | 11.7 Hz | 4096 | 4096 | 8192 | 16384 |

実装は `N = 2^round(log2(rate / target))`。**この表をテストで固定する** —
式を書き間違えても表が落ちる。

**44.1 kHz だけ 3 段とも目標から 8.1% 下に出る**（`NORMAL` で 21.5 Hz）。
`REQ-PUM-008` の受入条件（±10%）には入るが、端が近い。

- **hop = N/4**（75% オーバーラップ）。時間変化するゲインを掛けるので、
  50% では継ぎ目が出る。
- **申告レイテンシ = N。** 48 kHz `NORMAL` で 2048 サンプル = **42.7 ms**。

  **当初 `N − hop` と書いていた。それは誤り**（2026-09-01 に訂正）。
  出力サンプル `m` が確定するのは、`m` を覆う**最後のフレーム**が足された
  ときで、そのフレームは `m + N − 1` に終わる。**オーバーラップを増やしても
  最後のフレームが早く終わるわけではない** — 同じサンプルへの寄与が増える
  だけ。`StftHelper` がリング長を返しているのは同じ理由で、あちらが正しい。

| `QUALITY` | 48 kHz の N | レイテンシ |
|---|---|---|
| `LOW` | 1024 | 21.3 ms |
| **`NORMAL`** | **2048** | **42.7 ms** |
| `HIGH` | 4096 | 85.3 ms |
- **確保は最大 N = 16384 で 1 回。** `QUALITY` の変更は「使う長さ」を
  変えるだけで、`process()` に確保が来ない（`REQ-PUM-016`）。

### 窓と正規化

解析・合成とも Hann（`nih_plug::util::window` は使わない。
`pumice-core` は `nih_plug` を知らない — `REQ-PUM-015`）。

```text
w[n] = 0.5 − 0.5·cos(2πn/N)
```

hop = N/4 のとき `Σ w²` は 1.5 に収束するので、**合成後に 2/3 を掛ける**。
これで全ビンのゲインが 1 のとき再構成が unity になる（`REQ-PUM-007` の
「−120 dB 以下」はこの帰結）。

## 参照 — 何と比べて「突出」と呼ぶか

ビン `k` の参照 `R[k]` は、**そのビンの周りを穴として抜いたリングの平均
パワー**。

```text
穴   ±s/2 オクターブ          s = SHARPNESS が決める「1 つの特徴の幅」
リング ±(s/2 + m) まで         m = 1.0 オクターブ固定
R[k] = リング内の平均（前置和 4 回参照）
```

**穴が要点**（`PUM-4`、2026-09-01）。当初は穴の無い区間平均だった。
**参照が自分の判定対象を含んでいると、測ろうとしているもので参照が
膨らむ** — `SPK-18` と同じ間違いで、あちらは「帯域を 10 dB 上げたら参照も
6 dB 上がり、10 dB のキツさが 2 dB に読めた」。

穴が無いときの実測：**18 dB の共鳴が 8.2 dB の超過にしか読めず、しかも
`SHARPNESS` を狭くするほど悪化した**（窓が狭いほど共鳴自身に埋め尽くされる
ため）。検出を鋭くするはずのつまみが鈍くしていた。穴を入れて、
同じ共鳴への削減が **3.4 dB → 8.9 dB** になった。

**分子も平滑する。** 1 ビンのパワーは指数分布で、標準偏差が平均に等しい
（約 **5.6 dB**）。数百ビンのリング平均と比べると、その揺れが丸ごと超過に
見え、非対称フォロワが正の側を整流する。**`detail_octaves` = 1/12** で
√n だけ落とす — 共鳴と呼べるものより遥かに狭いので分解能は失わない。
**ノイズの p95 が 4.06 → 2.59 dB に下がり、同時に共鳴への削減が
11.5 → 13.1 dB に増えた**（下振れも減るため）。

- **前置和を 1 本持つのが要点。** 幅がビンごとに違っても、区間和は 2 回の
  参照で済む。`w` を広げてもコストが増えない。
- **`k` 自身を参照から抜かない。** 抜くと幅の狭い端で分母が 0 になる。
  代わりに超過量のしきい値でそのぶんを吸う（下）。
- **`lo == hi` になる低いビンでは参照を作らない。** `k < 4` は
  動作範囲の下限より下なので、重みが 0 になる（下）。

`w` は `SHARPNESS` が動かす。

| `SHARPNESS` | `w` |
|---|---|
| 0.0 | 1.00 オクターブ |
| 1.0 | 0.17 オクターブ（1/6） |

補間は `w = 1.0 · (0.17/1.0)^SHARPNESS`（**対数で線形**）。

超過量は dB で持つ。

```text
e[k] = 10·log10( |X[k]|² / R[k] )
```

**入力ゲインに依存しない**（分子と分母が一緒に動く）。
`nxe_audio::guard` が相対検出を選んだのと同じ理由。

## WHERE と WHEN

どちらも `e[k]` の 1 次フォロワ。**係数は `nxe_audio::envelope::coefficient`
に秒を渡して作る。ただし刻みはサンプルではなく hop** — hop 1 回が
`hop / sample_rate` 秒。

```text
WHEN [k] ← 非対称。上りは attack、下りは release（SPEED）
WHERE[k] ← 対称。時定数 τ_w。**鳴っている間だけ更新する**
```

**地図はゼロから始まる指数平均のバイアスを補正する**（`PUM-4b`）。
`n` 回更新した時点の状態は真の平均の `1 − (1−c)^n` 倍しかないので、
それで割って不偏にする。**補正が無いと最初の 10 秒は地図が役に立たない** —
実測で、定常共鳴への削減が**最初の 3 秒はちょうど 0、8 秒で半分**、
休符のある素材では 5 秒までゼロだった。挿してフレーズを再生しても
何も起きない状態で、それが「エフェクトがかかっている気がしない」の正体。

補正後は **1 秒で −17.4 dB**、以後横ばい。代償は「証拠が少ない間は
`STATIC` に寄る」ことで、`map_warmup_seconds`（1 秒）が地図の言うことを
どれだけ信じるかをランプする。**実害は歌の RMS で 0.34 dB。**

**地図は `reset()` を生き延びる**（`PUM-4b`）。ホストは停止・ループ・
再生位置の移動ごとに `reset()` を呼ぶ。変換のリングと短期フォロワは
**信号についての状態**なので消すが、地図は**素材についての知識**で、
消すと「フレーズを繰り返し試聴する」という実際の作業手順では永久に
形成されない。古い知識が残るリスクは無い — 6 秒の記憶なので、別の素材に
移れば自分で忘れる。

**地図は無音を学ばない**（`PUM-4`）。フレーム全体のパワーが「最近の最大」の
`map_gate_db`（−30 dB）より下なら、WHERE を**止める**（減衰させるのでは
なく保持する）。実測：同じ共鳴が duty 100% で 6.34 dB 削られるのに対し、
50% では **3.69 dB** しか削られていなかった。**歌はブレスと休符でできて
いるので、これは常時 3〜4 割の目減り**だった。ゲート後は 5.80 dB。

最大は「最近の最大」（`map_peak_seconds` = 2 秒で減衰する held peak）に対する
相対比なので、**入力ゲインで動かない**。

**WHERE は周波数方向に平滑しない。**

当初「同じ音程が続くパートで倍音が長期平均に残るため、1/6 オクターブで
平滑する」と書いていた。**`PUM-4` で測ったら、それが WHERE の仕事を
消していた** — 2.5 kHz で 1/6 オクターブは 14 ビン幅なので、20 dB 突出した
共鳴を dB の算術平均に通すと 1.4 dB になる。**`ADAPTIVE` が定常共鳴を
0.00 dB しか削らなかった**（`STATIC` は 2.19 dB）。

保険が守ろうとしていた相手——一定音程の持続——は、**`τ_w` と `STATIC` が
受け持つ**。長く同じ音程を保った声の倍音が WHERE に入るのは `ADAPTIVE` の
真の限界で、そのための逃げ場が `MODE` にある。

```text
ADAPTIVE   drive[k] = min( WHEN[k], WHERE[k] )
STATIC     drive[k] = WHEN[k]
```

**`min` が製品そのもの。** 倍音は「今出っ張っているが恒常的ではない」ので
`WHERE` が低く、`min` が低い。共鳴は「恒常的だが今は鳴っていない」ときに
`WHEN` が低く、`min` が低い。**両方が立ったときだけ削る。**

## ゲイン計算

```text
excess[k] = max(0, drive[k] − THRESHOLD)
raw[k]    = min(SLOPE · excess[k], CEILING)          dB
g_db[k]   = −raw[k] · weight[k] · DEPTH
```

- **`THRESHOLD` は超過量のしきい値であって、レベルのしきい値ではない。**
  ピンクノイズの `e[k]` がちょうど 0 dB 付近に来るので、**`THRESHOLD` が 0 なら
  普通の素材から引かない**（`REQ-PUM-003` の受入条件、`SPK-18` の再発防止）。
- **`CEILING` が機構としての上限**（`REQ-PUM-023`）。Advanced の最大削減量は
  これを超えられない。
- **`DEPTH` は最後に掛かる。** だから `DEPTH` = 0 で `g_db` が厳密に 0。

### ノード重み

対数周波数上のガウシアン。`width` は**半値全幅**（オクターブ）。

```text
bump_i(f)  = exp( −ln2 · (2·log2(f/freq_i) / width_i)² )
weight(f)  = clamp( 1 + Σ depth_i · bump_i(f), 0, 2 )
```

有効なノードが 0 本なら `Σ` が空で **`weight` は厳密に 1**（`REQ-PUM-004`）。
`depth_i` は `−1..=+1` で、`+1` はそこの削減を倍に、`−1` は 0 にする。

**動作範囲**は Advanced の 2 値で、範囲外は `weight = 0`。端は
**1/2 オクターブのレイズドコサイン**で落とす（段にすると帯域の縁で
削減が切り替わって聞こえる）。

| | 既定 |
|---|---|
| 下端 | 100 Hz |
| 上端 | 18 kHz |

`weight` はパラメータが動いたときだけ組み直す。**ノードは 6 本、ビンは最大
8192 本**なので、毎 hop 組み直すと無駄が大きい。

### 最後の平滑 — musical noise の床

`g_db[k]` を **1/12 オクターブ**で平滑してから線形ゲインに直す。前置和は
参照と同じ機構を使い回す。

- **固定値で、`SHARPNESS` からは触れない**（`REQ-PUM-005`）。ビンごとに独立した
  ゲインは「EQ っぽい音」ではなく「電話っぽい音」を作る。**ユーザーが 0 に
  できてはいけない。**
- 平滑は dB の上で行う。線形で平滑すると深い削減の底が浅くなる。

## 適用と再構成

```text
X'[k] = X[k] · 10^(g_db_smoothed[k] / 20)
```

**位相は触らない。** 大きさだけを動かすので、位相の再構成問題が発生しない。

L と R には**同じ `g_db`** を掛ける（`REQ-PUM-011`）。検波は
`(|X_L|² + |X_R|²) / 2` — 振幅ではなくエネルギーで合成するのは
`nxe_audio::guard` と同じ理由。

## dry と MIX と DELTA

```text
dry[n]   = DelayLine.read(N)
delta[n] = wet[n] − dry[n]
out[n]   = (DELTA ? delta[n] : lerp(dry[n], wet[n], MIX)) · OUTPUT
```

- **`DELTA` は `MIX` の前**（`REQ-PUM-019`）。削っている物そのものを聴きたい。
- ディレイラインは `nxe_audio::DelayLine`。長さは最大 N = 16384。

## CPU

**予算 533 µs、目標 250 µs**（512 サンプル / 48 kHz、`REQ-PUM-016`）。

| | |
|---|---|
| rFFT 順逆 × 2ch | N=2048 を 512 サンプルあたり 1 hop |
| 前置和 × 3（参照 / WHERE / ゲイン平滑） | O(N) |
| フォロワ × 2 × N/2 ビン | **hop ごと。サンプルごとではない** |
| ノード重みの組み直し | パラメータが動いたときだけ |

**実測 30.6 µs**（`PUM-8`、`HIGH` / ステレオ / 512 サンプル / 48 kHz）。
見積りは 50〜80 µs だったので、**見積りより安かった**。フォロワが hop レートで
回るのが効いていて、サンプルレートで回るバンドパス列（Velour の `Spectrum`
48 バンド × 2 本 = 45 µs）より安い。**`Spectrum` を別に回さない**ので、
表示のぶんは 0（`REQ-PUM-018`）。

| | /512 サンプル |
|---|---|
| `HIGH` 定常 | **30.6 µs** |
| `NORMAL` 定常 | 30.1 µs |
| `LOW` 定常 | 29.0 µs |
| `HIGH` + ノードを動かしながら | 75.6 µs |

**3 段のコストがほぼ同じ。** ブロックを倍にするとフレーム数が半分になるので、
`N log N / N` = `log N` 分しか増えない。**`QUALITY` は分解能とレイテンシの
取引で、CPU の取引ではない**（`REQ-PUM-008` がそう書いていたのが実測で
裏付いた）。

**ラインで 2 番目に安い** — Diorama 20.9、**Pumice 30.6**、Air 47.2、
Doubler 85、Velour 128、Sparkleur 129。音声パスに FFT を置いた 1 本が
2 番目に安いというのが、`architecture.md` の例外の根拠そのもの。

## 耳で詰める定数

**`PUM-11` で全部詰める。** ここに書いてある値は設計時のもので、
測定でも耳でもない。

| 定数 | 設計時の値 | 何で決まるか |
|---|---|---|
| `THRESHOLD` | **4.5 dB**（測った） | **0 dB は間違いだった。** 普通の素材は「近傍と同じパワー」を読まない — 1 ビンの揺れをフォロワが整流するので、白色ノイズで最悪 5.0 / 平均 1.0 dB を読む。歌の倍音は最悪 5.3 dB。4.5 が両方をちょうど 0 にして、18 dB の共鳴からはまだ 7.8 dB 取る |
| `SLOPE` | **2.0**（0.7 → 1.0 → 2.0） | `DEPTH` 全開での傾き。**つまみが行きすぎられるように 2.0**。1.0（参照まで均す）は最大値としては控えめで、**上端が上品なつまみは有用域の終わりを教えない**。2.0 なら半分で従来の音、上半分が引き返す領域。**普通の素材には影響しない** — 守っているのはしきい値で、傾きはその上しか触らない（傾き 1〜3 でノイズは 0.01 dB しか動かない）。3.0 は 3 つの試験共鳴のうち 2 つが `CEILING` に張り付き、つまみの上端が死ぬ |
| `detail_octaves` | 1/12 | 分子の平滑幅。**分解能ではなく分散の設定** |
| `map_gate_db` | −30 dB | 地図が学ぶ下限。最近の最大に対する相対比 |
| `map_warmup_seconds` | 1 秒 | 地図をどれだけ信じるかのランプ。**0 でもほぼ無害**（歌の RMS 0.45 dB）だが、4 秒にすると共鳴への効きが 4 秒待ちになる |
| `map_peak_seconds` | 2 秒 | 「最近の最大」の減衰。ブレスをまたぎ、フェードには追う |
| `CEILING` | **18 dB** | ここを超えると「守られた」ではなく「無くなった」（`REQ-PUM-023`）。7 kHz で 30 dB は舌足らずになる |
| `τ_w`（WHERE） | **6 秒** | **フレーズをまたぐ長さ**。短いと倍音が WHERE に残り、長いと曲の途中で変わった共鳴に追従しない |
| `SPEED` の attack | 5 〜 40 ms | 速い端は hop（10.7 ms）で床に当たる |
| `SPEED` の release | 40 〜 400 ms | 短いとポンピング、長いと次のフレーズまで引きずる |
| `SHARPNESS` の幅 | 1.00 〜 0.17 oct | 広い端で「なだらかな盛り上がり」が拾えるか、狭い端で共鳴 1 本に効くか |
| ゲイン平滑 | 1/12 オクターブ | **musical noise が出ない最小**。広げると削減が鈍る |
| 動作範囲 | 100 Hz 〜 18 kHz | 下端を上げすぎると箱鳴りが残り、下げすぎると基音を削る |
| `DEPTH` の既定 | — | **ノード 0 本で挿しただけで成立する値**（`REQ-PUM-024`） |

## まだ答えの無い問い

- **`SLOPE` をユーザーに出すか。** soothe は出していない。Advanced に置くか、
  `DEPTH` に畳むかは `PUM-3` で音を聴いてから。
- **44.1 kHz の 8.1% のずれを許すか。** 受入条件には入るが端が近い。
  目標ビン幅を 2 の冪に寄せて選び直せばゼロにできる（44.1 kHz を基準にすると
  48 kHz 側がずれる）。**どちらの端をずらすかは `PUM-2` で決める。**
