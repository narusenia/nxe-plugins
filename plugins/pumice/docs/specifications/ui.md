## 設計方針

**主役は削減カーブ。** `REQ-PUM-003` の処理は自動で働くので、見せないと
「何もしていない」に見える。Sparkleur の Guard（`REQ-SPK-008`）と
Vocal Glue の Spectral Cohesion（`REQ-GLU-013`）が同じ判断をしている。

**図が入力と処理の両方を持つのはラインで初めて。** 音声パスに STFT が
あるので、**表示しているスペクトルと処理しているスペクトルが同じ物**
（`REQ-PUM-016`）。`nxe_dsp::Spectrum` を別に回さない。他の 4 本は
「表示用の解析」と「処理」が別物で、そこがずれても誰にも分からなかった。

**タブを持たない。** メインは 5 本 + 3 モードで、`.agents/rules/ui.md` の
言うとおり数が決めるのではない — **`DEPTH` と `SHARPNESS` は一緒に問われる**
ので、半分のパネルには置けない。

**ノードは図の中にしか無い。** 24 個のパラメータ（6 × 4）を表にすると
それだけで窓が埋まる。図の上で置いて掴むのが唯一の操作系で、
**選択中のノードの値は status バーが読む**。

```text
│                                                               │
│  ┌─ NodeField ───────────────────────────────────────────┐    │

│  │  ─────────●───────────────●─────────────────────      │    │  ← ノード曲線 + ●
│  │            ╲___╱           ╲_╱                        │    │  ← 削減カーブ
│  │  100    200    500   1k    2k    5k   10k   18k       │    │
│  └───────────────────────────────────────────────────────┘    │

│   DEPTH      SHARPNESS     SPEED          MIX      OUTPUT     │
│    ◯           ◯            ◯              ◯         ◯        │

│  MODE [ ADAPTIVE │ STATIC ]   QUALITY [ L │ N │ H ]   [DELTA] │

```

- **ヘッダの wordmark は素の `Pumice`**、`NXE` は右に別の小さい印
  （`UI-19`）。
- **`.readout` は 1 領域に 1 つ**（`.agents/rules/ui.md`）。上段の主役は
  `REDUCTION`（最大削減量）で、`IN` / `OUT` はその横の同格ではなく従。
- **status バーは休んでいるとき空**。ノードに乗ったときだけ 1 行出す。

## 窓の寸法

**高さは算術**（`.agents/rules/ui.md`）。Diorama の `ui/mod.rs` と同じ形。

```text
HEIGHT = SPACE_3 * 2
       + header::HEIGHT
       + readout::HEIGHT
       + FIGURE_HEIGHT              // field::HEIGHT + SPACE_4 * 2
       + knob_block_height(MAIN_KNOB)
       + MODE_ROW_HEIGHT
       + status::HEIGHT
```

- **幅は `theme::WINDOW_WIDTH`（880）。** 5 本と同じ 1 つの定数。
- **図は `field::HEIGHT`（200）。** 5 本と同じ。上げない —
  「別々に調整した 2 つの図は、単体では正しく、並べると間違っている」。
  **ノードエディタが精度を要るのは周波数軸＝横**で、880 px / 対数 20 Hz〜20 kHz
  ≒ 88 px/オクターブ。縦は `depth`（±100%）という粗い量なので 200 で足りる。

## `NodeField`（`UI-22`）— 新規ウィジェット

`nxe-ui` に足す。**`examples/gallery.rs` にも同じ変更で追加する**
（`.agents/rules/vizia.md`）。

### 何を知っているか

**Hz も dB も知らない。** `CurveView` / `BandField` と同じ契約 — 正規化した
`x`（0..1、左から右）と `y`（0..1、下から上）だけを受け取る。Hz を対数軸に
写すのも、軸ラベルを置くのも呼び出し側の仕事（`draw_text` はビュー自身の
テキストしか描けない）。

### 4 つの層

| 層 | 何 | 描き方 |
|---|---|---|
| 入力スペクトル | 生きている | 塗り、`ANALYSIS_ALPHA` |
| 削減カーブ | 生きている | 上端から下へ落ちる曲線。**これが「今何をしているか」** |
| ノード曲線 | 設定 | アクセント、実線 |
| ノード | 設定 | ● 6 個まで |

**削減カーブとノード曲線を取り違えさせない。** どちらも「周波数上の曲線」
なので、**ノード曲線はアクセントの実線、削減カーブは塗りを伴う下向きの
逸脱**として別の種類の物に見せる。`dots.rs` が「同じ種類の 2 本の曲線は
同じものの 2 つの設定に読める」と書いているのと同じ問題。

### 操作

| 操作 | 何が起きる |
|---|---|
| ノードを掴んで動かす | `freq`（横）と `depth`（縦）が同時に動く |
| ノードの左右のグリップを横に引く | `width` |
| 空きでダブルクリック | そこに `enabled` なノードが 1 本増える |
| ノードでダブルクリック | そのノードが `enabled` = off |
| `Shift` を押しながら | `input::FINE`（他の全コントロールと同じ） |

- **2 次元ドラッグは `PolarField` が前例。** `input::Drag` は縦専用の
  状態機械なので再利用せず、`FINE` だけ共有する。
- **`width` のグリップは `BandField` の領域の端が前例。** `Shift` +
  横ドラッグにはしない — `Shift` は既に fine drag で埋まっている。
- **右クリックとスクロールは使わない。** どちらもこのリポジトリに前例が
  ゼロで、ホストのコンテキストメニューと baseview のスクロール挙動は
  DAW を開くまで分からない。
- **6 本埋まっているとき、空きのダブルクリックは何もしない。**
  一番古いものを消すような親切はしない。

### caller が動かす

**`PolarField` の傷をそのまま継ぐ** —

> ドラッグは**ポインタがどこへ行ったかを報告するだけ**。点は束縛された値が
> 変わったときに描き直される。ローカルコピーを先に動かすと、値を clamp する
> caller が「変わらない値」を書いたとき更新が返らず、点はドラッグした先に
> 取り残される。

ノードは `freq` が動作範囲で clamp され、`enabled` が 6 本で頭打ちになる。
**clamp する caller がまさにここに居る**ので、先に動かしてはいけない。

### 何を報告するか

ポインタがどのノードに乗っているか（`Option<usize>`）。**status バーが
それを読んで 1 行を出す**。ノードに数値ラベルは付けられない
（`draw_text` の制限）。

## 読み値と解析

`nxe_dsp::Handoff` で受け取る（`REQ-PUM-018`）。

| | 出どころ |
|---|---|
| 入力スペクトル | **STFT からそのまま**。`Spectrum` を回さない |
| 削減カーブ | 実際に掛けた `g_db` |
| 最大削減量 | `REDUCTION` の読み値 |
| IN / OUT | `nxe_dsp::Level` × 4 |

- **音が止まると 3 秒以内に 0 へ減衰する**（`REQ-PUM-013`）。
- **削減カーブは実際に掛けたゲインそのもの。** 別に計算し直さない —
  ずれたら図が嘘をつく。

## 必要なコンポーネント

| | 状態 |
|---|---|
| `nxe_ui::header` / `readout` / `status` / `knob` / `meter` / `segmented` | ある |
| **`nxe_ui::node::NodeField`** | **`UI-22` で新規** |
| `ToggleSwitch` | **要るかもしれない。** `DELTA` は `segmented` の 2 値でも足りる。`UI-9` は「3 個目でも要らなければ落とす」と書かれていて、**ここが 6 個目** |

## まだ答えの無い問い

- **`DELTA` を `segmented` にするか、`UI-9`（`ToggleSwitch`）を起こすか。**
  `PUM-10` で決める。`segmented` で足りるなら `UI-9` は落とす。
- **ノードが 0 本のときの図。** 削減カーブは出るがノード曲線は平坦な直線に
  なる。**それが「まだ何も置いていない」と読めるか**は実機で見るまで
  分からない（`.agents/rules/ui.md` — 寸法は実機でしか settle しない）。
- **`REDUCTION` の読み値を最大値にするか平均にするか。** 最大は 1 本の
  細い共鳴でも大きく振れる。`PUM-9` で解析を繋いでから決める。
