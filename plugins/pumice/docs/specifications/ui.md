## 設計方針

**主役は削減カーブ。** `REQ-PUM-003` の処理は自動で働くので、見せないと
「何もしていない」に見える。Sparkleur の Guard（`REQ-SPK-008`）と
Vocal Glue の Spectral Cohesion（`REQ-GLU-013`）が同じ判断をしている。

**図が入力と処理の両方を持つのはラインで初めて。** 音声パスに STFT が
あるので、**表示しているスペクトルと処理しているスペクトルが同じ物**
（`REQ-PUM-016`）。`nxe_dsp::Spectrum` を別に回さない。他の 4 本は
「表示用の解析」と「処理」が別物で、そこがずれても誰にも分からなかった。

**タブを持たない。** メインは 5 本 + 3 モードで、`.agents/rules/ui.md` の
言うとおり数が決めるのではない — **`DEPTH` と `SHARPNESS` は一緒に問われる**
ので、半分のパネルには置けない。

**ノードは図の中にしか無い。** 24 個のパラメータ（6 × 4）を表にすると
それだけで窓が埋まる。図の上で置いて掴むのが唯一の操作系で、
**選択中のノードの値は status バーが読む**。

## 画面

```text
┌───────────────────────────────────────────────────────────────┐
│  Pumice          resonance, only when         [L│N│H]    NXE  │
│  ═══════════════════════════════════════════════════════════  │
│  ┌─ NodeField（アクセント面、全幅）─────────────────────┐    │
│  │      ▁▂▃▅▆█▇▅▃▂▁▂▃▄▅▆▇█▆▄▂▁                          │    │  ← 入力スペクトル
│  │  ─────────●───────────────●─────────────────────      │    │  ← ノード曲線 + ●
│  │            ▔▔▔╲___╱▔▔▔▔▔▔▔▔▔╲_╱                      │    │  ← 削減（天井から）
│  │  20   100   500   2k    8k   20k                      │    │
│  └───────────────────────────────────────────────────────┘    │
│  ┌─ DEPTH ─────┐│┌─ その他 ──────────────────────────────┐   │
│  │             │││ SHARP SPEED  LOW  HIGH  MIX  OUTPUT   │   │
│  │     ◯       │││  ◯     ◯     ◯    ◯     ◯     ◯       │   │
│  │             │││                                       │   │
│  │ [ADPT│STAT] │││ [DELTA]                               │   │
│  └─────────────┘│└───────────────────────────────────────┘   │
│  ═══════════════════════════════════════════════════════════  │
│  2.4 kHz · 0.80 oct · +40 %      IN -18.2  OUT -19.4  GR -3.6 │
└───────────────────────────────────────────────────────────────┘
```

**図は全幅、その下を左右に割る。** 参照した fors の窓は左右 2 面だが、
**あちらの図は円形で縦長パネルに収まる**。Pumice の図は対数周波数軸なので
横幅が要る — 880 px / 10 オクターブ = 88 px/オクターブで、2 面に割ると 40 に
なり、6 本のノードを手で置くには狭い。**縦軸は `depth` という粗い量**なので、
横を取って縦を諦めるのが正しい向き。

**左右は罫線で分ける。反転面は増やさない。** `.agents/rules/ui.md` は反転面を
2 つまで（status バーと窓の図）に限っていて、図が既にその 1 つ。
アクセント色のコントロール面を図の隣に置くと、**図が受けるべき視線を先に
奪う**。分割が言っているのは「最初に手が伸びるのはこれ、残りはこちら」。

**`QUALITY` はヘッダの MODE 枠に入れた**（`UI-19`）。レイテンシを変える
非オートメーションのパラメータで、`DEPTH` の隣に置くと音を作るつまみに
見える。

**ヘッダの下に読み値の帯を持たない。** 一度持って `REDUCTION` / `IN` / `OUT`
を見出しサイズで印字していたが、**下の status バーが同じ 3 つを既に運んで
いる**。1 つの窓が同じことを 2 回言わない、というだけの理由で外した。
返ってきた 40 px は図が使う。

**重みのカーブは engine のビンから読まない。** ノードは測定値ではなく
**ユーザーが設定した数式**で、あらゆる周波数に厳密な値を持つ。ビン経由で
描くと **300 Hz 以下で階段になる** — 対数の表示格子は 100 Hz で 5.6 Hz
刻みなのに、48 kHz / 2048 点のビンは 23.4 Hz 刻みなので、複数の点が同じ
ビンを読む。窓は `nodes::weight_at` を直接標本化する（`Handoff` も
128 個ぶん軽くなる）。

**スペクトルは変換のスケールで割る。** `|X[k]|²` は変換長に比例するので、
2048 点では**フルスケールの正弦が +34 dB を読む** — 図は何を再生しても
上端に張り付いていた。**検出は気づかない**（比で働くのでスケールが約分
される）ので、絵だけが間違っていた。図が隠す種類のバグ。

- **ヘッダの wordmark は素の `Pumice`**、`NXE` は右に別の小さい印
  （`UI-19`）。
- **`.readout` は 1 領域に 1 つ**（`.agents/rules/ui.md`）。上段の主役は
  `REDUCTION`（最大削減量）で、`IN` / `OUT` はその横の同格ではなく従。
- **status バーは休んでいるとき空**。ノードに乗ったときだけ 1 行出す。

## 窓の寸法

**高さは算術**（`.agents/rules/ui.md`）。Diorama の `ui/mod.rs` と同じ形。

```text
HEIGHT = SPACE_3 * 2
       + header::HEIGHT      + SPACE_3
       + FIGURE_HEIGHT       + SPACE_3   // field::HEIGHT + SPACE_4 * 2
       + SPLIT_HEIGHT
       + status::HEIGHT
```

`SPLIT_HEIGHT` は左側（`DEPTH` + `MODE`）の高さ。**左が背の高いほう**なので、
右の 6 つのつまみと `DELTA` はその中に収まる。

- **幅は `theme::WINDOW_WIDTH`（880）。** 5 本と同じ 1 つの定数。
- **図は `field::HEIGHT`（200）。** 5 本と同じ。上げない —
  「別々に調整した 2 つの図は、単体では正しく、並べると間違っている」。
  **ノードエディタが精度を要るのは周波数軸＝横**で、880 px / 対数 20 Hz〜20 kHz
  ≒ 88 px/オクターブ。縦は `depth`（±100%）という粗い量なので 200 で足りる。

## `NodeField`（`UI-22`）— 新規ウィジェット

`nxe-ui` に足す。**`examples/gallery.rs` にも同じ変更で追加する**
（`.agents/rules/vizia.md`）。

### 何を知っているか

**Hz も dB も知らない。** `CurveView` / `BandField` と同じ契約 — 正規化した
`x`（0..1、左から右）と `y`（0..1、下から上）だけを受け取る。Hz を対数軸に
写すのも、軸ラベルを置くのも呼び出し側の仕事（`draw_text` はビュー自身の
テキストしか描けない）。

### 4 つの層

| 層 | 何 | 描き方 |
|---|---|---|
| 入力スペクトル | 生きている | 塗り、`ANALYSIS_ALPHA` |
| 削減カーブ | 生きている | 上端から下へ落ちる曲線。**これが「今何をしているか」** |
| ノード曲線 | 設定 | アクセント、実線 |
| ノード | 設定 | ● 6 個まで |

**削減カーブとノード曲線を取り違えさせない。** どちらも「周波数上の曲線」
なので、**ノード曲線はアクセントの実線、削減カーブは塗りを伴う下向きの
逸脱**として別の種類の物に見せる。`dots.rs` が「同じ種類の 2 本の曲線は
同じものの 2 つの設定に読める」と書いているのと同じ問題。

### 操作

**ノードのパラメータは Hz や オクターブではなく「軸の上の位置」**
（`params::position_to_hz`）。図はノードを**軸上の場所**へ落とすので、
パラメータが skew を持っていると窓は読み取った位置を書き戻すために skew を
逆算することになり、**対数に近いだけの skew では逆算も近いだけ**になる。
正規化値そのものを図の座標にすれば逆算が要らない。ホストの既定 UI は
`with_value_to_string` が Hz と オクターブで読ませる。

**幅は全ノードで常時見える。** ノードを通る横棒とその両端の縦マークが
「このノードはこの幅で、端が幅を動かす」を同時に言う。**ホバー時にだけ
グリップを出していたら、幅の設定方法が見つけられなかった** — 既にポインタが
乗ってから現れる取っ手は、誰も発見しない取っ手。

| 操作 | 何が起きる |
|---|---|
| ノードを掴んで動かす | `freq`（横）と `depth`（縦）が同時に動く |
| ノードの左右のグリップを横に引く | `width`（**常時見える・常時掴める**） |
| 空きでダブルクリック | そこに `enabled` なノードが 1 本増える |
| ノードでダブルクリック | そのノードが `enabled` = off |
| `Shift` を押しながら | `input::FINE`（他の全コントロールと同じ） |

- **2 次元ドラッグは `PolarField` が前例。** `input::Drag` は縦専用の
  状態機械なので再利用せず、`FINE` だけ共有する。
- **`width` のグリップは `BandField` の領域の端が前例。** `Shift` +
  横ドラッグにはしない — `Shift` は既に fine drag で埋まっている。
- **右クリックとスクロールは使わない。** どちらもこのリポジトリに前例が
  ゼロで、ホストのコンテキストメニューと baseview のスクロール挙動は
  DAW を開くまで分からない。
- **6 本埋まっているとき、空きのダブルクリックは何もしない。**
  一番古いものを消すような親切はしない。

### caller が動かす

**`PolarField` の傷をそのまま継ぐ** —

> ドラッグは**ポインタがどこへ行ったかを報告するだけ**。点は束縛された値が
> 変わったときに描き直される。ローカルコピーを先に動かすと、値を clamp する
> caller が「変わらない値」を書いたとき更新が返らず、点はドラッグした先に
> 取り残される。

ノードは `freq` が動作範囲で clamp され、`enabled` が 6 本で頭打ちになる。
**clamp する caller がまさにここに居る**ので、先に動かしてはいけない。

### 何を報告するか

ポインタがどのノードに乗っているか（`Option<usize>`）。**status バーが
それを読んで 1 行を出す**。ノードに数値ラベルは付けられない
（`draw_text` の制限）。

## 読み値と解析

`nxe_dsp::Handoff` で受け取る（`REQ-PUM-018`）。

| | 出どころ |
|---|---|
| 入力スペクトル | **STFT からそのまま**。`Spectrum` を回さない |
| 削減カーブ | 実際に掛けた `g_db` |
| 最大削減量 | `REDUCTION` の読み値 |
| IN / OUT | `nxe_dsp::Level` × 4 |

- **音が止まると 3 秒以内に 0 へ減衰する**（`REQ-PUM-013`）。
- **削減カーブは実際に掛けたゲインそのもの。** 別に計算し直さない —
  ずれたら図が嘘をつく。

## 必要なコンポーネント

| | 状態 |
|---|---|
| `nxe_ui::header` / `readout` / `status` / `knob` / `meter` / `segmented` | ある |
| **`nxe_ui::node::NodeField`** | **`UI-22` で新規** |
| `ToggleSwitch` | **要るかもしれない。** `DELTA` は `segmented` の 2 値でも足りる。`UI-9` は「3 個目でも要らなければ落とす」と書かれていて、**ここが 6 個目** |

## 決まったこと（実装で確定した 3 つ）

- **`DELTA` は `nxe_plug_ui::toggle`。** `.segment` が `:checked` を持っている
  ので新しいウィジェットは要らず、**`UI-9`（`ToggleSwitch`）は落としたまま**
  （これで 6 個目の製品でも要らなかった）
- **`REDUCTION` は最大値。** 1 本の細い共鳴でも振れるのは承知の上で、
  「今どれだけ取っているか」の答えは最深部。平均は「だいたい何もしていない」
  としか言わない（普通の素材で平均 0.1 dB 未満なので）
- **`nxe_ui::hint` に `HintEvent::Dynamic` を足した。** ノードには名前が無く、
  読ませたいのは値（周波数・幅・深さ）。ラインの他の全部は `&'static str` で
  自分を説明していて、**それが通常のまま** — これは値のための例外

## まだ答えの無い問い

- **ノードが 0 本のときの図。** 削減カーブは出るがノード曲線は平坦な直線に
  なる。**それが「まだ何も置いていない」と読めるか**は実機で見るまで
  分からない（`.agents/rules/ui.md` — 寸法は実機でしか settle しない）
- **左の `DEPTH` 面の幅 196 px が正しいか。** 60 px のつまみと
  `ADAPTIVE / STATIC` の切り替えが入る最小に近い値で、実機で窮屈に見えたら
  広げる
- **スペクトルの窓（−84〜0 dB）と削減の床（−18 dB）。** どちらも図が
  上端も下端も使うように選んだ値で、`DIO-17`（定数が 14 倍ずれて図の上端が
  一度も使われなかった）と同じ形の間違いをしていないかは目でしか分からない
