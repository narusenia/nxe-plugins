# Pumice — 実装計画

> 最終更新: 2026-09-01

要件は [`../requirements/REQ-PUM.md`](../requirements/REQ-PUM.md)。
DSP 仕様は [`../specifications/dsp.md`](../specifications/dsp.md)、
UI 仕様は [`../specifications/ui.md`](../specifications/ui.md)。

**まだ 1 行も実装されていない。** 着手は `PUM-1`。

**単位ごとに「完了条件」を満たしてからコミットする。** 完了条件は「動いた」
ではなく**測れること**で書く。

## 順序の考え方

```text
PUM-1  空のラッパで PDC を通す        ← ゲート。**人が 4 ホストを開く**
PUM-2  OLA バッファと窓
PUM-3  参照とゲイン計算（STATIC）     ← ここで音が出る
PUM-4  適応 WHERE と MODE             ← 2 つ目のゲート
PUM-5  ノード曲線
PUM-6  dry / MIX / OUTPUT / DELTA
PUM-7  レート・ブロックサイズ非依存
PUM-8  CPU 予算
PUM-9  解析の受け渡し
──────── ここでパラメータ集合が凍る ────────
UI-22  NodeField（gallery で単体検証）
PUM-10 窓
PUM-11 既定値と耳                     ← **人が要る**
```

**ゲートが 2 つある。** ラインで初めて。

**`PUM-1` が 1 番目**なのは `roadmap.md` の基準 0 そのもの
（前提が崩れると後続が無駄になるものを先に）。**PDC が 4 ホストで効かなければ、
FFT 方式ごと選び直す**ことになり、`PUM-2` 以降が全部無駄になる。
`DBL-2` と同じ扱いで、**空に近いラッパのうちに人の手で確かめる**。

**`PUM-1` は DSP を 1 行も持たない。** レイテンシを申告して、
`nxe_audio::DelayLine` でその分だけ遅らせるだけ。**PDC が効いていれば
トラックはずれない** — 自分自身が試験になっている。

**`PUM-4` が 2 つ目のゲート**（`REQ-PUM-003`）。崩れたら「倍音を削らずに
共鳴だけ削る」が成立せず、製品が soothe の劣化版に縮む。`PUM-3`（`STATIC`）が
先にあるので、**比較対象がある状態でゲートを測れる**のが利点 —
受入条件が「`ADAPTIVE` の削減量が `STATIC` より 6 dB 以上小さい」なので、
`STATIC` が無いと測りようがない。

**`PUM-3`（ラッパで音が出る）が `PUM-4` より前。** `VEL-5` / `AIR-4` /
`DIO-4` と同じ判断。`SHARPNESS` も `SPEED` も効いたかの判断が耳寄りなので、
ホストの既定パラメータ UI で音が出る状態を先に作る。

**`UI-22` が `PUM-9` の後。** `roadmap.md` の基準 1（パラメータ集合が固まる
まで UI に投資しない）。`NodeField` は**このリポジトリで一番大きい UI 投資**
なので、一番作り直したくない。

## 共有クレートに上げるもの

**無い。** `REQ-PUM-015` のとおり、OLA バッファは `pumice-core` に置く。

| 何 | どこ | なぜ上げないか |
|---|---|---|
| OLA バッファと窓 | `pumice-core` | **1 個目の客しか居ない**（`architecture.md`）。ただし**パラメータ構造体を知らない自立したモジュールとして書く**ので、2 個目が来たら移動はファイルの移動だけで済む（`REQ-VEL-015` と同じ） |
| 前置和の区間平均 | `pumice-core` | 同上。3 箇所で使うが全部この製品の中 |

**`nih_plug::util::stft::StftHelper` は使わない**（`REQ-PUM-015`）。理由は
ライセンスと AU の道。**答え合わせの相手としては使う。**

## 新しい依存

| | ライセンス | どこに |
|---|---|---|
| `realfft` | MIT | `pumice-core` |

`realfft` は `rustfft`（MIT OR Apache-2.0）の実数入力ラッパ。**どちらも
寛容側なので `pumice-core` は MIT OR Apache-2.0 のまま**（`LICENSING.md`）。
**`nxe-audio` / `nxe-dsp` は実行時依存ゼロを保つ** — ここには入れない。

### PUM-1 — 空のラッパで PDC を通す（**ゲート**）

`pumice` / `pumice-core` の 2 クレートを作り、ワークスペースと
`bundler.toml` に登録する。

**`pumice-core` は空ではなくなった。** 当初「`lib.rs` だけ」と書いていたが、
ラッパがレイテンシを申告するには **N が要る**。N の決め方は変換の性質で
あってラッパの都合ではないので、`.agents/rules/rust.md`（ラッパに DSP を
置かない）に従って `pumice_core::quality` に置いた。DSP はまだ 1 行も無い。

ラッパがやること:

- `AUDIO_IO_LAYOUTS` に 2→2 と 1→1（`REQ-PUM-011`）
- `initialize()` で `set_latency_samples(3N/4)`
- `process()` で `nxe_audio::DelayLine` を通してその分だけ遅らせる
- パラメータは `QUALITY` **1 つだけ**（`.non_automatable()`）。
  申告値が動くことをここで試す

**UI は持たない。** ホストの既定パラメータ UI で足りる。

- **完了条件**:
  - [x] `cargo xtask bundle pumice --release` が通る
  - [x] `mise run check` が通る（**610 本**、うち Pumice が 9 本）
  - [x] 申告値と実際の遅れがサンプル単位で一致する
        （`the_delay_matches_what_is_reported`、4 レート × 3 段）
  - [x] **Ableton Live（VST3）と Studio One Pro（CLAP）で位相が合う**
        — 反転して無音（2026-09-01）
  - [ ] Bitwig と Reaper
  - [ ] **再生中に `QUALITY` を変えて音が復帰する**

**方式の前提は抜けた**（2026-09-01）。**CLAP と VST3 が両方**通ったのが
大きい — フォーマットごとに PDC の伝え方が違うので、片方だけでは
「たまたま動いた」を排除できなかった。**FFT で進めてよい。**

残り 2 ホストは**方式の判断には影響しない**。Bitwig と Reaper はどちらも
PDC を持つホストで、ここで落ちるならホスト固有の問題であって
`REQ-PUM-007` の前提の問題ではない。`PUM-2` 以降と並行して確かめる。

**`QUALITY` の切り替えだけは性質が違う。** 落ちた場合に消えるのは方式では
なく `QUALITY` の**実行時可変性**で、対処は「停止中にだけ変えられる」を
仕様に書くか、`QUALITY` を落としてレイテンシを固定にするか
（`REQ-PUM-008`）。**`PUM-2` の前に知りたい** — N が固定なら
`pumice_core::quality` の作りが変わる。

確かめ方: 同じ素材のトラックを 2 本並べ、片方にだけ Pumice を挿す。
**PDC が効いていれば位相が合ったまま**（この版は音を変えないので、
片方の位相を反転すると無音になる）。
- **依存**: なし
- **これが駄目だったら**: `REQ-PUM-007` に戻る。`QUALITY` を殺して
  レイテンシを固定にするのが第一手、それでも駄目なら**減算型
  バンドパスバンク**（レイテンシ 0）へ方式ごと戻す。その設計は
  `REQ-GLU-003` に既にある。

### PUM-2 — OLA バッファと窓

`pumice-core` に `stft.rs`。**`pumice` クレートは触らない。**

- リングバッファ、Hann、hop = N/4、`2/3` の正規化
- `N` をレートと `QUALITY` から決める（`dsp.md` の表）
- **確保は最大 N = 16384 で 1 回**

- **完了条件**:
  - [ ] 全ビンのゲインが 1 のとき、再構成誤差が **−120 dB 以下**
  - [ ] **ブロックサイズ 1 / 64 / 512 / 4096 の出力が一致する**
  - [ ] `dsp.md` の N の表が 4 レート × 3 段で一致する（テストで固定）
  - [ ] 音声パスに確保が無い
  - [ ] `StftHelper` と同じ入力で同じ出力（答え合わせ）
- **依存**: PUM-1

### PUM-3 — 参照とゲイン計算（`STATIC`）＋ ラッパ

`pumice-core` に `reference.rs` と `gain.rs`。**ここで音が出る。**

- 前置和の区間平均（参照 / ゲイン平滑の両方が使う）
- `e[k]`、`WHEN`、`THRESHOLD` / `SLOPE` / `CEILING`
- 最終ゲイン曲線の 1/12 オクターブ平滑
- ラッパに `DEPTH` / `SHARPNESS` / `SPEED` を足す

- **完了条件**:
  - [ ] `DEPTH` = 0 で全ビンのゲインがちょうど 1
  - [ ] **ピンクノイズで削減量がちょうど 0 dB**（`SPK-18` の再発防止）
  - [ ] 削減量が入力ゲイン ±12 dB で 0.2 dB 以内
  - [ ] `SHARPNESS` を上げると広い盛り上がりへの削減が単調に減る
  - [ ] **ホストで聴いて、共鳴が引くことを確かめる**
- **依存**: PUM-2

### PUM-4 — 適応 WHERE と `MODE`（**ゲート**）

`pumice-core` に `adaptive.rs`。

- `WHERE` = `e[k]` の長期フォロワ（hop 刻み、τ_w）
- `WHERE` の周波数平滑（1/6 オクターブ）
- `min(WHEN, WHERE)`
- `MODE` を足す

- **完了条件**:
  - [ ] **合成倍音列（基音を掃引する鋸波）で、`ADAPTIVE` の削減量が
        `STATIC` より 6 dB 以上小さい**
  - [ ] **固定周波数の共鳴を足した同じ素材で、`ADAPTIVE` がその周波数を
        `STATIC` と同等以上に削る**
  - [ ] `MODE` の切り替えで不連続なノイズが出ない
  - [ ] 無音から立ち上げたとき、`WHERE` が発散しない
- **依存**: PUM-3
- **これが駄目だったら**: `REQ-PUM-003` に戻る。`min` を積や重み付き和に
  替えるのが第一手。**それでも倍音が削れるなら `ADAPTIVE` を落とし、
  製品は `STATIC` だけになる** — そのとき Pumice は soothe の再実装であって
  「ボーカルの soothe」ではなくなるので、**要件から書き直す**。

### PUM-5 — ノード曲線

`pumice-core` に `nodes.rs`、ラッパに 24 個のパラメータ。

- 対数周波数上のガウシアン、`width` は半値全幅
- `weight = clamp(1 + Σ depth·bump, 0, 2)`
- 動作範囲の端（レイズドコサイン、1/2 オクターブ）
- **パラメータが動いたときだけ組み直す**

- **完了条件**:
  - [ ] `enabled` が全部 off で重みが平坦（±0.1 dB）
  - [ ] `depth` < 0 のノードがその周波数の削減を減らす
  - [ ] `freq` を掃引して段差が出ない
  - [ ] `DEPTH` = 0 なら、どのノード設定でも出力が変わらない
  - [ ] `DEPTH` 最大 + ノード最大でも `CEILING` を超えない
- **依存**: PUM-4

### PUM-6 — dry / `MIX` / `OUTPUT` / `DELTA`

- `nxe_audio::DelayLine` を `3N/4`（`PUM-1` のものを本番に昇格）
- `DELTA` は `MIX` の前

- **完了条件**:
  - [ ] `MIX` = 0 で遅延入力との差が **−120 dB 以下**
  - [ ] `DEPTH` = 0 で遅延入力との差が **−120 dB 以下**
  - [ ] dry の遅延が申告値とサンプル単位で一致
  - [ ] `DELTA` の出力 + 通常出力 = 元の wet
  - [ ] `DEPTH` = 0 のとき `DELTA` が無音
- **依存**: PUM-5
