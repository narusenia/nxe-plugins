# REQ-DBL — Doubler 要件定義

> 最終更新: 2026-08-25

## 概要

Doubler は 1 つのソースから、音程・タイミング・定位・音色がそれぞれ僅かに
違う複数のボイスを作り、「同じフレーズを何回か録り重ねた」ように聞かせる
エフェクト。狙う領域は Waves Doubler / iZotope Nectar Doubler の系統で、
Eventide H3000 系のマイクロピッチシフト（定常 detune のみ、揺れなし）は
その部分集合として設定で作れる。

対象は Bitwig / Ableton Live / Reaper / Studio One。**AU は対象外**なので
Logic Pro と GarageBand では読み込めない（`REQ-DBL-009`）。

## 設計の中心にある 2 つの判断

**定常 detune を持つ。** ディレイの変調だけで作れるのはビブラートであって、
音程がずれたまま留まる別テイクにはならない。したがって本物のピッチシフタが
必要で、方式は 2 タップクロスフェード遅延線を採る（`REQ-DBL-002`）。

**マクロと個別値は上書きし合わない。** ボイスごとの値は正規化された「形」で
持ち、グローバルノブはそれを掛ける倍率として働く（`REQ-DBL-007`）。二層 UI で
どちらを触っても他方が消えないことを、UI の都合ではなくパラメータモデルの
性質として保証する。

## REQ-DBL-001: マルチボイスダブリングエンジン

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 入力から N 個のボイスを生成する。各ボイスは独立した遅延量・
  ピッチずらし量・定位・ゲインを持つ。N は 2 / 4 / 8 の離散値。
  **パラメータは常に 8 ボイス分宣言し**、`Voices` は有効なボイス数を決める
  （nih-plug のパラメータは起動時に静的に宣言する必要があり、実行時に増減
  できない）。有効なのは先頭 N ボイスで、無効なボイスは処理も出力もしない。
- **ボイス数を変えても定位が偏らないこと**: ボイスの既定の「形」は、先頭から
  N 個を取ったときに左右対称になる順で並べる（`specifications/dsp.md`）。
  Voices を 8 → 2 に変えても中央に寄ったり片側に寄ったりしない。
- **受入条件**:
  - [ ] `Voices` = 2 / 4 / 8 を切り替えられる
  - [x] 各ボイスに遅延・detune・定位・ゲインが独立に効く — `DBL-3`
  - [x] 無効なボイスは出力に一切寄与しない — `DBL-3`
  - [ ] どの `Voices` でも、既定値では wet の左右のエネルギーが等しい
  - [x] `Voices` の切り替えでクリックノイズが出ない — `DBL-8`
- **依存**: なし

## REQ-DBL-002: 2 タップクロスフェード式ピッチシフト

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 各ボイスの定常的な音程ずらしを、遅延線を等比レートで読む方式で
  実現する。読み出しレートは `2^(cent/1200)`。読み出し点が書き込み点に対して
  窓長を超えて離れる前に、もう一方のタップへ等パワーでクロスフェードする。
  H3000 / MicroShift 系と同じ原理。位相ボコーダと WSOLA は採らない
  （前者はレイテンシと水っぽさ、後者はピッチ検出が必要で和音・ギター・
  ドラムで崩れる）。
- **範囲の限界**: この方式は本質的にクロスフェードの継ぎ目を持つ。要件として
  保証するのは **±50 cent の範囲で継ぎ目が単体で聞き取れないこと**であり、
  1 オクターブ級のシフトの品質は要件に含めない（この製品はそれをしない）。
- **補間**: 線形補間は読み出し位置が小数のとき高域を落とすので使わない。
  4 点 Hermite（Catmull-Rom）補間とする。
- **受入条件**:
  - [x] 正弦波を入力したとき、wet の基本周波数が `2^(cent/1200)` 倍になる
        （±0.5 cent 以内） — `DBL-2`
  - [x] detune = 0 のボイスがピッチシフト経路を通っても音が変化しない
        （ビット一致で確認）— `DBL-2`
  - [x] ±50 cent の範囲でクロスフェードの継ぎ目が周期的なノイズとして
        聞こえない — `DBL-4` で Ableton Live で確認（クリックも質感の劣化も
        無し）
  - [ ] 高域を含む素材で線形補間相当の高域減衰が起きない
- **依存**: REQ-DBL-001

## REQ-DBL-003: ボイスの揺れ（Humanize）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: ボイスごとに独立した低速のランダム信号を持ち、そのボイスの
  detune と遅延の両方を微動させる。ランダム源は白色ノイズを 1 次 IIR で
  なました信号で、周期性が聞こえてはならない。`Humanize` ノブが深さを決める。
  **周期 LFO は採らない** — 周期が聞こえた瞬間にコーラスになり、別テイクでは
  なくなる。
- **トランジェント検出による更新は v1 に含めない**: 発話やフレーズごとに
  揺れを引き直す方式は「本物っぽさ」で上だが、検出の失敗が音の不安定さとして
  出る。低速ランダムで十分な結果が得られるかを先に確認する。
- **受入条件**:
  - [ ] `Humanize` = 0 で完全に静的な detune / 遅延になる（＝ MicroShift 相当の
        設定が作れる）
  - [ ] `Humanize` を上げると各ボイスが独立に揺れ、周期性が聞こえない
  - [ ] 揺れが遅延にも効くので、揺れている間はピッチも微かに動く
  - [ ] 揺れによる読み出し位置の変動でクリックが出ない
  - [ ] ボイスごとのランダム源は固定シードで再現可能（同じ設定・同じ入力で
        同じ出力になる）
- **依存**: REQ-DBL-001, REQ-DBL-002

## REQ-DBL-004: 入力経路モード（Mono Sum / True Stereo）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: ボイスの入力をどこから取るかを `Source` で切り替える。
  - **Mono Sum**: L と R を和してモノにし、全ボイスがそれを入力とする。
    `Pan` は最終的な絶対位置を意味する。モノ素材でもステレオ素材でも挙動が
    同じで、幅と位相が予測可能。遅延線のコストも半分。
  - **True Stereo**: ボイスは index の偶奇で L / R のどちらかを入力とする。
    `Pan` は**そのソース側からのオフセット**を意味する。すでに広い素材
    （ダブルトラック済みのギター、ステレオシンセ）で元の像を壊さない。
- **Pan の意味がモードで変わることを仕様として明記する**。同じプリセットを
  モード切り替えで使うと定位が変わるのは仕様であり、バグではない。
- **受入条件**:
  - [x] `Source` を切り替えられ、切り替えでクリックが出ない — `DBL-6`
  - [x] Mono Sum で、モノ入力とステレオ入力（同じ内容が L/R）の結果が一致する
        — `DBL-6`
  - [x] True Stereo で、L のみに信号があるとき R 由来のボイスは無音になる
        — `DBL-6`
  - [x] どちらのモードでも Dry は加工されずに素通しする — `DBL-6`（Dry は
        エンジンを通らないので構造的に成立）
- **依存**: REQ-DBL-001

## REQ-DBL-005: 音色（Tone / Tone Spread）

- **優先度**: Should
- **ステータス**: Draft
- **説明**: 2 つの独立した機能を持つ。
  - **Tone Lo / Tone Hi**: wet バス全体に低域・高域のシェルビングをかける。
    ダブルを引っ込めたり明るくしたりする用途。**Dry には一切かからない**。
  - **Tone Spread**: ボイスごとに 1 次の HPF / LPF を挿し、カットオフを
    ボイスごとに散らす。別テイクの音色差を、per-voice EQ の UI を持たずに
    作るための 1 ノブ。散らし方は固定シードで再現可能。
- **per-voice EQ とフォルマントシフトは v1 に含めない**。フォルマントシフトは
  ピッチシフタとは別のエンジンが必要で、UI もボイスマトリクスに膨らむ。
- **受入条件**:
  - [x] `Tone Lo` / `Tone Hi` が wet のみに効き、Dry のスペクトルが変わらない
        — `DBL-7`（Dry はエンジンを通らない）
  - [x] `Tone Spread` = 0 で全ボイスの音色が一致する — `DBL-7`
  - [x] `Tone Spread` を上げるとボイス間に音色差が生まれ、同じ設定なら毎回
        同じ散り方になる — `DBL-7`
- **依存**: REQ-DBL-001

## REQ-DBL-006: ミックス・出力・ゲイン補償・レイテンシ

- **優先度**: Must
- **ステータス**: Draft
- **説明**:
  - **Dry は遅延も加工もせず素通しする。** ダブラーではボイスが遅れているのが
    目的であって、原音を遅らせるのは目的ではない。
  - したがって**ホストに報告するレイテンシは 0**。ピッチシフタのクロスフェード
    窓が持つ遅れは wet 側に内包され、レイテンシ補償の対象ではない。
  - `Mix` は Dry と wet の比。100% で Dry が消える（センドで使う場合に必要）。
    **Voice Field の ▲ がそのハンドル**でもある（`specifications/ui.md`）。
  - 一度 `Dry Gain` という別パラメータを足したが、**`Mix` と役割が重なるので
    取り消した**（2026-08-26）。図の ▲ が dry のレベルを表すなら、それを動かす
    ものは 1 つでよく、`Mix` のほうが 0% と 100% の両端をきれいに満たす。
  - **wet はボイス数に応じてゲイン補償する。** ボイスは互いに非相関なので
    エネルギーは概ねボイス数に比例する。補償せずに Voices を 2 → 8 にすると
    ただ音量が上がり、比較にならない。
  - `Output` は最終段のゲイン。
- **受入条件**:
  - [ ] Dry のみ（`Mix` = 0）のとき、入力とサンプル単位で一致する
  - [x] ホストへの報告レイテンシが 0 である — レイテンシを一切報告しないので
        構造的に 0（`DBL-4`）
  - [ ] `Mix` = 100% で Dry が完全に消える
  - [x] `Voices` を 2 / 4 / 8 に変えても wet の RMS がほぼ一定（±1 dB 以内）
        — `DBL-3`
  - [x] `Mix` と `Output` の変更でクリックが出ない（スムージングが効く）
        — `DBL-8`（`dsp.md` のスムージング表どおりに宣言済み）
- **依存**: REQ-DBL-001

## REQ-DBL-007: 二層パラメータモデル

- **優先度**: Must
- **ステータス**: Draft
- **説明**: パラメータは 2 層に分かれる。
  - **マクロ層**（グローバル）: `Detune` / `Delay` / `Spread` / `Humanize` など
  - **形状層**（ボイスごと、8 ボイス分）: `Detune_i` / `Delay_i` / `Pan_i` /
    `Gain_i`

  形状層は**正規化された相対値**で、マクロがそれを掛ける。たとえば
  `実効 detune_i = Detune × Detune_i`。マクロを動かしても形状は保たれ、
  形状を編集してもマクロは変わらない。**どちらの層も他方を書き換えない。**
- **なぜこの形か**: 「マクロを触ると個別値が再計算される」方式にすると、
  ユーザーが個別に詰めた値がマクロ操作で消える。逆に「個別を触ると
  マクロが Custom になる」方式にすると、マクロが操作できなくなる。
  乗算関係にしておけば両方が常に生きている。
- **受入条件**:
  - [x] マクロを動かしても形状層の値が変化しない — `DBL-3`（形状を共有参照で
        受けるので型で保証されている）
  - [ ] 形状層を編集してもマクロの値が変化しない
  - [x] マクロを 0 にすると、その軸のボイス間の差が消える
        （`Detune` = 0 → 全ボイスが detune なし）— `DBL-2` / `DBL-3`
  - [x] `Gain_i` は絶対値（dB）で、対応するマクロを持たない — `DBL-3`
- **依存**: REQ-DBL-001

- **依存**: REQ-DBL-007

## REQ-DBL-009: プラグインフォーマットと対応ホスト

- **優先度**: Must
- **ステータス**: Draft
- **説明**: CLAP と VST3 を出力する。対応ホストは Bitwig Studio /

  Windows・Linux。
- **AU は対象外**: nih-plug に AU ラッパが無い。Logic Pro と GarageBand では

  `doubler-core` を呼ぶ（`REQ-DBL-010` がそのための要件）。
- **受入条件**:
  - [x] ホストで CLAP として読み込め、パラメータがオートメーションできる
        — `DBL-4` で Ableton Live で確認
  - [x] ホストで VST3 として読み込め、パラメータがオートメーションできる
        — `DBL-4` で Ableton Live で確認
  - [ ] 状態がプロジェクトに保存・復元される
  - [ ] Bitwig / Reaper / Studio One でも確認する（`DBL-13`）
  - [ ] macOS / Windows / Linux のバンドルがタグから CI で生成される
- **依存**: なし

## REQ-DBL-010: DSP のホスト非依存性

- **優先度**: Must
- **ステータス**: Draft
- **説明**: DSP は `doubler-core` に閉じ、nih-plug・Vizia・ホスト API に
  依存しない。`doubler` クレートはパラメータ宣言と UI と、その 2 つを core に
  渡す配線だけを持つ。
- **受入条件**:
  - [ ] `doubler-core` の依存に nih-plug / Vizia / OS の音声 API が現れない
  - [ ] `doubler-core` のテストがホストなしで実行できる
  - [ ] DSP のアルゴリズムに関する分岐が `doubler` 側に存在しない
- **依存**: なし

## REQ-DBL-011: リアルタイム安全性と CPU 予算

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 音声スレッドで確保・ロック・I/O を行わない。すべてのバッファは
  `initialize()` で最大ブロックサイズと最大サンプルレートから確保する。
  **CPU 予算**: 48 kHz / 512 サンプルブロック / `Voices` = 8 /
  `Source` = True Stereo で、Apple M シリーズの 1 コアの 5% 未満。
- **受入条件**:
  - [ ] `process()` の経路にヒープ確保・ロック・I/O が無い
  - [ ] パラメータをどの値にしても panic しない（範囲外の値を clamp する）
  - [ ] criterion のベンチが CPU 予算を満たし、回帰を検出できる
  - [ ] 遅延線のフィードバック経路が非正規化数に落ちない
- **依存**: REQ-DBL-001

## REQ-DBL-012: サンプルレート・ブロックサイズ非依存

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 44.1 kHz から 192 kHz、任意のブロックサイズで、同じ設定が同じ音を
  出す（時間で定義された量はすべて秒基準で保持し、サンプル数に変換して使う）。
- **受入条件**:
  - [x] 44.1 / 48 / 96 / 192 kHz で、同じ設定の遅延量が同じ時間になる
        — `DBL-8`（揺れの速度も同様に確認）
  - [x] ブロックサイズを変えても出力が変わらない（1 サンプルずつ処理しても
        同じ結果になる）— `DBL-8`。**構造的に成立**: `process` は純粋な
        サンプル単位ループで、スムーサは 1 サンプルに 1 回だけ読み、DSP は
        ブロック単位の状態を持たない。これを崩さないための規約を
        `.agents/rules/rust.md` に置いた
  - [x] サンプルレート変更時に確保済みバッファを超えない — `DBL-8`
        （`initialize` でサンプルレートが変わったらエンジンを作り直す）
- **依存**: REQ-DBL-011

## REQ-DBL-013: プリセット

- **優先度**: Won't (v1)
- **ステータス**: Decided
- **説明**: nih-plug はプリセット管理機構を持たない。v1 では**ホストの
  プリセット機構に任せ**、代わりに既定値を丁寧に決めることで初期状態が
  そのまま実用になるようにする。自前のプリセットブラウザは、既定値だけでは
  足りないと分かってから作る。
- **依存**: なし

## REQ-DBL-014: ミラー編集

- **優先度**: Should
- **ステータス**: Draft
- **説明**: 形状層の `Pan_i` / `Detune_i` / `Delay_i` を編集したとき、**対になる
  ボイスの同じ軸を鏡像の値で同時に書く**。対は形状表の並び順から決まる
  （0-1 / 2-3 / 4-5 / 6-7）。
- **鏡像の意味は軸で決まる**:
  - `Pan_i` と `Detune_i` は 0 を挟んで両側に振れるので、鏡像は**符号反転**
  - `Delay_i` は 0 から片側にしか伸びないので反転する符号が無く、鏡像は
    **同値**（対が同じ半径に並ぶ = 図が中心線について対称）
- **なぜ必要か**: `REQ-DBL-001` は「`Voices` を変えても定位が偏らない」ことを
  要求しているのに、**手編集には何の保護も無い**。既定の形状は対称なので、
  1 点動かした瞬間に像が傾き、相方を手で直す作業が発生する。ミラーはその作業を
  無くすためのもの。
- **対象は形状層の 4 軸すべて**: `Pan_i` / `Detune_i` / `Delay_i` / `Gain_i`。
  片側を下げて像を寄せたいときは `GAIN` のスイッチを切る。**軸ごとに
  スイッチがあるので、軸を除外する理由が無くなった**
- **`Delay_i` を含めるのは方針転換**（2026-08-26）。当初は「対で違う遅延を持つ
  ことがダブラーの中身そのもの」として除外していた。実物を触ると、**図が
  対称に見えないことのほうが問題**だった。厚みは対*どうし*の遅延差で出せるので、
  対の*内側*を非対称にする必要は無い。**代償**は、ミラーがオンの間は図から対を
  非対称にできないこと。従来の使い方はミラーをオフにすれば残る
- **UI の編集便宜であって、パラメータでも DSP の従属値でもない**:
  - パラメータにすると、音に直接作用しないものがホストのオートメーション一覧に
    並ぶ。オートメーションする意味が無いものなので置かない
  - DSP で従属値にすると、ホストに見えている `Pan_2` が黙って無視される状態に
    なり、それをオートメーションしていたプロジェクトが黄ばむ。`REQ-DBL-007`
    （二層が互いを上書きしない）とも衝突する
  - したがって**UI が 2 つのパラメータを書く**。パラメータは独立のままで、
    ホストのオートメーションも要件も壊れない
- **スイッチは軸ごとに独立**: `PAN` / `DETUNE` / `DELAY` の 3 個。マスター 1 個 +
  軸ごとの除外にすると、1 回の書き込みを 2 つの状態が決めることになり、
  「ミラーはオンだが Delay は連動しない」という読み取りにくい状態ができる
- **オン／オフの状態は保存する**: 音のパラメータではないので `ViziaState` に
  持ち、プロジェクトと一緒に復元される
- **既定は `PAN` と `GAIN` がオン、`DETUNE` と `DELAY` がオフ**: 図が対称に
  見えるかどうかを決めるのは角度（`Pan`）と半径（`Gain`）の 2 軸なので、
  点をドラッグして像が傾くのを既定で防ぐ。残る 2 軸は図に出ておらず、
  **対で違う遅延と揃いすぎない detune こそがダブラーの厚み**なので、
  既定では自由にしておく
- **受入条件**:
  - [x] ミラーがオンのとき、`Pan_i` を動かすと対のボイスの `Pan` が符号反転で
        追随する — `DBL-15`
  - [x] `Detune_i` も同様に追随する — `DBL-15`（Detail の表。図は角度と半径）
  - [x] `Delay_i` は同値で追随する — `DBL-15`
  - [x] `Gain_i` も同値で追随する — `DBL-15`（図の半径がこれなので必要になった）
  - [x] ミラーがオフのとき、どの軸も片側だけ動く — `DBL-15`
  - [x] 1 回のドラッグが、2 つのパラメータそれぞれについてホストへ 1 組の
        ジェスチャー（開始と終了）として届く — `DBL-15`
  - [x] 軸ごとにオン／オフできる — `DBL-15`
  - [x] オン／オフが DAW を開き直しても復元される — `DBL-15`
  - [x] Voice Field でも Detail の表でも同じように効く — `DBL-15`
- **依存**: REQ-DBL-007, REQ-DBL-008
