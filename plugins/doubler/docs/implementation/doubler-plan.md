# Doubler 実装計画

> 最終更新: 2026-08-25

要件は [`../requirements/REQ-DBL.md`](../requirements/REQ-DBL.md)、設計の正は
[`../specifications/dsp.md`](../specifications/dsp.md) と
[`../specifications/ui.md`](../specifications/ui.md)。この文書は**何を作るか**と
**その単位の完了条件**を持つ。順序の根拠は
[`../../../../docs/implementation/roadmap.md`](../../../../docs/implementation/roadmap.md)、
状態は [`../../../../docs/implementation/backlog.md`](../../../../docs/implementation/backlog.md)。

## 方針

**音が出るまでを最短で通す。** `DBL-4` で nih-plug ラッパを入れる時点で UI は
持たず、ホストが自動生成するパラメータ UI で音を確認する。2 タップシフタが
狙った音にならなければ、UI に投資したものが全部無駄になる。

**パラメータ集合が固まるまで UI を書かない。** UI は `DBL-9` 以降。それまでの
音の判断はホストの既定 UI で足りる。

## 実装単位

### DBL-1 — リングバッファ遅延線と Hermite 補間 ✅ `a84779d`

`doubler-core` に、秒で長さを決めるリングバッファと 4 点 Hermite 補間の
読み出しを置く。`initialize` 相当のコンストラクタで確保し、書き込み・読み出しは
確保済みバッファ内だけで動く。

- **完了条件**: インパルスが `delay × sr` サンプルの位置に出る。小数遅延で
  ピークの重心が期待位置にある。読み出し・書き込みの経路にヒープ確保が無い
- **要件**: REQ-DBL-002, REQ-DBL-011, REQ-DBL-012
- **依存**: なし
- **決めたこと**: バッファ長は 2 の冪に切り上げてラップをマスクで行う
  （割り算より速く、読み出しに分岐が入らない）。読み出せる最小遅延は
  2 サンプル（補間が 1 つ新しいサンプルを要るため）で、`dsp.md` に記録した。
  範囲外・NaN・∞ の遅延はクランプして panic させない

### DBL-2 — 回転タップピッチシフタ ✅ `f2501d6`

`dsp.md` の回転タップを実装する。窓とクロスフェード長は `const`。

**実装中に仕様を 1 つ差し替えた。** 元の `dsp.md` は位相 φ で 2 本のタップを
常に混ぜる書き方だったが、それは (1) 常にコムフィルタがかかり、(2) `cent = 0`
のとき φ が任意の値で止まるので静的なコムが残って透明にならない。回転タップ
（片方だけが鳴り、ラップ時だけ短くクロスフェードする）に変更し、理由を
`dsp.md` に記録した。窓は 40 ms → 50 ms、クロスフェード 5 ms。

- **完了条件**: 1 kHz 正弦を +100 cent で通したとき、ゼロクロス周期から求めた
  比が ±0.5 cent 以内 ✅（±100 / ±50 / 12 cent で確認）。detune 0 のボイスが
  素の遅延と一致する ✅（ビット一致）。ラップでクリックが出ない ✅。
  **±50 cent の範囲で継ぎ目が周期的なノイズとして聞こえない ✅ — 2026-08-25、
  Ableton Live で確認。クリックも水っぽさも無し。窓 50 ms / クロスフェード
  5 ms のまま確定（`DBL-13` で実素材を通したときに再確認する）**
- **要件**: REQ-DBL-002
- **依存**: DBL-1
- **決めたこと**: 遅延が窓の幅（50 ms）だけゆっくり揺れる。detune が付いた
  ボイスの遅延は固定値ではなく `[base, base + 50 ms]` のどこか。ダブラーとしては
  望ましい方向だが、**`Delay` マクロの表示値は `base` を指す**ので UI で
  意識する必要がある（`DBL-9`）

### DBL-3 — ボイスエンジン ✅ `3aec7af`

形状表、マクロ × 形状の実効値計算、等パワーパン則、`Gain_i` の二乗和による
ゲイン補償。この時点では Humanize も Tone も Source モードも無く、
Mono Sum 固定。

- **完了条件**: N ∈ {2,4,8} の先頭 N 個で `Pan_i` と `Detune_i` の総和が 0 ✅。
  白色ノイズで `Voices` を変えて wet の RMS が ±1 dB 以内 ✅。マクロを変えても
  形状層の値が変化しない ✅（`process` が形状を共有参照で受けるので型で保証）
- **要件**: REQ-DBL-001, REQ-DBL-006, REQ-DBL-007
- **依存**: DBL-2
- **決めたこと**:
  - `Voices` は `enum`（2 / 4 / 8）。範囲外の本数が存在できない
  - ゲイン補償はボイス数ではなく `Gain_i` の**二乗和**で割る。特定のボイスを
    下げた場合も自然に効き、全ボイスが無音のときも 0 除算しない
  - 形状表の遅延は、どの `Voices` でも先頭 N 個が互いに 0.05 以上離れている
    ことをテストで固定した（2 ボイスが同じ遅延なら 1 ボイスが 2 倍の音量で
    鳴るだけになる）

### DBL-4 — nih-plug ラッパと配線（ここで音が出る）✅ `556c5a0`

`doubler` クレートにパラメータを宣言し、`doubler-core` に渡す。UI は持たない
（ホストの既定パラメータ UI を使う）。CLAP と VST3 のバンドルが出る。

**43 個を一度に宣言しない。** 各単位が自分のパラメータを持ち込む形にする —
`DBL-4` で 38 個（マクロ 6 + 形状 32）、`Humanize` は `DBL-5`、`Source` は
`DBL-6`、`Tone` 3 個は `DBL-7`。効かないコントロールがホストの一覧に並ぶ状態を
作らないため。パラメータ集合が確定するのは当初の予定どおりフェーズ 2 の終わり
（`DBL-8`）。

- **完了条件**: Bitwig で CLAP、Reaper で VST3 として読み込め、パラメータが
  オートメーションできる。状態がプロジェクトに保存・復元される。`Mix` = 0 で
  出力が入力とサンプル単位で一致する。ホストへの報告レイテンシが 0
- **要件**: REQ-DBL-006, REQ-DBL-009, REQ-DBL-010
- **依存**: DBL-3, INFRA-1
- **既知の制限**: `AUDIO_IO_LAYOUTS` はステレオのみ。モノトラックに挿せない
  ホストがある。モノ入力の扱いは `REQ-DBL-004` の話なので `DBL-6` で決める

### DBL-5 — Humanize ✅

ボイスごとに独立した 2 つのランダム源（目標値 + 1 次スルー、xorshift、
index 由来のシード）。detune と遅延の両方に効かせる。

- **完了条件**: `Humanize` = 0 で完全に静的（同じ入力を 2 回通して出力が一致）✅。
  上げると各ボイスが独立に揺れる ✅。揺れによるクリックが無い ✅。
  **周期性が聞こえないことの確認は耳が要る — `DBL-13` で判定する**
- **要件**: REQ-DBL-003
- **依存**: DBL-3
- **決めたこと**:
  - ランダム源は「一定間隔でランダムな目標を引き、1 次スルーで近づく」形。
    出力が構造的に `[-1, 1]` に収まり、周期を持たない
  - **目標更新間隔はボイスごとに固定**（400〜1200 ms から乱数で 1 回引く）。
    全ボイスが同じ間隔だと足並みが揃って LFO に戻る
  - シードは `index × 2654435761 | 1` で散らす。連続する小さい整数をそのまま
    xorshift に入れると、ボイス 0 と 1 がほぼ同じ列で始まる
  - 深さは detune ±8 cent、遅延 ±3 ms。**遅延側を意図的に小さくしている** —
    読み出し位置が動くこと自体がピッチ変化なので、遅延を広く揺らすと
    タイミングではなくグライドとして聞こえる

### DBL-6 — Source モード

`Mono Sum` / `True Stereo` と、切り替え時の入力クロスフェード。`dsp.md` の
パン則をモードごとに実装する。

- **完了条件**: Mono Sum でモノ入力とステレオ入力（同内容）の結果が一致。
  True Stereo で L のみに信号があるとき R 由来のボイスが無音。切り替えで
  クリックが出ない
- **要件**: REQ-DBL-004
- **依存**: DBL-3

### DBL-7 — Tone と Tone Spread

wet バスの 2 段シェルビングと、ボイスごとの 1 次 HPF / LPF。`Tone Spread` = 0
のときはフィルタごと迂回する。

- **完了条件**: `Tone` が wet のみに効き Dry のスペクトルが変わらない。
  `Tone Spread` = 0 で全ボイスの出力が一致する。上げると音色差が出て、
  同じ設定なら毎回同じ散り方になる
- **要件**: REQ-DBL-005
- **依存**: DBL-3

### DBL-8 — スムージングと非依存性の詰め

`dsp.md` のスムージング表を実装し、サンプルレートとブロックサイズの非依存を
検証する。`Voices` / `Source` の切り替えフェードもここで仕上げる。

- **完了条件**: 44.1 / 48 / 96 / 192 kHz でインパルスの到達時刻が一致。
  512 サンプル一括と 1 サンプルずつで出力が一致。全パラメータの変更で
  クリックが出ない
- **要件**: REQ-DBL-012, REQ-DBL-001, REQ-DBL-004, REQ-DBL-006
- **依存**: DBL-5, DBL-6, DBL-7

### DBL-9 — UI マクロ層

`ui.md` の既定表示のうち、ノブとセグメントコントロール。`param_bind.rs` で
パラメータと結線する。この時点で Voice Field の領域は空箱。

- **完了条件**: 既定の表示に形状層のコントロールが無い。ノブが縦ドラッグ・
  `Shift` 微調整・ダブルクリックリセット・ツールチップに応じる。ドラッグが
  ホストのオートメーション記録で 1 操作としてまとまる
- **要件**: REQ-DBL-008
- **依存**: DBL-4, UI-4, UI-6, UI-2

### DBL-10 — UI Voice Field

`nxe-ui` の `PolarField` に「ボイス → 点」の対応を与え、既定表示の主役に据える。
角度 = 定位、半径 = 遅延、大きさ = `Gain_i`、揺れ = Humanize の実際の量。
点のドラッグで `Pan_i` と `Delay_i` を同時に編集する。

- **完了条件**: `Voices` を変えると点の数が変わり、無効な点がディムになる。
  マクロを動かすと点が動く。点をドラッグすると形状層の 2 つの値が同時に変わり、
  マクロは変わらない。`Humanize` を上げると点が揺れ、`0` で静止する。
  `Source` = True Stereo で ▲ が 2 つになり、各点がどちらの子か分かる。
  ドラッグがホストのオートメーション記録で 1 操作としてまとまる
- **要件**: REQ-DBL-007, REQ-DBL-008
- **依存**: DBL-9, DBL-5, DBL-6, UI-7

### DBL-11 — UI Detail 層

8 行のボイス表。**バーは形状値、数値は実効値。** 無効な行はディム表示だが
編集できる。開閉の状態を `ViziaState` に保存する。

- **完了条件**: マクロを動かすとバーは動かず数値が追随する。バーをドラッグ
  すると形状が変わりマクロは変わらない。**表と Voice Field が同じ形状層を
  即座に反映し合う**。`Voices` で無効な行がディムになる。DAW を開き直して
  開閉状態が復元される
- **要件**: REQ-DBL-007, REQ-DBL-008
- **依存**: DBL-10, UI-5

### DBL-12 — CPU 予算の確認

criterion のベンチを置き、48 kHz / 512 サンプル / `Voices` = 8 /
`Source` = True Stereo で 1 コア 5% 未満を確認する。

- **完了条件**: ベンチが予算を満たし、回帰を検出できる。満たさない場合は
  ボトルネックと対策（または予算の見直し）をこの計画に追記する
- **要件**: REQ-DBL-011
- **依存**: DBL-8

### DBL-13 — 既定値の詰めと実機確認

`dsp.md` の「耳で詰める定数」を実素材で調整する。ボーカル・ギター・シンセの
3 種で確認し、決めた値と理由を `dsp.md` に反映する。

- **完了条件**: プラグインを挿して既定値のまま実用になる。Bitwig と Reaper で
  一通り操作して問題が無い。`dsp.md` の定数表が最終値になっている
- **要件**: REQ-DBL-013（プリセットを持たない代わりに既定値で成立させる）
- **依存**: DBL-12, DBL-11
