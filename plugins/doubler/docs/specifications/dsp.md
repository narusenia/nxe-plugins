# Doubler — DSP 仕様

> 最終更新: 2026-08-25

要件は [`../requirements/REQ-DBL.md`](../requirements/REQ-DBL.md)。この文書は
「どう振る舞うべきか」を式のレベルで決める。実装は `doubler-core`。

## 信号フロー

```
                  ┌──────────────────────────────── Dry（無加工・遅延なし）──────┐
                  │                                                              │
 in L ─┬──────────┤                                                              ▼
       │          │   ┌─ voice 0 ─ delay line ─ 2-tap shifter ─ tone spread ─ pan ─┐
 in R ─┴─ source ─┴──▶├─ voice 1 ─ delay line ─ 2-tap shifter ─ tone spread ─ pan ─┤
          select      ├─ …                                                        ├─ wet bus
                      └─ voice N-1 ────────────────────────────────────────────── ┘   │
                                                                                       │
                                              humanize（各ボイスの delay / detune へ）  │
                                                                                       ▼
                                                       tone lo/hi ─ gain 補償 ─ mix ─ output ─ out
```

Dry は wet バスを一切通らない。したがってホストに報告するレイテンシは 0
（`REQ-DBL-006`）。

## 遅延線

**入力チャネルごとに 1 本**のリングバッファを持ち（つまり L と R の 2 本）、
各ボイスが独立した読み出し位置を持つ。ボイスごとにバッファを持たない（同じ
内容を N 本持つ意味がない）。

**モノ和のための 3 本目は持たない。** 遅延線も Hermite 補間も線形なので
`(readL(d) + readR(d)) / 2` は、和をとった線を読んだ結果と厳密に一致する。
バッファが 1 本減るだけでなく、書き込み経路にモードの分岐が入らず、そして
**`Source` の切り替えが「バッファの内容の間」ではなく「読み出しの式の間」の
クロスフェードで済む**。これが本当の利点。

代償として `Mono Sum` でも読み出しが 2 回になる（当初「遅延線のコストも半分」
と書いていたが、それは成り立たない）。8 ボイス・最大 2 タップで 1 サンプル
あたり最大 32 回の補間読み出しで、`REQ-DBL-011` の予算には収まる範囲。

長さは秒で決めて確保する:

```
最大遅延 80 ms + 揺れ 3 ms + シフト窓 50 ms + 補間マージン 4 サンプル
→ 余裕を見て 150 ms を最大サンプルレートで確保する
```

バッファ長は 2 の冪に切り上げ、ラップは剰余ではなくマスクで行う（割り算より
速く、読み出しに分岐が入らない）。

192 kHz でも 1 チャネルあたり 28,800 サンプル（115 KB）。`initialize()` で
確保し、`process()` では触らない（`REQ-DBL-011`）。

### 補間

4 点 Hermite（Catmull-Rom）補間。線形補間は読み出し位置が小数のとき高域を
落とし、それが常時かかるので使わない（`REQ-DBL-002`）。

**読み出せる最小遅延は 2 サンプル。** 補間は読み出し位置より 1 つ新しい
サンプルを必要とし、バッファ中で最も新しいサンプルは遅延 1 に居るので、2 が床。
シフタの `base_delay` はこれを下回れない（実用上の最小遅延は ms オーダーなので
制約にならないが、テストで 1 を渡すと黙って 2 に丸められる）。

## ピッチシフト — 回転タップ

各ボイスの定常的な音程ずらしは、遅延線を `2^(cent/1200)` のレートで読むことで
作る。レートが 1 でなければ読み出し位置は書き込み位置から無限に離れていくので、
**1 窓ぶん巻き戻して短いクロスフェードで継ぎ目を隠す**。

```
rate   = 2^(cent / 1200)
drift  = 1 − rate                  1 サンプルあたりに読み出し位置がずれる量
W      = 50 ms を sample 換算        窓
C      = 5 ms を sample 換算         クロスフェード長

毎サンプル:
  offset += drift                  offset は base_delay より奥への距離
  if offset > W:  fade_from = offset; offset −= W; fade_left = C
  if offset < 0:  fade_from = offset; offset += W; fade_left = C

  live = read(base_delay + offset)
  fade_left が 0 なら out = live                    ← 大半の時間はこちら
  そうでなければ
    p    = 1 − fade_left / C
    out  = sin(p·π/2) × live + cos(p·π/2) × read(base_delay + fade_from)
```

**大半の時間はタップが 1 本しか鳴っていない。** これがこの形を採る理由。
同じ信号を違う遅延で読んだ 2 本を常時混ぜると互いにコムフィルタになり、音に
恒常的な色が付く。回転タップならコムはラップの瞬間の数 ms だけで、その間隔は
秒のオーダー（±50 cent で約 1.7 秒に 1 回、既定の 12 cent なら 7 秒に 1 回）。

**`cent = 0` が特別扱いなしに厳密に透明になる。** drift が 0 なので読み出し
位置が動かず、ラップもクロスフェードも起きない。出力は遅延線を `base_delay` で
読んだ値そのもの（`REQ-DBL-002` の受入条件。テストはビット一致で確認している）。

### 連続 2 タップ版を採らなかった理由

位相 φ を回して 2 本のタップを常に `sin(πφ)` / `|cos(πφ)|` で混ぜる書き方が
広く知られているが、これは採らない。

1. **常にコムがかかる。** 2 本は `W/2` 違いの遅延で同じ信号を読むので相関が
   あり、パワーは保たれても櫛状の色が付き続ける
2. **`cent = 0` で透明にならない。** drift が 0 になると φ は**任意の値で
   止まる**。φ が 0 でも 0.5 でもなければ 2 本が鳴ったまま固定され、静的な
   コムが残る。要件を満たすには特別扱いが必要になり、その特別扱いに入る/出る
   境界で遅延が跳ねる

### 副作用: 遅延が窓の幅だけ揺れる

読み出し位置は `[base, base + W]` を往復するので、**聞こえる遅延は 50 ms の幅で
ゆっくり動く**。detune が付いているボイスの遅延は「`base` から `base + 50 ms`
のどこか」であって固定値ではない。

これは欠点ではなく、ダブラーとしては望ましい方向（テイクごとの微妙な
タイミング差そのもの）。ただし **`Delay` マクロの表示値は `base` を指す**
ことを UI 側で意識する必要がある。

### 補間

`base_delay + offset` は常に小数なので、遅延線の 4 点 Hermite 補間が全サンプルに
かかる（`DelayLine`）。

### 範囲の限界

クロスフェードの継ぎ目は原理的に消えない。保証するのは **±50 cent の範囲で
継ぎ目が単体で聞き取れないこと**だけ。1 オクターブ級のシフトは対象外。

なお、ラップの間隔がクロスフェード長より短くなると 3 本目のタップが必要に
なるが、実装は古いタップを捨てる。これが起きるのは ±50 cent を遥かに超える
シフト量のときだけで、この製品はそこを露出しない。

## ボイスの既定形状

形状層は正規化された相対値で、マクロが掛かる（`REQ-DBL-007`）。既定値は
**先頭から N 個を取ったときに左右対称になる順**に並べる。これで `Voices` を
8 → 2 に変えても定位が偏らない（`REQ-DBL-001`）。

| index | `Pan_i` | `Detune_i` | `Delay_i` | `Gain_i` |
|---|---|---|---|---|
| 0 | −1.00 | −1.00 | 1.00 | 0 dB |
| 1 | +1.00 | +1.00 | 0.62 | 0 dB |
| 2 | −0.45 | −0.40 | 0.84 | 0 dB |
| 3 | +0.45 | +0.40 | 0.44 | 0 dB |
| 4 | −0.75 | −0.70 | 0.92 | 0 dB |
| 5 | +0.75 | +0.70 | 0.30 | 0 dB |
| 6 | −0.20 | −0.25 | 0.72 | 0 dB |
| 7 | +0.20 | +0.25 | 0.52 | 0 dB |

`Pan_i` と `Detune_i` は先頭 2 個・4 個・8 個のいずれで切っても総和が 0。
`Delay_i` は対称である必要がないので、先頭から取ったときに値が散ることだけを
満たす。

既定のマクロ値（`Detune` = 12 cent / `Delay` = 22 ms）で `Voices` = 4 のとき、
実効値は `±12 / ±4.8 cent`、`22 / 13.6 / 18.5 / 9.7 ms`。

## Humanize

ボイスごとに独立した 2 つのランダム源（detune 用・遅延用）を持つ。

**方式**: 一定間隔でランダムな目標値を引き、そこへ 1 次のスルーで近づく。
出力は構造的に `[−1, +1]` に収まり、周期性を持たない。

```
目標更新間隔  400 – 1200 ms（ボイスごとに固定の値。乱数で決めて保持）
目標値        uniform(−1, +1)
スルー        1 次 IIR、時定数 300 ms
乱数          xorshift。ボイス index からシードを決めるので再現可能
```

周期 LFO は採らない（`REQ-DBL-003`）。

**深さ**:

```
detune 揺れ = ±(Humanize × 8 cent)
遅延  揺れ = ±(Humanize × 3 ms)
```

遅延が動くと読み出しレートが変わるので、揺れている間はピッチも微かに動く。
これは意図した挙動で、ダブラーの「テイク感」の大半はここから出る。深さの上限を
3 ms に抑えているのは、これ以上速く動かすとピッチの過渡が音程として聞こえ
始めるため。

`Humanize` = 0 でランダム源の出力を 0 に固定し、完全に静的な detune / 遅延に
なる（＝ MicroShift 相当の設定が作れる）。

## 定位

等パワーパン則。`p ∈ [−1, +1]` に対して:

```
θ  = (p + 1) × π / 4
gL = cos θ
gR = sin θ
```

`Source` モードで `p` の求め方が変わる（`REQ-DBL-004`）。

```
Mono Sum:     p_i = Spread × Pan_i

True Stereo:  src_i = −1（i が偶数 → L）/ +1（i が奇数 → R）
              p_i   = src_i × (0.5 + 0.3 × Spread) + Pan_i × 0.2 × Spread

モード切り替え中は両者を blend で線形補間する（blend は 20 ms で遷移）
```

True Stereo 側の係数は、`Spread` = 0 でソース側の位置が ±0.5（やや内寄り）、
`Spread` = 1 で ±0.8 を中心に `Pan_i` が ±0.2 動く、という設計。上限が
ちょうど ±1.0 に収まるので clamp が働かない（テストで固定してある）。

**`Pan` の意味がモードで変わる**ことは仕様。同じ設定でモードを切り替えると
定位が変わる。

## Tone

### Tone Lo / Tone Hi

wet バスにのみかかる 2 つのシェルビング。Dry には一切かからない。

```
Tone Lo: 低域シェルフ、200 Hz、±12 dB
Tone Hi: 高域シェルフ、4 kHz、±12 dB
```

RBJ のシェルビング係数で biquad 各 1 段。チャネルごとに独立。

### Tone Spread

ボイスごとに 1 次の HPF と LPF を挿し、カットオフをボイスごとに散らす。
散らし方は固定シード（ボイス index 由来）なので再現可能。

```
u_i, v_i    = uniform(−1, +1)、ボイス index からのシードで固定
HPF cutoff  = 20 Hz  × 2^(u_i × Spread × 3.5)     →  Spread=1 で 1.8 – 226 Hz
LPF cutoff  = 20 kHz / 2^(|v_i| × Spread × 2.5)   →  Spread=1 で 3.5 – 20 kHz
```

`Tone Spread` = 0 のとき HPF は 20 Hz、LPF は 20 kHz で実質的に透明になるが、
**係数を計算せずフィルタごと迂回する**。「0 のとき音が変わらない」を、
係数の丸めに依存させないため（`REQ-DBL-005` の受入条件）。

## ゲイン補償

ボイスは互いに非相関なのでエネルギーはボイス数に概ね比例する。補償しないと
`Voices` を上げただけで音量が上がり、比較にならない（`REQ-DBL-006`）。

```
wet_gain = 1 / sqrt( Σ_{i<N} g_i² )      g_i = dB→linear(Gain_i)
```

ボイス数ではなく `Gain_i` の二乗和で割るので、特定のボイスを下げた場合も
自然に効く。

## スムージング

パラメータの変化はすべて時間をかける。値ごとに時定数が違うのは、変化が
音に出る経路が違うため。

| 対象 | 時定数 | 理由 |
|---|---|---|
| `Mix` / `Output` / `Tone` | 20 ms | 単純なゲインと係数 |
| `Detune` / `Detune_i` | 30 ms | 読み出しレートの変化 |
| `Delay` / `Delay_i` | 100 ms | 読み出し位置が動く＝ピッチが動くので、速いと過渡が聞こえる |
| `Pan_i` / `Gain_i` | 20 ms | ゲイン |
| `Voices` の変更 | 20 ms | 無効化されるボイスをフェードアウト、有効化をフェードイン |
| `Source` の変更 | 20 ms | 遅延線への入力を 2 つの経路間でクロスフェード |

`Voices` と `Source` は離散パラメータなので、値そのものは飛ぶ。クリックを
防ぐのは値の補間ではなくゲインとクロスフェードの側（`REQ-DBL-001` /
`REQ-DBL-004` の受入条件）。

## 耳で詰める定数

次の値は理屈で決めた初期値であって、最終値は耳で決める。**実装では 1 箇所の
`const` ブロックにまとめる**。散らばると調整が事実上できなくなる。

- シフト窓 `W` = 50 ms、クロスフェード `C` = 5 ms
- Humanize の目標更新間隔 400 – 1200 ms、スルー時定数 300 ms
- Humanize の深さ係数 8 cent / 3 ms
- True Stereo のパン係数 0.5 / 0.3 / 0.2
- `Source` 切り替えのクロスフェード 20 ms
- Tone Spread の散らし幅 3.5 / 2.5 オクターブ
- Tone のシェルフ周波数 200 Hz / 4 kHz
- 既定の形状表（上記）

## 検証

`doubler-core` に `#[test]` で置く。ホストは要らない（`REQ-DBL-010`）。

| # | 何を確かめるか | 方法 |
|---|---|---|
| 1 | 遅延線が指定時間で出る | インパルスを入れ、出力のピーク位置が `delay × sr` サンプルであること |
| 2 | Hermite 補間が小数遅延を扱える | 小数遅延でピークの重心が期待位置にあること |
| 3 | シフタの音程が合う | 1 kHz 正弦を +100 cent で通し、ゼロクロス周期から比を測って ±0.5 cent 以内 |
| 4 | detune 0 が透明 | detune 0 のボイスがシフタを通っても、素の遅延と一致すること |
| 5 | 形状表が対称 | N ∈ {2,4,8} の先頭 N 個で `Pan_i` と `Detune_i` の総和が 0 |
| 6 | ゲイン補償が効く | 白色ノイズで `Voices` を 2/4/8 に変えて wet の RMS が ±1 dB 以内 |
| 7 | サンプルレート非依存 | 44.1 / 96 kHz でインパルスの到達**時刻**が一致 |
| 8 | ブロックサイズ非依存 | 512 サンプル一括と 1 サンプルずつで出力が一致 |
| 9 | Dry が素通し | `Mix` = 0 で出力が入力とサンプル単位で一致 |
| 10 | Humanize 0 が決定的 | 同じ入力を 2 回通して出力が一致 |
| 11 | Tone Spread 0 が透明 | `Tone Spread` = 0 で全ボイスの出力が一致 |

CPU 予算（`REQ-DBL-011`）は criterion のベンチで確認する。ベンチは予算を
主張するためだけに存在するので、他の用途で増やさない。
