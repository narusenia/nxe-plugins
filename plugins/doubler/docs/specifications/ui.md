# Doubler — UI 仕様

> 最終更新: 2026-08-25

要件は [`../requirements/REQ-DBL.md`](../requirements/REQ-DBL.md)、守るべき規約は
[`../../../../.agents/rules/vizia.md`](../../../../.agents/rules/vizia.md)。

## 設計方針

**何が起きているかが図で分かる。** マルチボイスダブラーの状態は「どのボイスが
どこに、どれだけ遅れて、どれだけ揺れて居るか」で、これは数値の列よりも図の
方が速く読める。画面の主役は Voice Field（下記）で、ノブはその図を動かすための
道具として下に置く。

**普段触るのは 4 つのノブだけ。** パラメータは 43 個あるが、実際に使うのは
`Detune` / `Delay` / `Spread` / `Humanize` でほぼ足りる。残りを常時見せると
「シンプルで使いやすい」が壊れる。

**マクロと個別値は同時に生きている。** どちらを触っても他方が消えない
（`REQ-DBL-007`）。図・バー・数値の 3 つの見せ方すべてがこの性質を保つ。

## Voice Field

画面の主役。ボイスは**定位**と**遅延**という 2 軸を持つので、極座標に載せると
両方が一度に見える。

```
            L                       C                       R
      22ms  ╭──────────────────────────────────────────╮
           ╱          ④                    ③           ╲
          │                 ②        ①                  │
    -24dB ╰────────────────────▲─────────────────────────╯
                            SOURCE
```

| 見た目 | 意味 |
|---|---|
| 角度 | 定位。左端が L、真上が C、右端が R |
| 半径 | **レベル。** 中心が `Gain_i` の下端（−24 dB）、外周が上端（+6 dB） |
| 点の大きさ | `Delay_i` |
| ▲ の半径 | Dry のレベル（`1 − Mix`）。ドラッグで `Mix` を編集する |
| ポインタが乗った点 | リングが付き、**index が通知される**（Detail 表の対応する行をハイライトするため） |
| 点の揺れ | `Humanize` が動かしている実際の量。**揺れが目で見える** |

**detune は図に載せない。** 4 軸目を詰め込むと記号の意味を覚える UI になる。
detune はマクロノブと Detail の表、そして揺れている点の動きで足りる。

**点に番号も描かない。** vizia の `draw_text` は view 自身のテキストしか描けず、
1 つの view に 8 個の数字を置く道が無い。代わりにポインタが乗っている点の index が
通知されるので、**図と Detail 表を相互にハイライトする**ことで対応が分かる形に
する。小さい数字 8 個より読みやすい。

**`Source` = True Stereo のとき ▲ が 2 つになる。** L と R の位置に立ち、各点が
どちらのソースの子かを細い線で示す。モードの差が図で分かる。2 つは**同じ `Mix` を
表示**していて、どちらをドラッグしても同じ 1 つの値を書く。

**▲ は `Mix` のハンドル。** 半径は dry の振幅（`1 − Mix`）で、**点の半径の
dB 目盛りとは別**。dB には下端が無く、この印が外してはいけないのは
「`Mix` = 100% でちょうど原点に来る」ことのほうだから（`REQ-DBL-006`）。
どちらも「外ほど大きい」の読み方は同じ。`Mix` との違いは、`Mix` が dry/wet の比で、`Dry Gain` がその外側に掛かる
Dry だけのトリムであること（`REQ-DBL-006`）。

### 操作

点をドラッグすると、そのボイスの `Pan_i` と `Gain_i` を**同時に**編集する。
これが図を主役にする理由で、形を直接いじれることが一番分かりやすい。

**ミラーがオンなら対のボイスの点も鏡に映ったように動く**（`REQ-DBL-014`）。
対は index の並び（0-1 / 2-3 / 4-5 / 6-7）で決まる。角度は反転し、半径
（レベル）は同値で追随する。

- ドラッグ = `Pan_i`（角度）と `Gain_i`（半径）を同時に変更
- `Shift` = 微調整
- 点をダブルクリック = そのボイスの形状値を既定に戻す
- 図の外周をドラッグしても何も起きない
- ドラッグ中はホストへジェスチャー開始／終了を通知する（2 パラメータぶん）

`Voices` で無効なボイスの点は**描かない**。ディム表示にしていたら図が
ごちゃついた。使っていないボイスの点からは読み取るものが無く、**先に仕込んで
おく場所は Detail の表**（そちらはディムのまま編集できる）。有効なボイスは
常に先頭 N 個なので、点の並び順はボイスの index のままで、表とのハイライトの
対応も崩れない
（8 ボイスで使う設定を 4 ボイスのまま仕込める方が実用的）。

### 実装の境界

`nxe-ui` に入るのは領域知識を持たない `PolarField`。点の一覧（角度・半径・
大きさ・ラベル・有効かどうか）と、ドラッグのコールバックしか知らない。
「ボイス」「遅延」「定位」を知っているのは Doubler 側の対応付けだけ。

この境界があると `PolarField` を gallery で単体レビューできる
（`.agents/rules/vizia.md`）。

## Filter View

Tone セクションは曲線で見せる。ノブ 2 つで低域と高域を上下させるより、
**かかっている形をそのまま見せて、その形を直接つかむ**方が速い。Voice Field と
同じ思想。

```
   +12 ┤                                                    ╭──────
       │╲                                                 ╭─╯
     0 ┤ ╰───────────────────────────────────────────────╯
       │▒▒▒▒▒░░░░░              ░░░░░▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒
   −12 ┤
       └────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬────
           20     50    200    500     1k     2k     5k    20k
```

| 見た目 | 意味 |
|---|---|
| 実線 | wet バスにかかる低域シェルフ + 高域シェルフの合成応答 |
| 左右のハンドル | `Tone Lo`（200 Hz）と `Tone Hi`（4 kHz）。**縦ドラッグで編集** |
| 薄い帯 | `Tone Spread` が各ボイスに与えている HPF / LPF の帯域。散らばりが目で見える |
| 横軸 | 対数。20 Hz – 20 kHz |

**Tone Lo / Tone Hi のノブは置かない。** 曲線のハンドルが同じことをする。
周波数は固定なので縦ドラッグだけで足り、ノブより情報量が多い。`Tone Spread` は
「散らばりの量」なのでノブのまま残し、その効果は帯の広がりとして曲線に出る。

`Tone Spread` = 0 のときフィルタは迂回されるので、帯も描かない
（`REQ-DBL-005`）。**画面に何も無いことが「何もかかっていない」ことを表す。**

### 実装の境界

`nxe-ui` に入るのは領域知識を持たない `CurveView`。折れ線の集合と帯の区間、
目盛りの x 位置、縦ドラッグ可能なハンドルしか知らず、座標はすべて正規化。

**周波数 → x の対数写像は Doubler 側が持つ。** ウィジェットに持たせない理由は、
軸ラベルを描けるのが呼び出し側だけだから（vizia の `draw_text` は view 自身の
テキストしか描けない）。同じ写像を使ってラベルを絶対配置する。dB → y の写像も
同様に Doubler 側。

## レイアウト

タブは `MAIN` と `DETAIL` の 2 つ。窓は 620 × 572 固定。

**Voice Field はタブの外**（常時表示）。このプラグインが何であるかを示している
図なので、タブに隠すと窓に見るものが無くなる。**`MIX` と `OUTPUT` もタブの外**で、
図の横に縦に積む — 全体に効く値は、効く対象の隣に置く。**`Mix` には ▲ と
ノブの両方がある** — 形状層に図と表の両方があるのと同じで、片方は読むため、
もう片方は数値を決めるため。

```
┌──────────────────────────────────────────────────────────────┐
│  NXE DOUBLER                 [ 2 │ 4 │ 8 ]  [ Mono │ Stereo ]│
├───────────────────────────────────────────────┬──────────────┤
│   L                    C                 R    │              │
│     +6dB ╭───────────────────────────╮        │      ◕       │
│         ╱   ④  ②              ①  ③   ╲      │     MIX      │
│        │            ▲                  │      │     40 %     │
│        │          SOURCE               │      │      ◕       │
│  −24dB ╰───────────────────────────────╯      │    OUTPUT    │
│                                               │    0.0 dB    │
├───────────────────────────────────────────────┴──────────────┤
│  [ MAIN │ DETAIL ]   ⇄ MIRROR [PAN][DETUNE][DELAY][GAIN]     │
├──────────────────────────────────────────────────────────────┤
│      ◕            ◕            ◕            ◕                │
│    DETUNE       DELAY       SPREAD      HUMANIZE             │
│    12.0 ct      22.0 ms      70 %         35 %               │
│  TONE   +12┤╲                    ╭────         ◔ SPREAD 0    │
│           0┤ ╰────────────────────╯                          │
│         −12┤ 20    200    1k    5k   20k                     │
└──────────────────────────────────────────────────────────────┘
```

`DETAIL` タブは `MAIN` の領域と入れ替わる。図と `MIX` / `OUTPUT` はそのまま:

```
├──────────────────────────────────────────────────────────────┤
│        DELAY            DETUNE           PAN          GAIN   │
│  1  ▓▓▓▓▓▓▓▓ 22.0ms  ▓▓▓▓▓▓ −12.0ct  ▓▓▓▓ L70   ▓▓▓  0.0dB   │
│  2  ▓▓▓▓▓░░░ 13.6ms  ▓▓▓▓▓▓ +12.0ct  ▓▓▓▓ R70   ▓▓▓  0.0dB   │
│  3  ▓▓▓▓▓▓▓░ 18.5ms  ▓▓▓░░░  −4.8ct  ▓▓░░ L32   ▓▓▓  0.0dB   │
│  4  ▓▓▓▓░░░░  9.7ms  ▓▓▓░░░  +4.8ct  ▓▓░░ R32   ▓▓▓  0.0dB   │
│  5  ░░░░░░░░ 20.2ms  ░░░░░░  −8.4ct  ░░░░ L53   ░░░  0.0dB   │  ← dim
│  6  ░░░░░░░░  6.6ms  ░░░░░░  +8.4ct  ░░░░ R53   ░░░  0.0dB   │  ← dim
│  7  ░░░░░░░░ 15.8ms  ░░░░░░  −3.0ct  ░░░░ L14   ░░░  0.0dB   │  ← dim
│  8  ░░░░░░░░ 11.4ms  ░░░░░░  +3.0ct  ░░░░ R14   ░░░  0.0dB   │  ← dim
└──────────────────────────────────────────────────────────────┘
```

**バーは形状（正規化値）、数値は実効値。** これが二層の見せ方の核。バーを
ドラッグすると形状層が変わり、数値はマクロを掛けた結果として追随する。
`Detune` マクロを動かすとバーは動かず数値だけが変わる。

`DELAY` / `DETUNE` / `PAN` / `GAIN` のバーは、その軸のミラーがオンなら対の行も
同時に動く
（`REQ-DBL-014`）。`DELAY` と `GAIN` は動かない。

表は**数値で詰めるため**に残す。図では detune を編集できないので、表を消すと
detune のボイス別編集ができなくなる。図と表は同じ形状層を別の見せ方で
出しているだけなので、片方をドラッグすればもう片方が即座に追随する。

## ミラー

`REQ-DBL-014`。**形状層 4 軸を編集すると対のボイスが鏡像で追随する。**
既定は `PAN` と `GAIN` がオン（図が対称に見えるかを決める 2 軸）、
`DETUNE` と `DELAY` がオフ（対の非対称さがダブラーの厚み）。対は `doubler_core::mirror_partner`
（`index ^ 1`）で、形状表がその並びで鏡像になっていることは core のテストが
押さえている。

**鏡像の意味は軸で決まる。** `Pan` と `Detune` は 0 の両側に振れるので符号反転、
`Delay` は片側にしか伸びないので同値。だから図では、点をドラッグすると対の点が
中心線を挟んだ反対側で同じ半径を保って動く — 見たままの鏡像。

- トグルは**タブ行の右側**に、`⇄ MIRROR` に続けて `PAN` / `DETUNE` / `DELAY` /
  `GAIN` の 4 個を置く。図と表の両方に効くので、Detail を開かなくても届く位置に
  要る
- **図の上に重ねない。** 4 個を右上に重ねると外周の点が隠れる。アイコンだけに
  すると（ツールチップが無い今）Detune と Delay を見分けられず、縦に並べると
  図の幅が減る。タブ行の右側はもともと空いていて、どれも払わずに済む
- **軸ごとに独立した 4 個**。マスター 1 個 + 除外にすると 1 回の書き込みを
  2 つの状態が決めることになる（`REQ-DBL-014`）
- 4 個は**別々の `.segmented` グループ**にする。1 つのグループに並べるのは、
  この UI では「どれか 1 つを選ぶ」の意味になっている（`Voices` / `Source` /
  タブ）
- オンのとき pill は accent、オフのときは `muted`
- **4 軸すべてが追随する。** 片側を下げて像を寄せたいときは `GAIN` の
  スイッチを切る。図の半径が `Gain_i` なので、`GAIN` を外したままだと点を
  ドラッグするだけで像が傾く — ミラーが防ぎたかったことそのもの
- ミラーで動いた側の点も、ドラッグしている間ハイライトする。何が連動したのかが
  見えないと「勝手に動いた」に見える。バーのほうは表の行のハイライトが兼ねる

**新しいウィジェットは要らない。** `.segment` のスタイル（`:checked` で accent）を
単体の `Label` に当て、`checked` と `on_press` を付ければトグルになる。
`ToggleSwitch`（`UI-9`）はスライドする switch の見た目で、フィールドの隣に置く
道具としては合わない。2 つ目の用例が出たら共通化する。

## サイズと DPI

- **窓は 620 × 572 の 1 サイズ固定。リサイズしない。**
  当初は Detail の開閉で高さを変える設計にしていたが、ホストにリサイズを
  要求すると Ableton でエディタが操作不能になった。同じレイアウトは窓を
  どちらのサイズで開いても正しく動き、ホストもリサイズも無い gallery でも
  問題が出ない。**タブなら誰の同意も要らない**ので、そちらに寄せた。
  この数字は組んだレイアウトを測ったもので、見積もりではない
- 切り替わる領域の高さも固定。タブを変えたときにフッタが動いて
  ポインタの下のものが変わらないようにする
- 選択中のタブは `#[persist]` で保存し、プロジェクトを開き直すと復元される
- スケールはホストが渡す値に従う。UI 側で独自のズームは持たない

## 見た目の方向

**shadcn / IntentUI 系。** ニュートラルな面を数段重ね、アクセントは 1 色だけ、
境界は 1 px、階層は余白と文字の大きさで作る。影とグラデーションで奥行きを
作らない。ダーク単一（ライトテーマは作らない — プラグイン UI は自己完結した
窓なので、ホストのテーマに合わせる意味が薄い）。

「シンプルすぎない」ぶんは次の 3 つだけに使う。増やさない。

- 面の上端に 1 px のハイライト（白 4%）。shadcn の質感はほぼこれ
- ノブの弧に accent の細いグラデーション（1 箇所だけの例外）
- ホバーと選択に 150 ms のトランジション。**値の変化には掛けない**
  （ノブが操作に遅れて見える）

## トークン

**Rust の定数が正で、CSS はそれを埋め込んで生成する。** カスタム描画の
ウィジェット（ノブの弧、Voice Field）は Rust 側で色を必要とするので、CSS を正に
すると二重管理になる。Vizia の CSS が custom property をどこまで解釈するかにも
依存させない。

### 面と線

| トークン | 値 | 用途 |
|---|---|---|
| `background` | `#0A0A0A` | 窓の地。**パネルもコントロールも同じ地に置く** |
| `elevated` | `#1F1F1F` | 一時的なものだけ — ホバー中の行、バーのトラック、入力欄 |
| `border` | `#2A2A2A` | 1 px の境界線。**常に 1 px**。面を分けるのはこれだけ |

**面は 2 段。** 一度は `card`（`#141414`）と面の上端 1 px の `highlight` を
持っていたが、平らな窓がカードの積み重ねに見えるだけだったので落とした。
パネルとボタンは地と同じ色で、境界線だけが区切る。

**面と文字は完全にニュートラル**（RGB の 3 チャネルが等しい）。グレーに色味が
乗ると配色として読まれてしまい、「アクセントだけが色を持つ」が崩れる。
テストで固定してある。

### 文字

| トークン | 値 | 用途 |
|---|---|---|
| `foreground` | `#FAFAFA` | 値、主要な文字 |
| `muted` | `#A3A3A3` | ラベル、単位 |
| `subtle` | `#737373` | 目盛り、無効な行・点 |

### アクセント

| トークン | 値 | 用途 |
|---|---|---|
| `accent` | `#38BDF8` | ノブの弧、バーの塗り、選択中のセグメント、点 |
| `accent-bright` | `#7DD3FC` | 弧のグラデーションの明側 |
| `accent-dim` | `rgba(56,189,248,0.18)` | フォーカスリング、点の縁取り |

アクセントは 1 色。**状態を色で区別しない**（有効／無効は彩度ではなく
`subtle` への置き換えで表す）。

### 形と間隔

- **角張った形。角丸は無し**（`RADIUS_CONTROL` / `RADIUS_CARD` とも 0）。
  当初は 2px / 3px にしていたが、実物では角のほうが良かった。
  完全な円は Voice Field の点とノブのつまみに限る
- 間隔は 4 px グリッド: `4 / 8 / 12 / 16 / 24`。この 5 つ以外を使わない
- フォーカスリングは外側に 2 px、`accent-dim`

## 文字と数値

- **Geist**（SIL OFL 1.1）を埋め込む。Sans と Mono の Regular 1 ウェイトずつ。
  階層はサイズと色で作るので他のウェイトは使わない。ライセンス文はフォントの
  隣に置き、**リリースのバンドルにも同梱する**（バイナリに焼き込まれるため）
- UI の文字は 12（ラベル）と 10（値）の 2 段。プラグイン名だけ 17
- ラベルは `muted` + 大文字 + わずかな字間、値は `foreground`
- **数値は Geist Mono で組み、小数点以下の桁数を固定する。** 桁数の固定だけでは
  足りない — プロポーショナルな字形では `1` と `8` で幅が違うので、ノブを
  ドラッグしている間に数字が横に揺れる。等幅にすればそれが消える。OpenType の
  tabular numerals に頼らないのは、feature の扱いが Vizia とフォントに依存する
  ため

## ウィジェット

`nxe-ui` に置くのは 5 つ。残りは CSS のクラスで足りる。

| ウィジェット | 用途 | 実装 |
|---|---|---|
| `PolarField` | Voice Field | `View::draw`。点の一覧 + ドラッグのコールバック。領域知識を持たない |
| `CurveView` | Filter View | `View::draw`。折れ線・帯・対数軸・縦ドラッグのハンドル。領域知識を持たない |
| `Knob` | マクロ層の 4 大ノブと小ノブ | `View::draw` で弧を描く。値は正規化 0–1 + 表示文字列 |
| `Bar` | ボイス表の細いスライダ | 横方向。塗りは形状値、右に実効値の文字列 |
| `SegmentedControl` | `Voices` / `Source` | ボタン列。選択中に `--accent` |

いずれも**値とコールバックしか知らない**。パラメータとの結線は
`plugins/doubler/src/ui/param_bind.rs` が持つ（`nxe-ui` は nih-plug に
依存しない — `docs/specifications/architecture.md`）。

同じ変更で `crates/nxe-ui/examples/gallery.rs` にも追加する。gallery に無い
ウィジェットは DAW を開かないとレビューできないので、レビューされない。

### 共通の操作

`Knob` と `Bar`:

- 縦ドラッグで変更（`Bar` も縦。横ドラッグは行を跨いだ誤操作が起きる）
- `Shift` を押しながらで微調整
- ダブルクリックで既定値に戻す
- ホバーでツールチップ。ホストが表示するのと同じ文字列を出す
- ドラッグ中はホストへジェスチャー開始／終了を通知する
  （オートメーション記録が 1 操作としてまとまるように）

## アイコン

Lucide の埋め込みフォント（`lucide.ttf`）を `cx.add_font_mem()` で登録し、
生成した定数モジュール経由で参照する。生のエスケープをビューに書かない。

| 定数 | 場所 |
|---|---|
| `CHEVRON_DOWN` / `CHEVRON_UP` | `Detail` の開閉 |
| `FLIP_HORIZONTAL_2` | ミラーのトグル |
| `SLIDERS_HORIZONTAL` | `Detail` のラベル横 |
| `ROTATE_CCW` | セクションごとの既定値リセット |

定数モジュールは Lucide の `font/info.json`（名前 → コードポイントの全対応表）
から生成する。生成物であって手で編集しない。

**線幅は変えられない**（ストロークアイコンをグリフ化したもの）。太さが要る
アイコンが出てきたら、そのアイコンだけ `usvg` でパス化して `View::draw` で
描く。それは記録された例外であって既定ではない。

## この UI が持たないもの

意図して持たないものを書き残す。後から「なぜ無いのか」を再検討するため。

- **任意リサイズ** — 固定 2 段で足りるかを先に確認する
- **ライトテーマ** — 上記
- **プリセットブラウザ** — `REQ-DBL-013`。ホストの機構に任せる
- **メーター・波形・スペクトラム表示** — Voice Field と Filter View が
  「何が起きているか」をすでに担っている。**入力信号の**解析表示は音を作る
  判断に要らない（Filter View が描くのは設定した応答であって、通った信号では
  ない）
- **Filter View 上での周波数の編集** — シェルフの周波数は固定（200 Hz /
  4 kHz）。動かせるようにすると Tone が EQ になり、ダブラーの役割を超える
- **Voice Field 上での detune 編集** — 4 軸目を図に詰め込まない。表で行う
- **ボイスの Mute / Solo** — `Gain_i` を下げれば足りる
- **`Voice Field` 上での detune 編集**（上記）以外の軸の除外 — 2026-08-26 に
  `Delay` と `Gain` もミラー対象へ移した。軸ごとにスイッチがあるので、
  非対称に使いたい軸はそれを切る
