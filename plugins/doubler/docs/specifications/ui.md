# Doubler — UI 仕様

> 最終更新: 2026-08-25

要件は [`../requirements/REQ-DBL.md`](../requirements/REQ-DBL.md)、守るべき規約は
[`../../../../.agents/rules/vizia.md`](../../../../.agents/rules/vizia.md)。

## 設計方針

**何が起きているかが図で分かる。** マルチボイスダブラーの状態は「どのボイスが
どこに、どれだけ遅れて、どれだけ揺れて居るか」で、これは数値の列よりも図の
方が速く読める。画面の主役は Voice Field（下記）で、ノブはその図を動かすための
道具として下に置く。

**普段触るのは 4 つのノブだけ。** パラメータは 43 個あるが、実際に使うのは
`Detune` / `Delay` / `Spread` / `Humanize` でほぼ足りる。残りを常時見せると
「シンプルで使いやすい」が壊れる。

**マクロと個別値は同時に生きている。** どちらを触っても他方が消えない
（`REQ-DBL-007`）。図・バー・数値の 3 つの見せ方すべてがこの性質を保つ。

## Voice Field

画面の主役。ボイスは**定位**と**遅延**という 2 軸を持つので、極座標に載せると
両方が一度に見える。

```
            L                       C                       R
      22ms  ╭──────────────────────────────────────────╮
           ╱          ④                    ③           ╲
          │                 ②        ①                  │
     0ms  ╰────────────────────▲─────────────────────────╯
                            SOURCE
```

| 見た目 | 意味 |
|---|---|
| 角度 | 定位。左端が L、真上が C、右端が R |
| 半径 | 遅延。中心の ▲（ソース）が 0 ms、外周が `Delay` マクロの値 |
| 点の大きさ | `Gain_i` |
| 点の番号 | ボイス index |
| 点の揺れ | `Humanize` が動かしている実際の量。**揺れが目で見える** |

**detune は図に載せない。** 4 軸目を詰め込むと記号の意味を覚える UI になる。
detune はマクロノブと Detail の表、そして揺れている点の動きで足りる。

**`Source` = True Stereo のとき ▲ が 2 つになる。** L と R の位置に立ち、各点が
どちらのソースの子かを細い線で示す。モードの差が図で分かる。

### 操作

点をドラッグすると、そのボイスの `Pan_i` と `Delay_i` を**同時に**編集する。
これが図を主役にする理由で、形を直接いじれることが一番分かりやすい。

- ドラッグ = `Pan_i`（角度）と `Delay_i`（半径）を同時に変更
- `Shift` = 微調整
- 点をダブルクリック = そのボイスの形状値を既定に戻す
- 図の外周をドラッグしても何も起きない（`Delay` マクロの操作はノブ側）
- ドラッグ中はホストへジェスチャー開始／終了を通知する（2 パラメータぶん）

`Voices` で無効なボイスの点はディム表示。**消さず、ドラッグも許す**
（8 ボイスで使う設定を 4 ボイスのまま仕込める方が実用的）。

### 実装の境界

`nxe-ui` に入るのは領域知識を持たない `PolarField`。点の一覧（角度・半径・
大きさ・ラベル・有効かどうか）と、ドラッグのコールバックしか知らない。
「ボイス」「遅延」「定位」を知っているのは Doubler 側の対応付けだけ。

この境界があると `PolarField` を gallery で単体レビューできる
（`.agents/rules/vizia.md`）。

│  DOUBLER                     [ 2 │ 4 │ 8 ]  [ Mono │ Stereo ]│
├──────────────────────────────────────────────────────────────┤
│   L                          C                          R    │
│      22ms ╭───────────────────────────────────────╮          │
│          ╱        ④                    ③          ╲         │
│         │              ②          ①                │        │
│    0ms  ╰──────────────────▲──────────────────────────╯      │
│                        SOURCE                                │
├──────────────────────────────────────────────────────────────┤
│      ◕            ◕            ◕            ◕                │
│    DETUNE       DELAY       SPREAD      HUMANIZE             │
│    12.0 ct      22.0 ms      70 %         35 %               │

└──────────────────────────────────────────────────────────────┘

**バーは形状（正規化値）、数値は実効値。** これが二層の見せ方の核。バーを
ドラッグすると形状層が変わり、数値はマクロを掛けた結果として追随する。
`Detune` マクロを動かすとバーは動かず数値だけが変わる。

表は**数値で詰めるため**に残す。図では detune を編集できないので、表を消すと
detune のボイス別編集ができなくなる。図と表は同じ形状層を別の見せ方で
出しているだけなので、片方をドラッグすればもう片方が即座に追随する。

## サイズと DPI

- 固定 2 段（620 × 420 / 620 × 680）。任意リサイズは v1 では持たない
- `nih_plug_vizia` の `ViziaState` にサイズと `Detail` の開閉を保存する
- スケールはホストが渡す値に従う。UI 側で独自のズームは持たない

## 見た目の方向

**shadcn / IntentUI 系。** ニュートラルな面を数段重ね、アクセントは 1 色だけ、
境界は 1 px、階層は余白と文字の大きさで作る。影とグラデーションで奥行きを
作らない。ダーク単一（ライトテーマは作らない — プラグイン UI は自己完結した
窓なので、ホストのテーマに合わせる意味が薄い）。

「シンプルすぎない」ぶんは次の 3 つだけに使う。増やさない。

- 面の上端に 1 px のハイライト（白 4%）。shadcn の質感はほぼこれ
- ノブの弧に accent の細いグラデーション（1 箇所だけの例外）
- ホバーと選択に 150 ms のトランジション。**値の変化には掛けない**
  （ノブが操作に遅れて見える）

## トークン

**Rust の定数が正で、CSS はそれを埋め込んで生成する。** カスタム描画の
ウィジェット（ノブの弧、Voice Field）は Rust 側で色を必要とするので、CSS を正に
すると二重管理になる。Vizia の CSS が custom property をどこまで解釈するかにも
依存させない。

### 面と線

| トークン | 値 | 用途 |
|---|---|---|
| `background` | `#09090B` | 窓の地 |
| `card` | `#131316` | セクションの面 |
| `elevated` | `#1B1B1F` | ノブ／バーのトラック、入力欄 |
| `border` | `#27272A` | 1 px の境界線。**常に 1 px** |
| `highlight` | `rgba(255,255,255,0.04)` | 面の上端 1 px |

### 文字

| トークン | 値 | 用途 |
|---|---|---|
| `foreground` | `#FAFAFA` | 値、主要な文字 |
| `muted` | `#A1A1AA` | ラベル、単位 |
| `subtle` | `#71717A` | 目盛り、無効な行・点 |

### アクセント

| トークン | 値 | 用途 |
|---|---|---|
| `accent` | `#38BDF8` | ノブの弧、バーの塗り、選択中のセグメント、点 |
| `accent-bright` | `#7DD3FC` | 弧のグラデーションの明側 |
| `accent-dim` | `rgba(56,189,248,0.18)` | フォーカスリング、点の縁取り |

アクセントは 1 色。**状態を色で区別しない**（有効／無効は彩度ではなく
`subtle` への置き換えで表す）。

### 形と間隔

- 角丸は 3 段だけ: `6px`（コントロール）/ `10px`（カード）/ 完全な円
  （Voice Field の点、ノブのつまみ）
- 間隔は 4 px グリッド: `4 / 8 / 12 / 16 / 24`。この 5 つ以外を使わない
- フォーカスリングは外側に 2 px、`accent-dim`

## 文字と数値

- フォントファミリは 1 つ。`nih_plug_vizia` の既定でまず始める。見た目の都合で
  埋め込むことになったら、ライセンス文をアセットの隣に置き、**リリースの
  バンドルにも同梱する**（バイナリに焼き込まれるため）
- UI の文字は 12 px（ラベル）と 13 px（値）の 2 段だけ
- ラベルは `muted` + 大文字 + わずかな字間、値は `foreground`
- **数値は右揃えで小数点以下の桁数を固定する。** Humanize が効いていると値が
  常に動くので、桁が増減すると数字がガタつく。等幅数字（tabular numerals）が
  使えるかはフォントと Vizia の OpenType feature の扱いに依存するため、
  それに頼らず桁の固定で解決する

## ウィジェット

`nxe-ui` に置くのは 4 つ。残りは CSS のクラスで足りる。

| ウィジェット | 用途 | 実装 |
|---|---|---|
| `PolarField` | Voice Field | `View::draw`。点の一覧 + ドラッグのコールバック。領域知識を持たない |
| `Knob` | マクロ層の 4 大ノブと小ノブ | `View::draw` で弧を描く。値は正規化 0–1 + 表示文字列 |
| `Bar` | ボイス表の細いスライダ | 横方向。塗りは形状値、右に実効値の文字列 |
| `SegmentedControl` | `Voices` / `Source` | ボタン列。選択中に `--accent` |

いずれも**値とコールバックしか知らない**。パラメータとの結線は
`plugins/doubler/src/ui/param_bind.rs` が持つ（`nxe-ui` は nih-plug に
依存しない — `docs/specifications/architecture.md`）。

同じ変更で `crates/nxe-ui/examples/gallery.rs` にも追加する。gallery に無い
ウィジェットは DAW を開かないとレビューできないので、レビューされない。

### 共通の操作

`Knob` と `Bar`:

- 縦ドラッグで変更（`Bar` も縦。横ドラッグは行を跨いだ誤操作が起きる）
- `Shift` を押しながらで微調整
- ダブルクリックで既定値に戻す
- ホバーでツールチップ。ホストが表示するのと同じ文字列を出す
- ドラッグ中はホストへジェスチャー開始／終了を通知する
  （オートメーション記録が 1 操作としてまとまるように）

## アイコン

Lucide の埋め込みフォント（`lucide.ttf`）を `cx.add_font_mem()` で登録し、
生成した定数モジュール経由で参照する。生のエスケープをビューに書かない。

| 定数 | 場所 |
|---|---|
| `CHEVRON_DOWN` / `CHEVRON_UP` | `Detail` の開閉 |
| `SLIDERS_HORIZONTAL` | `Detail` のラベル横 |
| `ROTATE_CCW` | セクションごとの既定値リセット |

定数モジュールは Lucide の `font/info.json`（名前 → コードポイントの全対応表）
から生成する。生成物であって手で編集しない。

**線幅は変えられない**（ストロークアイコンをグリフ化したもの）。太さが要る
アイコンが出てきたら、そのアイコンだけ `usvg` でパス化して `View::draw` で
描く。それは記録された例外であって既定ではない。

## この UI が持たないもの

意図して持たないものを書き残す。後から「なぜ無いのか」を再検討するため。

- **任意リサイズ** — 固定 2 段で足りるかを先に確認する
- **ライトテーマ** — 上記
- **プリセットブラウザ** — `REQ-DBL-013`。ホストの機構に任せる
- **メーター・波形・スペクトラム表示** — Voice Field が「何が起きているか」を
  すでに担っている。信号の解析表示は音を作る判断に要らない
- **Voice Field 上での detune 編集** — 4 軸目を図に詰め込まない。表で行う
- **ボイスの Mute / Solo** — `Gain_i` を下げれば足りる
