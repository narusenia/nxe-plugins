# REQ-VEL — Velour 要件定義

> 最終更新: 2026-08-31

## 概要

Velour は**ボーカルの存在感を生成する**サチュレータ。狙いは「アナログっぽく
歪ませる」ことではなく、芯・距離・密度・質感を足すことで、細い録音を太くし、
小さい声に存在感を与え、Mix の中で埋もれなくすること。

対象は Bitwig / Ableton Live / Reaper / Studio One。**AU は対象外**なので
Logic Pro と GarageBand では読み込めない（`REQ-VEL-014`）。

姉妹製品 Sparkleur（光・広がり・明瞭さ・Air・マルチバンドダイナミクス）とは
担当が分かれる。**Velour はステレオ像を変えず、原音のダイナミクスを潰さない。**
その 2 つは Sparkleur の仕事。

## 設計の中心にある 4 つの判断

**原音は歪みを通らない。** 3 つの帯域生成器は並列で、原音に**足す**だけ
（`REQ-VEL-001`）。クロスオーバーで分割して歪ませて再合成する方式は採らない。
これにより「何もしていない状態」が原音とビット一致になり、保護検出器の失敗が
原音の劣化として出ることも原理的に無くなる。

**倍音のカーブは 1 本。** 帯域ごと・モードごとに別の関数を持たず、非対称量 `β`
とドライブ `k` の 2 軸でパラメタライズした 1 つのカーブ族を使う
（`REQ-VEL-003`）。帯域の違いもキャラクタの違いも `(β, k)` 上の位置の違いに
落ちる。だから Warm と Clear の中間が存在し、入力レベルへの追従
（`REQ-VEL-008`）が別のサブシステムにならない。

**4 つの層が別のものを動かす。** シェイパの線形ゲインを 1 に正規化することで、
`DRIVE`（どれだけ歪んでいるか）・帯域ノブ（どれだけ足すか）・`MIX`（バス全体）・
`TEXTURE`（どういう歪み方か）が互いに干渉しない（`REQ-VEL-009`）。

**検出は絶対レベルではなく相対バランス。** Harsh / Sib の検出は、その帯域の
エネルギーを広い参照帯のエネルギーで割った比で行う（`REQ-VEL-006`）。絶対
レベルだと「強く歌った瞬間」すべてに反応し、`EMOTION` と正面から喧嘩する。

## REQ-VEL-001: 並列生成トポロジ

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 原音は加工されない経路をそのまま通る。3 つの帯域生成器は入力から
  分岐した並列のバスで、その出力を原音に加算する。

  ```text
  Input ─────────────────────────────────────────┬──→ Output
     └→ [OS up] → BODY / PRESENCE / AIR → sum → [OS down] ─┘
  ```

- **クロスオーバー分割を採らない理由**:
  - 分割と再合成の誤差が常に乗るので、「何もしていない状態」が作れない。
    常時挿すプラグインでこれは効く
  - 帯域を単体で試聴できない。分割型で「BODY を 0 にする」はその帯域が
    消えることであって、足した質感を外すことではない
  - 保護検出器（`REQ-VEL-006`）が原音の通り道に入る。検出の失敗が原音の
    劣化として出る
  - 位相を揃えようとすると FIR に行きたくなり、レイテンシ補償が必要になる
- **代償として持たないもの**: 原音側を減らせない。ドキュメントにあった
  「Dynamic EQ Reduction」は v1 では持たない（`REQ-VEL-020`）
- **受入条件**:
  - [x] `MIX` = 0 のとき、出力が入力と**一致**（`==`）— `VEL-5`
  - [x] 3 帯域の量がすべて 0 のとき、出力が入力と一致 — `VEL-5`
  - [x] 原音経路はフィルタも遅延も通らず、`OUTPUT` = 0 dB の乗算は
        ちょうど `1.0` — `VEL-5`
- **依存**: なし

## REQ-VEL-002: 帯域生成器（BODY / PRESENCE / AIR）と FOCUS

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 3 つの生成器を持つ。各生成器は「入力を帯域制限 → シェイパ →
  出力を帯域制限 → レベル」の 4 段。

  | 生成器 | 中心帯域 | 狙い |
  |---|---|---|
  | BODY | 100–500 Hz | 声の芯。細い録音の補強。低中域の密度 |
  | PRESENCE | 500 Hz–5 kHz | 発音を前に出す。声質・エッジ |
  | AIR | 5 kHz 以上 | 息遣いの質感。高域のディテール |

  並列なので帯域が連続していることも重ならないことも要求されない。
- **出力側も帯域制限する。** DC と、その帯域が担当しない高域を落とす。非対称
  シェイパは DC 成分を作るので、**DC ブロッカは省略できない**。
- **AIR の入力には上蓋がある**（`0.25 ×` ホストのサンプルレート）。帯域の端では
  なく**折り返し対策** — それより上の成分の倍音は生成された時点で折り返り、
  どのフィルタも届かない。上蓋と `k` の上限は交換関係にあり、上蓋を入れたことで
  `k` の上限を 6 → 8 に戻せた（`REQ-VEL-005`）。
- **帯域は重なってよい。** 2 次の傾斜は緩く、隣同士は境界付近で重なる。並列生成
  なので軸を敷き詰める必要が無い。
- **境界はユーザーが動かせない。** この 3 つの名前は、帯域がどこかを製品側が
  決めているから意味を持つ。動かせた瞬間ただの 3 バンドサチュレータになる
  （`REQ-VEL-020`）。
- **`FOCUS` が 3 本をまとめて上下させる。** 双極、±1 oct、既定センター。
  男声の基音 ~110 Hz と女声 ~220 Hz で BODY 100–500 の意味が変わり、男声で
  「太い」設定が女声では濁る。**6 個の境界パラメータではなく 1 個**で、
  声域の違いだけを吸収する。
- **受入条件**:
  - [x] 各帯域の中心（200 Hz / 1.5 kHz / 10 kHz）で、その帯域が他の 2 つより
        10 dB 以上大きい — `VEL-3`
  - [x] `FOCUS` を振り切ると境界が 1 オクターブ移動する — `VEL-3`
  - [x] `FOCUS` で AIR の上蓋が上がらない — `VEL-3`
  - [x] 生成器の出力に DC が残らない（平均がフルスケールの 1e-4 以下）— `VEL-3`
  - [x] 端を走行中に動かしても段差が出ない（係数の入れ替えで状態を消さない）
        — `VEL-3`
- **依存**: REQ-VEL-001

## REQ-VEL-003: 倍音生成カーブ

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 帯域・モードごとに別の関数を持たず、1 つのカーブ族を使う。

  ```text
  raw(x)   = f(k·x + β) − f(β)
  shape(x) = raw(x) / g
  ```

  - `β`（**非対称バイアス**）→ 偶数倍音。波形の上下を非対称にすると 2 次が出る
  - `k`（**ドライブ**）→ 奇数倍音とその次数の伸び
  - `f(β)` の減算 → 静止時のオフセットの除去
  - `g` での除算 → **レベルの正規化**。`REQ-VEL-009` の直交性はここだけで
    作られる

  **バイアスを `k·(x + b)` の内側に置かない。** そう置くと `k` を上げたときに
  バイアスも一緒に増え、カーブの膝に乗って傾きが消える。副作用としてドライブを
  上げるほど偶数倍音の相対量が減るが、これは `REQ-VEL-008` の「強く歌うほど
  edge（奇数寄り）」と同じ向き。

  帯域の違いは `(β, k)` の倍率の違いに落ちる。BODY は `β` 大 `k` 小、
  PRESENCE は中間、AIR は `β` 小 `k` 大
  （値は [`../specifications/dsp.md`](../specifications/dsp.md)）。

  **`g` は「参照振幅の正弦波に対する RMS ゲイン」**（`VEL-1` で仕様を差し替えた。
  原点の傾きで正規化すると無限小の信号でしか成立せず、現実的な入力では
  ドライブが可動域で約 12 dB の音量ノブになる）。固定の基準で、信号から測らない —
  測ると同じ設定が素材ごとに別の音になり、生成器に遅い AGC が掛かって
  `REQ-VEL-008` を打ち消す。

  **代償: 参照振幅でしか厳密ではない。** 4 倍の音量で −9.8 dB、1/4 で +2.9 dB
  （実測、テストで固定）。参照は混ざったボーカルの居る位置に置き、`DENSITY` が
  カーブに届く前にレベルを揃える（`REQ-VEL-007`）。

  **`k` の上限は折り返しの実測から決まる**（6。`REQ-VEL-005` / `REQ-VEL-020`）。
- **Chebyshev 多項式で次数ごとの量を直接指定する方式は採らない**: 入力振幅が
  1 から外れると倍音の比が崩れる。ボーカルは振幅が動き続けるので合わない。
- **帯域 × モードごとに別カーブを手で設計する方式は採らない**: 9 個が個別に
  育ってモード間の連続性が無くなり、「Warm と Clear の中間」が原理的に
  作れなくなる（`REQ-VEL-004`）。
- **`k` に下限を置く。** `k → 0` は 0 除算になる。下限より下は線形として扱う。
- **`f` の中身**（tanh / 多項式 / rational）は耳で詰める。仕様には固定しない。
- **受入条件**:
  - [x] `k` を下限まで下げると出力が入力と一致する（線形ゲイン 1）— `VEL-1`
  - [x] `β` を上げると H2/H1 が単調に増え、`β` = 0 では H2 が出ない — `VEL-1`
  - [x] `k` を上げると H3/H1 が単調に増える — `VEL-1`
  - [x] **`k` を可動域いっぱいに振っても参照振幅での出力 RMS が ±0.3 dB 以内。**
        全 `(β, h)` の組で — これが `REQ-VEL-009` の実測 — `VEL-1`
  - [x] 参照から外れたときのずれが実測値で固定されている — `VEL-1`
  - [x] どの `(β, k, h)` でも出力が有限（非有限値を出さない）— `VEL-1`
- **依存**: REQ-VEL-002

## REQ-VEL-004: TEXTURE モーフ（Warm / Clear / Edge）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: キャラクタは離散のモードスイッチではなく、**1 本の連続ノブ**。

  ```text
  TEXTURE   0.0 ──────── 0.5 ──────── 1.0
          Warm         Clear         Edge
  ```

  3 点を**アンカー**として `(β, カーブの硬さ, 帯域ごとのトリム)` の表に持ち、
  隣接点間を補間する。

  | アンカー | 性格 | 向く素材 |
  |---|---|---|
  | Warm | 偶数倍音主体、柔らかいクリップ、Body 寄り | Ballad / 男声 / 柔らかい女声 |
  | Clear | 倍音は増やすが低域を膨らませない、Presence 中心 | Pop / アニメ / 現代的なボーカル |
  | Edge | 奇数倍音多め、硬いクリップ、Presence と質感が強い | Rock / Hyperpop / EDM ボーカル |

- **スイッチとノブに分けない。** Warm → Clear → Edge にはすでに順序が付いて
  いる（滑らか → 中庸 → 攻撃的）。順序のあるものを 3 択にする理由が無く、
  分けると同じ `(β, h)` 空間を 2 箇所から操作することになる。
- **名前は目盛りで保つ。** ノブのトラックに 3 つの名前を刻む。「Warm にする」は
  「0 に振り切る」になる。
- **受入条件**:
  - [x] `TEXTURE` を 0 → 1 に連続で動かして、どの値も段差なく変わる — `VEL-4`
  - [x] 0 / 0.5 / 1 がアンカーの値と一致する — `VEL-4`
  - [x] Warm と Edge で H2/H1 と H3/H1 がはっきり違う — `VEL-4`
  - [x] `Texture_i` がその帯域だけを動かし、端まで届かない — `VEL-4`
  - [ ] オートメーションで動かしても不連続なノイズが出ない — 実機確認
- **依存**: REQ-VEL-003

## REQ-VEL-005: オーバーサンプリング

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 生成バス**全体**を共通のオーバーサンプラで回す。原音は通らない。

  AIR は 5 kHz 以上を歪ませる。8 kHz 入力の 4 次倍音は 32 kHz で、48 kHz 動作
  なら 16 kHz に折り返して**可聴域に落ちる**。後段のフィルタでは取れない
  （折り返した後だから）。

- **アップ／ダウンサンプラは各 1 個。** 3 つの生成器は同じ入力から分岐するので
  帯域ごとに持つ必要が無い。
- **最小位相（IIR polyphase）。** リニアフェーズ FIR にするとレイテンシ申告が
  必要になり、原音側も遅らせることになる。生成バスは質感の層であって再構成の
  一部ではないので、20 kHz 近傍の位相回りは聞こえない。`REQ-VEL-001` で分割を
  捨てたからこの判断が通る。
- **2x / 4x を切り替えられる。** 4x を 2 段の halfband として実装し、2x は
  2 段目を飛ばす。**バッファは無い**（クロージャで 1 サンプルずつ処理する）ので、
  切替は分岐 1 つで、確保もレイテンシ変化も起きない。既定 4x。
- **受入条件**:
  - [x] 10 kHz の正弦波を `k` 上限・硬い膝で通したとき、20 kHz 未満に落ちる
        非調和成分が −60 dB 以下。**実測 −68 dB**（2x は −44 dB）— `VEL-2`
  - [x] アップサンプラのイメージが −70 dB 以下。**実測 −88 dB** — `VEL-2`
  - [x] 各段の阻止域が ≥ 70 dB。**実測 78.5 / 78.6 dB** — `VEL-2`
  - [x] 2x / 4x の切替でクリックが出ず、確保が起きない（**そもそもバッファが
        無い**）— `VEL-2`
  - [x] 申告レイテンシが 0（バルク遅延を持つ段が無い）— `VEL-2`
  - [ ] 4x で `REQ-VEL-016` の予算に収まる — `VEL-16`
- **依存**: REQ-VEL-001

## REQ-VEL-006: 保護検出器（Harsh Guard / Sib Guard）

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 仕組みは 1 つ、インスタンスを 2 つ。ある帯域が出過ぎた瞬間に、
  その帯域の**生成器の出力ゲインを下げる**。

  | | 検出帯域 | 抑える相手 |
  |---|---|---|
  | Harsh Guard | 2–5 kHz | PRESENCE 生成器 |
  | Sib Guard | 5–10 kHz | AIR 生成器 |

- **検出は相対バランス。** その帯域のエネルギーを広い参照帯（300 Hz–8 kHz）の
  エネルギーで割った比で判定する。
  - 絶対レベルだと**強く歌った瞬間すべてに反応する**。それは harsh ではなく
    ただの大きい声で、そこを抑えると `REQ-VEL-008` と正面から喧嘩する
  - 相対なら**入力ゲインに依存しない**。ゲインステージングが違う環境でも
    同じ動作になる
- **動かすのは出力ゲインだけ。** `k` や `β` を動かすと質感が変わりながら消える
  ので、何が起きたか分からなくなる。ゲインなら「その瞬間だけ足すのをやめた」と
  読める。De-Esser との違いはここで、**音量を下げるのではなく歪ませすぎない**。
- **各 Guard に `amount` を出す**（Advanced、既定はオン、0 で無効）。完全自動で
  隠すと「AIR を上げたのに効かない」の原因がユーザーから見えなくなる。
- **L/R でリンクする**（`REQ-VEL-011`）。
- **受入条件**:
  - [x] 入力ゲインを ±12 dB 変えても動作量が **0.2 dB 以内** — `VEL-8`
  - [x] 2–5 kHz を持ち上げた素材で PRESENCE の生成器が 2 dB 以上引っ込む — `VEL-8`
  - [x] `amount` = 0 で完全に無効（リダクションがちょうど 0）— `VEL-8`
  - [x] 片側に寄った入力で無音のチャネルが無音のまま — `VEL-8`
  - [x] 引きが `MAX_REDUCTION_DB` を超えない — `VEL-8`
- **依存**: REQ-VEL-002

## REQ-VEL-007: DENSITY

- **優先度**: Should
- **ステータス**: Draft
- **説明**: **生成バスの入力にだけ**コンプレッサを置き、声量差によらず倍音量を
  一定にする。オートメイクアップで圧縮量ぶんを戻す。
- **原音は通らない。** だから `DENSITY` を振り切っても声のダイナミクスは潰れず、
  最悪でも「足される質感が平坦になる」だけ。ドキュメントにあった「完全に平坦に
  はせず歌唱ダイナミクスは残す」が、設定ではなく**構造として保証される**。
- **Transient Smoothing を専用に持たない。** 生成層にだけ掛かる副作用として
  自動的に出る。
- **メイクアップは自動。** でないと `DENSITY` がただの音量ノブになる。
- **受入条件**:
  - [x] `DENSITY` を上げると、小さいフレーズと大きいフレーズで足される倍音量の
        差が縮まる — `VEL-7`（実測 23.7 dB → 6.0 dB、ノブに対して単調）
  - [x] `DENSITY` を 0 → 100% に動かして出力のラウドネスが ±1 dB 以内 —
        `VEL-7`。**メイクアップの基準を full scale から `REFERENCE_DB` に
        差し替えて**達成した。教科書どおりの `−T·(1 − 1/R)` は −18 dB の
        ボーカルを +13 dB 持ち上げるので、この条件を構造的に満たせない
  - [x] 原音のダイナミクスがどの設定でも変わらない（`REQ-VEL-001` の帰結） —
        `VEL-7`。`density` = 1 でも出力が入力とビット一致する
- **依存**: REQ-VEL-001

## REQ-VEL-008: EMOTION

- **優先度**: Should
- **ステータス**: Draft
- **説明**: 入力のエンベロープで各帯域の `(β, h, k)` を動かす。小さい声 → warm /
  dense、大きい声 → edge / excited。単なるレベル追従ではなく**歌唱表現に反応
  する**サチュレーションを狙う。
- **検波は圧縮前の入力を見る。** `REQ-VEL-007` のコンプの後ではなく前。
  ここが `DENSITY` との衝突を解く唯一の点で、**`DENSITY` が倍音の「量」を
  揃え、`EMOTION` が倍音の「質」を動かす**という直交になる。エンベロープ検波器
  そのものは 2 つで共有する（1 個）。
- **Advanced にノブを 1 個出す**（amount、0 で静的）。ドキュメントでは
  Main Controls に載っていない隠し挙動だが、これはこの製品の差別化そのもので、
  **オフにして A/B できないと良し悪しを判断できない**。既定は 0 ではない値。
- **受入条件**:
  - [x] `amount` = 0 で完全に静的な `(β, h, k)` になる — `VEL-6`。**ほぼではなく
        厳密**: `amount · d` をカーブの再構築の判定に入れてあるので、0 なら
        エンベロープが動いてもカーブが動かない
  - [x] `DENSITY` を振り切っても `EMOTION` の反応量が変わらない — `VEL-7`。
        音ではなく**カーブの係数**で固定した（`DENSITY` はカーブに入るレベルを
        変えるので倍音は動く。動いてはいけないのは `(k, β, h)`）
  - [x] 追従でノイズやジッパー音が出ない — `VEL-6`
- **依存**: REQ-VEL-003, REQ-VEL-007

## REQ-VEL-009: 4 層の直交

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 並列加算では `out = dry + m·gen` なので、古典的な dry/wet
  クロスフェードは存在しない。`MIX` は生成バスのフェーダでしかなく、放置すると
  `DRIVE` と同じ値を掛けることになる。`REQ-VEL-003` の線形ゲイン正規化により、
  4 つが別のものを動かす。

  | ノブ | 動かすもの |
  |---|---|
  | `DRIVE` | `k` の全体量 = **どれだけ歪んでいるか** |
  | `BODY` / `PRESENCE` / `AIR` | その帯域を**どれだけ足すか**（チャネルフェーダ） |
  | `MIX` | 生成バス全体の量（マスタフェーダ） |
  | `TEXTURE` | `β` とカーブの硬さ = **どういう歪み方か** |

- **正規化しないと帯域バランスが `DRIVE` で動く。** すると `BODY` を触ったのか
  `DRIVE` を触ったのか音から区別できない。Doubler の 43 個のパラメータが
  破綻しなかったのは各層が別のものを動かしていたためで、同じ性質をここでも作る。
- **副作用**: `DRIVE` = 0 で帯域を足すときれいな帯域ブーストになる。害は無い。
- **受入条件**:
  - [ ] `DRIVE` を振っても 3 帯域の相対バランスが変わらない
  - [ ] `BODY` を振っても PRESENCE / AIR の出力が変わらない
  - [ ] `MIX` は 3 帯域の合計に対して線形に効く
- **依存**: REQ-VEL-003

## REQ-VEL-010: 二層パラメータモデル

- **優先度**: Must
- **ステータス**: Draft
- **説明**: Doubler の `REQ-DBL-007` と同じ性質 — **マクロと個別値は上書きし
  合わない**。どちらを触っても他方が消えない。

  **第 1 層（メイン、8 個）**:
  `DRIVE` `BODY` `PRESENCE` `AIR` `TEXTURE` `DENSITY` `MIX` `OUTPUT`

  **第 2 層（Advanced、帯域ごとに 2 個 + トグル）**:

  | | 何 |
  |---|---|
  | `Bias_i` | 双極。同じ「量」を、**深く歪ませて少し足すか / 浅く歪ませて多く足すか**に振り分ける。**レベル側の補正は 0** — カーブが既に正規化されているので `k` を上げても量が動かない（`VEL-9` の実測） |
  | `Texture_i` | 双極。全体の `TEXTURE` からのその帯域のオフセット |
  | `Solo_i` | その生成器だけを聴く |

  **Advanced のグローバル側**: `FOCUS`、`Harsh Guard` 量、`Sib Guard` 量、
  `EMOTION` 量、オーバーサンプル 2x / 4x。

- **`Bias_i` を Drive と Level の 2 ノブに割らない。** 割ると「量」が 2 箇所から
  出てきてメインの帯域ノブと三つ巴になる。1 本の双極なら**メインの値を保った
  まま質だけ振れる**ので、二層が壊れない。
- **VO-TT のような per-band ダイナミクス（UP / DOWN / GAIN）は持たない。**
  それは Sparkleur の担当で、ここに持ってくると 2 製品の境目が消える。
- パラメータ総数は 8 + 9 + 5 = **22 前後**（Doubler の 43 より小さい）。`VEL-7` で **22 個**宣言し終えた（`DISTANCE` は持たない）。
- **受入条件**:
  - [x] メインの帯域ノブを動かしても `Bias_i` / `Texture_i` の値が変わらない
        （層が別のパラメータなので型で保証）— `VEL-9`
  - [x] `Bias_i` を動かしてもその帯域の「量」が 1.5 dB 以内（実測 1 dB 未満）で、
        倍音の比は 1.5 倍以上動く — `VEL-9`
  - [x] `Solo_i` がオンのとき、他の帯域のフェーダを動かしても出力が変わらず、
        全フェーダ 0 なら出力が完全に 0（原音も落ちる）— `VEL-9`
  - [x] 複数の `SOLO` が同時にオンでも壊れない — `VEL-9`
- **依存**: REQ-VEL-009

## REQ-VEL-011: ステレオの扱いと像の保存

- **優先度**: Must
- **ステータス**: Draft
- **説明**: **像を変えない。** 生成器（フィルタとシェイパ）はチャネルごとに
  独立、**検波はすべてリンク**。

  - リンクするもの: `EMOTION` / `DENSITY` の検波エンベロープ、`DENSITY` の
    ゲインリダクション、`Harsh Guard` と `Sib Guard` のリダクション。
    L/R の和（またはピークの大きい方）から 1 本作り、両チャネルに同じ量を適用
  - リンクしないと、片側だけ Guard が引っ込んだ瞬間に**声が横に飛ぶ**。
    ボーカル処理でこれは即バレる欠陥
- **バス構成は 2→2 と 1→1。** Doubler は wet が定義上ステレオなので 1→2 を
  持つが、Velour はモノのトラックをモノで返す。
- **WIDTH / 広がりの操作は持たない**（Sparkleur の担当）。
- **受入条件**:
  - [x] L == R の入力に対して出力も L == R — `VEL-5`
  - [x] 2→2 と 1→1 の両方のレイアウトで動く — `VEL-5`
  - [x] 片チャネルに寄った素材で、処理によって定位が動かない — 検波は 3 つとも
        モノ和から 1 本（`VEL-6` / `VEL-8`）。片側に寄った入力で無音のチャネルが
        無音のまま、かつ**その入力でもカーブは動く**（検波がチャネルごとに
        止まっていない証拠）
- **依存**: REQ-VEL-006

## REQ-VEL-016: リアルタイム安全性と CPU 予算

- **優先度**: Must
- **ステータス**: Draft
- **説明**: `process()` の中で確保・ロック・IO・panic をしない。ホストから来る
  値はクランプする（Doubler の `DBL-12` はベンチで極端値の非有限出力を見つけた
  — 同じ罠を最初から塞ぐ）。
- **予算**: Doubler と同じ取り方。512 サンプル / 48 kHz のブロック周期
  10.67 ms の 5% = **533 µs**。4x オーバーサンプルの 3 帯域 + 解析 2 本で
  この中に収める。目標は 250 µs。
- **受入条件**:
  - [x] criterion のベンチで 4x / 512 サンプル / 48 kHz が 533 µs 以内 —
        `VEL-16`。**実測 128 µs**（エンジン 79 + 解析 48 バンド × 2 で 45 +
        `Level` × 4 で 4）。目標 250 µs も達成しているので、`Spectrum` の
        バンド数を削る必要は無かった
  - [x] 全パラメータを範囲外の極端値にしても非有限値を出さず panic しない —
        `VEL-10`。**サンプル側も**: 非有限のサンプル 1 個で検波器がラッチして
        Guard が黙って死ぬバグを見つけて直した
  - [x] 音声スレッドの経路に確保が無い — `assert_process_allocs`（既定で有効）
- **依存**: REQ-VEL-005

## REQ-VEL-017: サンプルレート・ブロックサイズ非依存

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 44.1 / 48 / 88.2 / 96 / 176.4 / 192 kHz で同じ音になる。ブロック
  サイズを変えても出力が変わらない。時定数はすべて秒で持ち、サンプルに直すのは
  1 箇所。
- **ナイキストを超える帯域を持たない**: `FOCUS` を上げた AIR の上端が
  ナイキストを超える場合、その生成器は無音として組む（`Spectrum` と同じ扱い）。
- **受入条件**:
  - [x] 同じ設定・同じ素材で 48 kHz と 96 kHz の出力が聴感上同じ — `VEL-10`
        （44.1 / 48 / 96 kHz でレベル 0.5 dB 以内、H2/H1 10% 以内、H3/H1 15% 以内）
  - [x] ブロックサイズ 32 / 512 / 2048 で出力が一致する — `VEL-10`
        （1 も含む。`EMOTION` はブロック長が検波の頻度そのものなので除く）
  - [x] 高いサンプルレートで係数が発散しない — `VEL-10`（192 kHz まで確認）
- **依存**: REQ-VEL-005

## REQ-VEL-019: DISTANCE

- **優先度**: Won't (v1)
- **ステータス**: Decided
- **説明**: 「声を後ろから前へ移動させる」1 個のマクロ。上げると Low-mid
  harmonics ↑ / Presence ↑ / Air ↑ 少し / Compression ↑ 少し。
- **v1 に入れない理由**:
  - **これは第 1 層の上に乗るもう 1 層。** `BODY` `PRESENCE` `AIR` `DENSITY` を
    同時に動かすので `REQ-VEL-010` の二層が三層になる。マクロのマクロは、触った
    瞬間に下の層の値が全部動く
  - **軌道が実素材でチューニングするまで決められない。** 今入れると中身が空の
    ノブが 1 個増える。順序が逆だと嘘の軌道が固定される
  - `DRIVE` がすでに「1 個で全部」の役をやっているので v1 で困らない
- **入れるとしたら**: チューニング段で「この 4 つはいつも一緒に動く」と分かった
  時点で、**実測の軌道**を 1 本のパラメータにする。あるいは `DRIVE` を捨てて
  DISTANCE を製品の 1 ノブにする（「量」より「Mix 上の目的」を操作するという
  主張になる）。

## REQ-VEL-021: MODE（Soft / Hard）

- **優先度**: Should (v0.2.0)
- **ステータス**: Decided
- **説明**: マクロ層から内部量への**写像だけ**を差し替える 2 値のモード。
  形と約束は Sparkleur の `REQ-SPK-022` と同じで、写像の中身だけが違う。
- **既定は Soft。** 既存セッションには `MODE` が保存されておらず、読み込み時に
  既定値が適用される。
- **何を差し替えたか**（`VEL-19`）: 生成器が足すものを
  `Shaper::shape` から `Shaper::residual` に替える。同じ曲線から**素通し分を
  引いて、残りを元のレベルまで正規化し直したもの**。`VEL-18` が測ったとおり、
  足していた層は**9 割方が入力の帯域コピー**で、フェーダーを上げて増えるのは
  主にレベルだった。Hard の層は中身が高調波になる。
- **`DRIVE_MAX` の 8 は動かしていない。Hard が自分の上限を持つ**
  （`velour_core::bands::HARD_DRIVE_MAX` = 6）。Hard は曲線が作ったものを
  9 dB 持ち上げるので**折り返しも一緒に上がり**、drive 8 では −52.9 dB で
  `REQ-VEL-005` を割る。6 なら −65.6 dB で、代償は高調波 **1.95 dB** だけ
  （残差は正規化されているので drive はほぼ質しか変えない）。
  これは `REQ-VEL-020` の順序の**真ん中の一段**で、最後の一段（倍率）には
  手を出していない。
- **受入条件**（すべて `velour-core` のテストが見ている）:
  - `MODE` = Soft のとき **`v0.1.4` とビット一致**（同じ `shape` 呼び出し）
  - Hard で、同じノブ位置の**生成成分が原音比で +8 dB 以上**。実測は
    BODY **+8.21** / PRESENCE **+8.33** / AIR **+11.79** dB
  - **それが音量で稼いだものでないこと** — Hard の出力は Soft より大きく
    ならない。実測では層はむしろ静かになる（引いた素通し分がその大半だった）
  - Hard でも**折り返しが 4x で −60 dB 以下**。`nxe_audio::shaper` が記録して
    いる測り方（11 kHz、ハードニー、実際の AIR 生成器を通す）を、**入った音を
    基準にして**使う — Hard は基音を抜くので「出てきた音より何 dB 下か」は
    もう無い数で割ることになる
- **Harsh / Sib Guard は緩めない。** `REQ-VEL-006` は製品の約束で、効きの天井が
  そこだった場合でも既定ではなく写像側で解く。
