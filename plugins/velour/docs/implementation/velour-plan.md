# Velour 実装計画

> 最終更新: 2026-08-26

要件は [`../requirements/REQ-VEL.md`](../requirements/REQ-VEL.md)、設計の正は
[`../specifications/dsp.md`](../specifications/dsp.md) と
[`../specifications/ui.md`](../specifications/ui.md)。この文書は**何を作るか**と
**その単位の完了条件**を持つ。順序の根拠は
[`../../../../docs/implementation/roadmap.md`](../../../../docs/implementation/roadmap.md)、
状態は [`../../../../docs/implementation/backlog.md`](../../../../docs/implementation/backlog.md)。

## 方針

**ゲートを先に通す。** `VEL-1` のシェイパで「`k` を振っても基音が動かない」が
成立しなければ、4 層の直交（`REQ-VEL-009`）が崩れ、パラメータの意味づけと UI が
全部書き直しになる。Doubler がピッチシフタをゲートにしたのと同じ扱い。

**ただしゲートは耳ではなく数値で通る。** Doubler の `DBL-2` はホストで聴くまで
判断できなかったが、こちらは正弦波を入れて倍音の比を測れば済む。だから
`VEL-1` は `velour-core` の単体テストで閉じ、ホストを開く必要がない。

**音が出るまでを最短で通す。** `VEL-5` で nih-plug ラッパを入れる時点では
`TEXTURE` を Clear 固定にし、UI も持たない。ホストが自動生成するパラメータ UI で
「原音に何かが足されている」ところまで確認する。

**パラメータ集合が固まるまで UI を書かない。** UI は `VEL-11` 以降。共通
ウィジェット（`UI-13` `BandField` / `UI-8` `Meter` / `DSP-4` `Level`）は
Velour のパラメータを知らないので、**先に済んでいる**。

**共通クレートに上げない。** `velour-core` の オーバーサンプラ・シェイパ・Guard は
Sparkleur が必ず使うが、上げるのは 2 個目が要求してから
（`architecture.md`）。代わりに**パラメータ構造体を知らない自立したモジュール**
として書き、移動がファイルの移動だけで済む状態にする（`REQ-VEL-015`）。移動
候補は各単位に印を付ける。

## 実装単位

### VEL-1 — シェイパ（ゲート）✅

`velour-core` クレートを作り、`shaper.rs` と `harmonics.rs`（測るための素朴な
DFT）を置く。この単位では帯域もフィルタも無い。

**`SPK-1` で `nxe_audio::shaper` に移動済み**（Sparkleur が同じものを使う）。

**実装中に仕様を 1 つ差し替えた。** `dsp.md` は正規化を `k · f_h'(β)`（原点の
傾き）と書いていたが、それが 1 にするのは**無限小の信号に対するゲイン**だけ。
圧縮性のカーブは飽和するにつれて基音を失うので、現実的な入力レベルでは
ドライブが可動域で約 12 dB の音量ノブとして働く。**参照振幅の正弦波に対する
RMS ゲイン**で正規化する方式に変え、理由と実測値を `dsp.md` に記録した。
導関数は要らなくなったので実装していない。

- **完了条件**（すべて単体テスト、17 本）:
  - [x] **`k` を下限から上限まで振っても参照振幅での出力 RMS が ±0.3 dB 以内。
        全 `(β, h)` の組で** — **これがゲート。通った**
  - [x] 参照から外れたときのずれを実測して固定した（4 倍で −11.6 dB、
        1/4 で +9.1 dB）
  - [x] `β` を上げると H2/H1 が単調に増え、`β` = 0 では H2 が出ない
  - [x] `k` を上げると H3/H1 が単調に増える
  - [x] `h` を上げると同じ `k` で H3/H1 が増える
  - [x] `k` を下限にすると出力が入力と一致する
  - [x] `(β, k, h)` に NaN / ∞ / ±1e9 を入れても panic せず非有限を出さない
  - [x] `set` が同じ値で再計算せず、答えも変わらない
  - [x] 両方の膝が傾き 0 で天井に到達する（クランプに角が無い）
  - [x] `β` > 0 では DC が出ることをテストで明示した（**出力側 HPF が必須**の
        根拠を、後で見つけるのではなく書いておく）
- **要件**: REQ-VEL-003, REQ-VEL-016
- **依存**: なし
- **決めたこと**: `β` の上限は 0.8。好みではなく `f_hard` の膝（`±1`）で決まる —
  バイアスが膝に乗ると傾きが残らず、正規化の除算が発散する
- **決めたこと**: 測るヘルパは `harmonics.rs` に**公開モジュール**として置く。
  4 つの単位とベンチが使い、うち 2 つは結合テストなので `#[cfg(test)]` では
  届かない。依存は足していない
- **決めたこと**: シェイパは **1 帯域に 1 個で両チャネルを賄う**。サンプルごとの
  状態を持たないので、係数を 2 組持つ理由が無い
- **`A_REF`（0.25）は細かい定数ではない。** 製品の中心的な主張が厳密に成り立つ
  場所そのもので、`VEL-17` の「耳で詰める」リストに入れた

### VEL-2 — オーバーサンプラ ✅

`oversample/`。polyphase IIR halfband を 2 段、最小位相、2x / 4x。係数は
`scripts/design-oversampler.py`（**標準ライブラリのみ**）で設計して
`src/oversample/coefficients.rs` に生成する。`mise run oversampler:design`。

**`SPK-1` で `nxe_audio::oversample` に移動済み。**

**実装中に仕様を 2 つ差し替えた。**

1. **バッファは無い。** 「初期化時に 4x ぶん確保する」と書いていたが、
   `process` がクロージャを取って 1 サンプルずつ回せば中間サンプルはレジスタに
   居る。2x/4x の切替は分岐 1 つで、リサイズも状態のクリアも無い
2. **`k` の上限を 20 → 6 に下げた。** 4x でも `k` = 20 の硬い膝は折り返しを
   −44 dB しか落とせない。`REQ-VEL-020` が「倍率で殴る前に `k` の上限を
   見直す」と決めていたのでそれに従った（`k` = 6 で −68 dB）

- **完了条件**:
  - [x] 各段が阻止域 ≥ 70 dB。**実測 78.5 dB（段 1、7 次）/ 78.6 dB（段 2、3 次）**、
        通過帯リプルは 1e-7 dB 台
  - [x] `VEL-1` のシェイパを通した 10 kHz 正弦で、20 kHz 未満に落ちる非調和成分が
        **−68 dB**（2x は −44 dB）
  - [x] **アップサンプラのイメージが −88 dB**
  - [x] 2x / 4x を切り替えてもクリックが出ず、確保が起きない
  - [x] 切替で使わなくなった段の状態を保持している
  - [x] 群遅延がホストに申告する必要のない量（**申告は 0**）
  - [x] 非有限のサンプルでフィルタが壊れない
- **要件**: REQ-VEL-005, REQ-VEL-016, REQ-VEL-017
- **依存**: VEL-1（折り返しを測るのに歪みが要る）
- **決めたこと**: **scipy を入れない。** 変わらない 14 個の数を再導出するために
  依存を足す取引は合わない。Nelder-Mead を 60 行書いた。**目的関数は局所解を
  持つ** — 多スタートを入れる前は 6 次が 4 次より悪い答えを出していた
- **決めたこと**: **阻止域の端は「ナイキスト」ではなく「可聴域に折り返してくる
  もの」から決める。** 段 1 は 28 kHz から、段 2 は 68 kHz から。これで必要な
  次数が一桁変わる（Butterworth なら 28 次要る、と計算した）
- **決めたこと**: 次数は 70 dB を超える最小 + **係数が 1 に近いものを避ける**。
  段 1 は 6 次でも 75 dB 出るが最大係数 0.990（極が |z| = 0.995）。オールパス
  1 段の値段でリンギングと桁落ちを買わない
- **踏んだ罠**: **アップサンプラの位相の割り当てを逆にしていた。** 往復テストは
  通り、低域の正弦も無事に戻ってくるのに、イメージが −88 dB ではなく −24 dB で、
  その間の非線形が自分の入力の複製と相互変調して折り返しだけが −11 dB まで
  悪化していた。**往復では絶対に見えない。** `the_upsampler_leaves_no_image` が
  それを固定するために存在する
- **踏んだ罠**: 折り返しの測定で、高次倍音が**基音のビンにちょうど折り返る**
  （10 kHz の 23 次と 25 次）。除外しないと「エイリアスが 0.0 dB」になる

### VEL-3 — 帯域生成器と FOCUS ✅

`biquad.rs`（**`SPK-1` で `nxe_audio::biquad` に移動済み**）と `bands.rs`。3 本の生成器（入力側フィルタ →
シェイパ → 出力側フィルタ）と `FOCUS`。2 次 Butterworth、direct form 1。

**実装中に仕様を 1 つ足し、1 つの数字を戻した。**

**AIR の入力に上蓋を付けた**（`0.25 ×` ホストのサンプルレート、48 kHz で
12 kHz）。仕様では AIR の入力は 4.8 kHz 以上が素通しだったが、それだと 20 kHz の
正弦が**どんなドライブでも −44 dB** の折り返しを出す（9 次 = 180 kHz が 192 kHz
に入らず、フィルタが見る前に 12 kHz に落ちている）。手の届く倍率では直らない。
上蓋を入れたので **`k` の上限を 6 → 8 に戻せた**。

- **完了条件**:
  - [x] 各帯域の中心（200 Hz / 1.5 kHz / 10 kHz）で他の 2 つより 10 dB 以上大きい
  - [x] `FOCUS` を振り切ると境界が 1 オクターブ動く
  - [x] `FOCUS` で AIR の上蓋が上がらない
  - [x] **バイアスを掛けた信号で出力の平均が 1e-4 以下**（DC ブロッカ）
  - [x] ナイキストを超えた端が passthrough / 無音になる（暴れない）
  - [x] 係数を入れ替えても状態が消えない（走行中に端を動かして段差が出ない）
  - [x] 最悪ケースの折り返しが **−63 dB**（AIR に 11 kHz、`k` 上限、硬い膝）
  - [x] hostile な `FOCUS` で非有限を出さない
- **要件**: REQ-VEL-002, REQ-VEL-009, REQ-VEL-017
- **依存**: VEL-1, VEL-2
- **決めたこと**: 上蓋は**ホストのレート**に比例させる。内部レート基準にすると
  2x のときだけ狭くなり、**倍率の切替で AIR の帯域が動いて音が変わる**。2x は
  折り返しで妥協した設定であって、別の帯域にするものではない
- **決めたこと**: `Generator::new(band, host_rate, factor)`。走る場所（内部レート）
  ではなく**ホストのレートと倍率**から作る — 係数は内部レートのもの、AIR の上蓋は
  ホストのレートのもので、両方が必要
- **決めたこと**: 倍率が変わったら**端は動かさず係数だけ作り直す**。同じ端を別の
  レートで表すだけなので応答は変わらず、切替は聞こえない
- **決めたこと**: **シェイパは帯域ごとに 1 つで両チャネルを賄う**
  （`process(&mut self, input, shaper: &Shaper)`）。フィルタだけがチャネルごと
- **決めたこと**: `FOCUS` も倍率も**変化していなければ再計算しない**。ノブを
  握っているだけで 12 個の biquad を作り直すのは無駄
- **決めたこと**: **帯域は重なってよい。** 2 次の傾斜は緩く、BODY と PRESENCE は
  480–520 Hz で重なる。並列生成なので軸を敷き詰める理由が無い。テストは
  「自分の真ん中で一番大きい」だけを固定する
- **踏んだ罠**: 上蓋を**内部レート基準**で書いていて、`FOCUS` = +1 で 48 kHz まで
  開いていた。テストが拾った

### VEL-5 — nih-plug ラッパと配線（ここで音が出る。UI 無し）✅

`velour-core` に `engine.rs`（バス全体を束ねる）を足し、`velour` クレートを作って
ワークスペースの `members` と `bundler.toml`（`[velour] name = "NXE Velour"`）に
登録した。パラメータ 8 個、`editor()` は `None`。

- **完了条件**:
  - [x] `MIX` = 0 で出力が入力と**一致**（`==`。ホストのバイパスと同じ意味）
  - [x] 3 帯域すべて 0 でも一致
  - [x] L == R の入力に L == R の出力
  - [x] 2→2 と 1→1 の両レイアウトで動く（コードパスが分かれている）
  - [x] ブロックサイズ 1 / 32 / 512 / 2048 で出力が一致
  - [x] `bundle` が CLAP と VST3 を出力する
  - [x] `CLAP_ID` が `com.nxe.velour`、表示名が `NXE Velour`
  - [x] 申告レイテンシが 0（`set_latency_samples` を呼ばない）
  - [x] **Ableton Live で読み込め、音が変わる** — 2026-08-26 確認
- **要件**: REQ-VEL-001, REQ-VEL-011, REQ-VEL-012, REQ-VEL-014
- **依存**: VEL-3
- **決めたこと**: `VST3_CLASS_ID` = `NXEVelour.......`（16 バイト）。
  **出荷後は絶対に変えられない**
- **決めたこと**: **`TEXTURE` はまだ宣言しない。** Clear の位置に固定してある
  （`engine.rs` の `CLEAR_BIAS` / `CLEAR_HARDNESS`）。何もしないノブを 1 個
  置くより、無い方がいい。`VEL-4` で足す。nih-plug は id で引くので後から足すのは
  安全（**変えるのと消すのは安全でない**）
- **決めたこと**: エンジンの API を**レートで割る**。`set_shape` がブロックごと
  （係数と正規化を作り直す）、`process` がサンプルごと（スムージングされる値）。
  混ぜるとサンプルごとに係数を作り直すか、スムージングをブロック境界に
  量子化することになる
- **決めたこと**: 帯域のフェーダは**線形振幅で、0 が本当に 0**。dB のレンジは
  無音の上のどこかで止まるので、「全部下げてビット一致」が言えなくなる
- **決めたこと**: バス構成は 2→2 と **1→1**。Doubler は wet が定義上ステレオ
  なので 1→2 を持つが、Velour は像を動かさない（`REQ-VEL-011`）
- **踏んだ罠**: ブロックごとに読むパラメータを `smoothed.next()` で読んでいた。
  スムーザは 1 回で 1 サンプル進むので、20 ms のランプが**ブロックサイズ倍**
  遅くなり、ホストごとに違う速さになる。`next_step(samples)` が正しい
- **踏んだ罠**: hostile なパラメータ（NaN のレベル）が**ダウンサンプラの状態に
  永住**して wet が黙ったまま帰ってこなかった。`Oversampler::process` が
  クロージャの戻り値も検査するようにした — **中で何をしても bus は死なない**
  という約束の方が、呼び出し側ごとに気をつけるより安い

### VEL-4 — TEXTURE モーフ ✅

`texture.rs`。3 アンカー（Warm / Clear / Edge）の表と、隣接点間の補間。帯域ごとの
`(β, h)` とレベルトリム。`Texture_i` のオフセットは ±0.35。

- **完了条件**:
  - [x] `TEXTURE` = 0 / 0.5 / 1 がアンカーの値と一致する
  - [x] 0 → 1 を 2000 段で舐めて、どの値も段差なく変わる
  - [x] `Texture_i` がその帯域だけを動かし、**端まで届かない**
  - [x] Warm と Edge で H2/H1 と H3/H1 が**はっきり違う**（偶数は 3 倍以上、
        奇数は 2 倍以上）
  - [x] 0 dB のトリムがちょうど `1.0`
  - [x] 帯域ごとの倍率が効いている（BODY は偶数寄り、AIR は奇数寄り）
  - [x] hostile な位置で非有限を出さない
  - [x] エンジン経由で**音が変わり、レベルが歩き回らない**
- **要件**: REQ-VEL-004, REQ-VEL-010
- **依存**: VEL-5
- **決めたこと**: **`β` と `h` を個別のパラメータとして露出しない。** 別々に
  触れると「Warm の丸さと Edge の硬い膝」のような、どのアンカーも意味していない
  点が作れてしまう
- **決めたこと**: `Texture_i` の範囲を ±0.35 に収める。1 つの帯域が Warm で別の
  帯域が Edge という状態を作れると、`TEXTURE` が音の名前でなくなる
- **決めたこと**（`VEL-9` で改めた）: 帯域ごとのオフセットのパラメータは
  `VEL-9` で宣言した。UI が無い状態では「置く場所が無い」がどの Advanced
  パラメータにも等しく当てはまり、`VEL-9` の `SOLO` と `Bias` は宣言しないと
  単位が完了しない。同じ扱いに揃えた
- **測定**: **Warm → Edge でレベルが −3.0 dB 動く。** トリムのせいではなく、
  硬いカーブが高次倍音に置いたエネルギーを**帯域の出力フィルタが捨てる**ため
  （BODY は 2 kHz で切る）。9 個のトリムはこの残差を吸収するためにあり、
  だから最後に詰める（`VEL-17`）。`dsp.md` に記録した

### VEL-6 — エンベロープ検波と EMOTION ✅

`envelope.rs`（**`SPK-1` で機構が `nxe_audio::envelope` に移動。時定数と
`REFERENCE_DB` は `velour-core` に残る**）と `emotion.rs`。共用の検波器（attack 5 ms /
release 150 ms、モノ和、**圧縮前の入力**）と、`(β, h, k)` の変調。
パラメータは 18 → **19** 個。

- **完了条件**:
  - [x] `amount` = 0 で完全に静的な `(β, h, k)` になる（**ブロック長を変えても
        ビット一致**、かつ `amount` を上げると一致しなくなる）
  - [x] 大きい声で H2/H1 が下がり H3/H1 が上がる（実測 H2/H1 0.0814 → 0.0564、
        H3/H1 0.0124 → 0.0257）
  - [x] 追従でジッパー音が出ない
  - [x] 検波が L/R でリンクしている（片チャネルだけの信号でもカーブが動く）
  - [x] `(β, h)` の反映がブロック単位（正規化係数の再計算がサンプルごとに
        入っていない）
  - [x] 検波器が hostile なサンプルでラッチしない
  - [x] 弾道が 44.1 / 48 / 96 / 192 kHz で同じ
- **要件**: REQ-VEL-008, REQ-VEL-011
- **依存**: VEL-4
- **決めたこと**: **既定は 0.5。** 0 で出荷すると、この製品の差別化そのものが
  既定でオフになる（`REQ-VEL-008`）。Advanced に出すのは、**オフにして A/B
  できないと良し悪しが判断できない**から
- **決めたこと**: `amount · d` を `CurveState` に入れる。`amount` = 0 なら
  この値は定数 0 なので、**エンベロープが動いてもカーブの再構築が起きない** —
  「完全に静的」がほぼではなく厳密になる
- **決めたこと**: 検波器は**ピーク**（`guard.rs` はパワー）。あちらは帯域比の
  しきい値なので二乗が要るが、こちらの問いは「どれだけ強く歌っているか」で、
  リリースの遅いピーク追従が音節の間で落ちない 1 個の数を返す
- **決めたこと**: `emotion::modulate` は**クランプしない**。`Shaper::set` が
  既にやっているので、2 か所でやると**どちらの範囲が効いているのか分からなく
  なる**
- **決めたこと**: `Engine` に `emotion` の量を持たせない。ブロック内のローカル
  で足りるものをフィールドにすると、読まれない状態が増える
- **踏んだ罠**: エンジンのテストヘルパ `rendered` は `set_shape` を**最初の
  サンプルの前に 1 回だけ**呼ぶ。検波器はまだ無音しか見ていないので `d = −1`
  になり、`EMOTION` の向きが**全部逆に測れた**（H3/H1 が 0.0124 → 0.0019）。
  エンベロープが絡むものは `blocked(shape, levels, input, block)` で
  **ホストと同じくブロックごとに `set_shape`** して測る。ヘルパを分けて
  doc コメントに理由を書いた
- **踏んだ罠**: `the_block_size_does_not_change_the_output` が落ちた。
  既定の `EMOTION` が 0.5 なので**当然落ちる** — ブロック長は検波器を読む頻度
  そのもので、それが機能。あのテストは `emotion: 0.0` に固定し、ブロック長で
  変わることは別のテストで固定した

### VEL-7 — DENSITY ✅

`density.rs`（**移動しない** — Sparkleur のコンプは別物、`SPK-1`）。**生成バスの入力にだけ**掛かるコンプレッサ。
しきい値とレシオの写像、静的メイクアップ。パラメータは 21 → **22** 個
（宣言はこれで打ち止め）。

**実装中に仕様の数字をもう 1 つ捨てた**（`VEL-9` に続いて 2 回目）。
`makeup_db = −T · (1 − 1/R)` は教科書どおりの自動メイクアップだが、これは
「0 dBFS が 0 dBFS に戻る」ゲインで、`density` = 1 では −18 dB のボーカルを
**+13 dB 持ち上げる**。受入条件は ±1 dB なので**構造的に通らない**。
**基準レベルが失う分だけを返す**形に差し替えた（`makeup = 1 / gain(REFERENCE_DB)`）。
支点が素材の居場所に来るので、平らになるのは差でレベルではない。

- **完了条件**:
  - [x] `density` = 0 でリダクションとメイクアップが 0（**全レベルでちょうど
        1.0**、比較 1 回で抜ける）
  - [x] 0 → 100% で出力のラウドネスが ±1 dB 以内（**基準レベルでは厳密に
        0.00 dB**。メイクアップの基準がそこなので）
  - [x] 小さいフレーズと大きいフレーズで足される倍音量の差が縮まる
        （実測 **23.7 dB → 6.0 dB**）、かつ**ノブを上げるほど単調に縮む**
  - [x] **原音のダイナミクスがどの設定でも変わらない**（`density` = 1 でも
        `MIX` = 0 とフェーダ 0 の両方で出力が入力とビット一致）
  - [x] `DENSITY` を振り切っても `VEL-6` の反応量が変わらない
        （**カーブの `(k, β, h)` が `density` 0 と 1 でビット一致**）
  - [x] 大きいフレーズを持ち上げない（エキスパンダになっていない）
  - [x] hostile な値で非有限を出さない
- **要件**: REQ-VEL-007
- **依存**: VEL-6
- **決めたこと**: **独自の追従を持たない。** 検波器が 1 個なら弾道も 1 個で、
  この段のゲインは検波器の読みの静的な関数になる。仕様の release 120 ms は
  消えて、検波器の 150 ms になった
- **決めたこと**: `REFERENCE_DB`（−18 dB）は `emotion.rs` ではなく
  **`envelope.rs` に置く**。`EMOTION` の軸の中心と `DENSITY` のメイクアップの
  基準は同じ「普通のボーカルが居る位置」で、2 か所に持つと片方だけ動いてズレる。
  耳で詰める数が 1 個になる
- **決めたこと**: 既定は 0。安全に振り切れる（原音を通らない）が、
  「どれだけ演奏を無視するか」は選択で、頼まれていないコンプはこの製品が
  避けようとしているもの
- **決めたこと**: `DENSITY` は `CurveState` に入れない。カーブを触らず
  ゲインを 1 個動かすだけなので、`EMOTION` と直交する — **`DENSITY` が量を
  揃え、`EMOTION` が質を選ぶ**
- **決めたこと**: 反応量の検証は**音ではなくカーブの係数**で見る。`DENSITY` は
  カーブに入るレベルを変えるので、倍音は `EMOTION` と関係なく動く。
  「検波が圧縮前」の主張は係数が一致することでしか固定できない
- **踏んだ罠**: `if !(level > threshold)` は clippy の
  `neg_cmp_op_on_partial_ord` に落ちる。NaN を早期 return に落とす意図だったので、
  `level.is_nan() || level <= threshold` と書いて理由をコメントに残した

### VEL-8 — Guard（Harsh / Sib）✅

- **決めたこと**: **既定はオン（0.75）。** 「痛くならない」が製品の約束なのに、

- **決めたこと**: dB への変換は**しきい値を超えたときだけ**。しきい値を線形の

### VEL-9 — Bias と SOLO ✅

`Bias_i` の割り振り、`Solo_i`、そして `Texture_i`（`VEL-4` から繰り越し）を
パラメータとして宣言。パラメータは 9 → **18** 個。

**実装中に仕様の数字を 1 つ捨てた。** `dsp.md` は `level_i_db` から
`bias_i · 6` を引くと書いていたが、**カーブが既にレベルで正規化されている**ので
（`REQ-VEL-003`）`k` を上げても生成器の RMS はほとんど動かない — bias の可動域
全体で 1 dB 未満。6 dB 引いたら `bias` はただの音量ノブになる。**係数を 0 に
した。**

残る 1 dB 未満は**固定の定数では直せない。符号が素材で変わる** — 217 Hz で
−0.15 dB、434 Hz で +0.80 dB。原因は `VEL-4` で見つけたのと同じで、余分な
ドライブが作った倍音を帯域の出力フィルタが捨てる量が成分の居場所で違うため。
定数は 0 のまま残した（補正すべきは知覚的な密度で、量は `VEL-17` の耳の話）。

- **完了条件**:
  - [x] `Bias_i` を振ってもその帯域の「量」が **1.5 dB 以内**（実測 1 dB 未満）
  - [x] `Bias_i` が倍音の比を **1.5 倍以上**動かす（＝何もしないノブではない）
  - [x] `Solo_i` がオンのとき、**他の帯域のフェーダを動かしても出力が変わらない**
  - [x] `Solo_i` がオンで全フェーダ 0 のとき出力が**完全に 0**（原音も落ちる）
  - [x] `SOLO` が無いときは原音がそのまま
  - [x] 複数の `SOLO` が同時にオンでも壊れない
  - [x] hostile な `bias` / `solo` で非有限を出さない
- **要件**: REQ-VEL-010
- **依存**: VEL-4
- **決めたこと**: `SOLO` は**メイクアップしない**。足している音量そのままで聞く。
  どれだけ小さいかも読み取るべき情報
- **決めたこと**: `SOLO` は `BoolParam` の `.non_automatable()`。音を変えるので
  Doubler の `#[persist]` フラグとは違うし、UI ができるまでこれ以外に触る道が
  無い。**保存されてしまうのは避けられない**ので、`VEL-14` で画面上に状態が
  はっきり出ることが要る
- **決めたこと**: 帯域ごとのパラメータは**ネストした配列ではなく素の 3 フィールド**。
  ネストするとホストのオートメーション一覧に「Band 1 Bias」と出るが、帯域には
  名前がある
- **踏んだ罠**: テストで「足している層」を `出力 − 原音` で作っていた。原音の方が
  大きいので**引き算が層の精度をほとんど捨てる**。`SOLO` を全部オンにして層を
  直接取るように書き直した — テストが機能を使い、機能がテストを通す形になった
- **踏んだ罠**: DFT の測定で、切り出した後半に**周期が整数個入っていなかった**
  （8192 サンプルに 37 周期 → 後半 4096 に 18.5 周期）。倍音の比が漏れで
  埋まって符号が逆に見えた。`VEL-2` でも同じ罠を踏んでいる

### VEL-10 — スムージングと非依存性の詰め ✅

ブロック単位の係数再計算、オーバーサンプル倍率の切替の連続性、極端値のクランプ。

**バグを 1 個見つけた。** 非有限のサンプルが 1 個来ると Guard が**そのセッション
の間ずっと無効になる**。検波器は再帰的な状態なので NaN が入ると抜けない。
症状は「Guard が黙って効かなくなる」だけで音は出続けるので、他のどのテストにも
引っかからない。**モノ和を 1 か所で消毒**して直した（検波器に入る唯一の場所）。
原音は消毒しない — 通し経路なので、NaN を送ってきたホストには NaN を返す。

- **完了条件**:
  - [x] ブロックサイズ 1 / 32 / 512 / 2048 で出力が一致（`EMOTION` = 0。
        オンだとブロック長が検波器を読む頻度そのものなので、一致しないのが正しい）
  - [x] 44.1 / 48 / 96 kHz で**レベルが 0.5 dB 以内、H2/H1 が 10% 以内、
        H3/H1 が 15% 以内**
  - [x] **全パラメータを範囲外まで振っても非有限値を出さず panic しない**
  - [x] **非有限のサンプルが検波器をラッチさせない**（← 上のバグ）
  - [x] どのノブを速く動かしてもジッパー音が出ない（100 ms で振り切っても、
        **止めているときの最大段差の 1.3 倍**を超えない）
  - [x] 音声スレッドの経路に確保が無い（`assert_process_allocs` が既定で有効）
- **要件**: REQ-VEL-016, REQ-VEL-017
- **依存**: VEL-7, VEL-8, VEL-9
- **決めたこと**: **仕様の「時定数 5 ms」は採らない。** 実装は線形ランプで
  20 ms（ゲイン系・`DRIVE`・`TEXTURE`・Guard・`EMOTION`・`DENSITY`）/ 30 ms
  （双極の 6 個）/ 50 ms（`FOCUS` — 係数 12 組を作り直すので一番長い）。
  係数の作り直しがブロック単位なので、**短いほうが段差が大きくなる**
- **決めたこと**: 段差の物差しは**入力の傾きではなく「同じエンジンを止めたとき
  の最大段差」**。生成層の倍音は原音より必ず急なので、入力と比べても
  「倍音が増えた」しか測れない
- **踏んだ罠（測定側）**: ジッパーのテストが**何も検出できない状態で通っていた**。
  1200 サンプルのブロック（可動域の 25% を 1 段で動かす）でも通る。理由は
  **エンジンにパラメータで跳ねるゲインが 1 つも無い**から — レベルと `MIX` は
  サンプル単位、Guard は検波器の後ろ、カーブはレベル正規化済み。**測定が失敗
  できることを同じテストの中で確かめる**行を足した（ブロック境界で段にした
  フェーダは検出される）

### VEL-15 — 通っている音の表示 ✅

`nxe_dsp` の配線。`Spectrum` 2 個（原音・生成バス）、`Level` 4 個（IN / OUT の
L / R）、Guard のリダクション。受け渡しは `Handoff`。UI 側の周期処理は
**`cx.spawn` の `ContextProxy`**（`cx.add_timer` は baseview で発火しない）。

- **完了条件**: 音が止まると両方の曲線が減衰して消える。Guard が働いた瞬間が
  区画の沈みに出る。**解析を止めても音が変わらない** — ✅（実機確認は残っている）
- **要件**: REQ-VEL-018
- **依存**: VEL-8, DSP-4
- **決めたこと**: **バンド数は 48。** 上の曲線は倍音列なので、32（1 オクターブ
  3 本強）だと数 kHz より上で隣り合う倍音が 1 本に潰れて、曲線が存在理由を
  失う。**コストは `VEL-16` で測る**。予算に入らなければ最初に削るのはここ
- **決めたこと**: 生成バスだけのスペクトラムは `Engine::wet()` から取る。
  **`出力 − 原音` で作らない** — `VEL-9` で踏んだのと同じ精度の罠。
  float 2 個を持つほうが安い。テストで「報告した層＝全 SOLO で鳴る層」を固定した
- **決めたこと**: Guard のリダクションは**モデルにコピーしない**。区画は
  リダクションを level と同じ値（`Band`）に持つのに**レンズは 1 フィールドしか
  map できない**ので、区画のレンズの中で `Handoff` を直接読む。
  モデルが変わればレンズは再評価されるので、心拍が 30 Hz でそれを回している

### VEL-16 — CPU 予算の確認 ✅

criterion。4x / 512 サンプル / 48 kHz。`velour-core/benches/engine.rs` と
`nxe-dsp/benches/analysis.rs`。

**実測（M シリーズ、release、512 サンプル / 48 kHz）**:

| 何 | 時間 | 予算に対して |
|---|---|---|
| エンジン 4x（`EMOTION` オン） | **79.1 µs** | |
| エンジン 4x（`EMOTION` オフ） | 80.7 µs | ← **差が測れない** |
| エンジン 2x | 43.6 µs | |
| `Spectrum` 48 バンド × 2 | 22.3 × 2 = **44.7 µs** | |
| `Level` × 4 | 0.92 × 4 = **3.7 µs** | |
| **合計（4x）** | **≈ 128 µs** | 予算 533 µs の **24%**、目標 250 µs の 51% |

- **完了条件**:
  - [x] 合計が 533 µs 以内（目標 250 µs も達成）
  - [x] 極端値でも非有限を出さない（`VEL-10` の hostile テスト）
  - [x] 測定値を記録する
- **要件**: REQ-VEL-016
- **依存**: VEL-15
- **決めたこと**: **削らない。** 削り順は (1) `Spectrum` のバンド数、
  (2) オーバーサンプラの次数、(3) 4x → 2x の既定変更 の順で決めてあったが、
  1 つも要らなかった。48 バンド × 2 本は据え置き
- **分かったこと**: **`EMOTION` のカーブ再構築はコストとして測れない。**

  サンプルごとの仕事は 512 × 4 × 3 帯域 × biquad 2 段 ≈ 1.2 万回。
  2 桁違うので、「ブロック単位で係数を作り直す」設計が正しかったことの確認になる
- **分かったこと**: **解析が合計の 35%**（44.7 / 128 µs）。エンジンより高いのは
  1 本あたり 48 個の biquad とフォロワをサンプルごとに回すから。それでも
  予算には十分収まる

### VEL-17 — 既定値の詰めと実機確認 ✅（既定値のぶん）

- **決めた既定値**（耳で、実素材で）:

| | 仮 | 決 |
|---|---|---|
| `DRIVE` | 40% | **80%** |
| `BODY` | 50% | **40%** |
| `PRESENCE` | 60% | 60% |
| `AIR` | 40% | 40% |
| `TEXTURE` | 50%（Clear） | 50% |
| `DENSITY` | **0%** | **50%** |
| `MIX` | 50% | **80%** |

- **決めたこと**: **もっと前に出す方向に振れた。** 落としどころが drive 0.8 /
  mix 0.8 なのは、「箱から出して何も起きないサチュレータは、趣味が良いのではなく
  壊れているように読める」から。全部安全に押せる — 原音は通らない
  （`REQ-VEL-001`）し Guard は入っている（`REQ-VEL-006`）
- **決めたこと**: **`DENSITY` の既定 0 → 0.5。構造からの議論を耳が引っくり返した。**
  0 にした理由は「頼まれていないコンプはこの製品が避けようとしているもの」で、
  筋は通っていたが**間違っていた** — `DENSITY` は声に掛かっておらず、
  足している質感に掛かっているので、常時少し入れておくと
  「演奏が平らになる」のではなく「足す質感が揃う」になる（`REQ-VEL-007`）
- **まだ仮のまま残したもの**（触る理由が出てから動かす）:
  - `TEXTURE` のトリム 9 個（Warm→Edge の −3.0 dB の残差）
  - Guard のしきい値 −8 / −14 dB（「普通のボーカルで動かない」は満たしている）
  - `REFERENCE_DB` −18 dB、`EMOTION` の係数 3 つ
  - `BIAS_LEVEL_DB` 0（知覚的な密度をどれだけ返すか）
- **要件**: REQ-VEL-020
- **依存**: VEL-16
