# Velour — DSP 仕様

> 最終更新: 2026-08-26

要件は [`../requirements/REQ-VEL.md`](../requirements/REQ-VEL.md)。この文書は
「どう振る舞うべきか」を式のレベルで決める。実装は `velour-core`。

数値のうち **「耳で詰める」印のあるものは仮の値**。全機能が揃ってから実素材で
決める（最後の節に一覧）。それ以外は原理から決まる値。

## 信号フロー

```text
 in ─┬──────────────────────────────────────────────────────────────┬─ × out gain ─ out
     │                                                              │
     │  ┌─ env ─┬─→ EMOTION（各帯域の β / h / k を動かす）           │
     │  │       └─→ DENSITY（下のコンプの動作量）                    │
     │  │                                                           │
     │  │  ┌─ guard 2–5k ──────────────┐                            │
     │  ├──┤                           │（生成器の出力ゲインを引く） │
     │  │  └─ guard 5–10k ─────────────┤                            │
     │  │                              ▼                            │
     └──┴─ [OS ↑] ─ comp ─┬─ BPF ─ shaper ─ BPF ─ × BODY ─────┐      │
                          ├─ BPF ─ shaper ─ BPF ─ × PRESENCE ─┼─ sum ─┴─ × MIX
                          └─ HPF ─ shaper ─ HPF ─ × AIR ──────┘        │
                                                          [OS ↓] ──────┘
```

**原音は乗算も遅延もフィルタも通らない**（`REQ-VEL-001`）。`MIX` = 0 かつ
`OUTPUT` = 0 dB で出力は入力とビット一致する。`10^(0/20)` はちょうど `1.0` なので
出力ゲインの乗算も値を変えない。

**検波は 3 つとも圧縮前の入力を見る**（`REQ-VEL-008`）。エンベロープ検波器は
`EMOTION` と `DENSITY` で 1 個を共有する。

## オーバーサンプリング

生成バス全体を 1 組のアップ／ダウンサンプラで回す（`REQ-VEL-005`）。**2 段の
halfband**で、4x は 2 段、2x は 1 段目だけを使う。

**構造は polyphase IIR halfband**（Valenzuela & Constantinides）。

```text
H(z) = 1/2 · [ A0(z²) + z⁻¹ · A1(z²) ]
```

`A` は 1 次オールパス `(a + z⁻²)/(1 + a·z⁻²)` の縦続。係数を昇順に並べて 2 つの
分岐に交互に配る。**全区間がオールパスなので通過帯は構造上平坦**（実測リプルは
1e-7 dB 台）で、設計で最小化するものは阻止域の最大値だけ 1 つ。

### 阻止域の端は「ナイキスト」ではない

**可聴域に折り返してくる成分だけが問題**で、そこを詰めると必要な次数が一桁違う。

| 段 | 変換 | 阻止域の開始 | 根拠 | 次数 | 実測 |
|---|---|---|---|---|---|
| 1 | 48 ↔ 96 kHz | `0.5833·π`（= 28 kHz） | 96→48 の間引きで 24 kHz 超が折り返る。24–28 kHz は 20–24 kHz に落ちる（聞こえない）。28 kHz 超が 20 kHz 未満に落ちる | 7 | **78.5 dB** |
| 2 | 96 ↔ 192 kHz | `0.7083·π`（= 68 kHz） | 192→96 で 48 kHz 超が折り返る。28 kHz より上に落ちるものは段 1 が消す。だから 96−f < 28 kHz、つまり 68 kHz 超だけ | 3 | **78.6 dB** |

halfband の対称性から通過帯の端は自動的に決まる（段 1 は `0.4167·π` = 20 kHz、
段 2 は `0.2917·π` = 28 kHz）。段 1 で 20 と 28 が 24 を挟むのはちょうど都合が
よかっただけ。

**係数は正規化周波数で固定する。** ホストのサンプルレートに依らず同じ定数を使う
ので、96 kHz で走れば阻止域の実周波数も 2 倍になる。止めるべきは「そのホストの
ナイキストを越えて折り返るもの」だから、これが正しい振る舞い（`REQ-VEL-017`）。

**次数は仕様ではなく設計の出力。** 70 dB を超える最小の次数を採るが、
**係数が 1 に近いものを避ける**という条件が付く。段 1 は 6 次でも 75 dB 出るが
最大係数が 0.990（極が |z| = 0.995）で、f32 にそこまでの余裕は要らない。7 次なら
78 dB で最大係数 0.88。オールパス 1 段の値段でリンギングと桁落ちを買わない。

係数は `scripts/design-oversampler.py`（**標準ライブラリのみ**、Nelder-Mead の
多スタート）で設計し、`src/oversample/coefficients.rs` に生成する。**目的関数は
局所解を持つ** — 多スタートを入れる前は 6 次が 4 次より悪い答えを出していた。

### 実装で決めたこと

- **リニアフェーズ FIR を採らない**: レイテンシ申告が必要になり、原音側も
  遅らせることになる。生成バスは質感の層であって再構成の一部ではないので、
  20 kHz 近傍の位相回りは聞こえない。**この取引が成立するのは並列トポロジだから**
  で、クロスオーバーなら位相を揃えないと合成が崩れる（`REQ-VEL-005`）
- **バッファは無い**（仕様を差し替えた。当初「初期化時に 4x ぶん確保する」と
  書いていた）。`Oversampler::process` がクロージャを取り、オーバーサンプルされた
  1 サンプルごとに呼ぶので、中間サンプルはレジスタに居る。2x/4x の切替は分岐 1 つ
- **切替時は段の状態をクリアしない。** 使わなくなった段の状態を残しておけば
  戻したときに続きから走る
- **ゲイン補正は要らない。** ゼロ挿入 + フィルタなら振幅が半分になるが、
  polyphase の各分岐はオールパスで全周波数でゲイン 1 なので、各出力位相が
  そのまま満振幅の複製になる。ダウン側の `0.5` は 2 本の分岐の和を戻すぶん
- **非有限のサンプルは投入せず捨てる。** 再帰フィルタなので NaN が 1 つ入ると
  状態に永住し、**原音は鳴り続けるのに wet だけが黙る**という気づきにくい壊れ方に
  なる

### 位相の割り当ては自由ではない

アップサンプラのどちらの分岐がどちらの出力位相になるかを入れ替えると、
**往復テストは通り、低域の正弦も無事に戻ってくるのに、イメージが −88 dB では
なく −24 dB になる**。その間に居る非線形が自分の入力の複製と相互変調するので、
折り返しだけが悪化する。だから `the_upsampler_leaves_no_image` が要る。

## 帯域生成器

3 つ。どれも「入力側のフィルタ → シェイパ → 出力側のフィルタ → レベル」。
並列なので帯域が連続していることも重ならないことも要求されない
（`REQ-VEL-002`）。

| 生成器 | 入力側 | 出力側 |
|---|---|---|
| BODY | HPF 90 Hz + LPF 520 Hz | **HPF 30 Hz** + LPF 2 kHz |
| PRESENCE | HPF 480 Hz + LPF 5.2 kHz | HPF 300 Hz + LPF 12 kHz |
| AIR | HPF 4.8 kHz + **LPF 12 kHz（上蓋。下記）** | HPF 4 kHz + LPF 20 kHz |

すべて 2 次（Butterworth、Q = 0.707）。**入力側と出力側で通過域が違う**のが
要点で、出力側は「そのシェイパが作った倍音のうち残したい範囲」を決める。BODY の
出力を 520 Hz で切ると倍音が全部消えるので 2 kHz まで通す。

**帯域は重なる。** 2 次の傾斜は緩く、BODY と PRESENCE は 480–520 Hz で、
PRESENCE と AIR は 4.8–5.2 kHz で重なる。並列生成なので軸を敷き詰める必要が
無い（`REQ-VEL-002`）。各帯域が自分の真ん中で一番大きいことだけをテストで固定
する。

### AIR の入力の上蓋 — `0.25 × ホストのサンプルレート`

**帯域の端ではなく折り返し対策。** 上蓋より上の成分の倍音は**生成された時点で
折り返る** — 20 kHz の 9 次は 180 kHz で、192 kHz には入らないのでフィルタが
見る前に 12 kHz に落ちている。手の届く倍率では直らないし、そもそもそこに
倍音を足す必要が無い（AIR の仕事は高中域から高域の倍音を作ること）。

**ホストのレートに比例させる。** 折り返しを決めるのは入力周波数と内部レートの
比で、倍率が固定ならこの 2 つは一緒に動く。96 kHz では上蓋も 2 倍になり挙動は
同じ。**内部レート基準にしない** — 2x のときだけ狭くなって、倍率の切替で
AIR の帯域が動いてしまう（2x は既に折り返しで妥協した設定であって、別の帯域に
するものではない）。

上蓋は `FOCUS` で上には動かない（下には動く）。`FOCUS` は声域を動かすもので、
折り返しの限界はサンプルレートの性質だから。

**出力側の HPF は省略できない。** 非対称なシェイパは DC を作る。`f(β)` の減算で
静的なオフセットは消えるが、信号のエンベロープが動けば残差が出る。BODY の
30 Hz HPF がその DC ブロッカを兼ねる（`REQ-VEL-002`）。

### FOCUS

上の周波数すべてに `2^focus` を掛ける（AIR の上蓋は下にだけ動く）。
`focus ∈ [−1, +1]`、既定 0。

男声の基音 ~110 Hz と女声 ~220 Hz で BODY 100–500 の意味が変わる。**6 個の境界
パラメータではなく 1 個**で声域の違いだけを吸収する（`REQ-VEL-002`）。

**ナイキストを超えた生成器は無音として組む。** `Spectrum` の帯域と同じ扱い
（`REQ-VEL-017`）。48 kHz + `focus` = +1 で AIR の入力 HPF は 9.6 kHz なので
実際には起きないが、係数の意味が無くなる領域を無言で走らせない。

## シェイパ

帯域ごと・モードごとに別の関数を持たず、1 つのカーブ族を使う（`REQ-VEL-003`）。

```text
raw(x)   = f_h(k·x + β) − f_h(β)
shape(x) = raw(x) / g
```

| 記号 | 何 | 範囲 |
|---|---|---|
| `k` | ドライブ。**奇数倍音**とその次数の伸び | `0.05 .. 8`（下記） |
| `β` | 非対称バイアス。**偶数倍音** | `0 .. 0.8` |
| `h` | カーブの硬さ | `0 .. 1` |
| `g` | 正規化ゲイン。下記 | — |

- `f_h(β)` の減算 → 静止時のオフセットの除去
- `g` での除算 → **レベルの正規化**。`REQ-VEL-009` の 4 層直交はここだけで
  作られる

**バイアスを `k·(x + b)` ではなく `k·x + β` と置く理由。** 前者だと `k` を上げた
ときにバイアスも一緒に増え、カーブの膝に乗って傾きが消える。後者なら `β` が `k`
から独立。副作用として**ドライブを上げるほど偶数倍音の相対量が減る**が、これは
`EMOTION` の「強く歌うほど edge（奇数寄り）」と同じ向きなので都合がよい。

**`β` の上限 0.8 は好みではなく `f_hard` の膝で決まる。** `f_hard` は `±1` で
平らになるので、バイアスが膝に乗るとカーブに信号が乗る傾きが残らず、`g` が 0 に
向かって除算が発散する。0.8 ならどの `h` でも傾きが残る。

**`k` に下限がある**のは `g` が下限で `k` に比例して 0 に向かうため。下限では
実質線形（ゲイン 1）で、そのとき帯域を足すときれいな帯域ブーストになる
（`REQ-VEL-009` の副作用）。

**`k` の上限 8 は折り返しの実測から決めた**（当初 20 と書いていた）。実測は
AIR の生成器を通した最悪ケース（11 kHz、硬い膝、4x）で、`k` = 6 で −77 dB、
**8 で −63 dB**、10 で −57 dB。`REQ-VEL-005` が要求するのは −60 dB。

**この数字は 2 回動いた。** `VEL-2` で折り返しを測って 20 → 6 に下げ、`VEL-3` で
AIR の入力に上蓋を付けたら 6 → 8 に戻せた。`REQ-VEL-020` が決めた順
（入力を絞る → ドライブを絞る → 倍率で殴るのは最後）そのまま。

上限は**実用域の外側**にある。参照振幅で `k` = 8 は `k·A` = 2 で、硬い膝が
振幅の半分より上を全部潰す（波形の 2/3 が平ら）。`k` = 20 なら 7/8 が平らに
なるが、音はほとんど同じで折り返しは 20 dB 悪い。

### `g` は `k · f_h'(β)`（原点の傾き）ではない

**この仕様は実装中に差し替えた**（`VEL-1`、2026-08-26）。原点の傾きで正規化する
と**無限小の信号**に対するゲインが 1 になるだけで、実際の信号では通らない。
圧縮性のカーブは飽和するにつれて基音を失うので、現実的な入力レベルでは
**ドライブを上げると帯域が静かになる**（可動域で約 12 dB）。誰も送らない振幅を
基準にしていた。

差し替え後の `g` は、**参照振幅の正弦波に対するカーブの RMS ゲイン**。3 つの
コントロールが動いたときに 1 周期を数値積分する。

```text
probe(n) = A_REF · sin(2π n / 64)                     A_REF = 0.25（−12 dBFS）
g        = rms( f_h(k·probe + β) − f_h(β) ) / rms(probe)
```

- **信号の測定ではなく固定の基準。** 同じ設定はいつでも同じに振る舞う。信号から
  測ると設定が素材ごとに別の音になり、しかも生成器に遅い AGC が掛かって
  `EMOTION` の「強く歌うほど edge」を打ち消す（`REQ-VEL-008`）
- **64 点。** 制御レートで 1 回なので、正弦のテーブルを持てば超越関数は 0 回
- **導関数は要らなくなった。** `f_soft'` / `f_hard'` は実装しない

**代償は参照振幅でしか厳密でないこと。** 実測（`VEL-1` のテストで固定）:

| 入力振幅 | ドライブ可動域でのレベル変化 |
|---|---|
| `A_REF`（−12 dBFS peak） | **±0.3 dB 以内**（全 `(β, h)` で） |
| `A_REF × 4`（フルスケール） | **−10.7 dB** |
| `A_REF × 0.25`（−24 dBFS peak） | **+4.3 dB** |

つまり `A_REF` は細かい定数ではなく、**製品の中心的な主張が厳密に成り立つ場所**。
`DENSITY` のコンプがカーブに届く前にレベルを揃えるので、実使用での露出は表より
小さい（`REQ-VEL-007`）。`A_REF` は**耳で詰める**リストに入れる。

### `f_h` の中身

2 本のカーブの線形補間。

```text
f_soft(x) = x·(27 + x²) / (27 + 9x²)        （|x| ≤ 3、外は ±1 にクランプ）
f_hard(x) = 1.5x − 0.5x³                    （|x| ≤ 1、外は ±1）
f_h      = (1 − h)·f_soft + h·f_hard
```

- `f_soft` は tanh の Padé 近似。±3 の範囲で誤差 0.5% 未満。**除算 1 回で済む**
  ので tanh を直接呼ぶより速く、テーブルも要らない
- `f_hard` は 3 次のソフトクリップ。`|x| = 1` で天井に当たるので、`f_soft` より
  ずっと早く飽和し高次の奇数倍音が出る
- **`n` 乗の膝（`x/(1+|x|ⁿ)^(1/n)`）を採らない**: 連続に硬さを変えられるのは
  魅力だが `pow` が**サンプルごと**に入る。線形補間なら乗算と加算だけ

**どちらも天井に傾き 0 で到達する。** `f_soft(3) = 1` かつ `f_soft'(3) = 0`、
`f_hard(1) = 1` かつ `f_hard'(1) = 0` なので、クランプに角が立たない。角が
あると特定の振幅で高次倍音が跳ねる。

**`g` の積分も制御レート。** `k` / `β` / `h` はサンプルごとに動かない
（`EMOTION` のスムージングを通した後の値をブロック単位で使う）ので、正規化係数は
1 ブロック 1 回。サンプルごとのコストは `f_h` 本体だけ。

**シェイパは 1 帯域に 1 個で両チャネルを賄う。** サンプルごとの状態を持たない。

### 帯域ごとの位置

同じカーブ族の上で、帯域ごとに `(β, k)` の倍率が違う（`REQ-VEL-003`）。

| 帯域 | `β` 倍率 | `k` 倍率 |
|---|---|---|
| BODY | 1.3 | 0.6 |
| PRESENCE | 1.0 | 1.0 |
| AIR | 0.5 | 1.6 |

**耳で詰める。** 狙いは BODY が偶数倍音主体で穏やか、AIR が細かく硬い、
PRESENCE がその中間。

## TEXTURE

離散のモードではなく、`(β, h, 帯域トリム)` の空間を通る 1 本の線
（`REQ-VEL-004`）。3 つのアンカーの間を線形補間する。

| | 位置 | `β` | `h` | BODY | PRESENCE | AIR |
|---|---|---|---|---|---|---|
| Warm | 0.0 | 0.55 | 0.10 | +2.0 dB | 0 dB | −3.0 dB |
| Clear | 0.5 | 0.30 | 0.35 | −1.0 dB | +1.0 dB | 0 dB |
| Edge | 1.0 | 0.10 | 0.85 | −2.0 dB | +2.0 dB | +1.0 dB |

**耳で詰める**（`β` と `h` と 9 個のトリムすべて）。表の形と補間の仕方は仕様、
値は仮。

`Texture_i`（Advanced の帯域ごとのオフセット、`REQ-VEL-010`）は、その帯域だけ
**位置を ±0.35 ずらして**同じ表を引く。パラメータを直接いじらせないのは、
`β` と `h` を別々に触らせると「Warm と Edge を混ぜた不整合な点」が作れて
しまうため。

## エンベロープ検波（EMOTION / DENSITY 共用）

入力（**圧縮前**）から 1 本。L/R の和のピーク側を取り、両チャネルに同じ値を
使う（`REQ-VEL-011`）。

```text
env ← attack 5 ms / release 150 ms の 1 次追従（ピーク）
env_db = 20·log10(max(env, 1e-6))
```

**リリースが遅い**のは音節ごとに暴れないため。フレーズの声量を見たいので、
子音 1 個で動くと `EMOTION` がガタつく。

## EMOTION

`env_db` を基準レベルからのずれに直し、各帯域の `(β, h, k)` を動かす
（`REQ-VEL-008`）。

```text
d = clamp( (env_db − REF_DB) / RANGE_DB , −1, +1 )      REF_DB = −18, RANGE_DB = 12

β ← β · (1 − 0.50·amount·d)      大きい声 → 偶数倍音が減る
h ← h + 0.40·amount·d            大きい声 → 硬くなる
k ← k · (1 + 0.30·amount·d)      大きい声 → 倍音が増える
```

`amount = 0` で完全に静的（`REQ-VEL-008`）。`REF_DB` / `RANGE_DB` と 3 つの
係数は**耳で詰める**。

`d` は `env` と同じ経路なので追加のスムージングは要らないが、**`β` と `h` は
ブロック単位で反映する**（サンプルごとに変えても聞こえず、正規化係数の再計算が
サンプルごとになるだけ）。

## DENSITY

**生成バスの入力にだけ**掛かるコンプレッサ（`REQ-VEL-007`）。オーバーサンプルの
後、帯域分割の前。

```text
T = −6 − 24·density        (dB)    しきい値が下がる
R = 1 + 3·density                  レシオが上がる
attack 5 ms / release 120 ms
gr_db = min(0, (T − env_db) · (1 − 1/R))
makeup_db = −T · (1 − 1/R)
```

- 検波は**この段の入力**ではなく共用の `env`（= 圧縮前の入力）を使う。同じ信号
  なので実質同じだが、検波器を 2 個持たない
- **メイクアップは静的**（`T` と `R` だけから決まる）。動的に戻すとゲインが
  信号に追従して二重に効き、ポンピングになる
- `density = 0` で `R = 1` なので `gr_db = 0`、`makeup_db = 0`。**完全に無効**

原音は通らないので、振り切っても声のダイナミクスは潰れない。「完全に平坦には
せず歌唱ダイナミクスは残す」が**構造として保証される**（`REQ-VEL-007`）。

## Guard

仕組みは 1 つ、インスタンス 2 つ（`REQ-VEL-006`）。

| | 検出帯域 | 抑える相手 | しきい値 |
|---|---|---|---|
| Harsh | 2–5 kHz | PRESENCE | −8 dB |
| Sib | 5–10 kHz | AIR | −14 dB |

```text
band_e  ← BPF の出力を二乗して attack 2 ms / release 60 ms で追従
ref_e   ← 300 Hz–8 kHz の BPF で同じことをする
ratio_db = 10·log10( (band_e + ε) / (ref_e + ε) )

reduction_db = −min( MAX_DB , amount · SLOPE · max(0, ratio_db − THRESHOLD_DB) )
```

`SLOPE = 1.0`、`MAX_DB = 18`。しきい値と `SLOPE` は**耳で詰める**。

- **エネルギー（二乗）で測る。** 振幅の比は素材によって端から端まで飛ぶ
  （`PanScope` で同じ判断をした）
- **相対比なので入力ゲインに依存しない**（`REQ-VEL-006`）。分子と分母が同じだけ
  動くので比は変わらない
- **速い**（attack 2 ms）のは子音 1 個を捕まえるため。`env` の 5 ms / 150 ms とは
  役目が違うので共用しない
- `reduction_db` は**生成器の出力ゲインにだけ**掛かる。`k` や `β` は動かさない
  （`REQ-VEL-006`）
- L/R でリンク（`REQ-VEL-011`）
- `amount = 0` で `reduction_db = 0`。完全に無効

**BODY に Guard を持たない。** 低域の濁りは検出より `FOCUS` と `BODY` の量で
解く問題で、検出器を足すと「効いていないのか壊れているのか」が増えるだけ。

## 帯域のゲインと Bias

```text
level_i_db = band_knob_i_db + texture_trim_i_db + guard_i_db − bias_i·6
k_i        = k · k_mult_i · 2^(bias_i·1.5)
```

`bias_i ∈ [−1, +1]`、既定 0。**`k` を上げたぶんだけ出力を下げる**ので、
「同じ量を、深く歪ませて少し足すか / 浅く歪ませて多く足すか」の振り分けになる
（`REQ-VEL-010`）。

**この釣り合いは厳密ではない。** 倍音が増えれば実効的なラウドネスは上がるので、
`6 dB` と `1.5` は**耳で詰める**。厳密に釣り合わせるには生成器の出力を測って
正規化することになり、それは `bias` を「量が変わらない」ではなく
「量が測定で固定される」ものに変えてしまう — 素材によって挙動が変わるノブになる。

## 出力

```text
gen  = Σ_i ( shape_i( band_i(x) ) の出力側フィルタ ) × 10^(level_i_db/20)
out  = ( x + mix · gen ) × 10^(output_db/20)
```

- `mix ∈ [0, 1]`、既定 **0.5**（耳で詰める）
- `output_db ∈ [−12, +12]`、既定 0
- **マスタのオートゲインを持たない**（`REQ-VEL-012`）。`MIX` と喧嘩する
- `SOLO` がオンの帯域があるとき、それ以外の `level_i` を 0 にする。`x` も
  落とす（足している層だけを聴くのが目的なので）

## スムージング

`velour-core` は**ブロックごとに目標値を受け取り**、内部で 1 次のスムージングを
掛ける（時定数 **5 ms**）。対象はゲイン系（`level_i`、`mix`、`output`、
`makeup`）と `k`。

- **フィルタの係数はブロック単位で再計算する。** `FOCUS` を動かしている間だけ
  再計算が入る。サンプルごとに係数を作り直すと、それだけで予算を食う
- `β` と `h` もブロック単位（正規化係数の再計算がそこに乗る）
- **`Voices` に相当する不連続な切替が無い**のでクロスフェードは要らない。
  オーバーサンプル倍率の切替だけが不連続で、そこは段の状態を保持することで
  対処する（上記）

## 耳で詰める定数

`REQ-VEL-020` でプリセットを持たないと決めたので、**既定値がそのまま製品の顔**。
実素材（男声 / 女声 / ラップ / ささやき）で決める。

| 何 | 仮の値 | 判断の材料 |
|---|---|---|
| `A_REF`（正規化の参照振幅） | 0.25 | ドライブが「量」を変えないと感じる範囲に素材が入るか |
| `k` の上限 | 8 | 音として足りるか。**上げるなら折り返しの表を読み直す** |
| AIR の入力の上蓋 | `0.25 × sr` | 上げると `k` の上限を下げることになる。この 2 つは交換関係 |
| 帯域ごとの `β` / `k` 倍率 | 表のとおり | BODY が穏やか、AIR が細かい、と聞こえるか |
| TEXTURE の 3 アンカー（`β` / `h`） | 表のとおり | Warm と Edge が別の製品のように聞こえるか |
| TEXTURE の帯域トリム 9 個 | 表のとおり | どの位置でも帯域バランスが破綻しないか |
| `EMOTION` の `REF_DB` / `RANGE_DB` / 係数 3 つ | −18 / 12 / 0.50, 0.40, 0.30 | 声量差で質感が変わるのが**分かるが不安定でない**か |
| `DENSITY` の `T` / `R` の写像 | −6−24d / 1+3d | 振り切って「平坦だが死んでいない」か |
| Guard のしきい値 2 つ | −8 / −14 dB | 普通のボーカルで動かず、痛い瞬間だけ動くか |
| Guard の `SLOPE` / `MAX_DB` | 1.0 / 18 dB | 引きすぎて AIR が消えないか |
| `bias` の `6 dB` / `1.5` | — | 振っても「量」が変わらないと感じるか |
| 各帯域ノブの既定値 | — | 素で挿して**良くなったと分かる**か |
| `MIX` の既定値 | 0.5 | 同上 |

## 検証

原理から決まっているもので、テストが書けるもの。

| 何 | どう測るか | 根拠 |
|---|---|---|
| `MIX` = 0 でビット一致 | 乱数列を通して入力と `==` | `REQ-VEL-001` |
| 全帯域 0 でビット一致 | 同上 | `REQ-VEL-001` |
| L == R でビット一致 | モノ信号を 2 ch に入れて L と R を `==` | `REQ-VEL-011` |
| `k` を振ってもレベルが動かない | `A_REF` の正弦、`k` を下限〜上限、出力 RMS が **±0.3 dB** 以内。全 `(β, h)` で | `REQ-VEL-003` **ゲート** ✅ |
| 参照から外れたときのずれ | `A_REF × 4` と `× 0.25` での実測値を固定する | `REQ-VEL-003` ✅ |
| `β` で H2/H1 が単調増加 | 正弦、DFT で H2 と H1。`β` = 0 では H2 が出ない | `REQ-VEL-003` ✅ |
| `k` で H3/H1 が単調増加 | 同上 | `REQ-VEL-003` ✅ |
| `h` で同じ `k` の H3/H1 が増加 | 同上 | `REQ-VEL-004` ✅ |
| DC が残らない | **生成器の出力**の平均が 1e-4 以下。シェイパ単体では `β` > 0 で DC が出る（だから出力側 HPF が必須） | `REQ-VEL-002` ✅ |
| 各帯域が自分の真ん中で一番大きい | 200 Hz / 1.5 kHz / 10 kHz で、担当外の帯域が 10 dB 以上下 | `REQ-VEL-002` ✅ |
| `FOCUS` が端を 1 オクターブ動かす | BODY の 90 Hz が `focus` = ∓1 で 10 dB 以上変わる | `REQ-VEL-002` ✅ |
| `FOCUS` で AIR の上蓋が上がらない | 18 kHz が全 `focus` で 6 dB 以上下 | `REQ-VEL-002` ✅ |
| 係数の入れ替えで状態が消えない | 走行中に端を動かして段差が出ない | `REQ-VEL-002` ✅ |
| 折り返しが −60 dB 以下 | **生成器を通した**最悪ケース（AIR に 11 kHz、`k` 上限、硬い膝）で 20 kHz 未満に落ちる非調和ビンの最大。**−63 dB** | `REQ-VEL-005` ✅ |
| 2x と 4x の差 | 素のカーブに 10 kHz（帯域制限なし）。**4x −58 dB / 2x −44 dB** | `REQ-VEL-005` ✅ |
| アップサンプラのイメージ | 1 kHz を 2x に上げ、`48 kHz − f` のイメージが −70 dB 以下。**位相の割り当てを守るのはこのテストだけ** | `REQ-VEL-005` ✅ |
| 各段の阻止域 | 阻止域内の正弦を入れて減衰を測る。**≥ 70 dB** | `REQ-VEL-005` ✅ |
| 2x / 4x の切替でクリックが出ない | 定常正弦の途中で切り替え、サンプル間の跳びを見る | `REQ-VEL-005` ✅ |
| Guard が入力ゲインに依らない | 同じ素材を ±12 dB で通し、`reduction_db` の系列を比較 | `REQ-VEL-006` |
| `amount` = 0 で Guard が無効 | `reduction_db` が全区間 0 | `REQ-VEL-006` |
| `density` = 0 でコンプが無効 | メイクアップとリダクションが 0 | `REQ-VEL-007` |
| 極端値で非有限を出さない | 全パラメータを範囲外まで振る | `REQ-VEL-016` |
| ブロックサイズ非依存 | 32 / 512 / 2048 で出力が一致 | `REQ-VEL-017` |
| 予算 | criterion、4x / 512 / 48 kHz で 533 µs 以内 | `REQ-VEL-016` |

**ゲートは 4 行目**（`k` を振っても基音が動かない）。ここが崩れると
`REQ-VEL-009` の 4 層直交が成立せず、パラメータの意味づけごとやり直しになる。
Doubler でピッチシフタをゲートにしたのと同じ扱い（`roadmap.md`）。
