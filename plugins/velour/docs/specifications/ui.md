## 設計方針

**足したものが見える。** 並列生成（`REQ-VEL-001`）を選んだ最大の UI 上の見返りが
これ。原音と、原音に足している倍音を**別の層として同時に描ける**。分割型なら
「処理前」と「処理後」の 2 枚しか無く、差分は目で引き算するしかない。

**約束が見える。** この製品は「前に出るのに痛くならない」を約束する。その約束を
守っているのは保護検出器（`REQ-VEL-006`）で、普通のプラグインではそれが働いた
瞬間に画面上で何も起きない。**Guard が働いたら区画が沈む。**

**普段触るのは 8 つのノブだけ。** パラメータは 22 個あるが、常用するのは
`DRIVE` / `BODY` / `PRESENCE` / `AIR` / `TEXTURE` / `DENSITY` / `MIX` /
`OUTPUT`。残りは Advanced タブ。

**同じ音量で A/B できる。** サチュレータで一番使う判断が「これは良くなったのか、
ただ大きくなっただけか」。IN と OUT を常時並べる。

## Band Field

画面の主役。横軸は対数周波数、縦軸は dB。3 つの層を重ねる。

```text
 +12dB ┌──────────────────────────────────────────────┐
       │        ╱‾‾╲    ← 付加された倍音だけ            │
       │   ╱‾‾‾╲    ╲___                              │
       │ ▓▓▓▓▓▓ │▓▓▓▓▓▓▓▓▓▓│ ▓▓▓▓▓▓▓▓▓▓▓              │
       │  BODY  │ PRESENCE │    AIR                    │
       │ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  ← 原音     │
 −60dB └──────────────────────────────────────────────┘
        20    100   500    2k    5k     20k
```

| 層 | 何 | 色 |
|---|---|---|
| 一番下 | **原音のスペクトラム**（`REQ-VEL-018`） | `FOREGROUND` を薄く。既存の `.analysis` と同じ約束 — 信号はニュートラル |
| 中間 | **3 帯域の区画。高さがその帯域の量** | `ACCENT_DEEP` → `ACCENT_BRIGHT` の 3 段。設定はアクセント |
| 上 | **生成バスだけのスペクトラム** = 足している倍音そのもの | `ACCENT` の線 |

区画の色を濃淡で刻むのは Doubler の Voice Field と同じ手。**色相は増やさない** —
アクセントだけが色を持つ、が保てる（`crates/nxe-ui/README.md`）。

### 何が図で読めるか

- **`FOCUS`** — 3 区画がまとめて左右にスライドする。ノブの数値では絶対に
  伝わらない情報（`REQ-VEL-002`）
- **Guard** — 働いた瞬間にその区画の上端が沈み、`ACCENT` から `MUTED` 側へ
  寄る。**沈んだ量がリダクションそのもの**（`REQ-VEL-006`）
- **`DRIVE` と帯域の量の違い** — `DRIVE` を上げると上の線（倍音）だけが伸び、
  区画の高さは変わらない。帯域ノブを上げると区画が伸びて線も一緒に上がる。
  **`REQ-VEL-009` の直交が図で確認できる**
- **`SOLO`** — その区画だけが `ACCENT`、他は `SUBTLE` に落ちる

### 操作

- **区画を縦ドラッグ** — その帯域の量（メインの `BODY` / `PRESENCE` / `AIR` と
  同じパラメータ）
- **下端のレールを横ドラッグ** — `FOCUS`。**「区画の外側」ではなくレール**に
  したのは、区画が全高になった瞬間に縦と横の区別が付かなくなるため。常にそこに
  ある帯なら常に掴める（`crates/nxe-ui/README.md`）
- `Shift` = 微調整、ダブルクリック = その帯域の既定値に戻す
- ドラッグ中はホストへジェスチャー開始／終了を通知する
- ポインタが乗った区画の index が通知される（Advanced 表と伝達曲線の小窓を
  連動させるため）

Doubler と同じ「図が主役、ノブは図を動かす道具」。

### 描かないもの

- **区画に周波数の数値を書かない。** vizia の `draw_text` は view 自身の
  テキストしか描けない。目盛りは Doubler の Filter View と同じく**呼び出し側が
  `Label` を絶対配置**する
- **伝達曲線を重ねない。** 軸が違う（周波数 vs 振幅）。小窓に分ける

## 伝達曲線の小窓

`BandField` の右。1 本の曲線だけ。**既存の `CurveView` をそのまま使う**（帯も
ハンドルも解析も渡さない）。

- 表示するのは **SOLO 中の帯域 → 無ければホバー中 → どちらも無ければ PRESENCE**。
  PRESENCE をフォールバックにするのはこの製品の主戦場だから
- 下にその帯域の名前を出す
- **読み取り専用。** 曲線を掴めるようにしても書き込む先が `(b, k)` の 2 つに
  分かれていて、どちらが動いたのか分からなくなる
- 線形ゲインを正規化した（`REQ-VEL-003`）ので**見た目はほぼ直線**。読めるのは
  **非対称**（上下の膨らみの差 = `b`）と**先端の丸まり**（= `k`）。
  `TEXTURE` を回したときに何が変わったかを見る窓であって、歪みの量を測る窓では
  ない

## メーター

右の縦帯。**タブで消えない**。

- **IN と OUT の 2 本**。それぞれ L / R（`REQ-VEL-011` の性質上、モノ素材では
  2 本が完全に一致する — それも情報）
- ピークホールド付き。値は dB で渡す（`nxe-ui` の `Meter` の契約）
- **リダクションのメーターは持たない。** Guard は `BandField` の区画が沈むこと
  で見えていて、同じ情報を 2 箇所に置く意味が無い

## タブ

`SegmentedControl` で 2 枚。

### MAIN

```text
  DRIVE   BODY   PRESENCE   AIR   TEXTURE   DENSITY
    ◯      ◯       ◯       ◯      ◯        ◯

                    MIX    OUTPUT
                     ◯       ◯
```

`TEXTURE` のトラックに **Warm / Clear / Edge** を刻む（`REQ-VEL-004`）。
離散モードを捨てた代わりに名前という手がかりをここで返す。

### ADVANCED

```text
          BIAS      TEXTURE    SOLO         FOCUS      ◯
  BODY   ──●──      ──●──      [ ]
  PRES   ──●──      ──●──      [ ]        GUARD
  AIR    ──●──      ──●──      [ ]          HARSH  ──●──
                                            SIB    ──●──
                                          EMOTION  ──●──
                                       OVERSAMPLE [2x][4x]
```

- `Bias_i` / `Texture_i` / Guard / `EMOTION` は `Bar`（双極は `Bar::bipolar`）
- `SOLO` は **`.segment` を当てた `Label`** に `checked` と `on_press`。
  `crates/nxe-ui/README.md` の通り**新しいウィジェットは要らない**
- `FOCUS` は小さい `Knob`（双極）
- オーバーサンプルは `SegmentedControl`

行にポインタが乗ったら `BandField` の対応する区画をハイライトする。Doubler の
`Ui::hovered`（1 つの値、両方向）をそのまま踏む。

## 必要なコンポーネント

### そのまま使える（変更なし）

| コンポーネント | 単位 | 使うところ |
|---|---|---|
| `theme` / `font` / `icon` | UI-1 / UI-2 | 全体 |
| `input::Gesture` | UI-3 | 全体 |
| `Knob` | UI-4 | メインの 8 個、`FOCUS` |
| `Bar` | UI-5 | Advanced の双極 7 個 |
| `SegmentedControl` | UI-6 | タブ、オーバーサンプル |
| `CurveView` | UI-10 | 伝達曲線の小窓（曲線だけ） |
| `.segment` を当てた `Label` | — | `SOLO` × 3 |

**`CurveView` に手を入れない**のは意識した判断。主役の図に必要なもの（掴める
区画、横ドラッグ、Guard の状態、解析 2 本）を足すと表面積が倍になり、Doubler の
Filter View がその複雑さを何の見返りも無く払う。**手を入れずに 2 個目の
利用者が付く**のは、今の契約が正しかったことの確認になる。

### 新しく作る

| コンポーネント | 単位 | 何 |
|---|---|---|
| `BandField` | `UI-13`（新設） | 主役の図。下記 |
| `Meter` | `UI-8`（既存の計画。**ここで初めて使う相手が現れた**） | バー 1 本 + ホールドの印。縦・横。目盛りは位置だけ受け取り、文字は呼び出し側 |

`nxe-dsp` 側:

| | 単位 | 何 |
|---|---|---|
| `Level` | `DSP-4`（新設） | peak + RMS、バリスティクス付き。IN / OUT メーターの値 |
| `Spectrum` | DSP-3（既存） | **2 インスタンス**。const generic なので新規コードは無い。バンド数は 32 → 48〜64 に上げたい（倍音が見える解像度）。**コストは実測してから決める** |

**`ToggleSwitch`（`UI-9`）は Velour も使わない。** `.segment` を当てた `Label`
で足りる。2 個目のプラグインでも要らなかったので、**計画から落とす候補**。

### `BandField` の契約

`PolarField` と同じ形 — 領域知識を持たず、値とコールバックだけ。

```rust
BandField::new(cx, bands, analysis_dry, analysis_wet, marks, |cx, gesture| ...)
    .highlight(lens)   // 外から 1 帯域を指す（SOLO / ホバー連動）
    .focus(lens)       // 下端のレールが書く値。繋がなければレールは死んでいる
```

```rust
pub struct Band {
    /// 区画の左右。正規化した x（呼び出し側が Hz から写す）
    pub low: f32,
    pub high: f32,
    /// 区画の高さ。0..=1
    pub level: f32,
    /// 鳴っている量と設定した量の差。−1..=1、全体の高さに対する割合
    /// （`SPK-10` で符号付きにした。Velour は負の値しか渡さない）
    pub delta: f32,
    /// アクセントの濃淡。0 が deep、1 が bright
    pub tint: f32,
    pub soloed: bool,
}

pub enum BandGesture {
    Begin(usize),
    Change { index: usize, level: f32 },
    End(usize),
    Reset(usize),
    Hover(Option<usize>),
    /// 区画の外側の横ドラッグ。`PolarField` のアンカーと同じ構造
    FocusBegin,
    FocusChange(f32),
    FocusEnd,
    FocusReset,
}
```

- **Hz の写像は呼び出し側が持つ。** ウィジェットは正規化した x しか知らない
  （`CurveView` と同じ）
- **目盛りの文字はウィジェットが描かない。** `marks` は位置だけ受け取り、
  文字は呼び出し側が `Label` を絶対配置する
- **ドラッグ中はローカルの値を先に動かす**（`CurveView` と同じ）。入ってきた値は
  次の更新で必ず上書きする。`PolarField` が楽観的更新をやめたのは**呼び出し側が
  別のパラメータと突き合わせてクランプする**ためで（Spread による Pan の上限）、
  その場合だけ `Data::same` が「変化なし」と見て修正が戻らない。`BandField` が
  書く量と `FOCUS` はどちらも素の `0..=1` で、突き合わせる相手がいない
  （`.agents/rules/vizia.md`）
- **ダブルクリックは掴んでいる状態に頼らず、その場を当たり判定する。** 掴みが
  まだ開いているかはイベントの順序に依存し、「たいてい効くリセット」は効かない
  リセットより悪い（`PolarField` と同じやり方）
- **区画が重なることを許す。** 重なった領域は**中心が近いほう**に属する。並列
  生成器は境界を共有するので、「宣言順で先のほう」では意味が決まらない
